---
name: doc-compact
description: Dedupe and compress persistent project rules or docs while preserving meaning; use on every rule write and documentation cleanup.
---

Persistent docs are a cache for future decisions. Before writing: discard facts derivable from code/search; reference an existing authority; merge duplicates; put rare details in a task-specific doc; add only a reusable, non-obvious rule. Prefer discard > reference > merge > compact > append.

One authority per fact: AGENTS routes and universal invariants; PROJECT stable gameplay; ARCHITECTURE locator; STATUS open issues; DECISIONS durable choices; specialty docs task rules. Do not keep completed work or history as active guidance.

For every rule write, prune nearby obsolete, repeated, or verbose text. Keep conditions, negations, units, approval boundaries, and behavior intact; avoid opaque shorthand. Future rules follow this same policy. Before deleting a doc, check references and unique content. Verify routes, links, authority, contradictions, and the default read cost. Do not run game tests for docs-only edits.
