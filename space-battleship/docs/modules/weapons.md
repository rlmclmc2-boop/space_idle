# 武器

## CONFIRMED · 原表

总览!A8:A9 与 equipment!B44/B64/B84：激光/火炮单目标；导弹按 para1 发射，优先锁定不同敌人，目标不足时允许多枚锁定同一敌人。伤害、冷却和弹速的字段及数据范围只见 [DATA](../DATA.md)。解锁规则见 [progression](progression.md)。

## CONFIRMED · 当前代码

- Phase 5：玩家剩余冷却唯一存于`BattleGame.cooldowns["weapons_<index>"]`，名称键不再读写；冷却不进入存档。卸下仅移除本槽键，剩余同名槽不受影响（U-016已获准修复）。敌方逐装备cooldowns数组保持原样。

- 2026-09-14 用户澄清“清零”是发射计时进度归零：`change_state(TRAVEL)` 将玩家武器剩余冷却设为当前等级完整CD；普通波次结束、死亡后退完成及开关卡均适用。前进不倒计时，下次遭遇等待完整间隔才开火。暂停与战斗内升级仍保留冷却。

- 2026-09-14 用户要求：`targets(damage_type)` 优先选择 armourType 与武器伤害类型不同的活敌，同组按 x 升序、距编队中线距离、slot 排序；全部抵抗时仍正常攻击，无参数调用保持原位置排序。玩家每次武器冷却到零时，导弹无论目标数量都按 para1 发射，先按该列表锁定不同目标，目标不足后循环复用目标；同轮导弹使用小幅上下错位，避免锁定同一目标时画面重叠；激光/火炮仍各发一枚。玩家开局与敌机初始冷却均为武器CD。
- `fire()` 创建字典弹体，携带目标对象、飞行方向、伤害、类型、速度、敌我、武器键。弹速乘 defaults.projectilePixelsPerUnit。目标死亡/移除时，仅导弹可按弹体 type 的抗性优先顺序重定向到活敌，并优先选择尚未被其他玩家导弹锁定的目标；没有可锁目标则解除锁定、保持最后飞行方向直至出屏，激光/火炮不换靶。下次开火仍重新选取活敌。来源：2026-09-13 用户本次换靶及继续飞行指令；抗性优先来自2026-09-14用户指令，同优先级位置顺序等剩余边界见 U-006。
- `tick_projectiles()` 在战斗、巡航、通关等待及死亡后退期间更新；普通敌舰死亡、普通波次结束不清除已发射弹体，敌方弹体仍可命中存活玩家。2026-09-14 用户重新定义BOSS战后，改为最后一场敌群全灭时立即清空所有武器弹体（前置大型舰及最后一场尚有其他活敌时不清弹）：`hit_enemy()` 清空敌我在途弹体，`tick_projectiles()` 立即停止处理旧弹体快照，避免同帧残弹击杀玩家导致后退、跳过通关判定；替代此前 BOSS 死亡保留弹体的规则。出屏判定包含32像素尾迹余量，绘制直接使用保存的方向，不依赖失效目标。
- 敌机每个 equipment 条目每轮只发一发；玩家导弹的 para1 数量规则不套用于敌机。当前编队没有引用敌方导弹；未来启用前见 U-011。
- 同船 equipment 中同名武器重复时，按条目顺序沿舰体上下对称、等距分布发射位置，单个武器仍从原位置发射。来源：2026-09-14 用户发射位置指令。实现 `enemy_weapon_offset()` 复用当前舰体半高39与普通舰/BOSS绘制缩放，允许舰缘偏移；只改变弹体起点及由此计算的方向，不改数量、冷却或伤害。验证：`../test/test_enemy_weapon_positions.gd`。
- `ShipDatabase.enemy_weapon()` 将 `_mon`/`-mon` 去掉映射同名玩家武器：敌方固定读取基础行（equipment 的1级行），整行缺失则采用玩家1级整行；已有行仅补 null 的 dmg/cd/dmgtype/para1/para2。para3 不在补全字段内。
- 2026-09-14 用户确认：mon.equipment 的 `name|数量` 没有等级概念，数量必须为正整数；导入按顺序展开为多个仅含 name 的武器条目，每件独立冷却、每轮一发，同名条目共用现有上下分布。运行 JSON 已转换，增量缓存版本提升以重新解析旧投影；U-002/U-003 已解决。
