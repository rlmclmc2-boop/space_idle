# Galaxy

Authority: `config_excel/galaxy.xlsx`, `galaxy_build.xlsx`, `galaxy_config.xlsx`; unlock level comes from `unlock.xlsx`, plus the Galaxy's conquered-planet condition. Asset paths are owned by the art workflow: [assets](../assets/galaxy/v3/README.md).

- `locked → available → exploring → developing → complete` retains existing save/assignment IDs; “exploring” now means construction. No assigned, unlocked crew means no work, finishing countdown, upgrade, cooldown or new random selection. Core exists at initialization; functional buildings expand from it.
- The complete blueprint is generated once and saved. Building types use the existing normal shuffle bags and special-cycle rule, before any construction. Selection chooses randomly among eligible empty nodes in the nearest depth, with all prerequisites built. Only one new building constructs at a time. An unavailable candidate consumes neither RNG nor a type.
- Existing `explore_work_total` is divided equally across functional nodes. Each selected node performs its share at `explore_power_base + crew × explore_power_per_crew`, then finishes for `construction_time` game-seconds. `build_interval` is the dispatch delay before each new node. No values are recalibrated. Serial finishing/dispatch adds time compared with the former overlapping exploration/building loop. Multiple crew speed work and upgrades; finishing seconds retain their prior fixed rate.
- After every functional building is active, shared upgrade work uses the existing base/per-crew rate and concurrent cap. Effects apply only to active/upgrading current levels. All configured nodes at maximum level complete the Galaxy. `GalaxyEffectAggregator` remains the sole effect owner; automated output never feeds its own income base.
- Only supplied online game time advances logic; caller owns pause/chrono conversion. Hidden batches retain their original crew count. Assignment changes settle already-earned time before changing crew; save v3 persists unprocessed online time and its crew count, never wall-clock catch-up. No new business-triggered save is added.
- Save v3 preserves the actual blueprint, node work, construction/upgrade states, RNG and compact map. Existing v2 buildings keep types, levels and timers by slot ID; legacy grid core entries are excluded as before. Old coordinates move to the connected blueprint. Earned exploration is prepaid work on remaining nodes; established buildings/effects are not removed. Multiple legacy construction sites finish serially. Other profile systems are untouched.

## Renderer contract

`region.blueprint` is authoritative; `region.layout_snapshot()` returns a detached JSON-safe copy with state. Renderer must not regenerate placement, select types or mutate this data. `galaxy_changed:{key}` remains the notification; `building_revision` tracks discrete building transitions. Read progress on the existing visible UI cadence. `layout_version` describes layout schema, not progress.

- `core_id="core"`; `core` is a separate active node. `nodes` contains exactly the configured functional slot count (first Galaxy: 30).
- Nodes: integer `id` (compatible with `region.slots[id]`), stable `node_id="node_%03d"`, `parent_id` (`-1` for core), `depth`, `type`/`planned_type`, `world_pos:[x,z]`, `footprint:[width,depth]`, `rotation_y` in radians, `visual_seed`, `connections` (undirected node IDs), `requires` (built predecessor IDs). Core integer ID is `-1`.
- Godot world units, ground Y=0. Grid centers are 26 units apart. Core footprint 32×32; functional maximum footprint 14×14, centered at the node, including model extensions. Orient model using `rotation_y`; do not scale beyond the reserved footprint. The first Galaxy extends to approximately ±104 units; camera must fit the whole blueprint including footprints.
- `edges`: `{from,to,width,path:[[x,z],[x,z]]}`. Paths stop at footprint boundaries, width 2, no third-party footprint intersections. Use these for connections/traffic. The historical compact fog map is presentation compatibility data, not the authoritative construction graph.
- Snapshot node state: `status` (`empty/constructing/active/upgrading`), `level`, normalized `progress` (initial construction), normalized `upgrade_progress`. Empty nodes have planned types but no effect. Panel construction progress must call `region.node_progress(slot)`, not infer it solely from the finishing countdown. `region.slots` retains numeric IDs and world positions for existing consumers.
