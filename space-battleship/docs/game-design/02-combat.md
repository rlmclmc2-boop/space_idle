# 02 战斗规则与命中

[回唯一入口](README.md)。本章所有伤害均在native核确认有效命中时直接结算。攻击诞生先确定来源参数与随机判定；是否有飞行等待由武器规则决定。我方炮在发射调用内立即完成命中与扣血，激光/导弹则等真实接触，均不预扣尚未发生的命中。

## 1. 战场与身份

`EncounterId` 标识本次编队实例；`CombatantId` 标识本次敌舰；`ModuleId` 标识实际槽位/无人机武器源；`AttackId` 标识一次规范攻击；`CarrierId` 标识一枚弹体；`HitId=(EncounterId, AttackId, EmitterId, hitOrdinal, targetId)` 标识一次可去重的接触。EmitterId统一覆盖普通弹体、光束和无弹体计时释放；CarrierId是可移动载体的EmitterId子类。相同 enemy 配置 ID 在同一编队可出现多次，不能作实例 ID。槽位换装替换模块代际，不能让旧延时任务误绑新装备。

普通阵型保留槽位和空位，按尺寸占用逻辑格；显式阵型保留 `slot_index` 及 `(x,y)`，当前超空间最多15槽。配置中的尺寸控制几何与舰型，不额外乘生命。普通旧表注释“10格”不能覆盖现行15槽。逻辑几何至少输出舰体包络、护盾边界、炮口、接触表面、朝向；所有坐标为逻辑战场单位，再由视口变换成像素。现行 572 宽的战场尺寸及边界常量迁入 `battle_rules.xlsx`，UI 实际显示高与逻辑高不同不能混用。

`combat_setup.gd`的逻辑姿态函数从同一位置与舰体形状给native核碰撞输入、给表现器插值姿态。炮口、敌舰进入位置、护盾命中点不可分别从截图尺寸推算。静态舰体烘焙、模型、GPU网格、尾迹可复用；战斗规则不读取节点 transform、绘制帧或动画是否完成。

目标优先级：存活敌舰；有盾时按盾类型、无盾时按装甲类型判断抗性，先选不抗当前伤害类型者；再选 y 更大者（更靠前）；再按 `abs(slot-4.5)` 小者；最后 slot 小者。`4.5`保留为固定槽位排序锚，15槽也不改成几何中心。新实现把排序键独立定义，稳定 ID 作最终确定性兜底。

## 2. 数值输入与敌方缩放

伤害类型为 `0=中性/无类型抗性、1=能量、2=物理`。匹配型抗性基线减伤 50%，不匹配不减。盾和装甲类型独立，不能把盾的减伤用于穿盾余伤的装甲。

主线关卡 k 有 n 个战点，第 j 个（0起）倍率：

```
entry = 显式 entryAtkRatio/entryLifeRatio（如有）
        否则 k=1 时1，否则上一关相应终点倍率
u = n<=1 ? 1 : j/(n-1)
ratio = entry + (本关终点倍率-entry)×u
maxHp = ceil(mon.health × lifeRatio)
maxShield = ceil(mon.shield × lifeRatio)
shotBase = ceil(enemyWeapon.dmg × mon.dmgMultiple × atkRatio)
```

资源倍率也按数据库该类别的战点插值计算，超空间使用所选主线关的终点战斗倍率及另行绑定的资源参考关。敌方武器先读取精确武器键（`laser_mon` 与 `laser-mon` 是不同合法行），缺行/空字段才使用 `enemy_weapon_base`；玩家等级、玩家攻击成长不泄漏到敌方回退表。

玩家属性组合见 [03](03-progression.md)。`AttackSpec` 保存产生这次攻击时的等级、攻击值、伤害类型、暴击结果、传说选择、强化效果、连锁/连发计划和运动参数。实际命中再读取目标存活、盾恢复、当前抗性、反应装甲、制导层等状态。攻击中途升级不回写旧 `AttackSpec`。连续光束也持有一次攻击源快照，周期跳单独结算。

## 3. 四类基础武器

| 武器 | 类型/1级基础伤害 | 周期 | 运动与命中 |
|---|---|---|---|
| laser | 能量 / 350 | 1.5秒 | 单个锁定目标；速度30×玩家换算28逻辑单位/秒；接触目标防御几何才命中 |
| missile | 物理 / 每枚170 | 每批2.4秒 | 每批4枚，轮转分配存活目标；目标少仍发满；逐枚离管0.12秒间隔；每枚接触各结算一次 |
| cannon | 物理 / 1200 | 3.5秒 | 我方普通炮发射时立即命中有效主目标；Higgs在同次调用结算冻结贯穿线。速度40×28×火炮速度倍率不作为我方炮伤害等待时间；周期末0.9秒蓄力包含在周期内 |
| longLaser | 能量 / 每跳35 | 跳间隔0.25秒 | 先蓄能1秒；连接存活目标后周期跳；命中持续时间2秒增长到3倍 |

非1级先按装备成长公式计算；表列数值不另加隐藏导弹倍率。首次进入战斗按完整周期开始普通武器倒计时，不默认立即开火。冷却缩短只能通过正式属性输入，不能用 UI 动画完成回调重置。

持续光束在计划命中时刻 `tHit` 计算蓄力增幅 `min(1+(maxMultiplier-1)×duration/rampSeconds,maxMultiplier)`；rampSeconds 为0则直接取最大值。计时按计划跳时刻，不用大步末尾时间给全部跳同样倍率。来源死亡/卸下、普通光束目标死亡立即断开；普通重锁形成新攻击并重置相关持续时间。无尽光束例外见传说表。

### 3.1 导弹运动合同

离管初速240；0.22秒开始平滑加速，0.65秒达到表中巡航速度；0.4秒开始制导；最大转角速度4弧度/秒。离管偏转12度交替左右；边缘55单位保护区及向前Y门槛-0.12防止初始出屏。目标在120距离内且角差>0.3弧度时刹车，指导速度不低于60，刹车因子0.7。以运动线段到目标的最小距离和5单位命中半径检测，不能只比较帧末点以免穿透。锁定飞行寿命4.5秒；已经飞出的失锁弹体直飞，不重锁，30秒或越界清理。未离管导弹可按0.12秒重选缓存换无效目标。上述全部是 `weapon_motion` 的可调规则。

发射者后来死亡不会自动抹去已独立飞出的普通弹体；持续源、待离管和延迟攻击要检查模块代际。跨波清理与最终击杀清理按航程终止边界执行，不能让旧EncounterId攻击误认新生敌舰；非终波已发敌弹仍可命中同一玩家，不能仅因当前EncounterId变化把合法敌弹全部判无效。

### 3.2 我方炮、Higgs、飞行弹体与连锁

**我方普通炮**：发射时先检查主目标仍在本场且存活，创建攻击/表现记录，在同一逻辑时刻发出impact并调用命中结算，随后无待飞行的炮弹业务实体。目标防御、死亡、掉落和命中衍生效果当次更新，不等待轨迹动画或速度/距离计算出的未来时刻。连发或额外攻击中的普通炮也在其实际发射调用时立即命中；它们的延迟来自触发安排，不来自弹头飞行。

**Higgs炮**：仅符合主触发权限的炮建立Higgs贯穿。发射时冻结起点、瞄准方向、到战场边界并向外延伸一个full_width的线段，以及当时各活敌的命中点。宽度`full_width=max(12,rail_trail_width)×max(1,1+area_bonus)`；点投影在线段范围内且到线段距离≤full_width/2才入候选，不把敌舰完整包络与射线相交当成此规则。候选按冻结命中点到起点距离平方升序排列，在同次调用依次emit impact并命中，每目标仅一次；每次仍由命中函数检查存活。若过程中遭遇终止/清场使该次射线失效，就停止剩余候选；最后退役射线。整条射线在同一发射逻辑时刻处理，不按弹速等待前后目标分别到达，也不在下一帧重采样敌位置。

这些是main实际玩家入口的行为：`battlefield.gd`装配`presented_battle_game.gd`，其`launch_player_attack`直接处理普通炮和`advance_higgs_projectile(shot,0.0)`；`game.gd`的freeze/advance函数定义冻结线和候选。现有native的`kind==1 && !hostile`分支同clock执行impact→hit_enemy→retire；Higgs按上述规则补入同一核。

**飞行弹体**：普通玩家laser以及敌方炮/激光保留飞行，沿逻辑路径检查实际接触后扣血；敌炮不套用我方炮的即时命中规则。导弹按3.1执行。**连锁载体**无论由哪种主武器触发，都独立以720速度到达额外目标才结算；即时炮的主命中不会把其连锁也改成即时。一次攻击的同一连锁机会只能消费一次。连续光束的连锁连接与每跳伤害分别处理，死目标断开，不在每个绘制帧重新抽目标。

## 4. 命中流水线

```
检查载体所属场次的存续规则、目标generation/存活、HitId尚未处理
→ 将目标恢复和到期防御推进到 hitTime
→ 读取该 AttackSpec 与此次接触位置
→ 处理黑洞吸收/闪避等截获
→ 计算命中时动态倍率与抗性
→ 分配盾/装甲/保护/延期损伤
→ 直接更新受击、死亡、衍生事件并生成掉落
→ 写入 HitReceipt 反馈，宿主在本次推进后取走
→ 画面消费 HitReceipt（数字、火花、盾波、音效）
```

命中被拒绝不重新抽取已在攻击出生时确定的暴击/爆伤结果，不产生重复受击或掉落。统计记录实际损失，不记超过剩余容量的部分。死亡只有由正生命跨到零的那次命中拥有一次 `DeathReceipt`。连锁/爆炸通过同时间队列排入，禁止递归直接调用到无限深。

### 4.1 敌方盾、装甲与反应装甲

有效命中先把护盾按时间补到命中时刻，再更新 `lastHitTime`，即使该次盾已空仍重置其恢复等待。恢复量：`maxShield × shieldRecovery × max(0,有效恢复时间)`，有效恢复时间是上次更新时间与本次之间、晚于 `lastHitTime+shieldDelay` 的那部分；钳到最大盾。死亡目标不恢复。

设原始伤害 R、盾抗性系数 `fs=1-r`（不匹配为1）：盾扣 `min(shield,max(1,R×fs))`；消耗的原始伤害为盾扣量/fs，剩余原始伤害才进入装甲，不能把盾减过的余量再次当成未经减伤伤害。装甲扣 `max(1,ceil(Rremain×fa))`。fs=0 时不做除零，视为该层完全阻挡。无剩余伤害不凭空制造1点装甲伤害；原基线最小伤害边界须在测试中固定。

反应装甲仅 `reactiveReduction=1` 生效。距上一齐射起点≤0.16秒是同一齐射，复用当前层。超过0.16但不超过2.2秒的新齐射加一层，上限3；超过2.2秒重置0层。每层减原始伤害20%，依次100%、80%、60%、40%。这是按有效命中时间分组，不按发射帧分组。数据迁入战斗规则表。

精准制导为每目标、每批首次有效命中记录层数；本批伤害系数固定为 `1.5^之前层数`，同批后续导弹不继续加层；新批+1，无配置上限时不设隐藏上限。敌人死亡清层，不能带到下一只同ID敌舰。

### 4.2 玩家多防具承伤

玩家装甲和盾都由启用槽位组成。每模块保存最大值、已经损伤值、盾受击时间、记忆保护、周期护罩和效果状态。合计生命是投影，不能同时存合计生命和模块剩余两份可独立写数据。

每次来袭尝试使全局受击历史+1，即使黑洞/闪避吸收。未被截获后依次执行：无人机统御减伤 → 全局分支原伤倍率 → 周期护罩 → 记忆保护 → 全部护盾模块 → 全部装甲模块。真正到达舰船防御层的命中重启所有盾模块恢复延迟，保护层吸收不意味着“没被打”。

同层按各模块当前可用容量比例分配原始伤害，再分别应用模块匹配抗性及延期比例。设模块可用A、层总可用T、原始剩余R、匹配系数f、延期比例d，则分配伤害 `P=R×A/T×f`；盾最多承担 `A/(1-d)`，即时部分 `taken×(1-d)`，延期部分 `taken×d`。换算已吃掉的原始伤害 `taken/f` 后，把余伤重新分配给其他未耗尽盾，直到没有盾容量或原伤耗尽；之后才到装甲。最后装甲允许完整过杀再钳零。防止混合抗性/延期导致有盾仍掉血。每层只在整次来袭结束作一次既定取整，不每次再分配都向上取整。

普通护盾恢复为容量×para2/秒，受击后等para3，基线0.3与2秒。装甲不带普通恢复，记忆材料单独恢复。容量改变使用03第1.4节的分操作HealthAdjustment：普通付费升级补容量差，换装/明确refit保留比例，研究/强化等保持绝对值并钳上限；不能统一套保比例或满血。新建战斗与撤退结束才按规则重置满防御。

## 5. 全局强化与六种基础效果

强化消耗碎片，购买等级G，永久附加等级B，有效等级E=G+B。费用取购买等级，效果与门槛取E，不取装备等级。武器/防御各有三个顺位，可排列；有效等级1/10/20开启第一/二/三顺位。每个效果的分支节点门槛为10/20/30加顺位偏移0/10/20，和基础效果门槛独立。

| 效果 | 完整基础行为 |
|---|---|
| 熟练 proficiency | 普通武器值乘 `1+round(0.1×E×log10(max(1,全局规范攻击数)),2)` |
| 连发 repeat | 每规范攻击50%触发一次0.5秒后的额外攻击，伤害乘`1+0.2E`；重复攻击不继续递归 |
| 暴击 critical | 武器没有天生基础暴击；该主效果生效时提供25%暴击率及每有效强化级+0.3暴伤倍率。再计已生效A节点、B2层和无人机加成。必暴B3把效果触发率置为100%，原始暴击率对应的爆伤机会仍保留，判定见下文 |
| 适应 adaptation | 防御值乘`1+round(0.1×E×log10(max(1,全局来袭次数)),2)` |
| 记忆材料 memory_material | 每0.2秒修复自身最大值×0.01E；真实防御满后给保护充能，上限自身最大值×0.1E；保护无自然衰减 |
| 延迟伤害 delayed_damage | 比例`d=max(0,(100-max(1,ceil(100/(1+E))))/100)`；即时扣1-d，延期2秒按0.2秒跳结算；每跳扣当期后全局25%判定清除全部余下队列 |

历史次数是跨战斗成长状态；一次导弹批/普通主攻击/整条主光束为规范攻击，不每枚/每跳刷攻击次数；一次来袭尝试记一次受击。派生连锁、反击、爆炸不递归产生无限熟练和触发链。重铸重置历史。

延期队列存层类型、每期额与剩余期数；队列扣款不重复走原始抗性和再次延期。延期扣款先周期护罩、再记忆保护，再当前全部护盾、最后装甲，全部按1:1扣除；队列原来来自盾还是装甲只作会计元数据，原来来自装甲的延期也不能绕过当前护盾。该扣款不增加来袭历史，不再减抗性，不再分成延期；实际扣到盾会重置该盾受击延迟。某全局0.2秒跳没有到期债务时不抽清除；有债务时先按盾来源、甲来源顺序支付，再全局一次抽清除余队，死亡/撤退则停止。记忆恢复同跳先修复真实模块，溢出乘充能修正进入保护容量；全体模块产生正恢复或正保护增量后只抽一次共享恢复Buff。同刻顺序见01第3.2节。

## 6. 强化分支全集

同一节点只能选A或B；三个节点可混选；未选不增加效果。A按该效果启用的A节点数叠加；B按具体节点。改变顺位导致门槛不满足时保留选择但暂不生效。以下数值均来自 `enhance_config`。

| 效果 | A（每节点） | B1 | B2 | B3 |
|---|---|---|---|---|
| 熟练 | 伤害+50%，节点先相加 | 对同一主目标持续每整1秒再×1.2；换目标清计时 | 周期×0.7 | 把匹配敌抗性的减伤改为30% |
| 连发 | 触发率+10百分点 | 主命中额外连锁1目标 | 不允许第二代连发；保留节点配置/已存选择但不启用该功能，也不显示已有第二代效果 | 普通攻击20%另锁一个目标；没有额外目标则不发 |
| 暴击 | 暴击率+15百分点 | 暴击后后续3次规范攻击伤害+50% | 暴击加1层，上限3；每层率+5百分点、伤害+10%；持续2秒，暴击刷新整组 | 保底暴击：暴击效果触发率固定100%；额外暴击伤害仍按原始暴击率R出现，强制补足的效果触发率不附赠爆伤 |
| 适应 | 最大防御+50%，节点相加 | 同敌来源后续来袭每层原伤-20%，上限3；来源死亡清 | 每2秒生成持续1秒的无抗性护罩，容量=自身真实最大防御+自身记忆上限 | 原本存在的匹配抗性+25百分点，钳1；不赠送中性层抗性 |
| 记忆 | 恢复与保护上限+20%，节点相加 | 实际全局恢复跳有正恢复时10%触发共享50%减伤1秒 | 同类来袭赋予该类50%保护抗性2秒；异类来袭清除并禁止重获2秒 | 每启用盾模块使记忆充能+40%；每装甲模块使记忆上限+40% |
| 延迟 | 全局清队概率+10百分点，每节点只计一次 | 清队后共享原伤-20%持续1秒 | 禁用随机清除，未强制清除概率×0.5转为减伤 | 强制清除概率1，但来袭伤害乘`1+(1-未强制清除概率)` |

### 6.1 保底暴击的来源、概率与爆伤

保底暴击是`critical`第三节点选择B的效果。生效要求强化系统开放、该节点已选B且已解锁、当前武器具有critical主效果。主效果按共享有效强化等级及排列顺位开放，不检查单件装备等级；所有合法武器（含无人机武器）共用该判定。主效果顺位门槛1/10/20；第三分支门槛30加顺位偏移0/10/20，因此critical在第一/二/三顺位时B3门槛分别30/40/50，默认第三顺位是50。

设I为critical主效果生效标志（1或0），E为有效强化等级，A为生效的critical A节点数，S为生效B2当前层数（否则0），C为无人机暴击率加成，D为无人机暴伤乘数。当前武器表没有cri/criDmg值，均按0；保留字段计算含义。先算：

```
R = clamp(cri + 0.25×I + 0.15×A + 0.05×S, 0, 1)
P = clamp(R + C, 0, 1)             B3未生效
P = clamp(1 + C, 0, 1)             B3已生效
M = max(0, 2 + criDmg + 0.3×E×I) × D
```

R是未被B3强制覆盖、且不含无人机C的原始暴击率。武器天生cri=0不等于把主效果提供的0.25删除；例如critical未生效且无其他来源时概率0，主效果生效且无其他加成时R=0.25。无主效果时无人机C仍可带来普通暴击，暴伤基础倍率2也仍存在。

每次新的规范攻击按现行调用顺序执行：先调用一次战斗随机`u1=randf()`，令`critical=(u1<P)`；`critical_bonus_applied`先等于critical。若critical为真且B3生效，再调用一次`u2=randf()`，令`critical_bonus_applied=(u2<R)`。只有bonus为真才把该次原伤乘M，否则暴击伤害倍率为1。B3未生效或首次判定为假时不执行这第二次调用。即使P=1，仍保留首次随机调用；这是main已有的两阶段判定，不新增或删减调用。B3的爆伤判定只读R，**不加C**，不得为了把两条概率统一而擅自修正。

`AttackSpec`分别保存`critical`与`critical_bonus_applied`及已经乘过爆伤的damage，不能用一个标志替代两者。暴击表现和B1/B2后续触发看critical，不能看bonus：规范攻击完成时，非derived且critical为真，才按已生效B1写后续3次加强、按B2加层并刷新持续时间。derived攻击不更新这两个后续效果。B1/B2本身的非暴伤增益仍正常参与伤害；它们不因为本次bonus失败而消失。同一齐射各成员和延迟连发沿用该攻击快照中的两个标志与伤害，不重新抽暴击或爆伤；独立规范攻击才新抽。

玩家说明使用：“暴击效果触发率固定为100%；额外暴击伤害仍按原暴击率出现。强制补足的暴击效果不附赠爆伤，原有爆伤机会保留。”详细概率显示同时列“暴击效果P”和“爆伤判定R”；原始R不含无人机暴击率加成。不能简写为“所有必暴都无爆伤”或“必暴都享受爆伤”。例如R=25%、C=0、M=17时，保底使每击都有暴击标记与后续效果，但仍只有25%的第二次判定得到17倍暴伤，其余维持该次非暴伤部分的伤害。

同源减伤先使用之前层数再增长，因此第一击不享一层。共享减伤彼此相乘，不求和。连发计划及暴击随机结果在攻击诞生时固化；延迟执行不重新抽一份结果。持续光束连发有自己的蓄能、跳时刻和生命周期，不把一次延迟安排当成每跳再连发。

## 7. 衍生攻击和传说连接

`TriggerPolicy` 明确主攻击可触发、可连锁、可击杀效果的位集，派生攻击带父AttackId与类型。基础规则是主攻击可生成规定的有限派生；派生不再次触发任意主攻击类效果；传说显式例外必须在表与测试注册。一次主击杀可以产生多份规定掉落，但不能因爆炸递归重跑原击杀。

十二种传说的具体规则和来源选择在 [04](04-hyperspace.md)；其执行入口只有 `onAttackBorn/onContact/onIncoming/onDeath/onTimer`。不存在“所有系统都监听hit然后随便改player”的实现。命中回执同时报告原伤、截获、护罩吸收、记忆吸收、盾损失、装甲损失、延期额、死亡归属，保证 UI 和测试使用同一解释。

## 8. native战斗与GPU表现连接

战斗由现有`addons/native_battle/src/combat_execution_kernel.h`扩展后执行；Godot提供装备/编队/逻辑几何，核直接拥有防御、弹体、冷却、临时效果、随机和接触结果。现有native缺少的强化分支及传说按本章与04加入同一核，具体清单和函数见[05](05-architecture.md)。数值接入统一C++ Amount；不保留数值越界时转旧业务的流程。

`advance_combat`完成后宿主一次`take_results`取得已发生的命中/死亡/掉落与波状态；先登记掉落，再处理死亡/通关和奖励，最后刷新页面。native不写钱包或存档；宿主不再次计算命中伤害。非终波的合法遗留弹体继续在该核推进，终波先清攻击、收齐掉落再转场。GPU和表现层可丢纯绘制帧或合并火花，不能丢业务结果或产生奖励。
