### 1.1 编译流水线

```
读取完整manifest指定Excel字节快照
→ 按schema解析（数据行从第4行；空行跳过但保留order字段语义）
→ 类型/范围/主键校验
→ 跨表引用/拓扑/布局/预算校验
→ 规范化稳定ID与顺序，生成具名运行结构
→ 全量规则校验、计算派生索引、内容hash
→ 写临时版本目录并回读校验
→ 原子替换active-manifest指针
```

编译入口建议 `python config_tools/compile.py --manifest ... --output ...`；生产manifest和测试manifest是不同文件，传同一个编译器。schema与转换逻辑共享，数据不共享。命令可在未安装/未运行Godot的环境执行。禁止编译器调用游戏场景或编辑器工具取得“默认值”。

表字段有明确literal类型；空值和0不同。可选字段的回退目标在schema列出，例如敌武器空字段→enemy_weapon_base。需要数值的字段不接受文本数字；Amount可用专门十进制文本列，但字段类型需声明amount_text。Excel公式如已存在且属于内容，保留原单元格，不由openpyxl假装重算；编译要求可信缓存值且记录公式/值hash，缓存缺失/错误则拒绝发布并给坐标。要求typed_literal的超空间表继续拒绝公式。禁止静默将`#VALUE!`、NaN、INF或空串转换为0。

错误统一为`{workbook,sheet,row,column,key,code,detail}`，一次收集独立错误，有限显示但完整报告保存本地；失败没有半份运行包。重编译相同字节得到相同hash/结构；物理行重排且显式order不变，语义hash应相同（来源hash可不同）。

### 1.2 必须执行的关系校验

* ID唯一、非空、类型稳定；字符串`laser-mon`与`laser_mon`不得自动合并。Excel数值ID规范化为十进制串时检查无小数/无重复。
* 所有外键存在：解锁目标、船员岗位、装备资源、敌武器、编组成员、关卡编组、星球建筑与Buff、星系建筑、超空间路线/词缀/传说/挂设/奖励参考。
* 科技前置无环；星球后继链和解锁依赖不得自锁；每种规则ID必须在实现注册表，未知effect不能默默跳过。
* 概率0～1、周期>0、冷却>0、成本非负、成长基底合法、盾比例及成长约束一致；普通数与Amount字段使用各自明确范围。
* 船槽/无人机限额可满足初始配装；编组槽索引不重复，空位保留，尺寸/坐标/包络合法，不因重新排列压缩空槽。
* 主线关ID、战点位置和数组顺序合法，引用完整；不存在就不自行复制上一关。当前220关必须完整保留。
* 超空间40组唯一覆盖四路线4/4/1/1；order在各作用域连续；成员预算块一一覆盖、不重复、不漏；零预算成员保留；奖励参考来源真实存在且绑定所选参考关。
* 词缀每tier区间min≤max且与量化步长兼容；传说验值接受当前生成区间或明确历史区间，不能错误取交集；不可编辑结构身份按schema锁定，不能只改说明文字绕过。

## 3. 统一近似数值Amount

用户已明确“大数统一近似计算”。采用单一非负科学计数值对象`Amount{mantissa:float64, exponent:int64}`，零规范为(0,0)，非零满足`1≤mantissa<10`，值为m×10^e。这一份算术在C++实现并通过GDExtension供Godot直接调用，核内使用值类型，脚本持有绑定值。所有经济、伤害、容量、成长工作量、每项目已完成研究工作量和船员经验均用它，不能普通值用float一路、大值另进特殊经济路径。小型比率、坐标、概率和有限秒数可用float64；实体ID、槽数、抽数、层次等用整数。

接口：`zero/from_decimal/normalize/add/sub_nonnegative/mul/div/pow/log10/compare/min/max/floor/ceil/round_significant/sum_geometric/to_ratio/to_display/encode/decode`。非法负数、NaN、非有限尾数、除0拒绝；减法最多钳到0，不能让钱包负数。禁止把Amount先转float再做可支付检查。

* add/sub先对齐指数，数量级差大于有效精度窗口时小项自然不可见；接近相等用同一规范化比较，不逐模块自设epsilon。
* mul/div分别处理尾数与指数，归一化；pow通过`log10(m)+e`计算输出指数和尾数，检查指数范围；指数上界是可报告的表示极限，不宣称无限精确。
* 当金额大到个位已经不可表达时floor/ceil为恒等近似；普通量级保留规则要求的整数或0.01精度。不得把“统一近似”理解为删除所有游戏规定的取整节点。
* 消费规则在同一Amount精度下比较/扣费；报价显示与提交共享规范化值。极小消费相对余额不可见是近似系统允许的损失，不补建精确隐藏账本。
* `to_ratio(a,b)`只在业务明确需要0～1比例时返回有界float，不把高等级伤害截成`1e308`。展示缩写、科学计数和进度条可不同精度，不能反向参与规则。

工程初值：指数支持`[-9000000000000000,9000000000000000]`，尾数归一化后按15位有效数字规范化，指数对齐差>16的小项忽略；非零下溢返回规范0，输入/报价计算上溢返回`AmountRangeExceeded`并拒绝该动作；若内部推进发生未预期上溢则停止会话且不保存该步，保留上一有效文件，不封顶为最大伤害或免费成本。此为可替换的表示能力边界，不是玩法等级上限；需支持更大规模时升级数值编码版本并验证同一接口。等级/ID用int64，超界同样显式错误，不能绕回负数。工程精度以二进制64可实现的约15位有效十进制为基础，测试普通范围相对误差≤1e-12（接近0用明确绝对误差），极大数只比较对数与单调性。是否精确保持每次扣除的末位没有需求，不造任意精度整数库。离散核心数量仍按整数语义呈现，但底层经济近似统一；核心抽奖结果本身是离散0/1。

### 3.1 普通价格一致与极端近似

预览、+1、指定数量、自动购买和MAX共用`quote_upgrade(current_level,count)->{count,costMap,range:ordinary|extreme}`。所有金额都用同一Amount，不保存另一份精确余额或历史尾差。**普通范围内，买n级就是这些等级各自单价之和，分批与一次购买总价一致；只有极端金额才允许差异。**

普通范围的技术界限为T=10^15：本次每一项已经按规则取整的单价及累计资源费用均小于T。它来自Amount的15位有效数字可保留普通整数的范围，不是等级数或购买次数上限。分类逐资源进行；若费用包任一资源进入极端，整体提示extreme，但不改变其他仍在普通范围资源的算法。离散等级始终为int64。

装备每一目标等级L的`raw(L)=costBase×r^(L-1)`，r=1+成长率；`unit(L)=ceil(Q(raw(L)))`，L=1保留原始初值。普通费用`Σ unit(l+i), i=1..n`。同一级unit函数只依赖该等级与配置，不依赖本次从哪里开始购买。因此base50、r1.2、当前1级：下一等级65，再下一等级75，+2及两次+1都付140。禁止把65当成新的几何曲线起点外推成143。

普通求和无需逐级循环。Q单价随等级单调，同一取整价格可覆盖连续多级：算当前等级价格p，用整数二分找本次区间内最后一个同价等级j，累加`p×段长`，再进入下一价格段。Q在100以下按十位分档，以上每个数量级只约90个价格档，普通范围总档数约千余；小增长率导致长段时仍一次乘段长。二分比较使用同一个unit函数，边界按该函数确定，不靠对数反解的浮点结果猜是否跨档。r=1直接`n×unit`。其他费用按03各自单价：反应炉为ceil的1.35曲线、强化为2倍曲线，同样累加实际单价；这些现行增长率在普通金额内只覆盖有限的少量等级，可用同价段求和，整数几何项也可直接求和。每段的乘积和累计仍用Amount，普通整数不得用显示缩写反向计算。

若发现某项单价或本次累计费用≥T，停止该资源的普通分组，**整批该资源**改用原始费用曲线的Amount几何和，不保留或拼接已计算前缀：

```
rawSum = firstRaw × S(r,n)
S(r,n) = n                       当r=1
         (r^n-1)/(r-1)           当r≠1
extremeCost = ceil(max(T, rawSum))
```

其中firstRaw为这次要买的第一个等级的原始费用，不是Q单价。`max(T,...)`只防止刚跨分类边界时报价倒退，之后rawSum随数量单调；不是额外费用比例。r=1本来就能直接`unit×n`，普通与极端都保持该线性结果。r接近1时S使用`expm1(n×log1p(r-1))/expm1(log1p(r-1))`稳定计算；巨大指数在Amount表示中运算，不转成double。极端MAX/分批允许数量级近似差异；最终显示和扣费必须使用同一次quote，既不先报精确数再改收近似数，也不在事后补差。

进化材料按跨越付费阶数直接求算术和：`a=floor(l/20)+1`，`b=floor((l+n)/20)`；b<a为0，否则`10×(a+b)×(b-a+1)/2`简并物质，用Amount计算，不逐阶循环。材料未开放时不得跨相应门槛。该算式在普通整数范围同样可加；极端按Amount精度计算。所有资源足够才购买。

MAX从0可付起按1、2、4…扩张数量上界，再整数二分，使用同一个quote比较每种资源钱包；最终重算该数量的同一quote并扣其costMap。普通求和、极端max(T,rawSum)与材料和均随数量不减，因此分类边界不会破坏搜索。当前等级+n不可超int64；若到表示界限仍未找到不可付上界，报告数值范围限制，不虚构玩法封顶。测试检查普通拆分可加、跨T单调、极端可付、无NaN/负余额/死循环。

## 4. ConfigBundle运行结构

包含`schemaVersion, semanticHash, sourceManifestHash, tables, ruleParameters, indices, provenance`。tables按领域定义强类型数据；indices含ID查表、关卡有序战点、科技拓扑、解锁反查、武器规则、几何引用、奖励预算映射。provenance能把一个字段追到Excel坐标，运行时不需要整个工作簿对象。

整份会话固定使用一个configHash；运行中不热替换半张表。新配置导入先编译完整包，再以明确会话重建/加载校验边界切换；有不可兼容玩家实体时返回结构化错误，不能丢失ID并继续。配置变更不是“偷偷修存档”；跨配置兼容由schema版本与明确迁移处理，不要求支持旧游戏的历史存档。

## 5. 新存档格式与生命周期

不承担旧SAVE_VERSION=11等历史兼容。新格式从1开始，保留明确未来迁移入口。Envelope：

```text
SaveEnvelope {
  formatVersion, sessionId, changeNumber, generation,
  configHash, savedUtc, payloadHash,
  payload: {
    campaign, economy, equipment:{slots,reactor}, enhancement,
    research, crew, planets, galaxy, hyperspace, notifications,
    randomStreams, acceptedTime, checkpoint, nativeState
  }
}
```

Amount编码为`{m:"规范十进制尾数字符串",e:"十进制整数字符串"}`，禁止JSON解析把巨大指数/ID变double。离散int64同样字符串保存，schema知道类型，不猜所有数字字符串。实体引用保存稳定ID而非NodePath/对象地址。

长期进度全部保存；nativeState固定保存`history_counts:{attacks,incoming}`、`rng_state`、`next_ids:{encounter,actor,attack,emitter,drop}`，即全局攻击/来袭历史、战斗随机和ID序号；不保存残血、弹体、光束、临时效果与战斗事件队列；派生CombatConfig、图形池、缓存、贴图和UI节点不保存。已完成未领超空间奖励、已接受付费时间、钱包和重复领取凭据必须可恢复。

### 5.1 保存文件与异步顺序

1. 在一个业务方法或完整固定步结束后取保存副本，分配generation并记录changeNumber。它只用于判断保存期间是否又有修改，不用于业务锁或报价校验。同步读取native长期字段，失败则不发起该次保存。
2. SaveFiles中的单一writer串行处理。后台序列化只读快照，不遍历运行时可变字典。若后请求覆盖前请求，可合并尚未开始的请求，但不能让generation较小的完成覆盖较新的成功文件。
3. 写同目录临时文件，完整写入、flush、关闭、回读hash/schema；保留上一个验证过的文件为backup，再原子替换主文件。目标平台不保证原子替换时使用A/B槽+带checksum的manifest，先完成新槽再切指针。
4. 成功回主线程发布`saved(generation,changeNumber)`，只更新对应成功时刻。期间又有新业务修改时dirty仍为true；不能旧保存完成就清掉新脏标记。
5. 写失败、磁盘满、权限错误或校验失败：旧有效文件不覆盖，保持dirty，提示可重试；不重放游戏收入。关闭时请求有限等待并报告未保存，不能卡死主线程。

自动保存间隔由设置控制，现实计时；暂停时可保存步骤完成后的状态，不推进游戏。一个固定步不中途挂起；帧预算耗尽时保存已接受但尚未消费的时间段和余数，不能丢掉已付微粒。

### 5.2 加载、导入、重铸与失败恢复

加载先读取主文件或最高有效A/B generation，失败可明确选择backup。解析、大小/版本/hash检查、ConfigBundle匹配、各领域不变量、跨域ID/占用、凭据状态、Amount合法性全部在候选会话完成。成功后一次替换当前会话，销毁旧表现，重建派生属性、占用索引和各系统到期时刻，再发布Ready。候选失败不部分安装、不“修掉未知无人机”后覆盖原档。

导入由用户显式选择文件/文本，先预览候选摘要及版本错误；当前会话暂停取得稳定快照并保留可恢复备份，候选有效才替换。导入后的文件写入失败不能同时告诉用户导入成功且文件仍是旧档，结果要区分“内存替换成功、持久化待重试”。重铸先完整创建新会话，成功才替换session；新档清空是独立明确操作，不拿损坏档回退成新档自动覆盖。

自然加载的离线微粒以已加载有效savedUtc计算，补偿与新的登录消费标识一并持久化；系统时间倒退得0，前跳受12小时上限。显式导入也以该文件savedUtc计算并发放同样离线微粒；每次操作只应用一次，不声称阻止玩家主动重复导入或回滚单机文件。恢复后待领CompletedPending保持同一奖励和随机结果，在线Started任务保留剩余工作，离线不推进；手动战斗中断按下段处理。

### 5.3 恢复成长进度后建立新战场

加载和导入都先恢复已保存的长期成长、钱包、船员占用、星球/星系/在线挂机工作、通知、未领奖凭据、付费待执行时间和native长期历史/随机/ID，再根据checkpoint建立全新战场。新敌群满防御，玩家按当前装备满防御，普通武器用初始冷却，不恢复旧残血、弹体、光束、暂态Buff、延期伤害或重建禁用。EncounterId取新的序号；允许再次击杀同配置敌人获取新的收益，不追踪旧波哪些敌人已死来禁止重刷。

checkpoint保存主线关、战点索引、航行距离/阶段、驻守位置及返回目的地：保存时在战斗则重开该战点；航行则在保存位置继续到下一战点；清关等待保留已通关结果及剩余等待；撤退保留目标与剩余路程，结束后按正常流程出击；选关则仍在选关。重开战场使各类当前防御恢复到对应最大容量；无装甲但有护盾不得因此拒绝出击，生存只按02的两类当前余量判定。暂停设置/引导原因按保存状态恢复，等待玩家继续。

保存时已经生成而尚未领取的可拾取物以DropId、资源、基础量/金额和剩余自动领取时间保存在economy，不依赖旧敌人/弹体对象；恢复后继续存在且每个只可领取一次。定时物另保留生成时算定的最终amount和productionBase，读档后的研究或其他倍率变化不能改写其已定金额；移动与领取不重算。已入账物不重放。新的重刷掉落使用新ID，可以正常领取。

Started手动超空间视为中断失败，无成功奖励、无票额可退，按该run返回目的地建立新主线战场；CompletedPending奖励及记录原样保留，不重复生成。在线Started单次/自动挂机恢复剩余工作，离线期间不推进；其CompletedPending同样保留。加载/导入发放离线微粒后保留已付时间队列，正常逐步消费，不能把它当离线挂机时间再额外推进一遍。显式再次导入旧档会回到该档进度并按其savedUtc再次补偿，这是允许的单机文件重放行为。
