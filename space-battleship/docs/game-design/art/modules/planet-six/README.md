# 六类天体与设施一体化概念

**最新返修方向：** [B 方案新结构](scheme-b/README.md)先有[固态同轨道平面完整态](scheme-b/orbital-plane-solid-complete.png)和[固态独立建设五态](scheme-b/orbital-plane-solid-stages.png)。此前 B 的固态／气态／恒星共用 C 形环带被用户指出更像附着球缘、没有物理成立的环绕关系，已在 B 页留档为退回参照，不作为这次新结构通过的证据。下文六套仍是先前 A 方案，供比较；A、B 均未获最终选择。

本页是六套新概念的唯一入口，承接[M7 星球](../planet.md)。用户方向是逐类设计固态行星、气态行星、恒星、红巨星、白矮星、脉冲星，让“天体+设施的完整布局”成为星球界面的主体。每套先对照**裸天体**与**同机位、同尺度的完整设施态**，由承载、作业和运输关系决定整体构图，再讨论如何让 UI 融入。以下图是静态概念图，尚非 Godot 画面或用户批准资产。

**状态边界。** 现行[第 3 章星球规则](../../../03-progression.md#5-星球探索与建筑)仍按星球 ID、既有空间站／精炼厂／工坊／船坞、施工门槛和贡献执行；六类的资源、产出、解锁、设施适用性或新建筑功能均未批准。图里的采集环、浮台、磁场弧等首先是视觉承载方案；若将其转为新功能，必须另立玩法提案待定。当前已审的单星球地表与轨道设施、R5 造型及 R14 局部修正只供风格和问题参照，不等于这六套概念获批。

**呈现尺度。** 当前 Godot 星球模块约 808×900、客户区 1440×900，只作设计参照，非用户冻结的六类最终尺寸。概念图保留天体外的建筑、运输和运动空间；真正接入时需在目标页面检查轮廓、操作避让和阅读尺度。先看无控件整体关系，再探索把星球选择、任务和设施管理放入附近留白，不能为塞控件破坏主体。图中无烘焙文字或数值。

**视觉共同语言。** 沿用已认可的象牙装甲、深青结构、克制青色能源和少量琥珀信号。六类不共用一个设施落点模板：每类的承载介质、遮挡、运输路径与动态节奏分别定义。图像生成的原提示词、原图文件、来源参照和哈希见[生成记录](generation-prompts.md)。

**给用户审图的重点。** 先比较同类左右两态是否仍是一颗天体，以及完整设施态的建筑是否有可信承载和清楚的作业／运输方向；再比较六类之间的构图是否真正不同。图像生成会把细节画得过密，尤其恒星弧、红巨星新月和白矮星瓣片，需以现有模块尺度复核简化程度。图中每个可见节点不等于新增可建项，实际设施身份仍须在后续设计审查中落回现行四类或作为待定提案。这里不宣称图像可直接切割成游戏资产。

## 独立建造的分步对照

按现行配置，六颗星球都适用空间站、精炼厂、工坊、船坞。空间站探索度 D1 解锁且施工 1 次，精炼厂 D20／5 次，工坊 D50／10 次；**第一星球**船坞 D30／180 次，**后五颗**船坞 D150／10 次，船坞另需一名施工船员。施工可独立推进、ready 后由玩家领取才 built，因此没有强制唯一的“建成顺序”。下方分步图采用一条可行的示例领取路径：裸态 → 空间站 → 精炼厂 → 工坊 → 船坞完整态。首星船坞虽早于工坊解锁，施工量更大，示例并不声称它必须最后领取；玩家先建成船坞的状态也须在未来实现中正确显示。

分步图只在已领取的那一步显示该设施及其自带基础、支架、局部管线；未建建筑不得以空平台、延伸半截的桥或悬挂未来设施的承载环提前出现。中间状态要以当前建筑自足地形成完整画面。A 方案的[固态](solid.md#分步对照)、[气态](gas.md#分步对照)、[恒星](star.md#分步对照)三套已固定，其余三套因 B 方案对照优先暂缓。B 方案现有三类五态见[新入口](scheme-b/README.md)。[自转优先的动态约束](rotation.md)共同约束两案，不从静态最佳角度推断整圈可见。
