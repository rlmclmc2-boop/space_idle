# 01 游戏流程、时间与经济

[回唯一入口](README.md)。本章是运行规则；程序对象见 [05](05-architecture.md)。所有时间若未标“现实”均为受加速的游戏秒。

## 1. 新游戏与进程

初始关卡 1，已通关集合为空，铁/铀为 0，强化与 AI 科技为 0，反应炉为配置初始等级 1，各模块分配 0。第一个解锁船型为初始船型；`startEquip=armour,laser` 选择初始配装，不赋予额外解锁。所有装备是否可用只按解锁表及永久授予集合计算。初始启用槽位等级为 1，空槽没有战斗贡献。船员定义创建成员，岗位依定义和解锁条件检查。星球初始探索度 0、未征服，建筑按门槛同步；星系尚未启动；超空间仓库、路线记录和奖励凭据为空。随机种子由创建新档一次生成，之后按独立流保存。

进程数据分别保存 `highestReached`（本轮已到达的最高关）、`clearedStageIds`（真实/重铸授予的通关集合）、`lifetimeHighestReached`、`bossSeen`、驻守位置。不能用一个最大关数推断已经通关所有中间关。

解锁 `cleared` 模式要求集合包含指定关；基线 `reached` 模式实际为 `highestReached > gate`，严格大于。0 级门槛初始开放；永久授予可覆盖本轮条件。超空间另用 `highestReached >= 8`，星系还检查其定义中的通关条件。不要把这些不同谓词统一改成 `>=`。星球的后继开放也可来自征服 Buff。

## 2. 航程状态机

| 状态 | 进入与工作 | 退出 |
|---|---|---|
| 选关/菜单 | 显示已开放目的地；不发射战斗攻击；共享在线系统是否工作由会话是否运行决定，不由面板可见性决定 | 有效出击命令建立航程，进入航行 |
| 航行 | 距离增长；目标战点是 `position × length`；仍可恢复防御和结算已有合法弹体 | 到达战点创建完整编队，进入战斗 |
| 战斗 | 双方自动武器、移动、命中、恢复与掉落 | 非终战点敌人全灭回航行；终战点全灭清关；玩家装甲归零且重建失败则撤退 |
| 清关等待 | 结算所有遗留掉落，记录通关、刷新解锁；基础等待 3 秒；有解锁引导时暂停等待 | 等待结束进入下一关；驻守重生原战点；最后关终点不越界生成关卡 |
| 撤退 | 清理敌人和攻击源，按既定后退目标插值；共享经济仍按时间规则工作 | 到达目标重置玩家战斗防御，回航行或驻守；无有效装甲进入选关并显示原因 |

基线还含 `UPGRADE/DEFEAT` 等旧状态名称，新方案不要求原样保留无独立行为的枚举。升级面板是显示模式，不是全游戏暂停状态。

航行速度 `max(ship.moveSpeed, (nextPoint-origin)/3)`，将一段航行限制在最多 3 秒；其中 origin 在本段开始固定，不能每帧更新造成渐近减速。若没有下一个战点，使用船速。非负距离、关卡长度、战点顺序由编译器验证。

撤退距离采用 `config.backRange=200`，不是未消费默认项 `deathRetreatDistance=300`。跨过关首时倒退到前关并加其长度，直到目标非负或抵达第一关，再钳到 0。撤退时长为 `clamp(deathRetreatDuration, 0.001, 3)`，基线 1.2 秒。目标前的战点跳过；跨关后若目标位于前关最后战点之后，仍触发该关最后战点，不能穿越终战点直接前进。

驻守保存关、战点索引、距离。重复间隔为 `min(3, 本战点与上战点距离差/船速)`。死亡选项保留三种：0 取消驻守，1 保留原驻守目标，2 退到新位置后更新驻守点。界面改变选项只修改策略，不瞬移。出击、通关和死亡清理换装锁的范围见装备章。

终战点身份与 `combatTier` 分开：normal、elite、boss、ultimate 由编组配置给出；尺寸大不等于 Boss，Boss 不必是最后一波，最后一波不必靠名字判断。终战点清空时先收齐奖励再进入解锁提示。

## 3. 时间与暂停

用四种明确时钟：

| 时钟 | 来源 | 用途 |
|---|---|---|
| 现实单调钟 `wall` | 本次在线实际经过时间 | 微粒扣费、收入显示与峰值窗口、自动存档计时；不用系统时钟跳变计算帧差 |
| 游戏钟 `game` | 接受的现实区间乘当时倍率 | 航行、战斗、自动购买、研究、探索、在线挂机、恢复、技能 |
| 日历钟 `utc` | 保存/加载时的系统时间 | 离线微粒；负时间差按 0 处理 |
| 表现钟 `visual` | UI 帧差 | 菜单动画、相机过渡、纯反馈；不能产生收入或命中 |

每次接收现实帧先检查会话可用，再处理暂停/离港等待，再按当前倍率和钱包可支付时长切割区间。基础固定步为`1/60`游戏秒，未执行整步及不足一步的余数保留；战斗按到期事件处理全部应到光束跳、离管和命中。科研、探索等任务在本步中途完成时，仅舍去该任务从完成点到本步末的微小余时，细则见3.2；不能丢掉未执行的整步或其他系统时间。

暂停用原因集合而非一个可互相覆盖的布尔值：用户暂停、首次引导、解锁引导、导入替换、错误恢复。任一原因持有时游戏时间和微粒消费停止；关闭引导只释放该原因，原用户暂停保持。空格按下只切换一次，键盘重复不连续开关。打开教程档案不自动清空未读记录。教程自动跳过设置只控制弹窗与引导持有，不改变解锁本身。

窗口失焦时加速恢复基础倍率 1，不能继续花微粒；在线失焦不是离线模拟。切换页签、隐藏星系面板不停止领域逻辑，只有图形可停止。重新出航的基线 1.6 现实秒离港展示不推进业务、不花微粒；该数值迁配置。

### 3.1 超时空微粒

`capacity = offlineMax × 3600 × chronoParticlesPerSecond`，基线 `12×3600×1=43200`。加载时：

```
offlineSeconds = clamp(floor(nowUtc - savedUtc), 0, offlineMax×3600)
gain = min(floor(offlineSeconds×rate), floor(capacity-current))
```

只发微粒，不离线推关、科研、星球、星系或无人机挂机。自然加载时顺序增加离线补偿并写登录标记，每次加载调用只发一次。显式导入同样按导入文件savedUtc与当前UTC计算离线微粒，应用同一12小时上限和容量；每次加载/导入调用只补偿一次，不额外阻止玩家人为重复导入单机档。

可选速度 1～10，每现实秒费用依次 0～9。设现实片段 `r`、速度 `s`、每秒费用 `c`、余额 `B`，可加速时长 `a=min(r,B/c)`（c=0 则 a=r）；扣 `a×c`，接受 `a×s` 游戏秒，余下 `(r-a)` 用基础速度。保存待执行时间时必须同时保存已经扣费的接受区间；恢复不得再次扣微粒。跨暂停、换倍率时按区间边界处理。

### 3.2 共享系统顺序

共享业务按以下顺序直接执行：超空间手动耗时记录 → 生产游戏钟 → 超空间在线工作/待领奖 → 星球 → 星系 → 船员任务 → 顶部自动资源 → 科研 → 普通掉落到期 → 科研自动投入刷新 → 战斗阶段。战斗临时效果不在共享阶段另减一次dt，统一由native战斗时钟按到期时刻处理。其余这些是GameSession中按行调用的具名函数；步骤完成后才向页面显示通知和进入暂停，不在步骤中间回调UI，也不从头重放共享收入。

固定步长度h=1/60。某任务距完成还需τ且0≤τ<h时，推进τ并完成，只舍去该任务的h−τ，不把它转交自动续开的下一项。自动续研/探索可以立即设置下一项，但从下一固定步才积累；若同一系统有多个并行工作，每个工作分别处理自己的完成边界，未完成工作仍消费本步应得时间。科研投入只扣到完成点。此规则也适用于星系连续工程阶段及超空间自动任务切换；不会减少其他系统的dt、连续生产、充能或正常战斗周期。帧积压的整步和已经扣微粒的待执行时间仍逐步执行。

同刻执行顺序直接固定：先完成上述共享系统调用并同步装备属性，再推进战斗。战斗每个到期时刻依次处理：①移除到期临时效果并恢复到该时刻的普通护盾；②周期护罩和记忆恢复；③到期延期支付及清队；④武器/连发/离管出生；⑤已有飞行弹体接触、光束伤害跳和其他到期攻击释放。相同阶段按我方普通槽序、我方无人机装备序、敌方slot及武器序排列，再按本地生成序号处理。即时我方炮/Higgs在④其自身发射调用内就命中，不延后到⑤。

每次命中直接更新防御、死亡与掉落；其合法同刻衍生按生成顺序先入本次命中的局部队列，处理完再开始下一根事件。衍生仍受02有限触发权限约束。目标先死则后续命中无效；玩家致死先尝试重建，失败则终止该遭遇剩余伤害；终波清空在该次死亡及允许的衍生处理后清攻击，再由宿主收物、转场。Higgs每处理一个候选都检查射线是否因清场失效。上述顺序不依赖字典遍历或显示帧率。

## 4. 经济账本与收入分类

钱包含铁 `1`、铀 `2`、强化碎片 `jewel`、微粒 `chrono`、四类超空间材料及究极核心。经济数量统一用近似 `Amount`；格数、ID、抽签次数等离散身份使用整数。钱包使用`credit/debit/transfer`具名函数，收入记录明确来源；奖励和掉落使用其本身的唯一ID防重复领取。消费检查全部资源够付才整体扣除，失败不能留下部分扣费。

基线把铁/铀掉落分为“基础生产量”和“实际到账量”；新模型显式保存两个字段，不从 UI 显示数反推。收入源至少有 `enemy_drop/timed_drop/fragment_drop/galaxy_yield/hyperspace_material/dismantle/forge_refund`；旧 `furnace` 分支仅作为停用规则记录，不能重新生成炉子。

| 来源 | 数量计算与到账时点 | 是否计入研究/峰值/星系基数 |
|---|---|---|
| 敌人铁/铀 | 死亡时按掉落项各自概率生成可收取物；拾取时到账 | 实际到账进收入与 AI 窗口；原生基础到账量进星系基数 |
| 顶部定时铀 | 活跃航行/战斗等状态每30游戏秒产生基础5铀，速度40；数量乘战点资源倍率向上取整，再乘资源采集挂设 | 与原生掉落同类；到达玩家纵坐标自动收取 |
| 击杀碎片 | 每敌人按 `jewelDropRolls` 次独立抽，概率0.2；每成功产生基础1碎片，采集后按下式 | 原生实际到账进研究、峰值；不作为铁/铀星系基数 |
| 星系收益 | 到10游戏秒结算边界，按当前率×积累秒数直接入账 | 排除原生掉落窗口，不能自我放大 |
| 超空间/拆解 | 奖励凭据领取或拆解函数完成时入专用材料/核心账 | 不进入铁铀与碎片窗口 |

敌人掉落生成：`base=ceil(drop.amount × encounterResRatio × smeltingFactor × ironOnHitFactor)`；非铁的 smelting 和 ironOnHit 均为 1。铁/铀 `visibleAmount=ceil(base×planetRefineryFactor)`。手动拾取保留全部，自动拾取 `ceil(amount×(1-autoCollectReduce))`，损耗基线 50%；之后按资源类别乘 AI 收入因子并向上取整。`productionBase` 同样应用手动/自动损耗，但不含星球、AI后续倍率。普通物体 5 秒后自动收取。通关强制收取是自动口径，不因强制而变成手动全额。

碎片原生收入：

```
input = base × (1+gemRefinerHanging)
             × crewGemFactor × reactorCondensation × galaxyFragmentFactor
credited = roundToCent(input × stageJewelRatio) × aiFragmentFactor
```

普通击杀碎片 2 秒后自动收取，基线不应用普通资源的 50% 自动损耗。炉子分支的特殊损耗不能扩散到普通碎片。倍率取值时点：敌人资源倍率在遭遇创建时固化；掉落金额在死亡时形成；采集损耗与收入因子在拾取函数执行时读取。此顺序允许玩家在物体落地后升级收入再拾取，是现行事实。

### 4.1 收入窗口

保留最近 60 秒所需样本；窗口左开右闭 `(now-60,now]`。不要以一帧收入×帧率估算。

* 资源栏近一分钟：现实钟，实际到账量；只记录被定义为收入样本的来源。
* AI 自动投入：最近 60 游戏秒实际收入总额 `/60`，再乘投入比例向下取整；每60游戏秒刷新，默认比例1%，下界0.1%。刷新不当场扣钱，真正研究片段才扣。
* 联合一体化历史峰值：最近60现实秒原生掉落实际到账总额 `/60`；只增不减，分别记录铁、铀、碎片；排除派生星系收入。
* 星系原生生产率：最近60游戏秒`productionBase`总和/60，再乘星系建筑比例得到每秒产出；排除派生星系收益。即使本轮在线不足60秒，分母仍为60。例如窗口总额600、比例0.05时产出0.5/秒，10秒到账5。

## 5. 通知、教学与玩家设置

解锁状态、是否弹过提示 `seen`、是否在档案点击已读 `read` 分开。弹过提示不等于读过档案，打开档案首页/切换分类也不算阅读；只有点击具体条目才清其红点。父级红点是未读子条目的投影，不另存一份布尔值。研究完成未读、超空间奖励未读和解锁未读分属不同通知主题。

新手引导记录首次装备、升级、拾取、撤退等实际命令/事件进展；不能用“按钮被点过”判定购买成功。通关提示只能在奖励入账后出现。自动跳过、音乐/音效、伤害数字模式、自动保存间隔和页面偏好属于设置，与玩法存档分离；清空新档是否清设置为明确 UI 选项，不隐式联动。

敌情页按正式敌种的名称、特点、机制键、视觉引用展示，不从内部描述猜战斗机制。伤害统计读取命中回执的实际防御损失，过量伤害不记为有效 DPS，吸收可单独显示；它不参与数值计算。
