# 待用户裁定的明显矛盾与覆盖缺口

[唯一入口](../README.md)。核对来源为拆分前 `main@7a85481`；下列原文按该提交保留，可用 `git show 7a85481:space-battleship/docs/game-design/<原路径>` 回读。只迁移来源，不修改冲突数值、规则或实现，不以归档视为已解决。涉及某项时只读取该项及双边来源；无关任务可继续。

## C1 无人机舰型容量：设计表与实际消费来源不一致（待裁定）

- 原文A：[03第1节](../03-progression.md#1-舰体槽位与升级)船型表，无人机容量按五舰列 `1、2、3、4、5`；[超空间快照](../reference/config/hyperspace_config.md)“舰型容量”同列该值。
- 原文B：[ship快照](../reference/config/ship.md)的 `para_5` 五舰为 `1、1、2、2、4`；[历史来源审计](../history/stage6-combat-audit.md#drone-capacity-source-conflict)原文：“`Campaign.ship_facts` returns para_5; Session passes that result to equip/preview/preset/ship-change operations”。
- 影响：驱逐、巡洋、战列、重型战列的可装备总数，以及换舰截断/预设/原生贡献。全局 `maximum_equipped=5` 与舰型更小上限可以并存，不是此矛盾。
- 待裁定：哪张舰型表应成为唯一权威，是否调整设计表/未消费表/实现；本轮均未改。

## C2 炮台朝向：固定向前与真实目标跟随（待裁定文档口径）

- 原文A：[05第6节](../05-architecture.md#6-页面连接与资源)：“炮台固定向前的挂点、裁切和资源`muzzle`坐标生成唯一世界炮口”。
- 原文B：原11“背景闪动与真实炮台方向修复”现存于[资产修复记录](../history/stage6-assets.md#背景闪动与真实炮台方向修复4452e7c4之后)：“**炮台方向改为消费native真实目标。**”及“宿主只按各武器的原生结果建立姿态”。
- 影响：显示朝向、数值/屏幕端口与真实命中一致性；最新全局规范要求保留真实目标修复。
- 待裁定：05中的“固定向前”是过时表达还是仅指源图/局部挂点约定，如何改写才不误撤已接受修复。本轮不替它指定新含义。

## C3 敌方VisualScale：统一尺寸声明与实际覆盖分支（待裁定文档口径）

- 原文A：[05第6节](../05-architecture.md#6-页面连接与资源)：“现有VisualScale字段在此契约下控制统一尺寸，保留历史列名，不另设显示尺度。”
- 原文B：原13第8.5节现存于[尺寸参考8.5](../reference/ship-scale.md#85-保留字段中已被覆盖或不再走当前链的倍率)：“旧 enemy_width 中间计算读取，但当前八家族及八分级 key 均以适配框重新写 `dimensions`，所以这些倍率不决定其最终舰体尺寸。”
- 影响：按旧 `enemyVisualScaleSize*` 调整当前静态敌舰会无效；误把中间值当最终尺寸会破坏空间预算与验收。
- 待裁定：05的概括适用范围及保留字段的现行用途说明；不擅自启用旧倍率、改配置或改变fit分支。

## C4 parent身份与保存水位：书面要求和已记录实现差异（待裁定）

- 原文A：[02第7节](../02-combat.md#7-衍生攻击和传说连接)：“派生攻击带父AttackId与类型。”[06第5节](../06-data.md#5-新存档格式与生命周期)规定 `next_ids:{encounter,actor,attack,emitter,drop}`。
- 原文B：[原11身份审计](../history/stage6-combat-audit.md#c10-identity-contract-audit)：“strange packets and counters do not retain a full parent attack relationship, and `next_ids.attack` is a carrier watermark.”原文亦明确“does not waive the design requirement”。
- 影响：派生溯源、ID语义、checkpoint兼容与审计观察口径；行为矩阵通过不证明完整表示契约等价。
- 待裁定：继续实现完整关系、修订书面要求或保留明确例外；不把历史“nonblocking”改成自动豁免，也不新增测试ID/保存字段。

## C5 批量命令拒绝：整体不变与已成交保留（待裁定适用范围）

- 原文A：[05第3节](../05-architecture.md#3-一次玩家动作)：“参数错误或资金不足返回原状态，随机也不前进。”同节先检查全部费用/引用再开始写。
- 原文B：[05现行交接](../05-architecture.md#现行模块交接契约)：“批量购买可能先接纳已成交子项，再返回后续子项的拒绝，已成交部分不回滚。”[03第1节](../03-progression.md#1-舰体槽位与升级)：“某槽买不起就跳过，不把已成交项回滚。”
- 影响：错误返回时钱包/等级是否变化、全体购级的反馈与验收，不能同时要求整批原状与保留已成交部分。
- 待裁定：明确单槽整批、跨槽批量及子命令的边界与对外结果；现有两组原文均不删除，不擅自改变原子性。
