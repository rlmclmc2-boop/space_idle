## 2. 全局美术与交互原则（规范）

### 2.1 专属资产统领构图与观看

- **以资产组织界面。** 战场以战斗与环境为观看主体；有专属美术的模块，以场景、设备及其空间关系形成界面的主设计语言和观看主体。先组织主体、空间联系与观看焦点，再将操作和读数融入对应部位或邻近区域；控件服务于理解与操作主体，不以通用表单骨架加一张美术配图代替专用界面。具体关系见 M1/M3/M4/M7/M8，不要求恢复旧像素布局。
- **让停驻观看有内容。** 不操作时，玩家仍能理解这里是什么、当前在运行什么或为何停下，并从战斗与环境延续、设备工作、探索过程或设施空间关系中获得持续观看的内容。变化取自真实航程、战斗、供能、研究、探索与建设状态；空闲、暂停和完成也应有清楚的静态状态，不用装饰动效假装工作。单纯放大图片或增加光效不构成此项完成。
- **延续已确认的美术。** 保留奶油白/象牙色装甲、海军蓝结构、青色能源与克制琥珀灯的圆润科幻语言，以及各模块的专用素材和语境。复用已接受的舰体、设备、设施、图标及字体，保持轮廓、透明边缘、色彩身份和模型枢轴，不为适配重画主体。旧 shell 色值 `#243d50/#ecebdc/#83cfcb` 可作依据；当前深蓝 `bridge_theme.gd` 是实现事实，不能取代已确认美术。D1 只处理布局适配，不重新开放换皮。
- **层次支持理解与操作。** 场景、主体、运行效果、控件和文字分层；信息取舍统一遵守 2.2；文字、数值、费用与进度由状态驱动，不烘焙进图片。能量沿结构/管路呈现，不能遮住主体或关键读数。识别兼用轮廓、图标和中文名称，品质、锁定、已装备、施工完成不只靠颜色；沿用[字体规范](../../assets/fonts/README.md)，保证实际尺寸下的图标、中文和金额可读，贴图无黑底、白边或串格。

### 2.2 全局信息层级与适配

所有界面按信息用途分层：常驻内容只保留当下判断所需的对象、状态、代价与结果；首次教程承担操作教学，之后由玩家主动打开手册或帮助查阅。重复按钮含义、泛化操作步骤及没有当前决策价值的解释从主界面移除；完整规则、公式和计算来历按需展开，不以长段说明占据场景。

精简教学不等于删去必要反馈：实际费用、冷却余时、缺人/占用、输入错误和操作失败原因必须在对应上下文清楚可见。关键选择前提供该次选择必要的效果、代价、风险与不可逆损失，不把它们藏到教程里；结果返回后显示实际变化。M1–M10 列举的是相应场景需要的信息与能力，不要求将所有说明同时常驻；预览、详情和确认层按当前决策展开，操作结束后收回临时信息。

当前 572×960 逻辑战场和六页舰桥仅是实现事实，不冻结目标布局。保留“战斗—舰桥—返回战斗”的清楚往返；专属美术模块按 2.1 的场景关系承载信息，不强制排列成统一表单，主操作与危险操作分开。

窄窗适配保留主体及其关键空间关系，将次要控制和长详情收纳在相应区域或抽屉；避免把舞台切成表单配图，或把旧 1364×1200 画布整体压缩到文字不可读。长中文换行，长金额保留单位/数量级，必要时提供完整值详情；列表纵向滚动且选中项可辨，不能让一个超长字段撑出横向溢出。弹层保持标题、关闭/返回及确认操作可达，覆盖时底层不误收点击。精确断点和控件尺寸尚未定稿，不以历史矩形为验收值。

展示对齐须区分四种边界：**资源边界**是贴图完整画布或模型包围盒；**可见主体边界**是实际呈现的主体轮廓/投影；**布局框**是容器分配的区域，含控件内边距；**点击区域**是实际接收输入的范围。四者不必重合，但各自用途和相互偏移须明确。不能只比较节点坐标或布局框，就判定视觉已经对齐；透明留白、样式内边距及模型原点偏移须在主体的最终显示变换中正确处理。

每类资产约定可见边界与用途相符的锚点（如视觉中心、设备底座、管口或挂载点），控件/模型按对应主体边缘或锚点对齐；不同资产不强用画布中心。旋转炮台、护盾和动效范围另列为扩展包络，不拿它们替代主体对齐，也不因对齐修正改变已定共享几何、真炮口或交互语义。可使用现有元数据、静态边界记录和消费端偏移适配，不要求一律裁切贴图、改模型原点或逐帧扫描 alpha。

### 2.3 所有模块共享的状态与反馈

| 状态/事件 | 玩家可见表现与操作语义 |
|---|---|
| 普通、悬停、焦点、按下、已选 | 普通保持足够对比；悬停/焦点有边框或底色提示，按下有即时反馈；已选持续可辨。悬停/详情补充规则，不重复解释清楚的按钮含义，也不替代当前决策必要信息。 |
| 未解锁、条件不足、余额不足、占用或冷却 | 显示锁/禁用态及具体原因，必要时列门槛、缺少的资源、占用者或剩余时间。不把全部失败都显示为无解释的灰按钮。未开放内容优先遵守明确的隐藏要求：科研前置未满足项、反应炉碎片凝聚未满足条件时直接隐藏，不保留锁定占位卡、禁用选项或设备空壳；其他内容仅在现行规则允许展示时解释限制，不用通用锁定态覆盖模块特例。 |
| 操作教学与规则查阅 | 首次教程讲解必要操作，之后主动查阅；主界面不常驻重复按钮含义或一般步骤。公式/规则细节按需展开；选择前仍提供当前对象的必要效果、代价与风险。 |
| 输入、选择与应用 | 草稿不伪装成已生效值；选择可预览对象，只有提交动作才修改业务。刷新保持正在编辑的草稿，当前值单列；非法输入留在原上下文并解释原因。 |
| 操作成功/失败 | 成功刷新对应对象、余额/效果并显示实际结果，临时成功反馈结束后收回；失败保留选择与可修正输入，显示领域原因和可修正目标，不以“去看教程”替代错误反馈。确认未返回前不能用成功动画冒充结算完成。 |
| 进度、完成、待领取 | 显示任务对象、进度、是否实际推进；完成与已领取分开。缺人暂停、等待、工作中使用不同文案，动效不得暗示实际没有发生的推进。 |
| 空列表、失效选择、加载 | 空仓/无岗位/无可选项有说明和可行入口；对象消失时清除旧详情并阻止向旧 ID 提交。准备中不假装已构建完毕。 |
| 暂停、倍速、离页 | 当前暂停可见、可恢复；状态提示不能依赖动画。战斗与任务时钟服从现行时间规则；隐藏的局部舞台停止无用绘制/动画，重开按当前快照显示。暂停时仍能查看、悬停和收到合法 UI 反馈。 |
| 预览—确认—取消 | 重铸、导入、新游戏、改造等现有事务显示对象、费用/损失、收益与保留项。更换对象或来源变化后旧预览失效；确认只执行所审阅操作，取消不提交；重复确认不重复扣费。具体业务按现行契约。 |

上述是交互目标，不要求为每次普通升级新增确认弹窗。沿用现有键盘/鼠标能力；新增快捷键、触屏手势、弹层自动暂停规则须先定稿，不能从旧行为推定。

## 3. 模块场景、布局与可见验收（规范）

每节的“来源”对应第 4 节，来源本身不是恢复清单。布局描述为适配后的信息关系。V1–V10 均须同时检查可见主体/锚点的实际对齐及点击区域，按第 6 节提供跨窗口与缩放证据；首次教程后主界面无重复操作教学，规则/公式可主动查阅；当前状态、真实代价、阻断原因和关键选择前的信息仍充分，结果反馈能对应实际变化。

### M1 导航、航行、战斗与资源

**场景/布局/控件：** 以敌我舰交火及已有场景背景组织战场，让待命、航行、战斗中的环境连续可见，保留当前背景资产与采样修复。HUD 紧凑地提供即时判断所需的盾甲余量/危险状态、关键战况及暂停/驻守状态；不以大防御面板、空框或常驻说明占据观看区。当前值/上限、资源明细、完整统计及策略设置按需查看，不能靠缩小文字或隐去必要盾甲信息换取空间。暂停、舰桥和返回战斗入口可辨，出航与驻守控制可达；具体布局服从下列空间预算。

**舰体层级与空间设计准则：**

| 类别 | 准则 |
|---|---|
| 设计目标 | 巡洋舰、战列舰、重型战列舰在正常战斗视图中具有可辨的体量层级。保留已确认模型与美术，通过相对尺度和布局适配实现，不靠持续放大高档舰拉开差距。 |
| 空间约束 | 先划定我舰最大完整占用、敌方编队、交火通道、无人机及未来扩展留白，再分配舰体尺度。普通敌舰占 1 格、精英占 2×2、首领居中占 3×2；占位包含舰体、转动炮台、护盾外缘、顶部盾甲条及间距，不拉伸舰图填格。完整包络取全部合法炮台朝向的扫掠范围与舰体、护盾的并集，并单列盾甲条范围；不得挤占相邻占位、画面边界或 HUD/导航遮罩。 |
| 当前参数事实 | 五舰基准高、全局/分舰倍率、逻辑尺寸及敌方适配框见第 8 节。这些是实现快照，不是本轮新批准尺寸；源图画布、UI 预览和舰体 alpha 框均不能代替完整装配包络。尺寸适配须继续使用共享几何和真实挂点/炮口，不另设命中尺寸。 |
| 待定参数 | 最大占用宽高、净空与留白预算、五档相对尺度及具体倍率尚未定。预算确定后，用同一逻辑单位和展示比例对比五舰，重点检查后三档；候选列宽高、统一 alpha 口径的可见面积、完整包络和剩余净空，并注明与当前值的差异。不得以外接框/透明画布面积冒充可见面积，也不能将当前尺寸或候选值默认为批准值。 |
| 验收标准 | 在预算内同时证明高级舰体量可辨与最大完整占用受控。覆盖各档我舰合法装配、敌方各阶及最密合法编队，记录最小净空及对应舰型/装配/朝向/编队；舰体、炮台、护盾和盾甲条完整可见，无相邻、敌我、顶边或 UI 重叠/裁切，交火、无人机及扩展空间保留。静态复算或已有背景/炮口专项不能替代这些画面证据；通过后另行批准参数实施。 |

**状态/反馈：** 保留空格暂停、G 驻守及点击掉落的操作能力，首次需要时给出相应短教学，之后在手册或按需说明中可查，不常驻占位；临时反馈结束后归还画面空间。输入框/弹层中不误触全局操作。敌我炮口、转向、光束连接与实际目标一致，环境随待命、航行、战斗状态衔接，背景随航程连续移动而不灰蓝跳变，不因停下或交战而丢失已有场景。护盾为零但装甲仍存、装甲为零但护盾仍存都仍显示存活，不能把一条空条表现为死亡。拾取用同一资源身份显示来源、数量与入账反馈，定时物数量按生成时确定，不能因领取时倍率变化跳数。教程覆盖时说明继续动作，暂停与恢复遵守 [01](01-runtime.md)。

**可见验收 V1：** **画面核对：** 交火和环境为主体，HUD 紧凑，盾甲/战况清楚，无大信息块、空框或常驻快捷教学；舰体层级、占位与净空按 M1 表记录。**操作核对：** 首次需要时教学暂停/驻守/拾取，退出后可主动回看；实际走待命→航行→战斗及撤退/再航行，背景连续且无整片闪变，炮台/活光束跟随真实目标；往返舰桥后暂停/驻守及按需详情一致，拾取提示与入账一致。完整品质和已专项通过项按 11 区分。来源 S1/S2/S3。

### M2 舰体、装备卡、换装与属性

**场景/布局/控件：** 舰体预览使用最新五舰静态图，清楚标出当前舰与候选舰、开放条件及武器/防御槽数量。装备以槽位为身份组织卡片，武器/防御分组；卡片含类型图标、名称、等级、主属性、当前装配和升级代价。详情展示当前与升级/更换候选的同口径属性比较；普通购级、批量/MAX、换装选择分清作用对象。小舰使槽位休眠时，区别“未启用”和“空槽”，不伪装进度丢失。

**状态/反馈：** 明示已装配、空槽、锁定、冷却剩余时间和不可支付的具体费用；材料与铁费用分别可辨。选择候选不立即冒充当前装备，提交后再更新卡片和属性。首防御槽不可卸空但可换合法防御类型；禁止照搬旧“固定装甲”的选择限制。大数比较用业务输出，不由 UI 重算成长、进化或 MAX。属性页区分基础/最终效果、当前盾甲和最大容量、临时效果，不能用预览图尺寸推导战斗碰撞。

**可见验收 V2：** **画面核对：** 舰体预览与槽位装备卡为主体，选择、比较、购级控制明确关联当前舰/槽；操作教学不常驻，属性、费用和冷却余时可读。**操作核对：** 同槽查看现装/候选并购级或换装，核对变化前后总费用、余额、属性和卡片；冷却/付款失败有具体原因，不换错槽，冷却结束恢复正确操作态；换舰后预览、卡片与 native 属性一致，首槽无卸空入口。来源 S2/S4。

### M3 反应炉供能

**场景/布局/控件：** 以“核心—主管—设备”的供能场景统领构图，核心是观看焦点，管路将已开放设备组织为可理解的工作系统，保留圆润控制台及设备身份。等级、容量/预算、购级费用融入核心控制区，分配与有效增益贴近对应设备；均分、清零、加减/输入可直达，不将机器缩成通用分配表的插图。

**状态/反馈：** 同时区分手动分配量/占比、重铸免费量、有效供能、最终增益。免费量不占手动预算；分配池不能把有效量当已占用手动量。核心、主管及设备动效读取真实有效负载，无供能不表现持续工作；预览值与已生效供能有区别。碎片凝聚未满足开放条件时，设备、分配行和可选项全部隐藏，不保留锁定占位；条件满足后再显示并接入供能关系。其他模块遵守其现行开放规则，滚动后管路与设备仍相接。

**可见验收 V3：** **画面核对：** 无操作时核心—管路—设备构成供能主体，工作/停机可辨，分配控制与读数对应实体；步骤/公式不常驻，手动、免费、有效供能与增益不混淆。**操作核对：** 在有/无免费量时执行均分、清零、购级，比较预算、读数和设备工作反馈；额度不足/非法输入保留实际值并给原因；碎片凝聚开放前不显示，开放后正确接入。来源 S5；旧接口坐标不作为硬约束。

### M4 AI 科技工厂

**场景/布局/控件：** 以工厂空间、当前研究设备和探针的工作关系构成观看主体，保留设备与背景的完整场景联系。当前研究名称、等级、进度、效果、速度及完成/剩余状态围绕设备呈现，投入控制融入工厂控制区；研究选择用抽屉/列表辅助切换，不能让选择器和输入行成为页面主体。只展示已满足前置条件的研究及设备，未满足项直接隐藏，不留锁定占位；选中研究明确。

**状态/反馈：** 研究切换保留各项工作量，画面必须跟随实际研究对象而非最后悬停对象。探针只为实际研究提供局部反馈；暂停/隐藏按时钟和可见性停动。投入输入显示“编辑中/未应用”及独立“当前生效值”，应用失败不改当前值；还原操作回到实际设置。自动投入预算刷新与岗位自动续研分开呈现当前开关、比例和岗位状态；预算刷新时机在相关选择时交代，完整机制按需查阅，不能承诺应用比例立即重算收入预算。完成后反馈等级/效果变化，不能补出未实现的十级换代或改装设备。

**可见验收 V4：** **画面核对：** 工厂设备为主体，探针、研究状态和投入控制围绕当前设备关联；教学不常驻，当前研究、草稿/实际值、应用生效时机清楚，推进/停顿/完成可辨。**操作核对：** 打开选择层、切研究，核对设备身份与保留进度；编辑投入时收入刷新不覆盖草稿，非法金额给原因；应用后核对实际设置，自动投入与续研的开关/岗位状态可区分；前置未满足项隐藏、满足后出现。来源 S6 及 `src/ui/research_panel.gd`。

### M5 强化效果、顺位与分支

**场景/布局/控件：** 保留强化的专用入口与碎片身份，顶部显示等级、费用及当前“购买 1 级”“最多购买 10 级”操作，不新增强化 MAX。武器/防御效果分组，按真实作用顺位显示效果卡，卡片含名称、当前有效效果摘要、状态、顺位操作和分支入口；完整作用规则按需查阅。分支选择前展示节点门槛、A/B 实际效果和当前路径，不能只给裸编号/字母。

**状态/反馈：** 已选分支持续标记，未开放节点解释门槛；移动顺位后显示实际生效顺序。详情区别购买等级、世界额外等级、有效效果，不能把奖励级当已支付级。分支选择成功才变更路径；失败保留原选择。不得因保留旧宝石美术恢复已撤的宝石装备/成长系统，也不能把现行强化键名改成旧玩法键。

**可见验收 V5：** **画面核对：** 效果卡与真实顺位为主体，顺位控制和分支入口对应所选效果；无常驻操作教学，完整规则可查，当前生效摘要与路径可读。**操作核对：** 打开分支时能看见本次选择的门槛和实际效果，未开放态不假装可选；前移效果或选分支后，对照顺位、路径和有效状态，失败保留原选择。来源 S7。

### M6 船员卡、岗位与任务

**场景/布局/控件：** 名册卡显示配置姓名、头像/岗位徽章、等级/经验与当前占用；选中后详情显示当前效果、岗位/目标、模式、派遣草稿和确认/释放。窄窗可名册→详情切换，保持当前人物身份。定制头像优先，缺图时按当前岗位回退；岗位徽章不成为永久职业或人物身份。

**状态/反馈：** 空闲、岗位工作、探索、施工、星系、超空间占用有不同状态文案及目标名。派遣候选和实际岗位并列可辨，选目标不先释放当前任务；满员、未开放及保留占用解释原因。详情提供人数/容量、任务进度或工作状态、完成奖励/经验反馈；等级提升按当前经验机制呈现，显示当前经验、升级进度及升级后效果，不新增付费船员升级或费用报价。岗位模式只操作现行允许的模式，不自行新增一键全派遣。

**可见验收 V6：** **画面核对：** 人物卡与当前任务为主体，派遣/释放对应选中船员；派遣步骤不常驻，姓名、等级/经验、岗位、人数/容量及占用原因清楚，锁定预览不冒充已拥有角色。**操作核对：** 同一船员空闲→派遣→切换/释放，对照名册、详情和目标人数；受限派遣显示具体原因；任务完成后核对实际状态、经验和等级变化。来源 S8。

### M7 星球探索、轨道设施与领取

**场景/布局/控件：** 以星球、探索机和轨道设施的空间关系组织页面，让探索与轨道发展成为观看内容；保留已接入的球体、独立云层和星体差异，不重画舞台。星球选择作导航，名称/探索度、人员/自动探索控制和任务读数围绕当前星球，设施详情与对应轨道对象关联，不把球体作为任务表旁的配图。设施图标与模型相符；详情含门槛、施工进度、额外施工人员、收益与领取，累计 Buff 和重铸入口可查。

**状态/反馈：** 区分未达门槛、building、缺人暂停、ready 待领、已领取；达到探索门槛不等于立刻建成。关闭自动为“本次完成后停止”，立即取消为独立动作。探索完成、发现设施、施工推进、可领取及领取成功各有对应信息；动画只强调实际事件，不以漂浮模型冒充已拥有。切球清除上一星球短暂反馈，未领取设施不能显示已生效收益。重铸按 M10 的预览确认，不照搬旧入口直接执行。

**可见验收 V7：** **画面核对：** 星球、探索机、轨道设施形成观看主体，任务和设施操作/详情对应场景对象；无常驻探索/领取教学，当前任务、缺人/施工/待领状态清楚，空闲/暂停不伪装推进。**操作核对：** 选择设施查看门槛与进度，补人后观察施工恢复；ready 后领取才显示实际所得与 Buff；分别关闭自动与立即取消，核对本次完成后停止和即时中止的区别。来源 S9。

### M8 星系地图、设施与建设

**场景/布局/控件：** 以总部、设施、平台桥与船只构成的星系空间为页面主体，保留已接入 galaxy_map 及设施渐进等级轮廓，让探索、建设与城市发展可供停驻观看。区域选择和人数/建设汇总服务于地图，所选节点的类型、等级、可达性、进度及收益/效果围绕选择对象展开，不让地图退为通用节点表的配图。支持现有平移、缩放和点击查看；人数调整经船员公开操作完成。

**状态/反馈：** 未探索的迷雾、规划地基、施工中、已建及升级中不同；施工显示真实进度，升级保留当前级主体。选中/悬停轮廓应能定位详情对象；拖动不误触选中。父节点可达规则和实际 explored 状态控制揭示，不能为美术摆放改变节点工作量或 RNG。运输船是表现，不用数量暗示真实收入或额外规则。星系建设/升级按现行自动完成规则反馈，不能照搬星球增加领取按钮。

**可见验收 V8：** **画面核对：** 总部、设施及交通/建设空间为主体，节点详情对应地图选择；无常驻平移/缩放教学，真实建设进度、节点收益与纯表现交通可区分。**操作核对：** 点击地基/设施、平移缩放后复核对象和详情；观察探索揭雾、建设完成/升级后的模型与读数一致；暂停/离页停止局部无用动画。来源 S10。

### M9 超空间挑战、挂机、仓库与改造

**场景/布局/控件：** 四路线以脉冲/导弹/舰炮/长激光图标及名称区分，展示挑战层数、最佳时间、能源、挂机对象和进度。探索、仓库、改造、过滤分区，沿用当前子页可适配。无人机以对应家族缩略图配武器、品质、等级、词缀/传说、挂设详情；主仓、溢出、封存及材料余额清楚区分。装备槽与仓库选择对应，当前装备/收藏/保留状态可辨。

**状态/反馈：** 手动挑战与在线挂机状态及开始/停止/结算/领取反馈分别显示，不让“查看路线”启动任务。品质同时有文字，收藏和已装备使用独立标记；不把封存/溢出项显示为可直接装备。改造先展示原形态/词缀与预期变化范围、费用和受保护项，再确认；随机结果不得在预览中宣称已获得。改变无人机、操作或参数后预览失效，完成后给出实际前后对照。过滤按当前操作显示可读条件、开关、全部/任一匹配方式、保留/拆解动作及应用/导入/导出反馈，不要求新增过滤影响预览；导入无效规则保留原规则；回执已领与可领分开。

应用仓库多选编队前明确本次会装备和卸下的对象，避免将批量装备与单架详情、拆解、挂设的作用范围混淆；Ctrl 多选等操作方法交给首次教程和按需帮助，不作常驻教学；不满足单选时明确提示。挂设列出已装/候选及限制，编队预设显示名称与应用结果；收藏、传说收藏与过滤保护的来源分别解释。材料兑换显示源材料、目标材料、支付量与收到量，数量单位不混用，失败保留原余额；具体比例和保护规则引用 [04](04-hyperspace.md)，不把旧兑换弹层形式变成必需步骤。拆解和封存释放显示目标与结果，保护阻断需明确原因。

**可见验收 V9：** **画面核对：** 路线/无人机及仓储状态为主体，装备、挂设、改造控制关联所选对象；多选/过滤教学不常驻，品质、装备、收藏/保护状态可辨。**操作核对：** 应用编队前可见本次装卸对象，改造前可见费用及保护限制；预览后换对象使确认失效，执行后只扣一次费并显示实际前后结果；过滤/领取/整理后核对余额与仓库，失败显示原因。舞台形式按 D4 定稿，不因旧 GLB 恢复旧渲染器。来源 S11。

### M10 重铸、保存、设置、档案与教程

**场景/布局/控件：** 重铸选择符合当前条件的星球及保留无人机，预览明确列出收益、清除和保留。设置中目录选择、保存/备份/导入、新游戏、音乐/音效、伤害数字模式和自动保存间隔有标签；现实时间与游戏时间单位分清。档案提供教程/敌方情报/通知，敌方缩略图与当前 visual_key 一致；通知已见与已读有区别。

**状态/反馈：** 重铸和导入预览绑定当前对象；取消不执行，状态变化重新预览。保存排队、写入中、有未保存进度、最近已写入、失败/恢复暂停必须可区别；仅排队不显示“已保存”。失败提示在战斗也可见，并指向设置中重试、换目录或恢复有效存档。恢复失败不静默覆盖文件；旧存档不兼容按 11 的明确决定拒绝且保留原文件。新游戏/恢复/重铸的说明不能被通用“完成”覆盖。首次教程有明确继续入口，已完成教学不在各页面反复常驻；跳过设置与档案重读保留；关闭音乐/音效的状态可见，不依赖声音证明操作成功。

**可见验收 V10：** **画面核对：** 当前事务对象、预览/恢复结果及档案内容为信息主体，确认/取消与其关联；常规设置不重复教学，实际保存状态和错误清楚，危险选择前的风险/损失不省略。**操作核对：** 导入/新游戏/重铸依次查看预览、取消和确认，核对对象一致及取消无副作用；保存失败时战斗/设置显示同一问题与恢复入口；首次教程可继续、已学操作可主动回看，通知已见/已读结果明确。真实音效、存档故障及完整流程须有各自运行证据。来源 S1/S12。

### 8.2 我方五档实际倍率与舰体逻辑尺寸

定义 `B=static_height`、`G=1.7`、`P=config.playerVisualScale<ship_key>`，当前 `mount_inputs` 使用：

```text
H = B × G × P
D = 源图画布尺寸 × H / (源图高度 × 标准化alpha凸包高度)
玩家逻辑轮廓 = transform_hull(标准化alpha凸包, (286,520), D, 0)
```

`H` 是目标舰体轮廓高度；`D` 是整张源画布的坐标变换尺寸，包含透明边距，不是舰体外接框。下表按当前 PNG 的 alpha>0 外接框静态复算，显示到三位小数；实际 Godot 以 `normalized_hull` 的边界及浮点结果为准。这些是舰体尺寸推导，不是完整装配包络实测。

| 舰型 / ship_key | 基准高 B | 全局 G | 分舰 P | 有效乘积 G×P | 舰体逻辑外接框 W×H | 整画布变换尺寸 D，W×H |
|---|---:|---:|---:|---:|---:|---:|
| 护卫舰 / Frigate | 60.2 | 1.7 | 1.3 | 2.21 | 98.124×133.042 | 112.268×147.186 |
| 驱逐舰 / Destroyer | 81.0 | 1.7 | 1.1 | 1.87 | 107.338×151.470 | 119.306×163.438 |
| 巡洋舰 / Cruiser | 104.8 | 1.7 | 1.2 | 2.04 | 162.792×213.792 | 175.848×226.848 |
| 战列舰 / Battleship | 109.6 | 1.7 | 1.3 | 2.21 | 212.602×242.216 | 226.746×256.360 |
| 重型战列舰 / Heavy_Battleship | 122.6 | 1.7 | 1.4 | 2.38 | 247.996×291.788 | 263.228×307.020 |

例如重型战列舰：`122.6×1.7×1.4=291.788`；当前 alpha 高 613、宽 521，故宽为 `291.788×521/613=247.996`。不能再乘 JSON 中的 `display_scale=0.12`，也不能把 UI manifest 的 `height=582.5876` 当战场基准高。

`mount_inputs.dimensions` 经 `prepare_player/_accept_player` 成为 `_player_dimensions`，随后生成 `_player_hull`。`_sync_geometry` 将它交给 `input_player_hull`，敌方凸包交给 `input_ballistic_geometry`，并把挂载/炮口交给同一 native 核；`_draw_hull_texture` 用这组轮廓和源 UV 绘制。因此表中我舰缩放同时影响共享轮廓与其接触几何、挂点空间关系；不是单独放大一张贴图。它不改变装备伤害、盾甲容量或经济数值。

炮台仍有自身投影参数：`approved_weapon_art.gd::player_pose` 取 `rendered_height/model_span` 与 `weapon_scale`，再由现行武器 manifest 的 `pixels_per_model/visual_scale/anchor/emission_pixels` 得到图像尺寸和每个真炮口。五档 `model_span/weapon_scale` 分别为 `5.669695/0.72`、`5.723601/0.68`、`6.304464/0.68`、`6.334/0.65`、`6.814157/0.58`。这些仍生效，不能将其当作废弃舰体倍率删除，也不能只凭舰体表推定转动炮台均在舰体框内。

**旋转及等比适配的实际顺序：**

```text
θ = 按 actor.uid/slot 的独立几何随机流产生的 [-4°, +4°] + 180°
(w,h) = 标准化alpha凸包外接框尺寸 × PNG画布尺寸
(rw,rh) = (w×|cosθ| + h×|sinθ|, w×|sinθ| + h×|cosθ|)
(Aw,Ah) = 该条目 display_size，缺省为普通框
fit = min(Aw/rw, Ah/rh)
D = PNG画布尺寸 × fit
逻辑轮廓 = transform_hull(标准化alpha凸包, actor位置, D, θ)
```

源船首朝上，转 180° 后朝下；±4° 扰动仍有效。每个 actor 的 fit 随其角度变化，横纵使用同一比例，不能把图拉伸填满适配框；矩形旋转边界公式是保守适配，不保证实际凸包同时触满框的两条边。分级模型同样用最终轮廓绘制、碰撞和挂点，不能另外给显示与命中应用两组尺寸。

### 8.6 本统计尚未证明的验收项目

最大**舰体**是本表中的 Heavy_Battleship，静态推导外接框约 `247.996×291.788`；这不证明它也是任意炮台装配下最大**完整包络**。本节没有测量炮台所有合法朝向、护盾外缘、盾甲条/间距、最密编队的实际组合包络，也没有测量其与画面边界、HUD、相邻敌舰及敌我间的最小净空。

现行普通框和分级 display_size 只进入舰体适配，代码的尺寸计算没有把两条盾甲条加入该框；因此不能据此认定盾甲条已计入占位。可见面积、完整包络与最小净空尚未测量，V1/G9 及整体画面品质仍待验收。
