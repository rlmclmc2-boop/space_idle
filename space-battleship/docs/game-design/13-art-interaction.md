# 13 全局美术与交互规范

[唯一入口](README.md)。本页定义桌面宽屏的构图、资产呈现、信息层级与控件反馈；各模块主体见第3节。Owner 提供对象、可见/可用状态、读数和操作结果，UI 将这些事实转为画面。解锁条件、触发时机和进度规则由[01](01-runtime.md)、[03](03-progression.md)、[04](04-hyperspace.md)及对应[模块接口](14-ui-contracts.md#2-主线现有模块连接)定义。

## 1. 设计依据

美术制作与完成判断以最新用户批准的设计稿及明确修订为准，尽可能还原整体构图、造型比例、空间关系、材质光照、细节层次和动态意图。共同风格用语用于说明稿中具体特征，批准稿本身是成品目标。

当前任务固定设计图文件/版本和用户批准范围；多张依据分别注明适用部分。只有方向或局部获准时，按该范围制作与评价，其余设计保留待定。未批准的新图保持候选身份，获准后才更新依据。制作来源见[11](11-stage6-contract.md)，未定选择见[适配问题](art/open-items.md)。

实际窗口、内容量或交互需要适配时，逐处说明设计稿位置、实际差异、具体约束、处理方式和视觉影响，优先保住原构图与造型意图；改变已批准整体设计的差异交用户裁定。分件、复用、渲染方式和导入参数服务于还原结果。

## 2. 全局呈现

### 2.0 整屏构图与全局UI

当前目标为桌面宽屏：战场持续可见，模块主体、紧凑导航和资源读数形成稳定主次。模块展开、收起与切换保持战场、操作区和焦点关系。各模块可以采用自己的场景主体及控件载体，共享字体、间距层级、数字角色与控件材质。

先对照批准稿建立整屏比例、主剪影与空间关系，再落实材质光照、细节、控件和动态。坐标、容器尺寸与一屏行数按实际内容适配，同时保持批准的构图、对象和操作关系。

### 2.1 场景与主体

采用统一简化分面装甲的科幻语言：主体、场景、舰船与控制台使用相近轮廓强度、大体块/中尺度分件、批准稿中的主要明暗与转折层次和宽而受控的反射。奶油白/象牙、深蓝、青色与暖金承担材质身份及主辅强调；金属、保护面和玻璃在同一抽象层级下区分。环境受光方向、冷暖关系、接触阴影及遮挡共同解释空间，局部能量光服务于工作过程和整页主次。背景、设备、管路、工作层、读数和控件分层，读数与状态实时绘制。持续观看时能辨认当前对象及工作、停顿、完成状态，操作控件与其作用对象关联。

**当前造型参照。** 以现有舰船的大剪影、深色外轮廓和简化明暗作为抽象程度参照，先将星球设备向此收敛。外轮廓强于装甲接缝，接缝强于内部小件；主要受光面、暗侧和内腔组成与批准稿相应的主次明暗和转折层次。深蓝承力结构、象牙装甲及局部功能色还须靠轮廓、开口和受光区分材质，不能只因配色相同认定同族。星球具体制作要求见[M7](art/modules/planet.md#与现有舰船统一的制作要求)。

### 2.2 全局信息层级与适配

**信息。** 常态优先当前对象、等级/属性、状态、费用和操作；教学完成后收起步骤说明，规则可主动查阅。长中文、极大金额、详情弹层及滚动内容仍有完整承载区。比较同时标明当前值、候选值和实际结果。

**边界与对齐。** 分别定义源资源边界、可见主体、布局框与点击区。按文字墨迹、图标光学中心和主体锚点对齐；设备底座、炮口、管口及动态包络使用各自实际几何。透明留白计入变换，交互区与可见对象对应。

**字体。** 名称、等级、属性、费用和操作采用共享字体角色；同类信息同字号/字重。装备卡名称、属性与费用标签保持一致角色。费用行的标签、图标、资源名和数值共用基线，双费用行同节奏；不足只将对应消耗数值标红，资源名和图标保留身份色。

**资源身份。** `1` 铁为暖金属锭，`2` 铀为绿色核，`chrono` 为青蓝沙漏，`jewel` 为紫晶，`degenerate_matter` 为灰蓝致密球。使用 `resource_visuals.gd` 的 `icon/icon_modulate/color` 及现有图集/补图。现行参考尺度为余额约17px、报价约20px、掉落约28px（外圈半径15px，拾取半径18px）；布局按最终可见体积适配。

**透明图标。** 读取原始带 alpha 纹理/图集区域；图标主体透明度与 UI 背景分层。导入保持 RGBA 与正确 alpha 混合，按最终小尺寸在深浅承载面核边缘、裁切和光学对齐。资源名、读数、底板由原生控件绘制。

**数字格式。** 通用数值经 `PlayerText.number`，直接消费规范 Amount 文本。按绝对值阈值 10³/10⁶/10⁹/10¹²/10¹⁵ 使用 k/m/b/t/kt，≥10¹⁸ 使用规范 e；保留一位小数，四舍五入跨阈值升单位（999.95k→1.0m，999.95kt→1.0e18，10²⁰→1.0e20）。通用整数保留 .0，零及负零显示0。资源经 `PlayerText.resource_number`：普通整数无 .0（12、12.0→12），大数保留缩写的一位小数（1000→1.0k）。资源读数消费Owner提供的有效整数结果，实际整数化与展示输入由[资源契约](contracts/resources.md)定义。

**数字与控件角色。** `BridgeTheme.number_role_color(role,surface)` 的 current/gain/cost/insufficient 在 light/dark 承载面上保持可读，使用 `apply_number_role`。普通操作深青、主要操作暖金；共用 `operation_plate/operation_button/apply_operation_button/apply_operation_select`，覆盖普通、悬停、按下、选中、不可用与焦点态。

### 2.3 所有模块共享的状态与反馈

数量键循环 **×1→×10→MAX**，只切本地模式并读取 Owner 报价；独立购买键执行当前模式。装备顶部全局数量键同步下方各槽模式、报价和可购买显示，顶部与各槽购买键分别执行既有命令。数量、费用、MAX 与实际成交由所属 Owner 提供。

普通资源不足在对应费用数值上标红，执行键保持可点击，Owner 拒绝后短提示具体原因；其他不可用状态显示所属接口提供的原因。选择、执行、当前选中、不可用和焦点角色可跨页辨认。交互反馈如下：

| 状态 | 呈现目标 |
|---|---|
| 悬停/选择 | 对象身份、候选与当前选择清楚；详情跟随选中对象 |
| 可见/不可见/不可用 | 按 Owner 输出映射显隐、剪影或不可用样式；各模块约定其具体表现 |
| 草稿/已生效/提交结果 | 编辑值与当前值分开；成功更新实际值，拒绝保留可修改草稿和原因 |
| 工作/进度/完成/空态 | 读数和局部效果对应同一对象的当前状态，空态给出必要入口 |
| 暂停/隐藏/重开 | 暂停可辨且可恢复；暂停仍可查看和获得合法控件反馈；隐藏停止局部刷新，重开投影最新状态 |
| 危险事务预览 | 持续显示对象、费用/损失、收益与保留项，提供确认/取消；按对应事务接口处理来源变化与实际结果 |

### 2.4 制作前的布局约束与整页校验

1. 先在批准构图中确定主体比例、可见内容区、边缘净空和遮挡关系，再安排控件。
2. 定义容器内边距、行内间距与组间间距三个层级；同类组保持一致，具体尺寸适配模块。
3. 名称/等级组成身份组，属性组成比较组，费用和操作建立明确关联；组内统一基线与对齐轴。
4. 用实际字体、最长名称和金额确定容纳量；空间不足时调整容器、排列、换行或滚动，保留文字可读性与组间留白。
5. 主体、图标、文字和控件边光均落在实际承载面内，动态包络和滚动边缘有净空。
6. 在少内容、满内容、长值及相关交互状态下看完整页面，确认主次、对齐、密度与操作关系持续成立。

## 5. 资产与业务接口

模块以稳定对象 ID 连接 Owner 事实、原生控件和资产。资产元数据维护画布、可见边界、锚点、图层、安装变换及动态包络；业务读写使用[14](14-ui-contracts.md)的模块端口。

## 6. 制作与双审证据口径

以同一固定实机版本的完整页面与批准稿并置比较，标明稿件版本/批准范围、实际窗口与视角、比例映射及覆盖状态；局部放大辅助判断细节。动态主体在正常观看速度下对照已批准的过程意图，可用受控Owner状态呈现工作、显隐或反馈。

**整屏验收 V0：** 成品尽可能还原批准稿的整体构图与主次、主体比例与空间、材质光照、细节层次及动态意图；展开、收起与内容变化保持这些关系，文字、点击区和动态包络完整。对照结论说明具体还原结果和仍有差异的位置，必要适配按第1节处理。M1–M10的V项规定本模块重点，均使用这一完成口径。

美术完成以整体还原效果判断。可复用、成功导入、接口正确、交互可用和性能数据分别记录为相应技术结果；美术结论另按稿件对照形成。审核主体、固定版本、覆盖范围与实际结果按[07](07-verification.md#5-实施顺序)记录。
