# 美术与交互设计规范

本篇由[唯一设计入口](README.md)进入，供现有制作与双审共同使用。核对基线为 `main@5fe73642`（简称 `5fe7364`），历史专用 UI 基线为 `b4729b9a9803458b5ac19a4945c2fe0d5f76e51f`。本次仅补文档；不表示画面已完成验收，不授权恢复旧代码、改玩法或改配置。

## 1. 要求、证据与规范的身份

| 标记 | 含义与使用方式 |
|---|---|
| 确认 | 用户要求保留现有美术与成熟交互，不想每次重新做美术；同时明确不完整复制之前表现。后三档高级舰体量应可辨，最大舰完整占用须受空间预算限制，给交火、无人机及未来扩展留空间；具体调整倍率未定。保留最新舰图、共享几何、背景及炮口修复；已接入的 planet_visual、galaxy_map 保留。敌方普通占 1 格、精英占 2×2、首领居中占 3×2，盾甲条计入占位；未满足条件的科研项及反应炉碎片凝聚隐藏。 |
| 事实 | 在上述指定提交、资产说明或当前消费端中可以查到的实现。只证明存在过或当前存在，不自动构成需求、品质通过或恢复授权。 |
| 规范 | 本篇补齐的制作与可见验收要求，落实确认的方向及已指出的页面缺口。描述玩家应看见/能完成什么，不指定旧实现关系。不得称为用户已逐项确认的像素稿。 |
| 待定 | 证据不足或有多个可行表现，需要视觉定稿/专项评审。未决项不由旧代码默认补齐，详见第 7 节。 |

规则冲突时：用户明确决定及现行 01–04/08 的玩法优先；当前资产接受与实现边界见 [11](11-stage6-contract.md)；本篇负责呈现，不重定义数值。历史资产 README 的“当前”“运行时”须结合本篇来源核对表理解。旧页面布局只提供信息层次和识别线索，不是当前硬尺寸。

## 2. 全局美术与交互原则（规范）

### 2.1 视觉延续

- 延续奶油白/象牙色装甲、海军蓝结构、青色能源与克制琥珀灯的圆润科幻语言。深色战场提供舰体与弹体对比，浅色卡片承载装备、人物与设施信息；AI 工厂的深色舞台可保留其专用语境。不把整套专用界面简化成同色文本清单。
- 优先复用已接受的舰体、炮台、设备、设施、图标及字体。保持原有轮廓、透明边缘、色彩身份和模型枢轴；适配裁切、留白与容器，不为凑布局重画已接受主体。新增素材沿用对应资产规范；没有新美术需求时不重新生成。
- 场景、主体、运行效果、控件、文字分层。文字、数量、价格、工作进度与发光强弱由当前状态驱动，不烘焙到图片里。青光沿结构/管路走，不能遮住舰体、目标、费用或输入框。
- 识别同时依赖轮廓、图标和中文名称；品质、锁定、已装备、施工完成不能只靠颜色。图标在实际消费尺寸可辨，透明贴图不出现黑底、白边、相邻图集串格。字体沿用 [字体说明](../../assets/fonts/README.md)，实际中文与数字可读性须看运行效果。
- 保留已确认的奶油白/海军蓝/青色圆润美术语言及各模块专用素材。旧 shell 的 `#243d50/#ecebdc/#83cfcb` 可提供现有语言的配色依据；当前 `bridge_theme.gd` 的深蓝主题是实现事实，不能据此取代已确认美术。D1 仅处理同一美术语言下的字号、间距、密度与排布适配，不重新开放换皮或重选风格。

### 2.2 适配与层次

事实：当前基线为 572×960 逻辑战场、舰桥六页（舰船、成长、星图、超空间、档案、设置）。这些尺寸和页面分组只记录当前实现，不冻结为目标规范；制作可在保留已确认美术、入口能力和交互语义的前提下适配布局。规范：保持“战斗—舰桥—返回战斗”的清楚往返；模块可用子区/抽屉适配，无需恢复旧全宽多列壳。阅读顺序始终为当前对象 → 当前状态/效果 → 可操作项与代价 → 结果。主操作与危险操作分开，长说明可折叠但实际值、费用、阻断原因不能藏在装饰后。

在现有窄窗按顺序重排卡片、舞台和详情，避免把旧 1364×1200 画布整体压缩到文字不可读。长中文换行，长金额保留单位/数量级，必要时提供完整值详情；列表纵向滚动且选中项可辨，不能让一个超长字段撑出横向溢出。弹层保持标题、关闭/返回及确认操作可达，覆盖时底层不误收点击。精确断点和控件尺寸尚未定稿，不以历史矩形为验收值。

### 2.3 所有模块共享的状态与反馈

| 状态/事件 | 玩家可见表现与操作语义 |
|---|---|
| 普通、悬停、焦点、按下、已选 | 普通保持足够对比；悬停/焦点有边框或底色提示，按下有即时反馈；已选持续可辨。悬停提示补充信息，不替代关键文字。 |
| 未解锁、条件不足、余额不足、占用或冷却 | 显示锁/禁用态及具体原因，必要时列门槛、缺少的资源、占用者或剩余时间。不把全部失败都显示为无解释的灰按钮。未开放内容优先遵守明确的隐藏要求：科研前置未满足项、反应炉碎片凝聚未满足条件时直接隐藏，不保留锁定占位卡、禁用选项或设备空壳；其他内容仅在现行规则允许展示时解释限制，不用通用锁定态覆盖模块特例。 |
| 输入、选择与应用 | 草稿不伪装成已生效值；选择可预览对象，只有提交动作才修改业务。刷新保持正在编辑的草稿，当前值单列；非法输入留在原上下文并解释原因。 |
| 操作成功/失败 | 成功刷新对应对象、余额/效果和结果提示；失败保留选择与可修正输入，显示领域原因。确认未返回前不能用成功动画冒充结算完成。 |
| 进度、完成、待领取 | 显示任务对象、进度、是否实际推进；完成与已领取分开。缺人暂停、等待、工作中使用不同文案，动效不得暗示实际没有发生的推进。 |
| 空列表、失效选择、加载 | 空仓/无岗位/无可选项有说明和可行入口；对象消失时清除旧详情并阻止向旧 ID 提交。准备中不假装已构建完毕。 |
| 暂停、倍速、离页 | 当前暂停可见、可恢复；状态提示不能依赖动画。战斗与任务时钟服从现行时间规则；隐藏的局部舞台停止无用绘制/动画，重开按当前快照显示。暂停时仍能查看、悬停和收到合法 UI 反馈。 |
| 预览—确认—取消 | 重铸、导入、新游戏、改造等现有事务显示对象、费用/损失、收益与保留项。更换对象或来源变化后旧预览失效；确认只执行所审阅操作，取消不提交；重复确认不重复扣费。具体业务按现行契约。 |

上述是交互目标，不要求为每次普通升级新增确认弹窗。沿用现有键盘/鼠标能力；新增快捷键、触屏手势、弹层自动暂停规则须先定稿，不能从旧行为推定。

## 3. 模块场景、布局与可见验收（规范）

每节的“来源”对应第 4 节，来源本身不是恢复清单。布局描述为适配后的信息关系。

### M1 导航、航行、战斗与资源

**场景/布局/控件：** 战场主体保持敌我舰、弹体、背景的层次；盾甲各显示当前值/上限及条形比例，资源余额与战斗统计独立排布。航程显示关卡、战点、航行/交战/等待/驻守/撤退状态；出航、驻守及死亡后驻守策略属于航行控制。暂停入口、舰桥入口及返回战斗始终可辨，教程提示与通知档案有清楚关系。

**编队占位与净空：** 普通敌舰占 1 格，精英占 2×2，首领居中占 3×2；格数描述占位，不等于把舰图任意拉伸到格框。占位须容纳该舰完整舰体、随目标转动的炮台、护盾可见外缘以及顶部护盾条/装甲条，条形显示与其间距都计入高度，不能只把舰体中心放进格子。布阵按占用格排除重叠，盾甲条不能被上方相邻舰、战场顶边或 UI 裁掉；首领居中与已接受模型缩放、共享逻辑几何一并核对，不为塞进旧布局缩回已接受舰图。

净空核对须覆盖敌方各阶最大包络、最密合法编队，以及五种我舰中的最大完整包络。完整包络取当前已接受舰体、全部合法炮台朝向的扫掠范围与护盾外缘的并集，并单列盾甲条范围；比较最近敌我边界、相邻占位边界、画面边界与 HUD/导航遮罩，记录实际最小净空及对应舰型/朝向/编队。不得只用舰体 PNG 宽高、alpha 凸包或旧 90.4×79.333 适配盒证明安全；alpha 共享碰撞几何仍保持原职责，表现包络检查不能改伤害几何。具体像素间距由适配决定，但完整可见、无重叠/裁切和最大我舰仍有作战净空是既定验收要求。本次静态来源核对不能代替运行画面的净空测量。

**状态/反馈：** 保留空格暂停、G 驻守和点击掉落的可发现提示；输入框/弹层中不误触全局操作。敌我炮口、转向、光束连接与实际目标一致，背景随航程连续移动而不灰蓝跳变。护盾为零但装甲仍存、装甲为零但护盾仍存都仍显示存活，不能把一条空条表现为死亡。拾取用同一资源身份显示来源、数量与入账反馈，定时物数量按生成时确定，不能因领取时倍率变化跳数。教程覆盖时说明继续动作，暂停与恢复遵守 [01](01-runtime.md)。

**可见验收 V1：** 战斗与舰桥往返后对象、暂停、驻守指示一致；连续航行/撤退/再航行无背景整片闪变；炮台及活光束随真实目标；普通 1 格、精英 2×2、首领居中 3×2 的最密合法组合中，舰体、炮台、护盾及两条盾甲条完整可见，盾甲条已计入占位且顶部不消失；给出最大我舰及敌方完整包络的最小净空记录，证明相邻、敌我、顶边和 HUD 之间不重叠/裁切；盾甲、资源、提示互不遮挡；点击可见掉落后余额与反馈一致。此处保留已专项通过项，完整品质仍按 11 的边界复验。来源 S1/S2/S3。

### M2 舰体、装备卡、换装与属性

**场景/布局/控件：** 舰体预览使用最新五舰静态图，清楚标出当前舰与候选舰、开放条件及武器/防御槽数量。装备以槽位为身份组织卡片，武器/防御分组；卡片含类型图标、名称、等级、主属性、当前装配和升级代价。详情展示当前与升级/更换候选的同口径属性比较；普通购级、批量/MAX、换装选择分清作用对象。小舰使槽位休眠时，区别“未启用”和“空槽”，不伪装进度丢失。

**状态/反馈：** 明示已装配、空槽、锁定、冷却剩余时间和不可支付的具体费用；材料与铁费用分别可辨。选择候选不立即冒充当前装备，提交后再更新卡片和属性。首防御槽不可卸空但可换合法防御类型；禁止照搬旧“固定装甲”的选择限制。大数比较用业务输出，不由 UI 重算成长、进化或 MAX。属性页区分基础/最终效果、当前盾甲和最大容量、临时效果，不能用预览图尺寸推导战斗碰撞。

**可见验收 V2：** 同槽查看现装与候选能辨认属性变化与总费用；冷却时说明原因并在结束后恢复正确操作态；失败不换错槽；购级/换舰后卡片、预览与 native 属性一致，首槽无卸空入口。来源 S2/S4。

### M3 反应炉供能

**场景/布局/控件：** 保留“核心—主管—设备”的供能关系，圆润控制台与四类设备保持身份。核心区显示等级、容量/预算和购级费用；模块区将设备、分配控件及有效效果关联。均分、清零、加减/输入等当前业务操作可直达；可用滑杆适配成熟交互，但不能以拖动动画代替成功提交。

**状态/反馈：** 同时区分手动分配量/占比、重铸免费量、有效供能、最终增益。免费量不占手动预算；分配池不能把有效量当已占用手动量。核心、主管及设备动效读取真实有效负载，无供能不表现持续工作；预览值与已生效供能有区别。碎片凝聚未满足开放条件时，设备、分配行和可选项全部隐藏，不保留锁定占位；条件满足后再显示并接入供能关系。其他模块遵守其现行开放规则，滚动后管路与设备仍相接。

**可见验收 V3：** 在有免费量和无免费量两种状态下，可解释预算与增益；均分/清零/购级后各读数及供能表现一致，额度不足或输入失败保留当前值；碎片凝聚开放前完全不显示、开放后正确接入。来源 S5；旧接口的坐标不作为当前布局硬约束。

### M4 AI 科技工厂

**场景/布局/控件：** 保留工厂背景、当前研究设备、独立探针的舞台语义。当前研究名称、等级、工作量进度、效果、速度和完成/剩余状态可在舞台旁或下方阅读。选择研究的抽屉/列表只展示已满足前置条件的研究及对应设备，未满足项直接隐藏，不展示锁定占位卡或禁用选项；选中项明确；铁/秒、铀/秒和自动投入独立成控制区。

**状态/反馈：** 研究切换保留各项工作量，画面必须跟随实际研究对象而非最后悬停对象。探针只为实际研究提供局部反馈；暂停/隐藏按时钟和可见性停动。投入输入显示“编辑中/未应用”及独立“当前生效值”，应用失败不改当前值；还原操作回到实际设置。自动投入预算刷新与岗位自动续研是两件事，标明当前开关、比例和实际生效时机，不能承诺应用比例立即重算收入预算。完成后反馈等级/效果变化，不能补出未实现的十级换代或改装设备。

**可见验收 V4：** 编辑铁投入时收入刷新不覆盖草稿；切研究能辨认当前机器和保留进度；非法金额有解释；自动投入与续研的开关/岗位状态可区分；前置未满足项不出现，前置满足后进入可选列表。来源 S6 及现行 `src/ui/research_panel.gd`。

### M5 强化效果、顺位与分支

**场景/布局/控件：** 保留强化的专用入口与碎片身份，顶部显示等级、费用及当前“购买 1 级”“最多购买 10 级”操作，不新增强化 MAX。武器/防御效果分组，按真实作用顺位显示效果卡，卡片含名称、作用说明、有效状态、顺位操作和分支入口。分支详情展示节点门槛、A/B 实际说明和当前路径，不能只给裸编号/字母。

**状态/反馈：** 已选分支持续标记，未开放节点解释门槛；移动顺位后显示实际生效顺序。详情区别购买等级、世界额外等级、有效效果，不能把奖励级当已支付级。分支选择成功才变更路径；失败保留原选择。不得因保留旧宝石美术恢复已撤的宝石装备/成长系统，也不能把现行强化键名改成旧玩法键。

**可见验收 V5：** 无需查代码即可读懂六种效果的当前顺位、所选分支和下个门槛；改顺位/分支后说明及实际有效状态一致，锁定态不假装可选。来源 S7。

### M6 船员卡、岗位与任务

**场景/布局/控件：** 名册卡显示配置姓名、头像/岗位徽章、等级/经验与当前占用；选中后详情显示当前效果、岗位/目标、模式、派遣草稿和确认/释放。窄窗可名册→详情切换，保持当前人物身份。定制头像优先，缺图时按当前岗位回退；岗位徽章不成为永久职业或人物身份。

**状态/反馈：** 空闲、岗位工作、探索、施工、星系、超空间占用有不同状态文案及目标名。派遣候选和实际岗位并列可辨，选目标不先释放当前任务；满员、未开放及保留占用解释原因。详情提供人数/容量、任务进度或工作状态、完成奖励/经验反馈；等级提升按当前经验机制呈现，显示当前经验、升级进度及升级后效果，不新增付费船员升级或费用报价。岗位模式只操作现行允许的模式，不自行新增一键全派遣。

**可见验收 V6：** 同一船员从空闲派到岗位，再切换/释放时，名册、详情与目标人数一致；任务完成后可见状态和经验变化；锁定预览与下一门槛不冒充已拥有角色。来源 S8。

### M7 星球探索、轨道设施与领取

**场景/布局/控件：** 保留已接入的球体、独立云层、星体差异、轨道设施和探索机，不重画舞台。页面提供星球选择、名称/探索度、人员/自动探索控制、任务状态、设施列表与详情。设施图标与实际模型相符，详情列解锁/探索门槛、施工进度、额外施工人员、收益和领取操作；奖励、累计 Buff 与重铸入口可查。

**状态/反馈：** 区分未达门槛、building、缺人暂停、ready 待领、已领取；达到探索门槛不等于立刻建成。关闭自动为“本次完成后停止”，立即取消为独立动作。探索完成、发现设施、施工推进、可领取及领取成功各有对应信息；动画只强调实际事件，不以漂浮模型冒充已拥有。切球清除上一星球短暂反馈，未领取设施不能显示已生效收益。重铸按 M10 的预览确认，不照搬旧入口直接执行。

**可见验收 V7：** 同球可查看设施门槛、缺人/施工/待领状态；补人后进度恢复；ready 后点击领取才显示所得与 Buff；探索停止与取消效果可辨。来源 S9。

### M8 星系地图、设施与建设

**场景/布局/控件：** 保留已接入 galaxy_map、独立总部、各类设施的渐进等级轮廓、平台桥与运输/施工/探索船。地图与区域选择、人数/建设汇总、所选节点详情相配，支持现有拖动平移、滚轮缩放及点击查看。详情显示真实节点类型、等级、可达性、探索/建设/升级状态及当前收益/效果；人数调整经船员公开操作完成。

**状态/反馈：** 未探索的迷雾、规划地基、施工中、已建及升级中不同；施工显示真实进度，升级保留当前级主体。选中/悬停轮廓应能定位详情对象；拖动不误触选中。父节点可达规则和实际 explored 状态控制揭示，不能为美术摆放改变节点工作量或 RNG。运输船是表现，不用数量暗示真实收入或额外规则。星系建设/升级按现行自动完成规则反馈，不能照搬星球增加领取按钮。

### M9 超空间挑战、挂机、仓库与改造

**场景/布局/控件：** 四路线以脉冲/导弹/舰炮/长激光图标及名称区分，展示挑战层数、最佳时间、能源、挂机对象和进度。探索、仓库、改造、过滤分区，沿用当前子页可适配。无人机以对应家族缩略图配武器、品质、等级、词缀/传说、挂设详情；主仓、溢出、封存及材料余额清楚区分。装备槽与仓库选择对应，当前装备/收藏/保留状态可辨。

**状态/反馈：** 手动挑战与在线挂机状态及开始/停止/结算/领取反馈分别显示，不让“查看路线”启动任务。品质同时有文字，收藏和已装备使用独立标记；不把封存/溢出项显示为可直接装备。改造先展示原形态/词缀与预期变化范围、费用和受保护项，再确认；随机结果不得在预览中宣称已获得。改变无人机、操作或参数后预览失效，完成后给出实际前后对照。过滤按当前操作显示可读条件、开关、全部/任一匹配方式、保留/拆解动作及应用/导入/导出反馈，不要求新增过滤影响预览；导入无效规则保留原规则；回执已领与可领分开。

仓库多选必须说明“应用整组编队，未选的原编队将卸下”，将批量装备与单架详情、拆解、挂设的作用范围分清；不满足单选时明确提示。挂设列出已装/候选及限制，编队预设显示名称与应用结果；收藏、传说收藏与过滤保护的来源分别解释。材料兑换显示源材料、目标材料、支付量与收到量，数量单位不混用，失败保留原余额；具体比例和保护规则引用 [04](04-hyperspace.md)，不把旧兑换弹层形式变成必需步骤。拆解和封存释放显示目标与结果，保护阻断需明确原因。

**可见验收 V9：** 同时辨认路线、无人机品质/装备/收藏/仓储状态；换选对象使旧改造确认失效；成功只扣一次费用并显示实际结果；过滤/领取结果与余额和仓库一致。素材有旧 GLB 不意味着恢复旧友方渲染器；当前无人机舞台形式见 D4。来源 S11。

### 8.2 我方五档实际倍率与舰体逻辑尺寸

定义 `B=static_height`、`G=1.7`、`P=config.playerVisualScale<ship_key>`，当前 `mount_inputs` 使用：

```text
H = B × G × P
D = 源图画布尺寸 × H / (源图高度 × 标准化alpha凸包高度)
玩家逻辑轮廓 = transform_hull(标准化alpha凸包, (286,520), D, 0)
```

`H` 是目标舰体轮廓高度；`D` 是整张源画布的坐标变换尺寸，包含透明边距，不是舰体外接框。下表按当前 PNG 的 alpha>0 外接框静态复算，显示到三位小数；实际 Godot 以 `normalized_hull` 的边界及浮点结果为准。这些是舰体尺寸推导，不是完整装配包络实测。

| 舰型 / ship_key | 基准高 B | 全局 G | 分舰 P | 有效乘积 G×P | 舰体逻辑外接框 W×H | 整画布变换尺寸 D，W×H |
|---|---:|---:|---:|---:|---:|---:|
| 护卫舰 / Frigate | 60.2 | 1.7 | 1.3 | 2.21 | 98.124×133.042 | 112.268×147.186 |
| 驱逐舰 / Destroyer | 81.0 | 1.7 | 1.1 | 1.87 | 107.338×151.470 | 119.306×163.438 |
| 巡洋舰 / Cruiser | 104.8 | 1.7 | 1.2 | 2.04 | 162.792×213.792 | 175.848×226.848 |
| 战列舰 / Battleship | 109.6 | 1.7 | 1.3 | 2.21 | 212.602×242.216 | 226.746×256.360 |
| 重型战列舰 / Heavy_Battleship | 122.6 | 1.7 | 1.4 | 2.38 | 247.996×291.788 | 263.228×307.020 |

例如重型战列舰：`122.6×1.7×1.4=291.788`；当前 alpha 高 613、宽 521，故宽为 `291.788×521/613=247.996`。不能再乘 JSON 中的 `display_scale=0.12`，也不能把 UI manifest 的 `height=582.5876` 当战场基准高。

`mount_inputs.dimensions` 经 `prepare_player/_accept_player` 成为 `_player_dimensions`，随后生成 `_player_hull`。`_sync_geometry` 将它交给 `input_player_hull`，敌方凸包交给 `input_ballistic_geometry`，并把挂载/炮口交给同一 native 核；`_draw_hull_texture` 用这组轮廓和源 UV 绘制。因此表中我舰缩放同时影响共享轮廓与其接触几何、挂点空间关系；不是单独放大一张贴图。它不改变装备伤害、盾甲容量或经济数值。

炮台仍有自身投影参数：`approved_weapon_art.gd::player_pose` 取 `rendered_height/model_span` 与 `weapon_scale`，再由现行武器 manifest 的 `pixels_per_model/visual_scale/anchor/emission_pixels` 得到图像尺寸和每个真炮口。五档 `model_span/weapon_scale` 分别为 `5.669695/0.72`、`5.723601/0.68`、`6.304464/0.68`、`6.334/0.65`、`6.814157/0.58`。这些仍生效，不能将其当作废弃舰体倍率删除，也不能只凭舰体表推定转动炮台均在舰体框内。

**旋转及等比适配的实际顺序：**

```text
θ = 按 actor.uid/slot 的独立几何随机流产生的 [-4°, +4°] + 180°
(w,h) = 标准化alpha凸包外接框尺寸 × PNG画布尺寸
(rw,rh) = (w×|cosθ| + h×|sinθ|, w×|sinθ| + h×|cosθ|)
(Aw,Ah) = 该条目 display_size，缺省为普通框
fit = min(Aw/rw, Ah/rh)
D = PNG画布尺寸 × fit
逻辑轮廓 = transform_hull(标准化alpha凸包, actor位置, D, θ)
```

源船首朝上，转 180° 后朝下；±4° 扰动仍有效。每个 actor 的 fit 随其角度变化，横纵使用同一比例，不能把图拉伸填满适配框；矩形旋转边界公式是保守适配，不保证实际凸包同时触满框的两条边。分级模型同样用最终轮廓绘制、碰撞和挂点，不能另外给显示与命中应用两组尺寸。

### 8.7 高级舰可辨体量与最大占用预算（新增确认约束，倍率待定）

用户已指出当前三档高级船大小难以区分，同时过大的我舰会挤占战场与未来扩展空间。因此巡洋舰、战列舰、重型战列舰的体量应在正常战斗视图中可辨；最大舰的完整占用必须受限，给交火、无人机及未来扩展保留空间。8.2 中的现行倍率与尺寸只记录实现，不能当作这次调整后的批准值，也不能把“体量应可辨”解释为持续放大高档舰。保留已确认舰体模型与美术，仅做有预算的尺度/布局适配；不以重画轮廓解决区分度。

制作按以下顺序形成可审阅候选：

1. **先确定空间预算。** 在拟采用的战场逻辑坐标与可用视区中，标出 UI/导航遮罩、敌方最密合法占位和盾甲条区，划定我舰最大完整包络、交火通道、无人机活动/装配空间及未来扩展留白。预算需同时记录宽、高与净空边界，不能仅分配一项舰体高度；尚未确定的预算数值明确留空，不从当前 572×960、玩家锚点或最大舰尺寸反推为已批准预算。
2. **再做同尺度对比。** 以同一逻辑单位、同一展示比例并列三档高级舰，同时保留五舰参照；对每个候选列舰体宽/高、可见面积、独立炮台及护盾的完整包络、盾甲条占用和剩余净空。可见面积须统一口径（例如同一 alpha 阈值或透明度加权面积）并注明方法，不能用源 PNG 画布面积、含透明边距的 D 或各自放大到同一预览框的图片作体量对比。当前表没有测这项面积，不能把外接框面积冒充可见面积。
3. **在预算内比较候选。** 核对三档辨识与最大舰占用是否同时满足，并展示交火、无人机和扩展留白；允许在预算内重新分配五档相对尺度和排布，但不不断上调高档舰来拉开差距。候选列出拟用基准/倍率、最终宽高与面积、相对差异及对共享几何/挂点的影响，复用当前模型与炮口修复。
4. **评审后才能确定倍率。** 本篇不指定新的最大尺寸、级差百分比、空间留白比例或全局/分舰倍率，也不授权修改 Excel。候选视觉可读性和完整包络净空按 M1/V1 共同验收，批准后再另行实施。

此项待定的是量化预算、相对尺度和布局适配，不是重新选择美术风格。现有参数统计、空间预算、候选值、批准值须分别标记，不能把静态复算或候选对比写成实机净空/整体品质通过。
