# 太空战舰：新游戏运行架构方案

本方案从 `main` 的实际游戏代码和 Excel 配置重新建立需求，再据此设计实现结构。基线为 `b4729b9a9803458b5ac19a4945c2fe0d5f76e51f`。它是一份供审阅的完整设计，不表示已获准实施。唯一交付入口是本页；下列正文共同构成方案，实现者不需要旧方案或聊天记录。旧重写方案未用作输入。

## 1. 游戏怎样工作

玩家驾驶一艘自动作战的飞船，沿关卡距离前进；到达战点后停留交战，消灭编队，收取铁、铀和强化碎片，继续前进或驻守重复作战。武器射出、弹体飞行、接触目标、结算伤害是不同事件。只有接触成功或持续光束的有效伤害跳到期，才改变目标的生命、防御、受击效果和死亡状态。舰体显示位置与命中几何来自同一个逻辑战场，画面帧率不决定伤害。

铁购买槽位等级，铀购买反应炉等级，强化碎片购买全局强化。槽位等级属于槽位，换装备保留等级；船型决定当前启用几个槽位。反应炉把能源分配给武器、防御、炼铁和碎片凝聚。AI 科技消耗研究工作量，可持续投入铁和铀加速；船员可以自动购买、自动续研，也能探索星球和星系。星球探索、建筑和重铸形成跨轮成长；星系的建设和资源收益形成另一条长期进度。超空间有四条武器路线，手动挑战建立层数和最佳时间，在线挂机按最佳时间生成无人机及材料；无人机提供额外武器、词缀、挂设和传说效果。

所有这些系统共享一份经济账本和一条游戏时间线。系统之间不互相寻找节点或直接修改对方状态：一次命令先计算完整结果，检查费用和引用，提交相关状态，再向界面发布已发生的事实。例如星球探索完成会同时增加探索度、推进施工、发放船员经验、重新计算装备和反应炉上限；任何观察者只能看见这一整次结算前或结算后的状态。

## 2. 已确定边界

| 范围 | 本方案约束 |
|---|---|
| 重写 | 业务代码与测试重写；不照搬原有管理器关系、存档对象和测试脚手架 |
| 可复用 | 静态资产、纯表现算法、现有 native/GPU 快路径；复用需经过新契约验证，不因“已有”而成为规则权威 |
| 战斗 | 命中时结算伤害；发射不扣血，不先决定未来死亡 |
| 数值 | 统一近似大数；极端 MAX 允许数量级近似，不建两套普通/大数经济系统 |
| 配置 | Excel 是唯一权威入口；保留配置内容；应配置的硬编码纳入 Excel；已删除成长配置保持删除 |
| 测试 | 测试数据使用独立 Excel，经同一编译器进入同一业务实现 |
| 存档 | 不要求旧存档连续性；设计新的清晰版本和恢复协议 |
| 编辑器 | 删除依赖游戏运行的编辑器；不安排编辑器开发。命令行配置编译和测试运行器不属于游戏内编辑器 |
| 变更权限 | 不自行决定玩法歧义，不将建议变更混入确定规则；仅设计，用户审阅后才实施 |

“保留配置内容”不意味着把已停用功能重新开启。旧科研、未消费配置字段、候选编组和发布副本有明确分类。进化配置是否属于用户要求保持删除的成长配置，尚不能由基线推断；其完整候选规则和处理分支列在决策 D01。

## 4. 关键设计选择

游戏由 `GameSession` 持有九个业务状态：进程、经济、装备、强化、科研、船员、星球、星系、超空间；活跃战斗由 `BattleState` 独占。`SessionRunner` 是唯一时间消费者和命令入口。领域规则是无场景树依赖的计算对象；每个状态只有一个写入方。跨系统动作由明确的用例函数协调，不靠全局事件总线传播写入。

派生属性不再散落在 UI、战斗和配置工具里。`AttributeResolver` 把等级成长、研究、反应炉、强化、星球、船员、星系和无人机贡献按规定顺序汇总，得到带版本的 `CombatSpec`。攻击诞生时保存不可变来源参数和随机结果；命中时结合目标当时的防御状态计算实际伤害。升级影响之后诞生的攻击，目标的盾恢复和临时抗性则在命中当时读取。换装导致的攻击失效规则是有名规则，不通过对象引用是否还活着来猜。

先提供一个易读、可无界面运行的参考战斗执行器，再把现有 native 代码接在相同输入/输出契约后。一个战场始终只有一个执行器拥有业务状态；GPU 只画快照。native 不支持某条规则时，完整交还状态后使用参考执行器，不能一部分子弹由两边同时结算。

这是单机游戏，不需要微服务、数据库服务器、通用工作流引擎或保存全历史的事件溯源。保留最小的命令幂等记录、奖励凭据、随机流状态和可恢复文件写入即可。缓存、布局、图形池和报告都不能成为第二份玩家进度。

## 5. 一次完整操作示例

玩家在战斗中把武器槽从 19 级购买到 20 级：界面发送带命令 ID 的购买请求；装备规则按槽位类别给出费用，检查钱包和材料门槛；会话在两个逻辑步之间验证报价版本。若 D01 决定保留进化，则该次跨 20 级还支付相应材料并获得进化倍率；若决定删除，则编译规则不包含这两项。未决定前不能擅自选分支。

提交时钱包扣费、槽位升级、派生属性版本变化一起完成；如果购买的是防御槽，非撤退时把新增容量差加入当前值以保留缺损绝对额；换装等其他操作按03的HealthAdjustment表处理，不能统一按比例。已经在空中的攻击保留其诞生参数，不回滚、不补发；尚未完成的连续源按其有效身份继续或失效。界面读到新的槽位等级、余额和属性，并从提交事件播放反馈。测试通过同一购买命令和同一战斗执行器验证结果，既不点击 UI，也不复制一个“测试版伤害公式”。
