## 组织和连续操作

在原808×900模块内，舰船在左侧约332px；逐槽工作台在x332–788。中／晚期台顶统一y280，早期台顶y320；晚期台底y844，内容视口y314–837。每槽的**身份／候选入口→本槽收益→本槽费用与两键**都在同一逐槽行组；预设单费容量84px、双费容量108px（不按失败动态升高）。没有紧凑索引＋远处单槽详情，也没有另一个候选半区。当前槽行可获得焦点并关联舰体观看；购买直接作用于该行明确的槽ID，不要求先去舰体上选槽。下一槽就是相邻行，舰船始终在操作区一侧。

早期、中期、后期沿同组织改变实际启用行数、舰型及数据内容；晚期增加同台视口滚动，行宽／图标／收益／费用／购买关系相同，行高按预分配费用容量预算固定，不能由当前原因增减高度；台体高度随启用行数增长，早期不保留八槽空壳或候选空台。未开放类型不占候选卡；现有但未启用的历史槽另按需查看，不伪装成当前可购买行。

操作序列（设计目标，尚未运行）：

1. 在武器1行看现装及当前→升级后；点该行数量键循环×1→×10→MAX→×1，只变报价，点独立购买才购级。费用明确是**该行现装的升级费用**。
2. 继续点相邻武器2行的两键，无需跨舰船回上方索引。余额变化后各行只接受所属Owner新的报价和可支付事实，不能沿用旧预算承诺成交。
3. 点防御2现装护盾名称／图标，下拉锚在同一身份入口；底部槽向上开，覆盖邻行时底层不能接收误点击；收起后恢复原画面，不重排工作台。
