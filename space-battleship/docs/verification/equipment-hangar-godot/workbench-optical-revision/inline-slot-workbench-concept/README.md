## 组织和连续操作

在原808×900模块内，舰船在左侧约332px；逐槽工作台在x332–788。每槽的**身份／候选入口→本槽收益→本槽费用与两键**都在同一逐槽行组；普通84px，双费或失败108px。没有紧凑索引＋远处单槽详情，也没有另一个候选半区。当前槽行可获得焦点并关联舰体观看；购买直接作用于该行明确的槽ID，不要求先去舰体上选槽。下一槽就是相邻行，舰船始终在操作区一侧。

早期、中期、后期只改变实际启用行数、舰型及数据内容，行宽／图标／收益／费用／购买关系相同，行高按必要内容分配；台体高度随启用行数增长，早期不保留八槽空壳或候选空台。未开放类型不占候选卡；现有但未启用的历史槽另按需查看，不伪装成当前可购买行。

操作序列（设计目标，尚未运行）：

1. 在武器1行看现装及当前→升级后；点该行数量键循环×1→×10→MAX→×1，只变报价，点独立购买才购级。费用明确是**该行现装的升级费用**。
2. 继续点相邻武器2行的两键，无需跨舰船回上方索引。余额变化后各行只接受所属Owner新的报价和可支付事实，不能沿用旧预算承诺成交。
3. 点防御2现装护盾名称／图标，下拉锚在同一身份入口；底部槽向上开，覆盖邻行时底层不能接收误点击；收起后恢复原画面，不重排工作台。
4. 点“装甲”候选主体即调用该槽换装；没有确认／预览页／安装按钮、没有资源换装价格。原现装只有在原生提交成功并由Owner接纳后才更新。普通拒绝留原现装，就地显示真实原因。
5. 成功后名称变装甲、收益／升级费仍服务本槽现装。再次点名称可立即选回护盾；不把这个动作解释为免费撤销升级或回滚付款。现实现同槽10游戏秒锁仍在，**本目标须在后续实施移除该锁并同步现有契约与03**；本次没有偷改或清锁。
6. 需要深入比较才点候选右侧独立描边“比较／仅查看”按钮／当前行“比较”按钮，展开同槽同口径主值与武器既有周期，防御只保必要容量、身份及准入。候选主体268×84与比较90×84之间有10px空隙，无横跨两者的整行点击目标；比较不拦截候选主体的直接切换；同物点选NoChange，不加确认。比较层不是本次另画的一套主页面。
