## 制作边界

四设备从设计稿各自制作完整本体与预制接口，不能从旧整场景硬裁或复用带问题的旧设备拼贴。先固定源坐标系、资产原点和缩放，以及每个核心出口和设备入口的中心、轴线、可见端面尺寸与前后深度；设备资产生成时就带接口。管段、管腔流光和设备接口读取同一份端口契约及变换。采用可复现的精确接口几何；生成图只负责表面，随机孔口不充当定位依据。尤其检查炼铁斜管端面与设备入口的实际相接，不能靠近似朝向、挪管或盖片掩缝。

核心需明确表达能量在球内产生、被约束、经出口送入当前有效管路；现有仅让铁架小幅上下的动作退出。四设备分别表现武器充能与释放、盾面建立、炼铁熔流、晶体凝聚等可辨工作过程；旧水波式通用效果退出。静态金属/玻璃与工作材质分层，真零停工作动作，正载强度与方向随已接纳 Owner 负载变化。公共壳、装备、`main`、Owner 规则、支付、分配及升级逻辑不在本组重做范围；文字和交互仍由 Godot 原生控件绘制。

下部控制区重新排版：均分按钮完整落在金色凹槽安全区，单路名称、滑条、百分比和增益形成清楚的读控组，四路状态保持完整行。按原尺寸 1/2/3/4 路整屏与正常 1× 连续动态一起判断核心主次、信息读序、字形净空、真实端面接合、零载/正载材质差异和工作因果。坐标参数正确、控件存在或文字可读都不足以证明视觉品质；每个设备的接口中心、轴线、端面和深度需在源画布及实机场景可复核。

## 当前固定与判定边界

`reactor_ports.json` 同时驱动四设备 Blender 端口、管壳生成和 Godot 放置；可见端面中心按投影对齐，共用源坐标和裁图矩形。管壳/管腔从会合面继续伸入设备空心套筒；管材短节按真实前后深度置于接口前层，其余埋入机体，不用圆片遮缝。四机改深蓝枪金属并以当前舱室图作环境反射，增加实体铸板、墙体轴承、落地承重柱、炉膛耐火层、凸面盾镜和分段投射鞋，武器双炮筒加厚，晶体簇收小。工作裁切覆盖设备所需范围，分别定位蓄能/释放、盾面扩展、熔流及晶体生长；核心用碎旋涡向中心收束和逐路向外的 Owner 负载能量包。旧设备整图、旧水波工作层和运动铁架序列已从运行闭包移出。均分按钮上移进入凹槽，单路名称、滑条、百分比、增益归为同一水平读控组。当前舱室、玻璃核心、静态夹具及控制台仍是被运行引用的材质，不能在替代闭包完成前删除。

当前候选的 1/2/3/4 路零载与正载原尺寸整屏、四路正常 1× 连续视频及复现驱动固定在[独立证据归档 `8293de818f73e37e5b88946339e7dd57b724f96e`](https://github.com/rlmclmc2-boop/space_idle/tree/8293de818f73e37e5b88946339e7dd57b724f96e/modules/reactor/r6-structural-20261031)。Godot 4.7.2 入口解析与运行通过；端口投影、管材入筒的实屏近景、八态显隐及负载驱动已有证据，不能代替对材质密度、工作因果和整页主次的独立判断。1/2/3/4 为隔离受控参数；自然解锁、混合零/正连续切换、极低正载、最终公共组合及目标硬件性能仍未凭此验收。本组不将软件渲染速度外推目标机。
