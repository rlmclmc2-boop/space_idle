# 桌面 UI 整体退回后的独立审计与重设计方案

- 审计对象：`9667e0dc3f117ac3a9891bf898e134673ebb8a56` 的 `space-battleship/docs/ui-design-candidate/`。
- 目的：先确认根因、方法和取舍，交用户审阅；不是新设计稿、资产规格、实现授权或验收通过。
- 范围：桌面宽屏整屏、左侧战场、反应炉、科研、舰装；本轮不做窄屏，不扩展其他模块，不生成资产、不修改设计/实现、不运行新复测。
- 结论：**当前设计整体不通过，纯视觉和结构均不能沿用此前认可。** 本报告撤回本审计者在 `48fd93e6` 中对 `0d37500b` 的“结构设计通过”结论；六项局部信息修正仍是历史事实，不是框架冻结依据。

2. `9667e0dc` 的 `space-battleship/docs/game-design/art/modules/battle.md`、`art/open-items.md`、`reference/ship-scale.md`、`11-stage6-contract.md`。用于核对尚未解决的战场观看、HUD、背景及完整包络问题。

本次不以静态图推断真实伤害、支付、时序或全部合法配置；不将已接受的背景 UV 闪动修复、真实炮口专项重开为“已发现回归”。

## 二、根因：为什么补齐控件仍不过关

### 1. 先铺容器，再往容器里塞场景

全局栏、模块导航、英文眉题、中文模块标题、内部面板重复建立层级。右侧真正的舱室从很低的位置开始，左侧则被强行固定成窄观看窗。内容虽然齐全，视觉组织却接近后台管理页：模块之间共享的不是清晰操作语言，而是重复框与表单。换一批更精细资产不能解决这一骨架问题。

### 2. “连接”没有变成可信的场所

反应炉有连线却没有令人信服的安装、空间深度和能量主次；科研有工厂背景，但机器、状态贴片和亮色终端像分别摆放；舰装有船体大图，却没有以高频工作流决定空间分配。管线连上、控件不盖机器，只是最低边界，不是场景品质。

### 3. 用单张状态代替完整操作周期

此前以“成功后不再展示旧报价”关闭问题，却接受了整个操作台撤下、没有下一笔动作的终点页面。反应炉失去直接表达分配意图的便捷路径，变成逐台填表；问题不是少了某个旧控件，而是连续调节成本变高。多张成功/失败图不能证明连续操作顺畅。

### 4. 审核尺度错误

本审计者此前把六项局部契约闭环提升为结构认可，没有同时审整屏空间、场景可信度和反复操作成本。这是审核遗漏，不应解释成用户后来只提高了美术要求。后续必须把整体构图、真实能力、连续路径分别判断；任一不成立都不能宣布设计通过。

## 三、应保留的是能力，不是旧稿的像素布局

- 战斗状态与必要反馈保持可知，切换/收起舱室不改变战斗驻守或暂停状态；这不等于战场与舱室必须左右并列。
- 资源、当前事实、候选草稿、业务结果分离；金额使用既有权威Amount表示，前端不重算玩法。
- 反应炉让玩家直接表达分配意图、快速调整不同用途的能源取舍，并看到系统换算后的实际分配与效果；手动/免费/有效供能区分、单设备清零和既有均分仍成立。精确手输、固定步进及某个比例粒度不是必须保留的需求。
- 科研的场景主体、当前与候选分离、保留工作量、暂停/完成真实状态、逐资源提交，以及自动投入与岗位续研的分离。
- 舰装的稳定槽位身份、挂点与逻辑槽区分、同口径比较、实际回执、失败保留选择。
- 已完成的战场真实炮口、共享几何和背景 UV 专项成果；原图及已核对事实继续可追溯。

不保留为既定要求：旧版精确输入框、固定金额步进、固定百分比分配粒度、左右分屏框架、31%/33% 战场宽度、62px 顶栏、巨型重复标题、反应炉设备等大、固定核心—三台机器排布、科研贴片位置、舰装成功终点页。也不凭旧截图恢复未被现行业务支持的 MAX、批量或新原子事务。

## 四、整屏组织与战场：先比较组织方式，再分配空间

### 问题与方法

当前 1440 宽稿从全局栏到舱室场景大约占去顶部两百像素，包含重复导航/标题层。钱包稀疏、中央留白缺少用途，底部审阅条又消耗常驻空间。不能靠缩小字体或压扁机器补救。

建议使用一条紧凑全局资源/系统带、一组舱室导航，以及与当前对象同处的状态和工具。去掉独立重复模块横幅；当前对象名仍需保留，但放到场景/工作区所属位置。审阅选择器和技术注释留在评审环境，不进入产品画面。全局持续错误有独立优先级，普通成功不抢全局。

用户明确左右分屏不是保留要求。先比较整屏组织方式，不把重设计缩成调整两栏比例；常驻并列、主视图与按需工作区、观看/操作模式切换等只是可比较的候选，不预先选定。比较依据是战斗信息可知、模块连续操作成本和整屏观看品质，再建立所选方向的空间预算：
- 战场有效观看区、必要即时 HUD、按需详情分别标界，不预先固定在左侧。
- 舱室的“主体观看”和“实际操作”按用途组织，不预先固定在右侧或对半分配。
- 收起舱室后给出有目的的战场/舰桥观看模式；不能留下历史开场图那样的大块无意义空白，也不能简单拉伸 572×960。
- 在既有宽屏代表尺寸比较同一状态。尺寸仅作为复审样本，不能反向宣布最终支持范围。

### 战场具体边界与重新设计路线

历史候选已收紧即时盾甲 HUD、移除空框与永久快捷教学；应保留这些改善。当前 HTML 只有固定敌影、单一巡洋舰和示意炮线，不包含完整炮台、护盾、无人机与真实事件，不能用它关闭历史 G9，也不能由它认定已完成的实机专项退化。

仍需解决：战场观看与信息占地、待命/航行/交战/撤退的环境连续性、全装配与敌阵/无人机净空、高阶舰辨识。已有背景连续性接受范围明确覆盖关卡 1–2；后续星空回退与完整状态链仍是未闭合范围，不应统称背景已完成。

方法应是先画预算和包络，再谈倍率：
1. 在同一逻辑坐标中标出 HUD 遮挡、玩家全部合法旋转炮台/护盾/盾甲条、敌方最密合法编队、无人机与预留区域。
2. 分别比较五舰的完整装配轮廓与敌方普通/精英/BOSS，不以裸舰外接框代替整体包络。
3. 以轮廓、装配和环境参照建立高阶辨识，再评估是否需要改显示倍率或战斗位置。不得只为“高级舰更大”挤掉交火与无人机空间。
4. 任何涉及坐标/倍率的方案必须说明对共享命中几何、真实炮口、拾取逆变换的影响；未批准之前不改实现。

取舍：若选择并列结构，增加战场宽度会压缩模块工作区；若选择主场景与按需展开，则要检查打开/收起及连续操作成本。各候选都比较空闲、模块打开、连续操作三状态，不只比一张空闲全景。一味放大船只也会损害敌阵净空；先按观看与操作需求比较组织方式，再在完整包络约束下分配空间，不先指定百分比。

## 五、反应炉：恢复配电操作，建立可信的机舱

### 现状、旧版证据与需求纠偏

现稿中央核心、分支线、等量级机器、平面椭圆底座和很小的操作读数彼此并列，大块平面空余却没有形成深度。用户看到的是供能流程图，不是可进入、可操作的反应炉舱。

旧版支持拖动、步进和文本提交，只能证明曾经存在这些操作，不能证明玩家需要保留全部控件。此前把“精确输入”列为必保留能力，是从实现倒推需求，应撤回。放置游戏的能源会增长到大数规模；玩家首先需要表达“更偏向武器、减少防御、留出余量”等分配意图，而不是计算或输入一长串金额。系统负责将意图换算为符合现行规则的分配请求，并展示实际接纳的结果。

本轮只读复核 `main@30d8552196f5a8dccab35a839fb6eb5c4540f3c3` 的规则和实现：
- `docs/game-design/03-progression.md` 第2节与 `src/systems/reactor.gd:145–224`：容量按增长及容量因子计算后向下取整；有效供能为手动供能加免费供能，增益为 `1 + 有效供能^0.8 / 100`。已开放设备没有“精确输入某一整数才启动/解锁”的分配门槛；开放条件另由进度决定。
- `reactor.gd:226–279`：请求向下取整并钳到其他设备分配后的剩余容量，均分处理整数余数。这要求系统准确结算，不等于要求玩家精细计算或手输。
- `03-progression.md` 第1.2、1.4节：下游属性存在取整，防御分配还关系到当前值与上限，因此也不能声称任何细小调整都无意义。当前证据未证明精确手输具有不可替代的玩法必要；不据此删除后端金额能力或改变玩法。

**设计起点是意图表达，不是确定一个更好输入的精确数值。** 拖动、比例化调节、快捷调整等都只是可能的表达方式；1%仅是待评估示例，不是本方案重点、既定步长或新规则。先确定玩家怎样快速表达取舍、怎样读懂结果，再选择控件与映射。若后来发现确实存在普通操作无法完成的必要意图，再论证是否需要深入入口；不能预先为精确手输保留一个必选位置。

### 推荐方向与取舍

先确立“能源核心—主管—设备舱”的真实安装关系：核心承担源头焦点，设备按功能与安装空间组织，管路有进出口、支承和遮挡逻辑，而非用等大的三个符号证明平等。场景主体与读数保持同一对象身份，工作/停机由真实状态驱动。

可优先探索**紧邻核心预算的共享配电区**，让玩家直接比较并调整不同用途，与场景设备联动高亮；设备细节按需展开。逐设备终端更有空间归属感，却会增加多目标调节的眼动与鼠标往返，不宜成为唯一高频入口。共享区域也不等于必须把每台设备做成金额输入表，不以展示所有数字为目标压住机舱主体。

信息先分两层：
- 普通操作首先看到总池/余量、各用途的分配关系和实际效果，知道“正在偏向什么、还能怎么调”。输入表达意图，系统换算金额；不要求心算大数、逐设备抄值或逐项填表。
- 主动深入时再看实际供能明细、手动与免费来源和增益口径。明细准确性独立于是否提供精确编辑；手动为零但有免费供能时，不得显示停机。

意图到金额的映射必须复用权威Amount与原分配规则，不用不安全float重建大数，也不新增自动挪用其他设备金额的隐含规则。预览与已接纳结果分开；容量变化后显示实际结果，不让旧意图或旧显示冒充提交成功。具体即时提交/确认方式、映射基准及交互粒度留待设计，不在本方案先冻结。

保留设备清零、既有均分；未开放碎片凝聚连设备及空位一起隐藏。核心购级数量与价格读取现有能力；不能把现有 purchase 的 automatic 布尔参数误当 MAX。

### 要成立的操作路径与未定项

看懂当前分配与效果 → 表达减少一项、增加另一项的意图 → 就地看见实际分配、余量和效果 → 继续调整；整个过程不要求玩家计算大数、不反复打开设备表单。满池、零手动有免费、容量变化、被钳制或拒绝时均须给出可理解的反馈，不能把显示变化当作接纳成功。

待设计确认的是：哪种意图表达适合连续使用、系统如何把它映射到既有合法请求、零/可用上限/余量怎样容易到达、变化中的容量怎样反馈。不是先决定精确手输或固定步进必须存在，再为其寻找理由。本次仅补方案，不启动粒度实验、新复测或实现。

## 六、科研：工厂是主景，终端是工作点

现稿的问题不是背景面积不足，而是机器落点/平台透视不够可信，身份、进度、投入摘要像分散贴片；展开后的高对比终端成为视觉主角。单纯扩大背景、再移动一块卡片仍不能建立工作关系。

推荐先校准机器与平台、探针的安装/透视关系，再把当前研究名、已生效效果、工作状态和主要进度归成一个与机器相邻的工作点。终端应像属于工厂的设备，而不是独立网页侧栏。空闲观看态需完整、安静；操作态也不能把机器压成角落装饰。

保持两个信息层级：
- 常驻：当前研究及效果、运行/暂停/完成、进度与当前投入摘要，快速回答“正在做什么、现在有什么效果、是否在推进”。
- 按需：选择候选、精确投入与自动设置。在稳定位置展开，不让每个区块各占一张亮色大卡。低频设置允许一次展开，高频观察不能依赖逐个打开。

选择候选不换当前机器；确认成功才更新。候选效果与保留工作量齐全，但无需强迫所有候选、完整投入和自动设置同时常驻。铁/铀逐项应用仍保留；自动投入设置不冒充立即产生的新投入，岗位续研不混为一个开关。改构图不能撤销这些正确契约。

验收路径：观察 → 打开候选 → 比较/取消 → 回到原研究；再次选择并成功切换 → 工作点一致更新；投入一项成功、一项失败 → 草稿与实际各自成立；收起/重开终端以及普通状态刷新不丢合法草稿。暂停与完成不靠装饰循环伪装工作。

## 七、舰装：以连续整备为中心，不以成功截图为终点

现稿把大量空间给船体与光环，槽位轨较弱，比较台在远侧。购级与换装共用操作下拉，增加高频操作步骤；成功后整个操作区被完成记录替代，没有下一笔报价。消除旧报价是对的，但把工作台关掉是错误解法。

### 先分信息层级，再设计操作

普通玩家换装时首先需要回答：**正在改哪个槽、现在是什么、候选能做什么、主要取舍是什么、现在能不能换。** 当前对象、候选身份与用途、少量关键差异、锁定/不可用原因及重要后果应在同一工作点读懂；不以完整属性表或公式要求玩家先精细计算。换装保留槽位等级、换装锁与升级操作的区别，在相关动作处说明，不能把升级报价当成换装费用。

主动深入时再提供同口径详细属性、攻击周期/类型、增益来源与成长细项、防御容量/当前余量的变化和复杂限制。**同口径是比较正确性的要求，不是完整数值表必须常驻的理由。** 不编造通用DPS或综合评分，把不同武器的取舍压成虚假的单一优劣；关键阻断与重要后果仍须在确认前可见，不能藏在详情里。首槽换型造成两类当前余量双零的即时死亡判定仍按03保持未定，不由UI文案裁决。

依据 `main@30d85521` 的 `03-progression.md` 第1节及 `src/systems/equipment.gd:511–537`，稳定槽位、等级保留、分类/开放限制与换装锁已有规则；详细比较输出是否充分仍按接口契约审查，不能在前端补算。先确定这些信息支持什么选择，再决定控件和布局，不为“展示完备”牺牲连续整备。

### 持续整备的操作组织

推荐保留一个**持续存在的整备工作区**：
- 常驻分组槽位轨/列表显示当前装备、等级与状态；点击一个槽就能到对应工作区，不需先开菜单找操作。
- 舰体挂点用于定位与确认，不垄断操作空间；防御逻辑槽不捏造物理挂点。
- 购级作为高频动作，使用稳定位置的数量/按钮和其有效报价；换装才展开候选列表与上述首要比较信息，候选选择和确认同处一个工作区；详细比较由玩家主动深入，不挤走下一步操作。
- 成功后更新当前事实、余额、下一笔合法报价，操作台不离场；短回执与可展开历史分离。下一笔报价尚未到达时只禁用对应提交并显示读取状态，不继续用旧价，也不删除整个工作区。
- 不自动跳到下一槽，避免连续点击改错对象；切槽后一切候选/报价/冷却均明确绑定目标 ID。失败保留仍有效的选择；失效报价不可继续提交。
- 既有批量/MAX/全等级操作照所属业务规则，不因整备方便发明全槽原子购买。冷却限制只施加在规则要求的目标与操作，不能笼统锁死其他槽。

核心路径：W1 连续购级两次 → W2 换装 → W3 购级 → 返回 W1 查看当前事实/冷却。中途不重开页面、不手动清除成功态、不重选操作类型；无余额时明确缺口并允许继续查看其他槽。另用全启用与休眠槽状态检验列表承载，不用三个样例槽宣布所有舰型设计完成。
