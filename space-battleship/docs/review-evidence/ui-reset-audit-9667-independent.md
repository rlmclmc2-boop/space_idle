# 桌面 UI 整体退回后的独立审计与重设计方案

- 审计对象：`9667e0dc3f117ac3a9891bf898e134673ebb8a56` 的 `space-battleship/docs/ui-design-candidate/`。
- 目的：先确认根因、方法和取舍，交用户审阅；不是新设计稿、资产规格、实现授权或验收通过。
- 范围：桌面宽屏整屏、左侧战场、反应炉、科研、舰装；本轮不做窄屏，不扩展其他模块，不生成资产、不修改设计/实现、不运行新复测。

## 二、根因：为什么补齐控件仍不过关

### 1. 先铺容器，再往容器里塞场景

全局栏、模块导航、英文眉题、中文模块标题、内部面板重复建立层级。右侧真正的舱室从很低的位置开始，左侧则被强行固定成窄观看窗。内容虽然齐全，视觉组织却接近后台管理页：模块之间共享的不是清晰操作语言，而是重复框与表单。换一批更精细资产不能解决这一骨架问题。

### 2. “连接”没有变成可信的场所

反应炉有连线却没有令人信服的安装、空间深度和能量主次；科研有工厂背景，但机器、状态贴片和亮色终端像分别摆放；舰装有船体大图，却没有以高频工作流决定空间分配。管线连上、控件不盖机器，只是最低边界，不是场景品质。

### 3. 用单张状态代替完整操作周期

此前以“成功后不再展示旧报价”关闭问题，却接受了整个操作台撤下、没有下一笔动作的终点页面。反应炉丢掉拖动和步进，变成逐台填表。多张成功/失败图不能证明连续操作顺畅。

### 4. 审核尺度错误

本审计者此前把六项局部契约闭环提升为结构认可，没有同时审整屏空间、场景可信度和反复操作成本。这是审核遗漏，不应解释成用户后来只提高了美术要求。后续必须把整体构图、真实能力、连续路径分别判断；任一不成立都不能宣布设计通过。

## 三、应保留的是能力，不是旧稿的像素布局

- 持续战场与当前舱室并列；切换/收起舱室不改变战斗驻守或暂停状态。
- 资源、当前事实、候选草稿、业务结果分离；金额使用既有精确表示，前端不重算玩法。
- 反应炉的直接调节、精确输入、手动/免费/有效供能区分、单设备清零和既有均分。
- 科研的场景主体、当前与候选分离、保留工作量、暂停/完成真实状态、逐资源提交，以及自动投入与岗位续研的分离。
- 舰装的稳定槽位身份、挂点与逻辑槽区分、同口径比较、实际回执、失败保留选择。
- 已完成的战场真实炮口、共享几何和背景 UV 专项成果；原图及已核对事实继续可追溯。

不保留为既定要求：31%/33% 战场宽度、62px 顶栏、巨型重复标题、反应炉设备等大、固定核心—三台机器排布、科研贴片位置、舰装成功终点页。也不凭旧截图恢复未被现行业务支持的 MAX、批量或新原子事务。

## 四、整屏与左侧战场：先一起分配观看空间

### 问题与方法

当前 1440 宽稿从全局栏到舱室场景大约占去顶部两百像素，包含重复导航/标题层。钱包稀疏、中央留白缺少用途，底部审阅条又消耗常驻空间。不能靠缩小字体或压扁机器补救。

建议使用一条紧凑全局资源/系统带、一组舱室导航，以及与当前对象同处的状态和工具。去掉独立重复模块横幅；当前对象名仍需保留，但放到场景/工作区所属位置。审阅选择器和技术注释留在评审环境，不进入产品画面。全局持续错误有独立优先级，普通成功不抢全局。

先建立整屏空间预算，再决定左右占比：
- 左侧有效战斗观看区、常驻即时 HUD、按需详情分别标界。
- 右侧把“主体观看”和“实际操作”作为可协调的两个用途，而不是对半塞满。
- 收起舱室后给出有目的的战场/舰桥观看模式；不能留下历史开场图那样的大块无意义空白，也不能简单拉伸 572×960。
- 在既有宽屏代表尺寸比较同一状态。尺寸仅作为复审样本，不能反向宣布最终支持范围。

### 左侧具体边界与重新设计路线

历史候选已收紧即时盾甲 HUD、移除空框与永久快捷教学；应保留这些改善。当前 HTML 只有固定敌影、单一巡洋舰和示意炮线，不包含完整炮台、护盾、无人机与真实事件，不能用它关闭历史 G9，也不能由它认定已完成的实机专项退化。

仍需解决：战场观看与信息占地、待命/航行/交战/撤退的环境连续性、全装配与敌阵/无人机净空、高阶舰辨识。已有背景连续性接受范围明确覆盖关卡 1–2；后续星空回退与完整状态链仍是未闭合范围，不应统称背景已完成。

方法应是先画预算和包络，再谈倍率：
1. 在同一逻辑坐标中标出 HUD 遮挡、玩家全部合法旋转炮台/护盾/盾甲条、敌方最密合法编队、无人机与预留区域。
2. 分别比较五舰的完整装配轮廓与敌方普通/精英/BOSS，不以裸舰外接框代替整体包络。
3. 以轮廓、装配和环境参照建立高阶辨识，再评估是否需要改显示倍率或战斗位置。不得只为“高级舰更大”挤掉交火与无人机空间。
4. 任何涉及坐标/倍率的方案必须说明对共享命中几何、真实炮口、拾取逆变换的影响；未批准之前不改实现。

取舍：增加战场宽度有助观看，却会压缩右侧工作区；一味放大船只又会损害敌阵净空。优先减少整屏无效框和 HUD，再在全包络约束下选比例，而不是先指定一个好看的百分比。

## 五、反应炉：恢复配电操作，建立可信的机舱

### 现状与旧版可用证据

现稿中央核心、分支线、等量级机器、平面椭圆底座和很小的操作读数彼此并列，大块平面空余却没有形成深度。用户看到的是供能流程图，不是可进入、可操作的反应炉舱。

旧版的价值不在四象限布局，而在直接配电能力。源码确认：
- 滑条/覆盖输入支持点击定位、拖动，拖出控件范围仍能接收直到释放；
- ± 步进与精确文本提交并存；非法文本不伪装成功；
- 可分配上限按“总容量－其他已分配量”约束，并显示可用区；
- 手动/免费供能区分；操作后刷新实际值。

旧实现在极大数值下禁用不安全浮点滑条，仍有精确输入；新设计不能照搬 float 转换与旧 Game 耦合。直接拖动的比例映射、量化与最终提交须走权威金额/分配规则。

### 推荐方向与取舍

先确立“能源核心—主管—设备舱”的真实安装关系：核心承担源头焦点，设备按功能与安装空间组织，管路有进出口、支承和遮挡逻辑，而非用等大的三个符号证明平等。场景主体与读数保持同一对象身份，工作/停机由真实状态驱动。

操作推荐采用**紧邻核心预算的共享配电台**，每个设备一条稳定行，与场景设备联动高亮。这样能跨设备快速比较和转移分配；设备细节仍可就地展开。逐设备终端更有空间归属感，但会增加多目标调节的眼动与鼠标往返，不宜作为唯一高频入口。不要恢复旧版多区域各自滚动的困难，也不要把共享配电台做成覆盖全舱的大表格。

直接拖动/步进是即时有效操作，不再要求每次额外点“应用”；精确文本则明确是草稿，Enter/应用后才成为实际值。界面可以展示拖动预览，但必须区分预览与已接受结果。容量/收入异步变化时由权威结果纠正，不在前端计算新玩法。

保留设备清零、均分；手动为零但有免费供能时不得显示停机。未开放碎片凝聚连设备及空位一起隐藏。核心购级数量与价格读取现有能力；不能把现有 purchase 的 automatic 布尔参数误当 MAX。

### 要成立的操作路径

查看总池与三台实际值 → 拖动/步进减少一台 → 增加另一台 → 不离开配电台看到新余额、实际供能和效果；精确大数输入另走明确提交。满池、零手动有免费、非法输入、拖出释放、容量在编辑时变化，均应有可解释的结果，不重置其他设备草稿。

## 六、科研：工厂是主景，终端是工作点

现稿的问题不是背景面积不足，而是机器落点/平台透视不够可信，身份、进度、投入摘要像分散贴片；展开后的高对比终端成为视觉主角。单纯扩大背景、再移动一块卡片仍不能建立工作关系。

推荐先校准机器与平台、探针的安装/透视关系，再把当前研究名、已生效效果、工作状态和主要进度归成一个与机器相邻的工作点。终端应像属于工厂的设备，而不是独立网页侧栏。空闲观看态需完整、安静；操作态也不能把机器压成角落装饰。

保持两个信息层级：
- 常驻：当前研究及效果、运行/暂停/完成、进度与当前投入摘要，快速回答“正在做什么、现在有什么效果、是否在推进”。
- 按需：选择候选、精确投入与自动设置。在稳定位置展开，不让每个区块各占一张亮色大卡。低频设置允许一次展开，高频观察不能依赖逐个打开。

选择候选不换当前机器；确认成功才更新。候选效果与保留工作量齐全，但无需强迫所有候选、完整投入和自动设置同时常驻。铁/铀逐项应用仍保留；自动投入设置不冒充立即产生的新投入，岗位续研不混为一个开关。改构图不能撤销这些正确契约。

验收路径：观察 → 打开候选 → 比较/取消 → 回到原研究；再次选择并成功切换 → 工作点一致更新；投入一项成功、一项失败 → 草稿与实际各自成立；收起/重开终端以及普通状态刷新不丢合法草稿。暂停与完成不靠装饰循环伪装工作。

## 七、舰装：以连续整备为中心，不以成功截图为终点

现稿把大量空间给船体与光环，槽位轨较弱，比较台在远侧。购级与换装共用操作下拉，增加高频操作步骤；成功后整个操作区被完成记录替代，没有下一笔报价。消除旧报价是对的，但把工作台关掉是错误解法。

推荐保留一个**持续存在的整备工作区**：
- 常驻分组槽位轨/列表显示当前装备、等级与状态；点击一个槽就能到对应工作区，不需先开菜单找操作。
- 舰体挂点用于定位与确认，不垄断操作空间；防御逻辑槽不捏造物理挂点。
- 购级作为高频动作，使用稳定位置的数量/按钮和其有效报价；换装才展开候选列表与同口径比较，候选选择和确认同处一个工作区。
- 成功后更新当前事实、余额、下一笔合法报价，操作台不离场；短回执与可展开历史分离。下一笔报价尚未到达时只禁用对应提交并显示读取状态，不继续用旧价，也不删除整个工作区。
- 不自动跳到下一槽，避免连续点击改错对象；切槽后一切候选/报价/冷却均明确绑定目标 ID。失败保留仍有效的选择；失效报价不可继续提交。
- 既有批量/MAX/全等级操作照所属业务规则，不因整备方便发明全槽原子购买。冷却限制只施加在规则要求的目标与操作，不能笼统锁死其他槽。

核心路径：W1 连续购级两次 → W2 换装 → W3 购级 → 返回 W1 查看当前事实/冷却。中途不重开页面、不手动清除成功态、不重选操作类型；无余额时明确缺口并允许继续查看其他槽。另用全启用与休眠槽状态检验列表承载，不用三个样例槽宣布所有舰型设计完成。

## 八、后续验收标准与阶段门槛（本次只提出，不执行）

### A. 先批准方案，再出稿

用户先判断本报告的方法与取舍。若方向获准，下一批先给整屏空间预算、主要场景构图及完整操作路径的低成本设计，不先生产最终美术，不按旧稿继续扩展其他模块。不能把本报告本身当作执行授权。

### B. 设计阶段必须同时满足三类标准

1. **整屏品质：** 同一宽屏整屏中主次可读，导航/标题没有重复占地；反应炉像机舱、科研像工作场所、舰装像持续整备台；空闲与操作态都成立。用户仍须实际审图，不能用机器检查替代。
2. **操作效率：** 反应炉可直接跨设备调节；科研观察不必打开表单；舰装上述连续多槽路径无成功死路、无多余重选。所有展开/收起保持对象与合法草稿。
3. **事实与边界：** 当前/候选/草稿/回执明确，错误留在所属对象；无虚构事务、浮点金额和错误属性口径。无溢出、可点击、焦点正确是基础条件而非通过结论。

任何一个标准不满足，不能再标“结构通过、美术以后再说”。

### C. 战场与实现阶段的独立门槛

后续实机证据需要覆盖全装配、敌方密阵、无人机、五舰辨识与 HUD 净空，并区分关卡和状态链。普通船/精英/BOSS的包络不是仅看中心距；盾甲一项为零仍显示另一项有效状态。还需验证拾取坐标、HUD 输入隔离、收起舱室不暂停、环境衔接。

静态设计可以先证明预算与意图，不能关闭 G9 或宣布这些实机行为成立。已有 UV/炮口专项不因重新设计而抹去，只有实际变更影响到相同路径时再做针对性回归。
