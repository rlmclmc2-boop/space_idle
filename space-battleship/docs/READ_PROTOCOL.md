# 限量读取与交接

## 启动与度量

项目可控制的默认入口仅两层短 `AGENTS.md` 和 `docs/knowledge/CURRENT.md`。执行者按任务种类读 `READ_ROUTE.md` 的一个表行，再读明确的文件、章节或符号；审阅者先读变更清单、短结论、证据路径及新增实现，只在结论无法判断时查必要原件。平台可能另行自动注入上下文，仓库规则不能阻止或计量它。

读取成本分别记为打开的文件数、扫描的字节数及返回的字符数。返回字符仅是 TOKEN 压力的代理；真实计费 TOKEN 需要平台数据，不能从字符数推算，更不能编造节省百分比。

## 查找

先查文件名，再查单文件符号，最后读至多 80 行的片段。`python tools/read_budget.py --help` 可看子命令。默认 stdout 上限 1800 字符，最高可显式调到 10000；超限只返回结果行数、字符数、临时文件路径及续读命令，不静默截断。临时结果属本机非版本化材料，交接时只给证据路径和摘要，结束后按需清理自己生成的临时文件。大 JSON 先用 `json --keys` 查结构，再用 `--key`、`--where`、`--fields` 提取；Excel 用 `xlsx --sheet --find --columns` 找行。`diff` 必须给路径，日志先保存原始文件再用 `log` 查错误及邻行。不要整库全文搜索、重复全文读取、无界 `rg` 输出、遍历缓存、个人存档或 `test/work`。

扩读前写明“缺口：…；扩读：文件:行段/符号；理由：…”。只读该范围，不跟随其中链接继续展开。已有直接证据足够时停止。不能因限额隐藏关键错误；结果太大时使用续读入口检查相关错误。

## 执行与验收

JSON 键名本身含句点时，`--key` 用 `/` 分隔层级，例如 `entries/battle.finale_cleared`。

短自足任务交接包括目标、范围、禁止项、完成条件、基准提交、需读定位、待验证风险及下一动作。执行者交变更清单、短结论和必要证据路径；父只审新增实现与必要原件。优先等待完成通知，不轮询重复状态。失败先按错误定位原因，修复后重跑失败项和直接影响项。按风险选最小必要测试，停止条件是受影响行为与已识别风险被覆盖；没有依据不扩测试矩阵或独立复测。既有 `docs/TEST.md` 和 `docs/BATTLE.md` 的正确性要求仍适用。

## 记忆与增长

`knowledge/INDEX.md` 只保留公开、稳定、不可轻易由代码搜索恢复的事实与决定，并记来源提交、适用范围、权威目标及失效条件。`knowledge/CURRENT.md` 只保留当前任务的短状态；完结后归档到 `knowledge/archive/`，清空当前状态。归档不默认读取。聊天全文、用户权限规则、私人记忆或安全规则均不复制为长期授权。写入前按 `.agents/skills/doc-compact/SKILL.md` 去重，优先删除、引用或合并；每次新增规范核对入口字符数、相同规则是否已有权威位置、链接和适用范围。入口超出短状态应移到按需文档。

Git 分支和提交是唯一交接载体；不把 Library、凭据、个人存档、缓存或大型产物打包。未经父审批不合入 `main`，不改全局 Codex 配置，不永久删除未知或不可恢复数据。
