# 四武器与同比缩放：公式审计（待定点实测）

这是 `df3e18cd` 后的优先级改动。前三关 18 点及敌机数值暂为草案，不应并入 main。下列数值来自当前 Excel 投影和源码；尚无本批 Godot 实测击杀时间。

## 同比边界

选定同一装备等级、武器槽位数、编队数量与位置、目标规则、时间参数、减伤比例和初始生命比例。先完成关卡生命插值与装备等级取整，然后将双方当前伤害、HP、护盾、装甲及有同一量纲的临防/绝对恢复量统一乘 `k`；护盾恢复若以最大护盾每秒比例表示，保持该无量纲比例。比较 `k=1、100、1000、100000、1e40`，不把解锁、增槽、等级成长、重铸或物资成本混入纯倍率实验。

理想连续模型中：攻击 `D→kD`、生命 `H→kH`、盾 `S→kS`，固定冷却和飞行使每次命中时刻不变；`(kH-kD)/(kH)` 等归一化状态、按最大盾比例恢复的速率与软克制比例不变。实际执行器有 `ceil`、最低伤害 1、护盾最低吸收 1、绝对 epsilon、撞击几何与死亡零界，因此只能检验给定范围和容差，不能证明无限倍率严格不变。

`GrowthNumber` 允许超过普通浮点上限的尾数/指数表示，但原生描述符仅接受有限标量，并会在超出安全范围时拒绝/交回旧执行器。`1e40` 本身处于双精度有限范围；乘上任意巨额成长/增益后仍需重查中间乘积。高倍率浮点约有 15–16 位有效数字，归一化对比应使用相对误差，不做逐位相等承诺。小倍率的最低 1 与 `ceil` 偏差最大，故 `k=1` 必须保留。

源证据：`scripts/game.gd` 的 `hit_enemy`、`jewel_hit_player`、`settle_enemy_shield`；`scripts/database.gd` 的 `equipment_growth`/`equipment_combat_growth`；`scripts/growth_number.gd`；`scripts/native_execution_compiler.gd` 的 `native_scalar`；`addons/native_battle/src/combat_execution_kernel.h` 的 `configuration_schema`、`hit_enemy`、`player_hit` 与 `beam_periods`。高等级不同成长指数属于另一类测试，不能被同比试验覆盖。

## 已明确的草案风险与最小候选

1. `270007` 当前盾恢复等待 1.8 秒，单脉冲间隔 1.5 秒即可无限续停回；不能称持续束有专属压制优势。先测当前盾量曲线，再试仅把该敌机的 `shieldDelay` 降至脉冲周期以下，并调 `shieldRecovery` 到脉冲能缓慢推进、持续束更快的软克制区间。不能做成脉冲绝对无法突破的锁。
2. 目前导弹 4×200/2.4 秒长期输出比脉冲高 67%，且开场蓄力短。它在大量低血目标优势明确，但中等数量/血量也可能压过脉冲。先测实际有效弹、过量浪费及击杀时间；必要时只降低单弹基础伤害约至 100–125，或仅调整首轮以外的节奏，不同时改其他三武器。
3. 火炮 1500/3.5 的高单发和高面板输出需实测少量高血优势是否足够，同时检测其对中等目标是否也通吃。连击舰的同轮窗口按实际到达时刻而非发射时刻，因此不同炮位/弹道可能超出 0.16 秒；需专门核同轮多炮不互罚。导弹 2.4 秒周期天然略大于 2.2 秒重置窗，也可能绕过层数，须和火炮在高血目标上比较。
4. 当前第三关就有护盾舰，但持续束在第五关后才开放。第三关此舰不能当作持续束教学；后续关卡方案应在武器基准核实后重写。草案中“手动选威胁”“控制齐射”的措辞也不符合自动战斗，需要改为可观察的自动索敌结果及购买/装备决策。

## 最小验证顺序

1. 源表和投影一致性、旧/原生可接受的标量范围；直接命中/盾恢复/连击机制在五个倍率下的归一化结果。
2. 固定一槽、等级 1、无随机增益、固定几何，对四武器×四类敌人仅在 `k=1` 测首击和击杀数据。四类依次为中等数量/中等血量、至少 10 个低血、最多 3 个高血、持续恢复盾；先关机制再开软克制。
3. 对四类各自的优势与最近竞争武器抽查 `k=100、1000、100000、1e40`，并单测同轮两炮、过等级碾压。此为定点公式核验，不能代替完整新档体验，也不扩成宽性能矩阵。

在同机串行运行窗口到来前，仅准备脚本和静态审计，不启动 Godot、原生构建或长试玩。
