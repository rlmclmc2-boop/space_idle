# 前三关：整舰成长目标与18战点候选

本稿先定玩家可操作的装配、升级和能源分配，再定整舰输出/耐久目标，最后反推敌阵与每点铁收入。四武器基准候选沿用脉冲350/1.5秒、导弹4×170/2.4秒、磁轨炮1200/3.5秒、光束35/0.25秒；光束第5关后才开放，前三关不得要求它。18点已在隔离分支的权威 Excel 挂载并生成 JSON，尚未通过短QA或体验验收。

## 前稿失效项：代码路径审计

- 新档资源铁0、铀0。护卫舰有3武器槽、2防御槽；空槽的 level 已是1。初始自动放入脉冲1与装甲1，防御槽0固定装甲。见 game.gd 的 fresh_profile、default_loadout、empty_loadout。
- 起始已解锁脉冲与装甲，可立即在另2武器槽免费装脉冲、在防御槽1免费装装甲。第1关通关解锁导弹和反应炉；第2关通关解锁护盾与磁轨炮。equip_slot 仅验证已解锁、槽位及约束，然后修改 key，保留该槽 level；没有资源扣费。卸下再换也保留槽级。因此前稿“导弹50铁”“炮+盾100铁”和“开档只有单枪单甲可用”的预算失效。装备表 level1 的 cost_1=50 **不是装配价格**。
- slot_upgrade_cost 按武器/防御槽当前 level 报价；upgrade_slot 从 profile.resources 扣费，之后该槽 level 增加。现有费用曲线的1→2为65铁、2→3为75铁、3→4为85铁。空槽也可按槽类别报价升级；装备 key 以后可以免费换，级别仍在槽上。前稿把每种武器当独立新购件也失效。
- unlock_condition_available 按已通关关卡放行装备；碎片功能的 unlock 行是 level=7/mode=reached，而 unlock_condition_available 对 reached 判定 highestLevel>gate；因此第7关通关后的进度才开放。前三关击杀碎片收益为0，不能继续传播此前“第3关碎片掉落谷”判断。前三关现有敌方无铀掉落，反应炉以初始100容量免费分配为基线，不假设已升炉。
- 战斗自动索敌、开火；玩家能真实决定的是装哪种武器/防御、把铁投在哪个槽、如何分配反应炉、在哪个战点驻守或回退。前稿的手动“先打谁”“瞄准”“规避”不是操作，应从教学目标删除。

## 硬数值口径：整舰能力而非战力分

所有下列伤害为无暴击、全弹命中、不计飞行与自动索敌空档的理论值；真实战斗须核命中阈值与过量伤害。20%装备成长与数据库取整使脉冲候选单槽1/2/3级为350/420/500，即持续233/280/333每秒；导弹1/2为每2.4秒四弹680/800，即理想283/333每秒；磁轨1/2为1200/1440每3.5秒，即343/411每秒。4弹群体伤害是同周期总伤，不保证4个不同目标。敌人匹配能量/物理抗性各减相应类型50%。

甲1/2单槽为1000/1200，盾1/2为500/600；甲抗物理50%，盾抗能量50%且先于甲吸伤。初始实际一甲的纯能量/物理有效耐久1000/2000；玩家免费补第二甲后为2000/4000。甲2+甲1为2200/4400；甲2+盾1为2200/2900：双甲持续承伤更强，盾在无伤间隙可恢复，二者是不同路线。盾回复率30%最大盾/秒，但每次命中重置2秒等待，连续受击不能把回复算进持续承伤。前三关装甲无常驻自动恢复。

反应炉第1关后免费分配100容量，装备各槽先按等级算，随后乘 1+分配点数^0.8/100 并向上取整。武器50/防御50时两边各约×1.229；武器100约×1.398，防御无此加成；不能把两边收益直接相加或重复使用100点。以100原始伤害/秒连续命中作统一参考，双甲1约可承受纯能量20秒/物理40秒；双甲2约24/48秒；甲2+盾2且防御分配50点约29.5/36.9秒。此为满态量尺，不是实战存活保证。盾经2秒无伤后才逐渐补满；甲不会战间自修。碎片功能开放后的记忆恢复不列入开场能力。

这些区间的上端是偏重投资和炉分配的结果，不能当关卡最低入场值。例：三脉冲1持续3×350/1.5=700；两脉冲1+一导弹1为2×233+283=750；若50点投武器约922。每种抗性只折对应武器；首轮同射不能假设系统必定把弹分给不同敌人。未来新增系统应在这些输出、有效耐久和恢复时间三个口径内重新分配贡献，逐项算乘法后决定敌强度，避免默认叠乘膨胀。

偏低成长是未及时填满免费槽或很少升级：前几个战点应能过，界面引导免费补槽，后段允许在**本关**回退几个战点攒首项65铁。达标成长是开场补槽、关1选2–3次槽位升级，关2按蜂群/耐久反馈把导弹和反应炉换配；关3可在炮、盾、双甲之间取舍。偏高成长把铁集中升多个槽，会缩短清场，但敌强度不能以此为硬门槛。没有手动瞄准/规避路径。

**奖励落实预检：**每点铁目标必须拆成当前已有的普通敌人 drops 与关卡 resRatio；按每敌上取整核对后，候选静态总和应与表一致。已用32条独立敌数据行承载同原型不同铁掉落，保留原8个原型ID及 archetype_id，逐敌取整后18点正好为205/370/500。权威 config_excel 已生成 JSON。旧15个冻结奖励来源组及其敌人行保持不变，通过关卡的 rewardReferenceGroups 显式留作奖励引用，不参与玩家战斗；导入器与超空间运行时均校验此映射。不得为了前三关铁使用 jewelDropRolls/rewardDrops 或发明完成奖励；前三关碎片功能未开放。若后续真用自定义抽取，candidate_rewards.gd 要求同关 legacy 参考组、抽取次数与资源掉落多重集一致且 BOUND，不能跳过。现有高关碎片收益问题独立继续研究，不以这个开场预算代替。

**放行前最小验证：**先静态检查新档默认槽/免费重复装配、解锁时点、各槽升级报价与资源扣除、逐敌取整铁总量、旧/原生公式一致。获同机执行窗口后仅做短检查：初始一枪与免费补满槽的1-1/1-3，低成长1-4/1-5，至少10只蜂群的2-1/2-2，3-3与3-5分开学习及3-6组合。记录自然清场时间、每点实收铁、入/出场甲盾、炉分配、驻守几轮才能付下一次升级；不另开长时间新档试玩，不与性能线程并跑。方案中的输出和铁/分钟均是待验证预测，不当成体验验收。
