DATA: config_excel/*.xlsx -> tools/import_workbook.py -> data/game_data.json -> ShipDatabase -> BattleGame/UI. Legacy workbook -> tools/config_workbooks.py by explicit split. Import uses cached Excel formula values. Edited/new tables use field names, concise per-column descriptions, types, then data; importer skips both metadata rows. New columns require descriptions.

OWNER: profile retains progression/unlocks/journey metadata. Economy owns spendable balances; equipment_state owns hull/modules; ai_tech_tree, crew_system, planet_state, reactor_state, enhancement_growth, galaxy_system and hyperspace_system own their domain state. Game composes their save_data exports. progress_runtime, galaxy_runtime and hyperspace_runtime coordinate concrete cross-domain commands. attribute_projection and compiled_combat_rules derive values from contribution revisions. Equipment read views are immutable; exported snapshots are detached. player/enemies/projectiles/drops remain session state; main/pages own selection/controls/UI snapshots only. Reads may cache derived values but must not mutate authoritative state.

LOCATE: attack=game.fire/tick_projectiles/hit_enemy/hit_player; beam=lock_long_laser/tick_long_laser; equipment=commit_loadout_change/commit_equipment_upgrades; enhancement=settle_jewel_fragments/upgrade_enhancement/set_enhancement_order/set_enhancement_branch; neutral protection/debt=advance_jewel_repair; branch hooks/timers=scripts/enhancement_branches.gd; save=load_progress/load_progress_data/portable_save_data. Save version is defined by BattleGame.SAVE_VERSION and validation by save_transfer.gd; this locator makes no historical-save continuity promise. Music preference remains separate user://music_settings.cfg.

BOUNDARIES: native_execution_compiler admits its supported subset; native_execution_session/handoff own execution transfer. PresentedBattleGame motion is distinct from Lab exact/fast. Portable analysis consumes the captured package JSON and published workbook templates. It does not probe adjacent source directories or marker.source_mon. Dependency closure and configuration isolation do not establish model equivalence.

COMMIT CONTRACT: command_result creates detached, deeply read-only outcomes. Game equipment/loadout/reactor/enhancement/income commands and Progress/Galaxy/Hyperspace coordinators use commit_effects for save dirty, committed-fact crew scheduling, then UI publication. Product bool/int facades derive from full results. Capacity reconciliation precedes configuration publication; refit health changes only where needed. crew_system.on_committed owns scheduling; UI events have no scheduler connection. Native preparation precedes installation, with proposal/context rechecks after handoff. Nested commands are rejected during installation/notification.

TIME OWNERSHIP: step_progress owns session-only paid budget segments, one reserved interval, shared/combat/substep position and stable domain operation cursors. Game.consume_external_time is the live wall-time entry; Presented and native execution use the same reserved step. Galaxy preparation retries use the retained interval; Crew retains blocked purchases/allocation separately; Hyperspace retries pending completion/claims even when its remaining time is zero. Completed work is not replayed. This is not arbitrary interruption recovery: invalidated contexts and interrupted legacy combat without an inner cursor freeze and retain the session. No refund, process-restart continuation or performance guarantee follows from freezing.

INCOME: income_history is the bounded receipt owner for display, research, unification peak and Galaxy production queries. Native pickup eligibility is shared: enemy drops and top timed resource blocks count; derived furnace/Galaxy receipts do not. Purpose-specific clocks and amount bases remain distinct. Wallets/queries reuse growth_number arithmetic and discard precision-external small amounts, without exact bookkeeping or compensation.

SNAPSHOTS: incomplete reserved/shared/combat work gates ordinary save/export/import backup/load/capture/tool snapshots. Economic revisions invalidate stale continuation; research badge reads and Hyperspace receipt acknowledgements do not. Prepared economic commands preserve intervening UI reads unless they create a new completion/receipt. ProductLifecycle now coordinates replacement as described below; no historical-save migration promise is introduced.

HOT PATH: consume_external_time rejects commit/logical-step reentry before save checks, countdowns, particle spending or time acceptance. Ordinary planet/research progress retains lightweight commit_effects.begin_progress/finish_progress; paid research uses its existing resource-notice cadence. No per-frame full domain snapshot or additional time ledger is required.

S3 LIFECYCLE: product_lifecycle owns prepare/install/ready/recovery_required gates for disk import, startup recovery, memory replacement and restart. save_transfer prepares a private candidate; successful filesystem replacement alone cannot authorize a new session. The actual loaded source and target identity must match the installation, otherwise recovery material remains. Game.create_session_candidate preserves allocation counters before creating new actors. PresentedBattleGame prepares its actual subtype and replaces missile queues, target registries and derived combat state when installing; retained UI references cannot alias new actors. Reforge uses this same complete session boundary. The QA clear-save restart goes through lifecycle before deleting the slot; the full restart host requires the new process's ready/ownership acknowledgement.

S3 CONFIGURATION: configuration_manifest.json is the committed authority for all data JSON and managed config_excel/published workbook templates. config_snapshot.py and configuration_snapshot.gd share the native OS exclusive file-handle lock with configuration_snapshot.ps1. Ordinary readers reject unresolved journals and hash mismatches. They capture and verify the entire generation under one lock, then parse only captured bytes. Runtime startup explicitly activates a generation; database, dynamic hyperspace inputs, UI catalogs, F8/F9 policies and XLSX exports share that capture. Schema caches use captured identity. Normal result/report files are not configuration transactions.

config_publication.py supervises split/import/full import and the public level-editor Store. It captures separately held source XLSX inputs, prepares and validates in a private workspace outside the root lock, then rechecks generation and source identities for one publication. Source workbooks are externally editable inputs, not members of the old JSON generation. An explicit external selection records a stable frozen snapshot. Split updates sources but keeps runtime projections/templates until import. Only explicit complete initialization can create the first manifest. Ordinary consumers cannot certify loose JSON.

Public save responses are prepared from the private candidate before publication, then bound to that commit and its updated source fingerprints. Full import returns the same committed projection. Neither response refreshes the live root after commit; a later writer or lock holder cannot turn success into failure or mix generations.

The publisher retains installing/committed/recovery_required journal state. Rollback holds verified workbook handles through restore/readback or same-handle deletion; unknown source content retains recovery instead of overwriting an outside edit. CLI failures expose the actual recovery path and reason. The old atomic_batch remains private preparation machinery; its return no longer publishes product authority. Direct public editor writes and ad-hoc runtime JSON reads have exited supported consumers.

Both builders capture once and materialize those bytes after unlocking. Packages carry a runtime-only manifest with source-generation provenance and published templates, independent of repository paths. Release staging continues its separate native/payload/export/runtime gates. Configuration capture alone establishes neither model equivalence nor performance; no old-save migration is provided.

S4 EXECUTION: execution_contract admits the existing finite Lab subset before start and on relevant runtime revisions; native_execution_compiler remains the native authority. execution_identity captures the loaded implementation, private inputs, parameters and engine at batch start. Comparison, retest and merge apply their own difference policies; unknown identity is not equality. Nested merged results retain every constituent identity. Runtime arithmetic and reports use GrowthNumber where supported; Lab damage is HP-only. See [Lab limits](BALANCE_LAB.md).
