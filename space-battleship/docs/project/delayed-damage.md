# 延迟伤害

- Delayed damage splits the full incurred post-mitigation damage by the configured integer-percentage curve. Ordinary shield capacity limits the actual immediate payment, so damage reaches armour only after current shields are exhausted; overflow from a capped shield module first uses remaining shield modules. Final armour still incurs overkill before clamping actual loss. Independent sources add installments into bounded global game-time buckets: the first installment occurs at least one configured interval later; quantization can extend completion by less than one interval. Each due tick pays its current portion, then makes one global configured chance roll to clear all remaining debt. Selected A-node probability contributions count once globally. Delayed30B overrides Delayed20B's ordinary no-clear rule; both its penalty and Delayed20B's passive reduction reference the underlying probability before forced clearing. Delayed10B's timed reduction starts only after an actual queue clear; no roll precedes the first due payment. Due damage runs before same-tick memory healing and death checks. Existing short cover and neutral temporary protection absorb already-mitigated debt first, then every installment uses current ordinary shields before armour regardless of its source bucket, without further mitigation or deferral. Recovered shields can absorb older armour-source debt; depleted/removed shields fall through to armour. The player dies only when both shield and armour are depleted. Reorder/refit does not forgive debt; clear-state ticks continue payments. Protection/debt follow existing reset_player/reload/full-health restart policy, except the suspended main state owned by an active manual hyperspace receipt; pause freezes them and offline does not replay them.
