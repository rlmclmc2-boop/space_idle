# CREW: rules
SRC: crew/crew_assignment/unlock sheets; crew_config owns level parameters and level UI des templates.
- Six unlocks at cleared levels 10/20/25/30/35/40 via unlock.xlsx; crew.unlockId references. crewId is saved identity, independent of display name. Hide crew tab until first unlock; preview only next number/silhouette/threshold, no effects.
- Levels unlock through unlock feature crew_level; before unlock no level UI, XP gain or level effects. Start/missing-save Lv0, no level cap. XP for next level=round(crew_config.base_exp × crew_config.exp_multiplier^current level), min 1; base>0, multiplier>=1, finite. Deduct level by level, keep remainder. Reward/old-save/display XP integers; required_exp shared by logic/bar. Level does not change assignment interval. Planet exploration is current natural XP source; preview/payout/notice share game.planet_exp_reward. Its stage coefficient uses lifetime_max_stage and survives reforge. An active planet_buff crew_exp_share/all conquest effect gives each unlocked crew member the full exploration XP once, including the explorer; both individual and crew-level unlock gates apply. Locked crew receive no XP and no later backfill.
- Level effects use the active assigned crew: equipped stats ×(1+equip_bonus)^L; per-tech dedicated AI=L×tech_ai_per_level, outside the ordinary pool; research rate ×(1+tech_speed×L); direct fragment drops ×(1+gem_bonus×L); reactor energy ×(1+charge_bonus×L). Derive from current level and bases, never accumulate. des edits change text only; unknown placeholders remain literal.
- One assignment per crew; one crew per targetType+targetId. Locked/idle/invalid target contributes 0; target reads passive modifier, no cfg base write. Excel cannot create new business handler: register behavior explicitly.
- equipment_upgrade: weapon then defense, enabled modules only (empty enabled module allowed), saved 1/10/MAX mode, original upgrade API; insufficient resource skips module. hightech_scientists: x1/x10/MAX original buy; distribute equally only after successful buy; old efficiency job stays retired. jewel_auto: combine and clean obsolete bag gems, then existing enabled sockets prefer strictly higher same-ID replacement else in-place upgrade; fill empty sockets with a random compatible available gem, without duplicate IDs per module; no action -> no save/UI event. reactor_upgrade: each game-second try original uranium-paid +1, then equal energy split even if unaffordable; unchanged split+failed upgrade -> no save/event.
- Interval from sheet, game-time clock; pause freezes, offline no catch-up, large-step missed intervals not replayed. Reassign/unassign resets clock; upgrade-mode edit does not; clock unsaved. Explorer cannot hold job; completion/recall returns idle.
- profile.crew saves dynamic fields only; names/base power/job values from cfg. crewEquipment reserved; no current crew equipment gameplay. Legacy weapon_upgrade/defense_upgrade -> equipment_upgrade; smelting_speed -> jewel_auto; production_output/hightech_efficiency -> idle, preserving level/XP/mode. Conflicting old target keeps first crew in cfg order; unknown static fields dropped; valid temporarily unavailable assignment retained. crew_level.xlsx retired.
- UI: compact identity/level/status left; XP/two-line effect/assignment right. Idle hides effects/remove control with no gap. Occupied target disabled; exploration shows status/time/XP, planet page handles recall. One crew indicator on system tab only. Local refresh retains selection/focus/draft/scroll.
