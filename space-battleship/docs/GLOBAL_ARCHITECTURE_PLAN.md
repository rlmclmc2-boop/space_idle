## 1. 选择与目标

选择**领域所有者 + 具体用例协调器 + 明确的运行/恢复边界**。保留现有 Godot 单进程结构、GrowthNumber、领域 prepare/commit、贡献版本缓存、攻击出生投影、原生执行会话和现有测试 runner。整体改造不等于整体重写：将跨域提交、时间结算、执行能力、产品替换、产物身份各自收敛到一个可定位责任；让每项迁移覆盖其受支持消费者。

比较过三条路线：

| 路线 | 收益 | 主要代价 | 结论 |
|---|---|---|---|
| 只补失效事件、旧字段、清单 | 当前缺陷修复快 | 下次新增跨域能力仍靠记忆接线 | 作为迁移中的修复，不能作为整体方案 |
| ECS / 通用事务框架 / 全局消息总线重写 | 统一抽象和调度 | 重建已有效领域边界；更多运行间接层；难证明玩法无变化 | 不采用 |
| 在现有具体协调器收敛提交和生命周期契约 | 可逐条迁移、保留优化、可独立回退 | 迁移期间需兼容门面与消费者核对 | 采用 |

验收目标是稳定不变量和扩展步骤减少，不以文件数、类数、测试数或代码行数判定完成。不得借架构重构调整数值、时间倍率、掉落资格、存档规则或删除受支持工具。

## 3. 目标责任图与状态寿命

```text
正式场景 / 页面 / F8 / F9 / 独立分析器
                ↓ 命令或只读查询
Game 兼容门面 / 组合根（显式装配依赖、拥有会话）
                ↓
具体用例协调器：装备/成长、Progress、Galaxy、Hyperspace
                ↓ prepare / 复核 / 无回调共同提交
领域所有者：Economy、Equipment、Research、Crew、Planet、Reactor、…
                ↓ 已提交变更
共同完成边界：派生协调 → 调度唤醒 → UI 通知

战斗会话 → 执行器适配器 → 共享规则/投影（按能力准入）
产品生命周期 → 保存/加载/导入/重载适配器（就绪后恢复消费）
构建/分析入口 → 已验证配置快照 + 规则/执行器身份
```

箭头不是要求新增对应大类；先扩展已有 runtime 和门面。依赖方向：UI 不写领域内部状态；领域不依赖场景、保存或 UI；用例可协调多个领域；纯投影读所有者版本；基础设施承载 IO；执行器不拥有持久进度。仍需 g 的现有方法逐用例改成显式参数/窄查询，不为消灭所有 g 引用而大规模改签名。

| 状态 | 权威与寿命 | 保存/替换约束 |
|---|---|---|
| 持久进度、余额 | 现有领域所有者，跨会话 | 由保存组合器按现有 schema 导出；界面不可修改快照 |
| 待结算工作 | 产生工作的领域，直到结算/按既有规则结束 | 单一所有者；不得在全局余量和领域待办重复记账；是否跨重启保持按现有契约，不暗改 schema |
| 战斗会话 | 当前执行会话，至离场/替换 | 每刻只有一个执行所有者；交接不隐式结算额外奖励 |
| 派生属性/规则 | AttributeProjection/CompiledCombatRules | 由贡献版本重建，不保存缓存、不由 UI 事件使其正确 |
| 表现状态 | 场景/表现对象，至解绑 | 订阅可释放；绑定会话代号，拒绝旧会话回调 |
| 配置快照 | 一次已验证加载/分析批次 | 批次内固定；来源 Excel 与生成数据的实际差异可追踪 |
| 分析产物 | 批次身份 + 输入 + 结果 | 旧结果可查看；缺身份不能标为可比或无条件复测 |

## 4. 业务提交：保留具体算法，统一完成条件

先迁移装备升级/换舰与 Progress 两种不同复杂度用例，然后 Galaxy/Hyperspace、反应炉/强化等剩余公开写入口。新建小型提交结果/完成辅助（建议 `command_result.gd`、`commit_effects.gd`），不是命令注册中心或反射框架。

结果包含明确 `status`（committed/no_change/rejected/blocked）、原因、已变化的领域/资源/槽位、贡献变化，以及需要发布的业务事实。结果由协调器从真实计划生成，调用者不能随意指定“刷新全部”。业务 plan 保留各自结构。当前 bool API 可在门面临时映射，但时间消费者必须使用完整结果。冻结或复制跨回调结果，防止消费者改写已提交事实。

固定顺序：

1. 领域准备完整 proposal；拒绝没有副作用。
2. 完成必要原生准备/交接；这些操作可能触发观察者，之后复核所有相关版本。
3. 所有可失败校验在安装前完成。共同安装区禁止信号、IO、await、外部回调；仅赋值/领域 commit。native 数值批次保留，必须证明 native 提交后主机安装不可业务失败；否则先做可安装准备或回到既有交接路径。
4. 稳定派生状态：容量协调、健康/攻击来源约束按具体用例现有语义处理，然后确定最终贡献版本和执行描述。不能在反应炉调整后留旧描述。共同辅助复用顺序，健康重配不是每个变更的默认副作用。
5. 标记保存脏；用已提交事实唤醒自动任务；最后发布 UI 事件。回调可读到完整状态。重入写命令在提交期间拒绝/排队到下一边界，不能插入共同安装区。

`attribute_projection.gd` 继续拥有派生依赖表。贡献版本仍由所有者在贡献真的改变时增加，不能用每 tick 全局 dirty 替代。自动任务增加面向变更的入口（资源、装备、解锁、分配等），在其内部维护任务依赖；移除已迁移业务对 `crew.on_event` 的重复唤醒。UI 事件保留兼容外观，不再承担业务正确性。初期允许兼容桥，单条命令切换时必须证明不会两次发事件/执行任务。

## 5. 时间、收入事实与失败语义

外部真实时间/倍率转换仍归 `consume_external_time`；战斗内部细分仍归当前执行会话。各进度消费者返回“本次已消费、仍持有待办、阻塞原因”。不把所有消费者放进可配置调度图。

每项时间迁移先画出输入时间去向：未接纳的预算仍在调用者；已接纳未完成的工作只在领域；已结算部分只能消费一次。对同一步内多个消费者，不能因为后一个阻塞重跑前面已提交部分。采用现有逐域待办和明确的共享步阶段记录；只有必要的阶段游标保留在会话。已付粒子与时间记账必须一同有确定结果，不能遇到失败额外扣费或静默重放。超空间有界完成循环及星系 pending 保留，不退化成每帧全量扫描。

收入历史从 `Game.resource_samples` 的混合用途数组收敛为一个有界事实所有者（可先提取 `income_history.gd`）：记录真实已入账的来源、资源、数量及现有时间坐标；战场拾取、星系生产、其他衍生收入从各自提交边界写入一次。用途查询明确参数/命名：显示收入、科研自动输入、合格战场收入峰值等；消费者不能各自重建来源判定。保留窗口有界、增量裁剪，不保存无限事件日志。

审计报告要求联合一体化排除衍生收入、与星系查询共用权威事实，但同时列出时间、倍率和 auto_gen 资格未定。实施先完成事实归属和保持现有查询行为的兼容迁移；受未定规则影响的玩法修正单独列为需求门槛，请 dot 核实已有用户决定。不得以架构批准代替玩法批准，不得以保留兼容行为宣称这项业务缺陷已修完。

## 6. 执行器与共享玩法语义

新增能力评估的公共结果格式，复用 native compiler 的实际检查；每个执行器在启动前和能力变化边界验证输入。能力矩阵是公开契约和实现适配器的定位，不创建第二套手填规则真值。

| 环境 | 目标声明 | 不支持时 |
|---|---|---|
| PresentedBattleGame 正式脚本 | 正式运动、目标、攻击和时间规则参考实现 | 输入无效时明确失败；不退回不同运动模型冒充正式 |
| 原生 | 现有明确子集 + 数值域 | 安全交接到正式脚本；交接失败冻结该会话，保留可诊断状态 |
| BalanceGame exact | Lab 自身精确步进模型；当前不承诺正式运动等价 | 支持范围外拒绝并记录原因；只有验证过的共同子集标为可比 |
| BalanceGame fast | 加速近似/调度模型，声明差异 | 明确拒绝或用户已选模型内降级，不能偷偷变更模式 |

共享的是 GrowthNumber 运算、攻击出生语义、属性投影、奖励规则和输入验证。Lab 的普通乘法/float 签名要迁移到共享数值语义，或在能力评估拒绝该输入；禁止先转 float 后检查。清理旧科研分支时按当前 Research 所有者判断，不能直接删掉研究推进。F8、F9、自动关卡、复测和独立分析结果都携带模型/能力/数值域信息；未知能力默认拒绝。改模型语义需单独记录模型版本，不把 exact 当通用等价保证。

## 7. 产品替换与恢复

建立小型产品生命周期状态：ready → preparing → installing → ready，失败进入 recovery_required。失败原因和权威来源一起返回。运行中的命令、时间、自动保存统一检查可消费/可写状态，不由多个独立 bool 任意恢复。

存档替换：在私有候选对象准备合法领域快照、派生属性和必要会话绑定；旧会话停止消费后安装。成功必须是新状态完成加载且所有权明确，而不是磁盘 rename 成功或 reload API 返回 OK。重载失败且回滚成功，只在旧权威状态重新校验后恢复；回滚失败保留备份和错误路径、禁止自动写入。保留现有 ProgressWriter 写锁和临时文件校验，UI 仅负责交互，不负责恢复决定。导入导出、启动恢复、大小重启与普通内存 load 逐项接入，不修改玩家真实存档做测试。

配置多文件替换：先采用现有 journal 扩展为可检查的提交状态和完整内容指纹。导入器/编辑器写入期间持有同一配置写锁；新启动/分析/打包在加载前检查 journal、校验所有文件属于同一提交，未恢复不读混合代际。游戏已加载的内存快照继续独立存在。进程中断留下 journal 时拒绝新消费并提供恢复材料；不能自动猜测新旧何者正确。此方式比改为版本目录+指针改动小；若现有全部读取入口无法可靠门控，再以独立决策升级版本目录，不能宣称 best effort 已实现跨文件原子性。

## 8. 入口闭合与版本身份

维护一份短的受支持入口映射（建议 `tools/supported_entrypoints.json`）：正式玩家、F8、F9、独立分析器、配置导入、关卡编辑器、玩家构建以及测试入口。只记录入口、运行数据模式、能力模型、验证命令定位；不重复列全仓文件。

分析器从已有明确入口计算静态脚本依赖闭包，结合显式动态数据/资源允许清单；保留漏列/缺文件硬失败。Godot class_name、场景资源和动态拼接不能仅靠当前正则推断，必须补实际解析/显式边界并运行隔离导入确认。依赖抽取结果只证明打包闭合，不证明功能正确。玩家构建保留隔离 staging 与最终验证，不直接复制工作树运行缓存。

分析/发布身份含：规则源内容指纹、相关运行数据实际快照指纹、执行模型/版本、引擎版本、原生二进制哈希及对应构建源码/工具链记录（适用时）、种子与时间模式。内容指纹覆盖脏源码，不能仅记 Git HEAD；同一批次只计算一次，不进入热循环。纯素材变化不使战斗规则身份失效。外部 mon.xlsx 的输入哈希和转换后的实际数据都需记录，不能用项目 JSON 哈希代替外部源。

旧产物保留查看能力，身份缺失标未知；复测/跨版本比较须显式显示身份差异，不能自动视为同一实验。构建记录是来源证据，不是二进制正确性证明，仍需原生实际准入检查。

接口迁移完成的判据：所有受支持消费者已切换，或经批准明确退役；文档指南/manifest/覆盖声明在同一变更更新。删除旧测试前盘点独有断言并迁入当前公共 API 场景；不通过删除断言把旧测试“修绿”。

| S1 共同提交试点 | 装备升级/换舰、Progress；完成结果和自动唤醒入口；门面兼容 | 钱包/领域/投影/事件的一致性，原生拒绝与重入下无部分提交；旧事件消费者迁移完 |
| S2 全量业务提交与时间 | Galaxy/Hyperspace/反应炉/强化等公开变更；逐域待办和共享步结果；收入事实 | 逐公开写入口的迁移清单无遗漏；中途阻塞不丢工作、不重复费用/奖励；未定资格修正仍受独立门槛 |
| S3 生命周期 | 启动/内存 load/导入/重启恢复；配置 journal 读取门控 | 任一故障出口权威来源明确；恢复未完成不自动消费/覆盖；全部工具读取入口门控 |
| S4 执行契约与身份 | Lab 数值和科研接口；能力矩阵、F8/F9/分析器/复测身份；构建来源记录 | 所有支持输入成功或明确拒绝，未知能力不产出假有效结果；身份能追溯实际输入 |
| S5 兼容收尾与整体验收 | 移除已无消费者的桥、同步架构/测试/发布文档 | 所有入口闭合、当前覆盖可信、相同工作量性能证据、双审 |

S0 → S1 → S2；S3 可在 S1 完成契约后进行；S4 以 S0 可运行工具为前提；S5 等待全部。每片先列精确符号及消费者，再改代码。若某片需改变存档 schema、玩法资格或正式模型，先拆出并交审，其他独立工作继续。

回退以 Git revert 单片为主，保留现有磁盘格式和门面直到迁移完成；禁止通过重置玩家档回退。跨片存在格式依赖时不得只回退写方：必须带读方兼容或停用新入口并保留恢复材料。方案阶段不删除任何存档、缓存或历史任务目录。

## 10. 可复用验证与资源预算

沿现有 `test/run.py` 与主题指南选单项，从仓库根目录执行 `python test/run.py <相关现存test文件>`；没有实际检查的名称不当作已通过命令。测试隔离项目和 user 目录，保持可识别完成摘要；退出 0 但缺摘要不能称通过。文档阶段只做事实、引用和 diff 核对。

新增场景只填真实覆盖缺口，夹具通过领域安装/命令构造；预期从公开不变量和表输入独立计算，不复制生产算法。一个共享场景描述输入、命令序列、可观测断言；各执行器用适配器复用输入和共同子集断言，不强行断言不同模型轨迹一致。

| 风险 | 必要证据 |
|---|---|
| 提交/失效 | stale proposal、native 准备失败、提交后回调读取、重入；成功时共同状态/贡献/任务一致，失败时无部分钱包变更 |
| 时间 | 完成边界前后、两个消费者中第二个阻塞、恢复重试；所有权转移守恒；pending 保存仅按当前规定 |
| 收入 | 同资源不同来源、同窗口、不同用途；事实只入账一次；规则未定的断言不得自造 |
| 替换 | 写失败、reload 失败、rollback 失败、配置批处理中断；保留可恢复材料且普通写入保持禁止 |
| 执行器 | 每项支持能力正例与拒绝边界，大数/有限标量/未知分支；只在声明共同子集做确定性对照 |
| 工具交付 | F8/F9、独立分析器、配置/编辑、玩家包各自真实入口的最小样例；动态依赖、结果身份和错误说明 |
| 扩展维护 | 用一个现有跨域场景解释新增贡献应改哪些边界；不新增玩法来证明架构；无需修改 UI 事件分派才能唤醒业务 |

性能比较使用同一机器、引擎、数据、种子、工作量和暖机条件：正式战斗含原生驻留、一次成长批次、一个 F9 批次。记录 CPU/帧耗时分布、峰值内存、属性重建/原生交接次数及输出体积。先测基线再评估；没有数据不声称提升。提交结果仅在有变化时分配，时间热路径尽量用固定小结果；禁止每帧全域扫描、全状态深拷贝、完整规则哈希或无限事实日志。任何稳定可复现退化先定位，再决定是否接受；不凭空设定性能承诺。

## 11. 审查交接与未决项

dot 审查需求/范围与用户约束，独立 high 审查架构、失败顺序、消费者闭合和轻量程度。审查意见应针对此提交，以各自 Git 提交/分支交接，记录批准或阻塞项及适用 SHA；不能仅凭聊天中“看过了”宣称双审完成。修改方案后，两位审查者确认最终方案版本；实施后再审最终代码提交，未经双审不合 main。

待审具体决定：

1. 是否同意在既有协调器收敛契约，而非全量重写或继续补事件？
2. 是否同意 Lab 明确模型差异，并以能力拒绝替代默默转换数值？
3. 是否同意配置以 journal+统一读取门控起步，若不能覆盖所有读取方则升级版本目录？
4. dot 核实收入资格、时间、倍率、auto_gen 的已有用户决定；目前不自定。
5. high 重点核查原生先提交后主机安装的不可失败条件、共享步中部分消费者完成后的重试语义，以及 reload 成功但新启动失败的恢复闭合。

尚未完成：实现、运行验证、性能测量、两份独立审查。此方案不代表当前系统已可靠，也不把上述未决玩法项包装成已解决。下一步只接收方案审查并修订；批准后按 S0 开始。
