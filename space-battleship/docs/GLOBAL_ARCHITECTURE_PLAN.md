## 1. 选择与目标

选择**领域所有者 + 具体用例协调器 + 明确的运行/恢复边界**。保留现有 Godot 单进程结构、GrowthNumber、领域 prepare/commit、贡献版本缓存、攻击出生投影、原生执行会话和现有测试 runner。整体改造不等于整体重写：将跨域提交、时间结算、执行能力、产品替换、产物身份各自收敛到一个可定位责任；让每项迁移覆盖其受支持消费者。

比较过三条路线：

| 路线 | 收益 | 主要代价 | 结论 |
|---|---|---|---|
| 只补失效事件、旧字段、清单 | 当前缺陷修复快 | 下次新增跨域能力仍靠记忆接线 | 作为迁移中的修复，不能作为整体方案 |
| ECS / 通用事务框架 / 全局消息总线重写 | 统一抽象和调度 | 重建已有效领域边界；更多运行间接层；难证明玩法无变化 | 不采用 |
| 在现有具体协调器收敛提交和生命周期契约 | 可逐条迁移、保留优化、可独立回退 | 迁移期间需兼容门面与消费者核对 | 采用 |

验收目标是稳定不变量和扩展步骤减少，不以文件数、类数、测试数或代码行数判定完成。不得借架构重构调整数值、时间倍率、掉落资格、存档规则或删除受支持工具。

本轮不新增“旧档连续性”目标，不建设历史版本迁移链或永久旧 schema 兼容层。保护现有个人存档是操作约束，不等于承诺所有历史档可在新架构中继续运行；当前受支持存档入口的替换安全仍须满足。格式支持范围若需变化单独交审，不以此方案授权删除、重写或迁移个人档案。

## 3. 目标责任图与状态寿命

```text
正式场景 / 页面 / F8 / F9 / 独立分析器
                ↓ 命令或只读查询
Game 兼容门面 / 组合根（显式装配依赖、拥有会话）
                ↓
具体用例协调器：装备/成长、Progress、Galaxy、Hyperspace
                ↓ prepare / 复核 / 无回调共同提交
领域所有者：Economy、Equipment、Research、Crew、Planet、Reactor、…
                ↓ 已提交变更
共同完成边界：派生协调 → 调度唤醒 → UI 通知

战斗会话 → 执行器适配器 → 共享规则/投影（按能力准入）
产品生命周期 → 保存/加载/导入/重载适配器（就绪后恢复消费）
构建/分析入口 → 已验证配置快照 + 规则/执行器身份
```

箭头不是要求新增对应大类；先扩展已有 runtime 和门面。依赖方向：UI 不写领域内部状态；领域不依赖场景、保存或 UI；用例可协调多个领域；纯投影读所有者版本；基础设施承载 IO；执行器不拥有持久进度。仍需 g 的现有方法逐用例改成显式参数/窄查询，不为消灭所有 g 引用而大规模改签名。

| 状态 | 权威与寿命 | 保存/替换约束 |
|---|---|---|
| 持久进度、余额 | 现有领域所有者，跨会话 | 由保存组合器按现有 schema 导出；界面不可修改快照 |
| 待结算工作 | 产生工作的领域，直到结算/按既有规则结束 | 单一所有者；不得在全局余量和领域待办重复记账；是否跨重启保持按现有契约，不暗改 schema |
| 战斗会话 | 当前执行会话，至离场/替换 | 每刻只有一个执行所有者；交接不隐式结算额外奖励 |
| 派生属性/规则 | AttributeProjection/CompiledCombatRules | 由贡献版本重建，不保存缓存、不由 UI 事件使其正确 |
| 表现状态 | 场景/表现对象，至解绑 | 订阅可释放；绑定会话代号，拒绝旧会话回调 |

## 4. 业务提交：保留具体算法，统一完成条件

先迁移装备升级/换舰与 Progress 两种不同复杂度用例，然后 Galaxy/Hyperspace、反应炉/强化等剩余公开写入口。新建小型提交结果/完成辅助（建议 `command_result.gd`、`commit_effects.gd`），不是命令注册中心或反射框架。

结果包含明确 `status`（committed/no_change/rejected/blocked）、原因、已变化的领域/资源/槽位、贡献变化，以及需要发布的业务事实。结果由协调器从真实计划生成，调用者不能随意指定“刷新全部”。业务 plan 保留各自结构。当前 bool API 可在门面临时映射，但时间消费者必须使用完整结果。冻结或复制跨回调结果，防止消费者改写已提交事实。

固定顺序：

1. 领域准备完整 proposal；拒绝没有副作用。
2. 完成必要原生准备/交接；这些操作可能触发观察者，之后复核所有相关版本。
3. 所有可失败校验在安装前完成。共同安装区禁止信号、IO、await、外部回调；仅赋值/领域 commit。native 数值批次保留，必须证明 native 提交后主机安装不可业务失败；否则先做可安装准备或回到既有交接路径。
4. 稳定派生状态：容量协调、健康/攻击来源约束按具体用例现有语义处理，然后确定最终贡献版本和执行描述。不能在反应炉调整后留旧描述。共同辅助复用顺序，健康重配不是每个变更的默认副作用。
5. 标记保存脏；用已提交事实唤醒自动任务；最后发布 UI 事件。回调可读到完整状态。重入写命令在提交期间拒绝/排队到下一边界，不能插入共同安装区。

`attribute_projection.gd` 继续拥有派生依赖表。贡献版本仍由所有者在贡献真的改变时增加，不能用每 tick 全局 dirty 替代。自动任务增加面向变更的入口（资源、装备、解锁、分配等），在其内部维护任务依赖；移除已迁移业务对 `crew.on_event` 的重复唤醒。UI 事件保留兼容外观，不再承担业务正确性。初期允许兼容桥，单条命令切换时必须证明不会两次发事件/执行任务。

## 5. 时间、收入事实与失败语义

外部真实时间/倍率转换仍归 `consume_external_time`；战斗内部细分仍归当前执行会话。各进度消费者返回“本次已消费、仍持有待办、阻塞原因”。不把所有消费者放进可配置调度图。

每项时间迁移先画出输入时间去向：未接纳的预算仍在调用者；已接纳未完成的工作只在领域；已结算部分只能消费一次。对同一步内多个消费者，不能因为后一个阻塞重跑前面已提交部分。采用现有逐域待办和明确的共享步阶段记录；只有必要的阶段游标保留在会话。已付粒子与时间记账必须一同有确定结果，不能遇到失败额外扣费或静默重放。超空间有界完成循环及星系 pending 保留，不退化成每帧全量扫描。

### 5.1 共享步、子步与域内进度的唯一恢复位置

用一份会话内 `StepProgress` **替换**分散的 shared/native phase、remaining、cancelled-step 补偿和无返回 tick 完成推断。它记录当前逻辑步身份、预算区间、当前子步区间、当前阶段以及当前阶段内的续行位置；不复制领域进度、战斗对象或领域 pending。只有一个未完成逻辑步，恢复的是同一份记录，不另开重试队列。原生/脚本适配器读写这一份进度，不能各保留一个可独立推进的镜像。

1. 外层先从已换算预算预留一个逻辑步区间；预留即从可再次派发的余量移除。该区间要么由 StepProgress 持有，要么完成退休，绝不同时留在可派发余量。只有整个逻辑步退休后才派发下一步。
2. 执行器按既有截止时间和原有先后顺序确定子步 `[start,end)`，在执行前固定该子步边界。子步内按现有业务顺序逐阶段推进，不因重构改变时间模型或战斗/经济先后关系。前一子步完成后递增子步位置；后续失败不能重新执行前一子步。恢复尚未完成子步时也不能从更新后的状态重新计算其起点和长度。
3. 阶段返回 committed（本阶段完成）、retained（输入已移交领域但领域仍有待办）或 blocked（尚未接纳/无法继续），并明确完成区间与下一个位置。领域接纳 dt 与外层标记“已移交”在同一无回调区完成；恢复 retained 时调用领域 drain，不再次 add_time。retained 不自动意味着可进入下一阶段：若待办影响本子步后续规则，停在此阶段；仅本来允许延后的工作可结束本阶段，由领域继续拥有。
4. 单个域内若按多个星球/区域/完成项循环，协调器保留稳定的项目列表与当前项目位置；每项成功提交与位置前移在同一无回调区完成。一个项目内部若可分段提交，则该领域保留已提交位置或 remaining；上层只记项目位置，不再复制其余额。重试从首个未完成单位开始，不能重跑已领奖/已扣款的前项。所有原先 return 的失败分支都要说明本次是在接纳前、部分完成后，还是完成通知后。
5. 战斗子步若已经产生伤害、随机数消费、掉落或共享经济效果，就不能把“blocked”解释为整子步未执行。适配器必须报告可确认的完成区间和阶段；原生交接携带同一子步/阶段身份及剩余量，接收方从该点续行。结果不确定时冻结会话并报错，禁止猜测回退、重放或切换后从子步零点开始。现有内核若不能给出该边界，先把可失败准备移到子步执行前；仍无法保证则拒绝该快路径，不能靠试运行后重放兜底。
6. 业务 UI 通知在该提交的位置已前移后发布；由通知引发的命令不得穿插安装或触发嵌套 tick。重试不会再次发出已发布单位的通知。保存、重载和全局替换只能在共享步完整边界取快照；未完成时延后保存/替换，不能把领域已推进而 StepProgress 未持久化的半步存成普通档。不能恢复的阻塞保持冻结并保留诊断，不把退出进程后的半步恢复能力加入本轮。

以上是所需契约，不预设当前每个后端已具备续行接口。S2 必须逐阶段列出真实符号、可失败点、最小不可分提交单位和恢复位置；没有此表及对应证据，不能迁入新入口或宣称覆盖完成。

### 5.2 费用与时间预算归属

粒子支付发生在外部时间转换成游戏预算时，一次转换产生带已付身份的预算段，固定当时的倍率/费用参数。钱包扣除与预算段接纳在同一无回调提交区完成；准备失败时二者均不发生。外部时间中不受加速的部分使用其原有倍率，不能和已付段混成一个无来源浮点数后再猜费用。预算段只保留尚未派发区间，已派发区间归 StepProgress；字段用于取代 `game_time_remainder` 的无来源记账，不另建第二份时间余额。

共享时间是给各消费者的同一时间轴输入，不是把 dt 在各域之间相加分摊。守恒分别检查：外部预算 = 未派发 + 当前步持有 + 已退休；对每个时间消费者，已派发区间 = 尚未接纳 + 领域待办 + 该域已结算（加上既有规则明确规定的不活动时间）。不得把多个域的 dt 合计后与全局 dt 比较。科研投入、领奖等领域费用仍随本域最小提交单位发生，与加速粒子费用分开。

阻塞后的续行使用原预算段身份，不再次扣粒子、不按后来倍率重算、不重新领取相同外部帧时间。已退休子步和领域已完成项绝不退款；尚持有的已付预算原样保留用于恢复，不自动退款或丢弃。暂停/阻塞期间新到达的外部时间仍按已有暂停政策处理，不能凭重构新增离线累积。用户要求放弃未完成预算、强制重启或跨进程续费恢复的语义不在本方案中擅定：没有既有明确契约时保持冻结、延后普通保存/替换并交审。不得借“兼容旧档”新增持久时间账本。

验收必须包含：第二个消费者失败而第一个已完成；一个域内第二项失败而第一项已领奖；逻辑步中第二子步阻塞；原生已推进后交接；重复恢复请求；阻塞前后修改倍率；半步自动保存请求。分别检查 RNG/伤害/奖励/扣款/通知次数与未完成位置，不仅比较最后余额。

收入历史从 `Game.resource_samples` 的混合用途数组收敛为一个有界事实所有者（可先提取 `income_history.gd`）：记录真实已入账的来源、资源、数量及现有时间坐标；战场拾取、星系生产、其他衍生收入从各自提交边界写入一次。用途查询明确参数/命名：显示收入、科研自动输入、合格战场收入峰值等；消费者不能各自重建来源判定。保留窗口有界、增量裁剪，不保存无限事件日志。

审计报告要求联合一体化排除衍生收入、与星系查询共用权威事实，但同时列出时间、倍率和 auto_gen 资格未定。实施先完成事实归属和保持现有查询行为的兼容迁移；受未定规则影响的玩法修正单独列为需求门槛，请 dot 核实已有用户决定。不得以架构批准代替玩法批准，不得以保留兼容行为宣称这项业务缺陷已修完。

## 6. 执行器与共享玩法语义

新增能力评估的公共结果格式，复用 native compiler 的实际检查；每个执行器在启动前和能力变化边界验证输入。能力矩阵是公开契约和实现适配器的定位，不创建第二套手填规则真值。

| 环境 | 目标声明 | 不支持时 |
|---|---|---|
| PresentedBattleGame 正式脚本 | 正式运动、目标、攻击和时间规则参考实现 | 输入无效时明确失败；不退回不同运动模型冒充正式 |
| 原生 | 现有明确子集 + 数值域 | 安全交接到正式脚本；交接失败冻结该会话，保留可诊断状态 |
| BalanceGame exact | Lab 自身精确步进模型；当前不承诺正式运动等价 | 支持范围外拒绝并记录原因；只有验证过的共同子集标为可比 |
| BalanceGame fast | 加速近似/调度模型，声明差异 | 明确拒绝或用户已选模型内降级，不能偷偷变更模式 |

共享的是 GrowthNumber 运算、攻击出生语义、属性投影、奖励规则和输入验证。Lab 的普通乘法/float 签名要迁移到共享数值语义，或在能力评估拒绝该输入；禁止先转 float 后检查。清理旧科研分支时按当前 Research 所有者判断，不能直接删掉研究推进。F8、F9、自动关卡、复测和独立分析结果都携带模型/能力/数值域信息；未知能力默认拒绝。改模型语义需单独记录模型版本，不把 exact 当通用等价保证。

## 7. 产品替换与恢复

建立小型产品生命周期状态：ready → preparing → installing → ready，失败进入 recovery_required。失败原因和权威来源一起返回。运行中的命令、时间、自动保存统一检查可消费/可写状态，不由多个独立 bool 任意恢复。

存档替换：在私有候选对象准备合法领域快照、派生属性和必要会话绑定；旧会话停止消费后安装。成功必须是新状态完成加载且所有权明确，而不是磁盘 rename 成功或 reload API 返回 OK。重载失败且回滚成功，只在旧权威状态重新校验后恢复；回滚失败保留备份和错误路径、禁止自动写入。保留现有 ProgressWriter 写锁和临时文件校验，UI 仅负责交互，不负责恢复决定。导入导出、启动恢复、大小重启与普通内存 load 逐项接入，不修改玩家真实存档做测试。

### 7.1 配置检查与实际读取的隔离协议

采用**单个跨进程互斥锁 + 持锁捕获完整快照 + 提交清单/journal**。锁按规范化配置根路径确定唯一身份，覆盖导入器、关卡编辑器、游戏数据库启动、分析器、复测和构建；首次实现用读写均独占的简单锁，不引入读写锁升级协议。进程退出由系统释放锁，磁盘锁文件本身不能作为“无进程持有”的判断。互斥实现、超时和路径别名行为须跨 Godot/Python/PowerShell 验证；拿不到锁则明确 busy，不无锁继续。

写方先在私有目录准备并验证全部候选数据；随后持锁重新核对原输入/目标身份，持久写入 installing journal，再执行现有批量替换。在所有目标和完整提交清单的长度/哈希校验通过后发布 committed 身份，最后完成 journal 收尾并释放锁。回滚也全程持锁；失败保留 recovery_required。进程中断后的下一个持锁者只做恢复判定，不把“当前能解析”当成一个新完整代际。现有 `atomic_batch` 保留低层替换职责，移除调用方把它成功返回直接当“可以发布数据”的判定。

读方必须在**同一次持锁区间内**执行以下步骤，消除“检查后释放锁，再 load 文件”的间隙：

1. 检查 journal 状态和当前完整提交清单，拒绝 installing/recovery_required/未知状态。
2. 读取该入口所需的全部配置字节，包含清单列明的动态包；每个实际读取结果按同一清单验证身份和哈希。缓存只能以已验证提交身份命中，不以路径或 mtime 命中。
3. 将捕获的字节形成私有不可变快照，或写入本次隔离构建目录并核对副本哈希；完成后才释放锁。解析可在释放后使用这些字节进行，不能再打开可变源路径。解析/跨文件校验失败则丢弃私有候选，绝不发布部分数据库。
4. 游戏、分析批次、构建后续只使用这份快照；构建不能先验证源目录再 Copy-Item 源目录，分析器也不能开始后再次读外部 Excel。需要重新读取就是新的捕获操作，不能混用两个提交的缓存。

外部 Excel 编辑器不会遵守项目锁，因此该锁不声称保护外部工作簿。导入/分析捕获实际 workbook 输入时，必须使用能禁止并发写入/替换的文件句柄，将所有本次相关输入复制成私有字节后再解析，并记录实际快照指纹；拿不到稳定读取句柄则拒绝并要求编辑器释放文件。若平台不能提供这一保证，使用显式已冻结的输入副本，不降级为“读前读后 mtime 一样”。外部 workbook 本来不属于同一次提交的，也不宣称其与生成 JSON 同代；记录两者实际身份和来源模型。普通配置文件被未遵循协议的编辑器改动时，读入字节与已提交清单不符即拒绝，不自动生成新清单认可混合内容。

首次建立提交清单只能由完整配置准备/验证入口在持锁区发布；不得让首个普通读者把未知散落文件自动认证为同一代。发布包携带构建时捕获的已验证只读快照及清单；解压后的新运行无需返回源码目录读取配置。现有已加载内存快照不受新提交影响，切换配置需要完整捕获并重新安装。

S3 的闭合条件是所有受支持读取入口都通过快照捕获，所有写入口都通过持锁发布，且故障测试覆盖：读者检查完后写者尝试进入、捕获中写者等待、写者替换一半崩溃、快照释放锁后新版本提交、外部 workbook 正在写、构建捕获后源目录改变。若不能覆盖某个读取方，该入口保持不可发布状态；需另审版本目录/指针方案，不能继续称此协议完成。

## 8. 入口闭合与版本身份

维护一份短的受支持入口映射（建议 `tools/supported_entrypoints.json`）：正式玩家、F8、F9、独立分析器、配置导入、关卡编辑器、玩家构建以及测试入口。只记录入口、运行数据模式、能力模型、验证命令定位；不重复列全仓文件。

分析器从已有明确入口计算静态脚本依赖闭包，结合显式动态数据/资源允许清单；保留漏列/缺文件硬失败。Godot class_name、场景资源和动态拼接不能仅靠当前正则推断，必须补实际解析/显式边界并运行隔离导入确认。依赖抽取结果只证明打包闭合，不证明功能正确。玩家构建保留隔离 staging 与最终验证，不直接复制工作树运行缓存。

分析/发布身份含：规则源内容指纹、相关运行数据实际快照指纹、执行模型/版本、引擎版本、原生二进制哈希及对应构建源码/工具链记录（适用时）、种子与时间模式。内容指纹覆盖脏源码，不能仅记 Git HEAD；同一批次只计算一次，不进入热循环。纯素材变化不使战斗规则身份失效。外部 mon.xlsx 的输入哈希和转换后的实际数据都需记录，不能用项目 JSON 哈希代替外部源。

旧产物保留查看能力，身份缺失标未知；复测/跨版本比较须显式显示身份差异，不能自动视为同一实验。构建记录是来源证据，不是二进制正确性证明，仍需原生实际准入检查。

接口迁移完成的判据：所有受支持消费者已切换，或经批准明确退役；文档指南/manifest/覆盖声明在同一变更更新。删除旧测试前盘点独有断言并迁入当前公共 API 场景；不通过删除断言把旧测试“修绿”。

## 9. 实施切片与回退

各片为可审查 Git 提交。不是仅完成下表前两项就宣称整体完成。

| 切片 | 主要改动与受影响入口 | 验收/停止条件 |
|---|---|---|
| S0 消费者事实基线 | 入口映射、分析器闭包、旧状态测试迁移；当前 ARCHITECTURE/指南改为真实所有者 | 隔离分析器依赖/导入及相关测试可用；记录环境与既有失败，不能借架构顺手改玩法 |

| S2 全量业务提交与时间 | Galaxy/Hyperspace/反应炉/强化等公开变更；逐域待办和共享步结果；收入事实 | 逐公开写入口的迁移清单无遗漏；中途阻塞不丢工作、不重复费用/奖励；未定资格修正仍受独立门槛 |

回退以 Git revert 单片为主，禁止通过重置玩家档回退。跨片存在格式依赖时不得只回退写方：优先整体回退关联切片或停用新入口并保留恢复材料；临时读方适配必须有具体退出提交，不成为历史档兼容承诺。方案阶段不删除任何存档、缓存或历史任务目录。

### 9.1 责任替换与退出清单

新增辅助必须同时删去或改为单纯委托对应旧责任；不能先叠一套状态，留待未来无限期合并。每片提交在审查说明中给出“旧符号 → 新唯一所有者 → 仍存消费者 → 删除点”，仍有消费者就不把该片标为迁移完成。

| 新机制 | 替代的旧责任 | 保留内容与退出条件 |
|---|---|---|
| 提交完成结果/辅助 | 各协调器重复维护的 save_dirty、共同派生完成顺序、业务唤醒拼接 | 具体 prepare/commit 算法与按用例健康策略保留；每迁一条命令删除其重复后处理，不双发结果 |
| 基于提交事实的调度入口 | `crew.on_event` 中已迁命令对应的资源/装备/分配等唤醒分支 | UI 通知继续展示；同片删除旧事件唤醒分支。未迁命令才用临时桥，最迟 S2 清空该业务桥 |
| StepProgress + 已付预算段 | `game_time_remainder`、native/shared phase/remaining/cancelled 补偿中的同一进度责任及 void 完成推断 | 领域 pending 和战斗对象保留各自权威；改为引用/报告统一步骤，删除可独立推进镜像。S2 不允许两个时钟账本并存 |
| IncomeHistory | `Game.resource_samples` 存储、散落裁剪与按用途自行筛选事实 | 原查询函数可暂作无状态转发；S2 将所有消费者转到命名查询后删除旧混合存储/重复裁剪，不保留双写 |
| 生命周期状态 | `import_committing`、恢复中 save_enabled/process 等组合对“能否恢复写入”的独立裁决 | 写锁、用户暂停/用户保存设置是不同责任，保留但不能绕过生命周期。UI bool 若保留只从状态派生，不再可独立恢复。S3 删除旧恢复裁决 |
| 配置快照捕获/发布 | 各入口先检查再直接读取可变源、散落快照校验与批量成功即就绪 | 导入校验和 atomic_batch 低层 IO 保留；S3 删除无锁读取旁路/源路径重开，构建消费捕获副本 |
| 执行能力结果与身份 | 各入口对 exact/继承关系的隐式支持假设、散落不完整结果身份拼装 | native compiler 仍是原生能力真值，公共格式仅包装；S4 统一入口评估和身份构造，不复制第二套能力规则表 |
| 入口映射/闭包验证 | 手填脚本依赖允许清单与旧指南作为受支持范围的混合职责 | 动态数据/资源显式清单仍必要；S0 改为入口推导静态闭包，指南引用当前入口，不维护平行完整脚本列表 |

Game 可作为稳定公共门面继续存在，但只转发，不作为兼容历史字段/历史调用语义的容器。S1 的临时 bool 转发最迟在 S2 完成其业务调用者迁移后删除；确有 UI 仅需成功/失败的公开方法可保持为当前产品 API，必须由完整结果派生且无第二套实现。S5 仅核对前片退出证据并移除无消费者残留，不用“S5 再清理”延迟每片的责任替换。

## 10. 可复用验证与资源预算

沿现有 `test/run.py` 与主题指南选单项，从仓库根目录执行 `python test/run.py <相关现存test文件>`；没有实际检查的名称不当作已通过命令。测试隔离项目和 user 目录，保持可识别完成摘要；退出 0 但缺摘要不能称通过。文档阶段只做事实、引用和 diff 核对。

新增场景只填真实覆盖缺口，夹具通过领域安装/命令构造；预期从公开不变量和表输入独立计算，不复制生产算法。一个共享场景描述输入、命令序列、可观测断言；各执行器用适配器复用输入和共同子集断言，不强行断言不同模型轨迹一致。

| 风险 | 必要证据 |
|---|---|
| 提交/失效 | stale proposal、native 准备失败、提交后回调读取、重入；成功时共同状态/贡献/任务一致，失败时无部分钱包变更 |
| 时间 | §5.1 的跨域、跨子步及域内部分完成故障矩阵；§5.2 的预算/费用分别守恒；半步不写普通存档、不承诺进程崩溃后的续行 |
| 收入 | 同资源不同来源、同窗口、不同用途；事实只入账一次；规则未定的断言不得自造 |
| 替换 | 写失败、reload 失败、rollback 失败；§7.1 的持锁捕获与发布并发/崩溃矩阵；保留可恢复材料且普通写入保持禁止 |
| 执行器 | 每项支持能力正例与拒绝边界，大数/有限标量/未知分支；只在声明共同子集做确定性对照 |
| 工具交付 | F8/F9、独立分析器、配置/编辑、玩家包各自真实入口的最小样例；动态依赖、结果身份和错误说明 |
| 扩展维护 | 用一个现有跨域场景解释新增贡献应改哪些边界；不新增玩法来证明架构；无需修改 UI 事件分派才能唤醒业务 |
