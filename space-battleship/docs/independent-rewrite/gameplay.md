# 玩法与规则

本文件规定新实现应直接提供的功能。参数沿用基线有效 Excel；列出的默认数字是迁表初值，不是重新平衡。没有注明改变的玩法保留。内部事件排序、属性更新方式按结构文档执行；S1–S4 可选改变及不采用时的规则见 README；正文采用建议的地方按对应编号生效。

## 1. 主线、驻守与战斗行程

`Journey` 使用 `mode = campaign | guard | manual_challenge`，`phase = travel | fight | clear_wait | retreat | idle`。主菜单、装备页和升级页属于 UI，不再混入战斗状态枚举。

- 新档根据起始舰型、起始装备和解锁表建立模块，进入第一关。所有关卡、遭遇顺序、位置、编队、敌人、入口和终点倍率来自内容包。
- 旅行按距离推进，到表定位置生成遭遇；UI 的星空拖尾只是显示。旅行上限时间、离开/返回停顿、清关等待、撤退距离与时长迁入 `journey_rules.xlsx`，保留当前初值（清关等待 3 秒、旅行上限 3 秒、返回停顿 1.6 秒、撤退 backRange=200、默认时长 1.2 秒）。停顿期间不重复付加速费。
- 一关中点倍率按 `lerp(entry_ratio, final_ratio, i/(count-1))`，没有 entry 时取上一关终点；单遭遇直接终点。敌方生命/攻击按表的基础值乘对应倍率并 ceil。收益倍率独立，不从敌方实际扣血倒算。
- 非末遭遇结束后继续旅行；最后一个遭遇完成才清关，敌人标签 boss/ultimate 不代替末点判定。首次清关解锁下一关并记录永久事实；反复打同一关不给“首次清关”奖励。处于最后配置关时保持可驻守/重打，不访问不存在关卡。
- 驻守保存关卡、遭遇点、距离与死亡策略；可以到目标点后重复战斗。死亡策略保持退出驻守、原点继续、退到新位置驻守三种行为。自动推进不要求玩家点一次“升级页继续”。
- 死亡/主动撤退按距离跨前关回退，重新定位遭遇点；若落在上一关末点之后，重新安排末遭遇。恢复防御后再出发。手动异空间失败则返回主线，不套普通后退距离。
- 战场清除有两种边界：普通相邻遭遇允许仍有效的已出生载体按规则存续；关卡结束/撤退/手动模式切换清除会误伤新场景的战斗载体。导弹失去目标后在同遭遇有效目标内重选，无目标按现有游离寿命离场。视觉尾迹不继续伤害。
- 解锁可用性直接从条件计算；读过教程与拥有能力是两个事实。S2 未批准时清关等待可被教程阻止，其他工作仍正常前进。

保存普通 `JourneyCheckpoint={mode,stage,encounter,distance,phase,guard_target,death_policy}`，不存衍生布尔。手动挑战另外存一个 `ReturnPoint`。正常旅行和驻守返回位置不依赖显示节点。

## 2. 钱包、拾取、收益和时间粒子

所有扣费、改造、研究、奖励都写同一 Wallet。资源 1 是铁、2 是铀；旧字段 `startingTitanium` 只是一项历史名字，新表改成资源 ID，不在产品中恢复钛资源。强化碎片与时间粒子分开；四种材料和究极核心也使用同一有限精度 Amount，不保留精确整数账本。

战斗奖励流程：native 的单次死亡产出掉落规格→Economy 创建 `Pickup(id,resource,amount,production_base,source,born,position)`→手动悬停拾取或到期自动拾取→一次性入账并移除。拾取 ID 不复用。UI 只发送拾取 ID；轨迹/命中区域取只读显示映射，不由画面消失推断领取。

- 常规铁/铀手拾全额；自动拾取乘 `1-autoCollectReduce`，再按配置取整。默认 delay=5 秒、折扣=0.5 保留。漂落生产块到玩家高度触发自动拾取，手动仍可提前拾取。
- 掉落铁的冶炼倍率在奖励基础量上计算；星球精炼、AI 收入倍率、挂设等按其实际来源阶段应用。不能在 native 编译和拾取时重复乘同一倍率。
- 强化碎片来自当前有效掉落和凝聚渠道，不恢复实体宝石品质、孔位、合成。普通碎片拾取的自动时限 2 秒迁表；不无意套铁/铀自动折扣。旧炉核心若无当前创建来源，不创建新功能来消费残留 `hightech` 标记。
- 周期资源生成沿用 `autoGenRes` 的四项意义：间隔、资源、数量、下落速度；转成有类型的表行。基线 `30,2,5,40` 不是可任意解析的脚本文本。
- 普通切换场景按基线自动规则结算待拾取物，之后才销毁画面。仅 S1 获批时将保存边界的未领取记录写入 Profile.pending_pickups，读档继续剩余期限；否则不保存临时拾取物。重铸沿用清除旧掉落而不额外入账的规则，见第 9 节。

收入只记录一份收据，含 resource、credited_amount、production_base、source、真实时间和游戏时间。两个时钟用途不同，不能因为“去重状态”合并成一个：

| 消费者 | 窗口/口径 |
|---|---|
| 资源条最近收入 | 真实 60 秒的已入账总额 |
| 工厂自动投入 | 游戏 60 秒的有效已入账额 / 60 |
| 联合一体化历史峰值 | 真实 60 秒、原生拾取 source=drop 的已入账额 / 60 |
| 银河被动派生收入 | 原生来源的 production_base，排除自身派生收益，按其表定周期计算 |

保留这几种口径，删除的是同一收据在多个 owner 中的拷贝。滚动收据只保留仍被任何窗口使用的部分；峰值单独持久保存。派生收益标明 source，不进入原生生产基数，避免自我放大。

时间粒子离线获取 `min(floor(elapsed*rate), capacity-current)`，elapsed 截到 offlineMax，时间倒退取零。倍率/粒子每真实秒消耗由表给出；余额不足时按可支付时长分段回到默认速率。自动保存间隔是用户设置；不是推进游戏工作的额外时钟。

## 3. 装备、反应炉和共享强化

### 装备与属性

保留五类舰体及配置的活动槽/装备上限，六类装备（装甲、护盾、激光、导弹、炮、持续激光）、独立模块等级、单次/10次/MAX/全部升级、换装、换舰。模块等级跟稳定模块而不是 UI 卡片走；非活动模块保留成长，装备计数上限按舰型核对。

属性顺序明确：付费等级 + 永久虚拟等级→普通成长→**仅付费等级**的装备进化倍率→科技乘积（ceil）→反应炉（ceil）→熟练/适应计数（ceil）→对应分支→星球工坊→船员→银河→无人机对应来源。UI 预览和 native 参数编译用同一计算，不再另设 player_weapon_database 调整玩家数值。普通成长和累计费用改用统一连续大数公式，不逐级复刻历史舍入，详见结构文档第7节。

装备进化保留每 20 个付费等级的初值：首次×1.6、后续×1.5；每层简并物质费用初值 10。虚拟等级不能白拿进化/材料豁免。这些项在指定基线的属性、费用、显示正式调用链仍有效，核实依据见内容文档，不因 JSON 存在便自动保留其全部历史字段；有效初值迁 `equipment_growth.xlsx`。切换冷却保留表定 10 秒，期间禁止再次换装而不是禁止新装备攻击；新武器按自己的 CD 起步。暂停/关卡结束处理见结构文档；清遭遇时沿用当前清除切换冷却的规则。

### 反应炉

保留等级、铀升级、手动数值分配、一键均分及自动升级。四个模块为武器、防御、冶炼、凝聚，各自按解锁条件显示。

`capacity=floor(base*growth^(L-1)*crew*galaxy*drone)`；`next_cost=upgrade_base*upgrade_growth^(L-1)`；`boost=1+(allocated+capacity*permanent_free_ratio)^exponent/percent_scale`。L 从 1 起；下一次升级费用沿用当前 L 的指数定义，统一公式中的 p 取该 next_cost，不误写成装备目标级的指数。费用单买/批购共用连续曲线，不逐级 ceil；表中 100、1.5、10、1.35、0.8、100 等初值不改。免费比例不消耗手动分配额度。总手动分配不得超过容量；容量下降时按固定模块次序裁剪超额，UI 同时显示实际值。自动船员升级成功后按解锁模块均分。

凝聚仅提升规定的碎片来源，冶炼仅提升规定的铁来源；不把 reactor multiplier 整体乘到所有 Wallet 入账。Amount 覆盖容量与分配，避免大数容量导致按钮失效。

### 共享强化与分支

只保存全局购买等级、武器/防御各自三效果排序、各节点 A/B 选择和 native 的全局历史计数。无宝石实例和装备插槽。顺位门槛 1/10/20、分支基础门槛 10/20/30 与位置偏移 0/10/20分别读取 `enhance_config`，不能相加两遍。升级费用 `cost_base*cost_growth^(target-1)`，批购用几何累计公式近似求和，MAX 用其反函数。

| 效果 | 基础规则 | A / B 分支全部保留；native 新增状态 |
|---|---|---|
| 熟练 proficiency | `1+round(growth*effective_level*log_base(max(attacks,1)),scale)`，按规范主攻击增加计数 | A 各节点伤害加成相加；B1 同目标每整段蓄力独立累乘，B2 攻击间隔倍率，B3 穿透后匹配抗性比例。每武器：主目标 handle、保持时长 |
| 连发 repeat | 主攻击按概率触发配置延迟的一次额外攻击，额外伤害随有效等级成长 | A 加概率；B1 附加连锁目标，B2 有限额外连发次数，B3 主攻击概率增加第二目标。每根攻击：剩余额外次数/连锁预算，禁止无界自递归 |
| 暴击 critical | 基础暴率、基础暴伤+装备暴伤+等级成长；在攻击快照中确定 | A 加概率；B1 暴击后有限后续规范攻击增伤，B2 有时限/上限的连势，B3 保底暴击。每武器：余势次数、连势层/到期；派生伤害不另算主攻击 |
| 适应 adaptation | 与熟练相同对数形式，输入全局受击尝试数 | A 加模块上限；B1 同来源后续攻击叠层减伤，B2 周期短时护罩，B3 强化已有抗性。状态按来源 handle 与防御模块存 |
| 记忆 memory | 每 memory_interval 回复自身最大值×heal_fraction×等级；多余恢复进入本模块 buffer，容量自身最大值×buffer_fraction×等级 | A 提升回复与上限；B1 有效全局恢复跳概率共享减伤，B2 记忆保护获得来袭类型抗性/异类清除与禁获时段，B3 按启用护盾/装甲件数改变充能/容量。状态：buffer、抗性类型/到期、共享减伤截止时间 |
| 延迟 deferred | 比例 `floor((1-1/(1+k*level))*percent_scale)/percent_scale`；受保护后的分期伤害在 duration/interval 跳扣除，当期后判定清除剩余债务 | A 清除概率按全局节点只加一次；B1 清除后共享减伤，B2 未强制清除概率转减伤，B3 必然消散并按缺口增加伤害。状态：固定长度到期桶与共享减伤到期 |

分支系数/周期全部来自现有 enhance_config 对应键。短时状态在 native，换页不会重置；换装按稳定来源删除失效武器未来触发；已经形成的伤害债务不因换装备免除。分支逻辑是六组直接函数，不为每节点生成脚本对象。

## 4. 命中、武器与传说机制

### 共同攻击路径

`选择目标 → 主攻击上下文/计数 → 计算攻击快照 → 飞行/持续/瞬时射线各自判定命中 → 来源效果 → 防御扣除 → 命中/死亡效果 → 领域奖励与纯显示反馈`。有飞行时间的弹体不能提前扣血；玩家炮是瞬时命中，不人为增加飞行等待。UI 打出的伤害数字不能触发这一链。

攻击记录包含 root_id、source_module、weapon_kind、出生参数、主/派生标志及剩余连锁/连发额度。导弹一批多颗共享 root；一次光束锁定是一项攻击，多次 hit 是不同命中。连发和反击是指定的派生攻击；只有明确声明的效果可再产生下一层，不能依靠任意递归深度上限来决定正常玩法。

保持物理、能量、中性类型与目标匹配抗性，先护盾再装甲。护盾消费后按实际抵消的原伤计算剩余量，再应用装甲抗性，不把盾扣除后的量重复减伤。保留基线最小伤害/ceil 规则，迁到明确 damage_rules 配置。模块防御的护罩、记忆层、真实层、延迟债务按顺序处理；不能把所有防御合并成一条总血条而丢掉各模块的记忆/抗性。受击尝试计数包括被吸收的来袭；显示伤害统计只计实际损失，避免吸收也记 DPS。

多防御模块结算采用明确数值步骤：先消费周期中性护罩，再消费各模块记忆保护，再到真实护盾/装甲；真实护盾层按各模块当前可用量占比分配原伤，各自应用类型抗性与延迟比例。一个模块达到可支付容量时，将剩余原伤在其余护盾间再分配，直到护盾无可用量，才触及装甲。只在整层完成后取规定舍入，不能每轮分配都 ceil。native 不再同时维护可写总 HP 与损失表：每模块 loss 为权威，总条是汇总。

分期伤害已经在受击时减伤；将金额按 `ceil(duration/interval)` 分入到期桶，首跳不早于受击后一 interval，末份吃掉分割余量。到期只经过当前护罩/记忆/盾甲以 1:1 扣除，不重复类型减伤、延迟或增加受击历史；实际扣除后才做全局清队概率。零伤/吸收反馈与死亡奖励分开。连锁/奇异物质/黑洞等派生事件使用共同命中，但禁止再次产生同类递归根。

恢复、命中、持续束跳伤和延迟伤害共用 native 时间。敌盾受击重置延迟，未受击区间按配置速率恢复至上限；持续束每伤害跳也是受击。反应式减伤保留 3 层、每层 0.2、2.2 秒重置、0.16 秒齐射窗口初值，迁表，不每颗同批导弹错误叠层。

| 武器 | 必须保留的执行 |
|---|---|
| laser | 紧凑直线载体、实际交点/中心到达后命中；出生固定射线；保持 native 紧凑表示与 GPU 接触反馈 |
| missile | 一批多颗、逐颗弹出间隔、点火/寻敌/巡航阶段、转向/刹车、失目标重选和游离；已发与排队未发分开；每批主攻击计一次 |
| cannon | 玩家炮保留发射当刻的瞬时射线命中与同刻扣血，希格斯同刻完成射线范围命中；轨道光效寿命只是表现，不加伤害延迟。敌方炮仍按其配置/现有实际载体路径，不把玩家规则无条件套给敌方 |
| longLaser | 锁定、蓄力、持续跳伤、增幅、目标失效中断/重锁、链接目标退出；光束有效命中才扣血，视觉余辉不扣 |

| drone_master | 存活已装备无人机最高品质系数/究极品质系数×maximum_reduction；同效果取选定来源 | 内核来源贡献；需补齐。新生成范围 0.5..0.6，不恢复旧档范围 0.8..0.9 |
| black_hole | period 内 absorption_duration 吸收双方攻击；只累计我方被吸收原伤，窗口结束乘参数对存活敌人结算一次派生伤害 | 下次开启/结束时刻、累计 Amount；需补齐 |
| drone_rebuild | 致死前按低品质再稳定 ID 选择可用无人机暂时失效；叠伤害/防御奖励、恢复防御并清延迟债务，达到上限后正常死亡；遭遇结束恢复失效机 | disabled IDs、层数、加成；需补齐 |

同类传说按首主参数强者优先、并列稳定 ID；词缀同类加总，之后按类别组合乘数；不能把所有同类传说无条件叠加。装备上限和有效来源筛选在配置变更时做；战斗内牺牲仅更新来源块。新增未覆盖效果必须实现 C++，不是把它加入编译器拒绝名单。

现有强化白名单外的 A/B 分支、上述五个未接受的传说、手动异空间、大数全部属于正式切换前的必要工作，不是“后续扩展”。

## 5. 科技与自动化

保留现行 8 个节点：AI 奇点、武器精度、装备强化、资源精炼、强化碎片凝聚、装备精制、铀提炼、联合一体化。节点名和效果表保留；科学家招募、科学家成本、旧科技点不实现。旧 hightech 中作为解锁门槛的身份一次迁成新节点的 unlock_id，删除运行时 legacy_unlock 翻译。

研究工作量为 `base_seconds*growth^current_level`；AI 数量 `1+singularity_level`；基础效率 `(AI+9)/10 * (1+distributed_algorithm_bonus) * crew_tech_effect`。铁/铀每游戏秒投入量可分别设置，正量加速因子 `1+log10(input)/4`，无投入为 1。实际支付的区间才享受其因子；资源耗尽后的剩余时间按剩余有效输入继续，不能免费完成。

工厂船员开启自动投入和续研：每 60 游戏秒，以各资源上一游戏分钟均值乘用户比例向下取整、至少 1；比例下限 0.001 迁表。完成后选可研究、剩余工作耗时最短的节点，并列按表序，未完成节点工作量保留。核心节点要求 `10*target_level+1` 的前置，最终节点要求表定等级；编译成 `linear_requirement(a,b)` 或固定最低等级，不执行字符串表达式。

常规倍率为各节点 `factor^level` 相乘。联合一体化在等级>0时为 `level * Π max(1,1+log10(peak_resource)/5)`，仅对有正历史峰值的铁、铀、碎片项计算。9、10、4、5、工厂周期与门槛系数等迁 `research_rules.xlsx`。Amount 覆盖极高等级需求，不用 INF 意味着研究永远坏掉。

船员自动装备升级、强化购买、反应炉升级和续研调用与玩家相同的具体方法。船员没有另一套费用和战斗更新途径。通知合并显示，但实际每次扣费不合并成估计数。

## 6. 船员、星球与征服

保留船员配置、解锁、经验等级、系统岗位、星球探索/建筑助手、银河和异空间派遣。每人只占一个岗位，空闲就是 Assignment 为空。派遣新任务时先核对目标容量，成功后一次更改；UI 根据岗位表显示所在位置。没有“船员说空闲但星球还持有他”的第二状态。

船员当前等级 L 从 0 开始。基线由 L 升到 L+1 的需求为 `max(1,round(base_exp*exp_multiplier^L))`，初值依次为 100、120、144；新实现下一级需求统一为 `max(1,base_exp*exp_multiplier^L)`，以该曲线的有限精度累计值反解连续升级，不逐级循环补齐舍入。界面所示“Lv0”不是付费装备的“Lv1”。系统效果按 crew_config 和岗位表累计，不读取已废弃的 crew.baseLevel/maxLevel/expGroup 等成长字段。

星球探索 `duration=max(minTime,baseTime²/(baseTime+degree))`。一次完成 degree+1，并发放 `round(baseExp*当前/历史最高关对应planetExpRatio*银河经验倍率)`；已征服共享经验效果按表向全员发放，否则给探索船员。取消探索释放岗位并清本次 elapsed，不返一部分经验。

建筑按 planet_rule、order、unlock_explore、build_explore、extra_crew 驱动：达到门槛才开始计建设次数；跨过门槛的那次探索不提前算建设。满足额外助手数量的 building 每次探索+1工作，达到要求进入 ready，玩家启用后才生效。空间站启用自动探索；精炼厂/工坊倍率为 `(1+config1*degree)^config2`，多星球相乘；船坞是征服门槛。现有第一星球与后续星球的不同船坞条件保留。

可用/建设中/就绪由工作和启用标记推导；**启用是事实必须保存**，不能把 ready 自动等价于 built。自动探索保存开关，空间站条件未满足时不能开。征服效果（虚拟装备等级、免费能源、强化等级、幸运、下一星球、经验共享）严格按 planet_buff 生效。

## 7. 银河

保留第 60 关等配置解锁、主动开始探索、派遣人数加速、节点布局、普通/特殊建筑分配、建造间隔、施工、并行升级、建筑等级、全部现有美术与运输动画。

节点是业务实体：`node_id,type,status,explore_work,construction_remaining,upgrade_work,level`；布局由 seed 和表节点数生成一次，只保存 seed 与节点选择结果。探索功率=`base+per_crew*count`，节点探索工作需求=`explore_work_total/node_count`；建成前置节点后解锁后继；建设按 build_interval 投放、construction_time 完工。升级功率与并发数从表读，按稳定节点顺序分配工作，level2..5 费用沿用表值。特殊建筑按 special_cycle 的配置次序出现。等级上限不是视图决定。

建筑完成/升级时更新效果总额；装备值、能源、船员经验、铁/铀派生收入、碎片来源各接入对应函数。隐藏页不改变工作速率。地图网格、frontier、运输船、光脉冲是可重建表现，不再存一份能影响探索完成时间的格子权威。保留 chunk 更新和隐藏视觉停更等有效性能参数。

## 8. 异空间、无人机与改造

### 挑战和挂机

保留 alpha/beta/gamma/delta 四路线，分别对应激光/导弹/炮/持续束和四材料。当前路线层数、最低层、主线门槛、表定敌人编队和独立奖励源继续有效。手动请求在逻辑边界进入，最多一个待进入请求；进入前存主线 ReturnPoint，清理前台场景载体，再用同一个 native 建正式挑战。

成功记录该路线/层的最短 x1 游戏秒，并生成一次奖励；失败不生成。完成返回原主线模式/检查点。战绩不能用“模拟战 DPS”替代；查看其他 UI 页不会影响挑战。

已经有该层成绩后可单次挂机；派遣自动挂机按 `best_seconds*k/(k+crew_level)` 计算时间，无船员时 best_seconds。手动前台与一个后台挂机任务可并行；不会复制前台战斗。Job 保存 route、level、mode、work、duration、开始时幸运/来源快照、reward_seed、状态。岗位变化对下一次任务生效，当前任务的承诺参数不反复重算。

保留基础供应能源累积与后段供应渐增的有效参数：第 60 关等门槛后按 ramp_seconds 从基础速率线性增长，材料奖励也按对应倍率。**基线 prepare_start 的 ticket=0，挂机/手动不扣旧票价**；不因为配置里还留 ticket/energy 字段就恢复付票玩法。能源若仅供当前显示就继续显示其余额，不赋予不存在的门禁。

任务完成时先生成并固定奖励，之后尝试入库/入账；有空间自动领取，满仓保留这个唯一 pending reward。停止开始下一单，也不为满仓期间积累可回放完成债务；清空容量后从当下继续。手动和挂机各最多一个待领取结果，存其任务 ID；领奖成功同步清结果。无需通用去重命令账本，但不能删除满仓时的持久待领事实。

### 奖励与库存

品质权重、词缀和挂设初始概率、各阶范围、幸运重抽、奖励材料、核心概率完全来自 hyperspace Excel。幸运只改善对应阶级抽取，不把普通奖励重复生成。究极核心结果独占，不同时送无人机。奖励 RNG 与战斗 RNG 分开；UI 预览不推进正式 RNG。

保留普通仓、溢出仓、收藏、保护装备、预设及挂设装配、封存机领取、筛选保留/清除与筛选导入导出。容量按表和征服记录计算，溢出机能展示/处理。装备、收藏、封存等保护规则在拆解命令检查一次。更小舰型容纳不下时沿用基线 prepare_hull_fit：按顺序保留前 capacity 个装备 ID，取消尾部机装备状态；机本体仍在原库存，不移动仓位、不重新挤占容量；预设不自动解除封存/绕过数量和传说/究极限制。

词缀放大 `value*(1+amplification_rate)^(drone_level-start_level)`（仅 amplified 项）。挂设保存系统等级/经验，装配的每份同类加成相加。传说同类选择规则和战斗作用见第4节。无人机普通武器等级取玩家基础关联及品质/究极奖励，沿用 `weapon_level_bonuses`/`ultimate_weapon_bonus`；不能为每架另造不可见升级货币。

### 改造直接命令

所有操作先用该机 RNG 副本算结果和同一 Amount 公式的总价，确认可支付后同时写无人机、钱包和 RNG；失败不消耗随机。预览返回费用与结果描述，正式提交重新核对当前机与预算；不要求保存历史命令重试账本。

| 操作 | 具体语义 |
|---|---|
| 添词缀、添挂设槽 | 不超过品质对应上限；抽适用词缀/增加槽；按表扣费 |
| 替换词缀 | 只选择未锁词缀；预兆优先最低阶，同阶随机；指定词缀按当前 RNG 试算至命中，总价乘实际次数；有明确 forecast 上限 |
| 锁定词缀 | 从全部未锁词缀随机，不受预兆偏好影响；费用随已锁数按 lock_cost_multiplier 增长 |
| 升阶 | 抽阶比当前好才成功；成功只升一阶，重新抽该阶值；失败仍按表付一次费 |
| 重洗数值 | 未锁词缀与传说随机参数重抽；保底最高值按离散结果数量乘 guarantee_multiplier 计算确定费用 |
| 预兆开关 | 只影响本机替换目标选择，不影响他机、锁定或升阶 |
| 传说化 | 按武器适用效果抽取；已收集效果可指定并预估次数；不开放未接入的重复传说操作 |
| 现代化 | 取已完成且主线允许的本路线最高记录；按表公式、词缀阶权重、传说倍数和材料单位算费用，升级机等级/星球归属 |
| 究极化/还原 | 花核心按表变究极，额外词缀只首次生成并保留，不能通过反复还原刷属性；究极期间只允许有效白名单操作 |
| 拆解/材料交换 | 保护机不得拆；材料和挂设经验同一命令到账；交换读取当前配置单位及规则，不把核心当普通材料乘十 |

这些是有效功能，不为简化删掉。`drone_rewards/forge/filter` 只用于识别有效玩法，业务算法和测试重新实现；不默认复用其代码或以“纯函数”为由搬入旧复杂度。明确保留的例外是纯表现资源/路径与已有高效 native/GPU 实现。
