# 太空战舰：独立重写设计（待审阅）

基线：`rlmclmc2-boop/space_idle@b4729b9a9803458b5ac19a4945c2fe0d5f76e51f`。本稿只以该提交的程序、工作簿、资源和入口约束识别产品，不采用历史重构方案。未读取 `design/complete-rewrite-spec` 或 `docs/rewrite-design`（包括项目内同名位置）。本次只有设计文档，没有实现、游戏运行或测试运行。

## 1. 设计结论

重写成一个 Godot 应用、一份长期进度、一个常驻 native 战斗实例和一套只读表现层。游戏功能直接写在少数领域模块里；所有玩家命令在主线程的明确边界顺序执行。Excel 编译成只读内容包。删除旧/新结算切换、整份 Game 的候选复制、分阶段中断续跑、表现反查游戏、编辑器对正式游戏的依赖。

这不是重新把所有东西塞进 `game.gd`。长期进度按玩法分组；战斗中的生命、飞行物、触发器、时钟只在 native 中存在。每个领域直接处理自己的命令和时间，跨领域规则由 `Session` 明确调用，没有通用事件总线、插件式效果解释器、事务框架或 ECS 改造。

**native/GPU 是新架构的基础，不是可选优化。** 现有 native 尚不支持全部有效玩法。重写须补齐这些规则及大数，再删除 GDScript 结算；不以“支持白名单外回退旧算法”收尾。不以发射即扣血、DPS 估算替代命中结算。不未经效率证据更换现有紧凑弹体、批量显示、保留式 GPU 特效路径。

## 3. 需要用户决定的两项玩法简化

| 编号 | 建议及用户可见变化 | 能删除什么 | 不接受时的完整处理 |
|---|---|---|---|
| S1 | 普通战斗在退出/读档后从当前遭遇开头重新打；保留已经到账收入、成长及拾取物，敌人和我方临时战斗状态重建。异空间手动挑战中断视为失败，回原主线位置。不保存弹体、部分伤害和短时 buff。基线已经不保存完整战斗，本稿把规则明确成统一产品规则。 | 战斗快照格式、弹体/效果恢复、不同场景专用续跑；不删除长期进度 | 保存 native 的一个版本化 `BattleCheckpoint`，含 actor/weapon/flight/effect/RNG/时钟；由 native 自己读写，不恢复旧 Game 和移交协议。异空间仍须保存原返回位置。多一个二进制字段和约 1 个存档用例，不能偷偷采用半恢复。 |
| S2 | 解锁教程显示通知并进入可重读列表，不再强制卡住自动通关；手动暂停仍有效。用户可自行打开教程。 | `pending_unlocks` 作为通关条件、弹窗关闭驱动行程 | 保留 `Journey.waiting_for_notice` 一个显式状态，仅阻止下一关开始，不冻结经济或向 native 注入 UI 状态。 |

推荐 S1、S2。没有提出移除强化分支、无人机传说、手动拾取、换装冷却、驻守或银河等玩法来降低实现难度。若用户不同意这两项，主架构照常成立。

## 4. 基线中确认的事实

- 正式入口是 `main.tscn → scripts/battlefield.gd → scripts/main.gd`；实际游戏还派生了 `presented_battle_game.gd`，不能只读 `main.gd` 中返回 false 的基础显示钩子而断言 native 未启用。
- `game.gd` 4,132 行、`main.gd` 3,792 行（本基线）；它们同时处理进度、战斗、保存、UI 协调和兼容。行数只解释阅读范围，不作为重写成功指标。
- `native_execution_compiler.gd` 有两种 scope、数量门槛、强化分支和传说白名单，并拒绝手动异空间；`native_execution_session.gd` 会将数值越界或配置变化移交旧执行器。
- `step_progress.gd` 与 `progress_runtime.gd` 保存逐阶段/逐项目游标，用于处理跨领域变更和 native 移交中断。新实现消除这些正常流程中的失败来源，不把游标框架换名重做。
- `config_excel` 顶层有 26 个工作簿；另有根总表、published 副本与多个 JSON。`equipment_evolution.json`、导入器 DEFAULTS、AI 常量等还需迁入权威表。具体迁移见内容文档。
- 共享强化已经替代旧宝石槽与合成成长；AI 科技树已经替代科学家研究。旧 ID、旧字段留存在代码/表里不表示应恢复旧玩法。

## 5. 重写完成的具体形态

玩家从新档可以完成主线、驻守、升级换装、共享强化/分支、科技、生产和能源分配；派遣船员探索星球、建造、征服重铸；发展银河；手动挑战异空间、挂机、获取和改造无人机。各功能用同一配置和数值规则接入 native 战斗，现有美术、声音、特效与 GPU 路径继续使用。

增加一条敌人/装备/关卡/已支持效果的配置只改 Excel；增加一种真正新机制时改该领域的直接代码和一个有意义的用例，不建立通用规则语言。发布物自带 native 与编译内容，正常启动不调用 Python/Excel/编辑器。开发编译和测试缺少其声明的源 Excel 时必须失败。

实现须在本设计审阅后另开分支，由 **sol medium** 执行；本分支不合 main，不包含“先做部分实现便于评审”。
