# 太空战舰：独立重写设计（修订稿，待审阅）

基线：`rlmclmc2-boop/space_idle@b4729b9a9803458b5ac19a4945c2fe0d5f76e51f`。本稿依据该提交的正式代码、工作簿和本任务给出的用户指令重新设计；未读取 `design/complete-rewrite-spec` 或 `docs/rewrite-design`。本次仅文档，不实施、不运行游戏/构建/测试、不合 main。

## 1. 一致的设计边界

一个玩家会话、一份长期进度、一个常驻 native 战斗实例；领域模块直接实现游戏功能，表现只读。Excel 是内容权威，公式与工作簿内计算缓存保留。纯表现及现有 native/GPU 高效路径明确保留，业务与测试重新写；旧代码只帮助识别有效功能，不默认复用无人机、经济或存档业务算法。

所有增长量都用同一种有限精度大数，材料/核心也不另设精确账本。MAX 用累计费用公式和反函数近似计算，数量级合理即可。取消逐级精确求和、前缀缓存、异步长报价及其协调状态。单买和批购采用相同成本曲线，避免另一套“精确单买”继续牵制设计。

战斗仍是命中扣血：飞行弹体等命中，玩家炮/希格斯炮保留发射当刻的瞬时射线命中；不人为给炮增加飞行延迟，也不把其他弹体改成发射扣血。补齐 native 正式玩法和大数后，删除旧结算与 handoff，不靠能力白名单回退。

只删除不能脱离游戏的**编辑器**，不把 F8/F9 关联的模拟、分析、候选生成和批次用途一并删除。保留这些用途，使用新模型和同一 native 重写必要入口；不为旧编辑器投入开发。

## 3. 可见变化及理由

### 已给定边界，按此设计

| 项目 | 实际变化 | 理由/边界 |
|---|---|---|
| 统一近似大数与 MAX | 极大材料/次数允许丢低位；批量费用和最终购买数不逐项精确复刻；普通成长取消历史逐级舍入，改为同一连续曲线 | 用户已明确大数统一算法、无额外精确记账、极端 MAX 数量级合理即可；参数起点/倍率保留 |
| 新档 | 旧档不导入；使用新格式和新路径 | 已明确无需兼容，删除旧成长/字段迁移负担 |
| 内容编辑工作流 | 选 config_excel 为权威工作簿集合，JSON 为产物；删除运行中编辑/发布的游戏依赖型编辑器 | 已明确 Excel 唯一权威、编辑器不投入开发；**保留现有公式与缓存工作流**，不要求改为字面量 |
| 业务与测试重写 | 新公开命令/模型；测试用独立小型 Excel，不使用旧测试布局约束新实现 | 已授权；纯表现和高效 native/GPU 是明确保留例外；少量测试复用须具体选择，不作为默认方案 |

### 本稿建议，须随方案审阅决定

| 编号 | 可见变化与理由 | 不采用时 |
|---|---|---|
| S1 | 将未领取的普通拾取物加入小存档检查点，读档后继续其领取期限，避免保存时未领物丢失；普通战斗仍从当前遭遇重建，不保存弹体 | 沿用基线不保存临时拾取物的行为。仍只存 Journey，不为此开发全战斗快照 |
| S2 | 解锁改为通知+可重读教程，不阻止自动进入下一关，减少 UI 阻塞游戏流程 | 保留一个 `waiting_for_notice` 状态，只阻止下一关，不引入 UI 驱动战斗 |
| S3 | 共享工作采用文档明确的步内顺序，行程转换统一到 1/60 秒步末；科研完成后的可用余时继续使用。并列事件/极短阶段收益可能与旧游标顺序不同 | 保留旧产品层的先后顺序和科研完成截断口径；native 命中仍按实际时刻执行，不保留中断续跑框架 |
| S4 | 开发工具改为“平衡模拟、舰队实验/批次、结果分析”明确入口；解决 F8 与战场动效开关的冲突，动效开关放显示设置；混合窗口仅删除游戏依赖的编辑功能 | 保留原工具快捷入口，动效开关另设无冲突键；不能用冲突为由删除模拟分析用途 |

新界面按功能页面组织、延迟创建控件，但保留原操作能力与反馈；不借刷新方式改变暂停、投入、拾取或解锁规则。上述时间顺序是明确的行为建议，不包装为纯性能优化。

### 上一稿额外行为的撤回与澄清

| 项目 | 本稿最终规则 | 核实/理由 |
|---|---|---|
| 退出自动保存、保存失败拦退出 | **撤回新增行为**，保留手动和定时保存；关闭时不强加写档 | 存档架构重写不等于保存策略授权 |
| 重铸必须写盘成功 | **撤回**；内存完成重铸并 dirty，按既有保存策略落盘 | 正常玩法不受临时磁盘结果阻断 |
| 升级后按剩余比例改 CD | **撤回**；保留已排定的下一发时刻，后续周期用新间隔 | 不给强化/升级额外提前或延后攻击 |
| 换装后等待切换锁才开火 | **撤回**；切换锁只限制再次换装，新武器按自身 CD 起步，原持续束在来源移除时结束 | equipment_state.prepare_refit / game.invalidate_module_attack 的实际行为 |
| 重铸自动收取掉落/待领奖励 | **撤回**；保留已入账余额，清除本轮未领和在途，玩家可在确认前自行领取 | progress_runtime._prepare_reforge / hyperspace.prepare_reforge；不额外赠送清算收益 |
| 换小舰自动“退仓” | 改为准确描述基线行为：只裁短 equipped ID 列表；无人机本体仍在原库存，不移动仓位、不改变容量 | `hyperspace_system.prepare_hull_fit` 已如此；不是新增自动整理规则 |
| 炮增加飞行等待 | **撤回**；玩家炮/希格斯同刻射线命中扣血，纯轨道特效可继续播放 | `presented_battle_game.launch_player_attack` 的正式行为 |
| 船员经验以 L−1 为指数 | **纠正公式**；船员当前 L 从 0 开始，下级需求基数×倍率^L，0→1 初值100 | 装备付费等级从1起，不能混用等级定义 |
| 装备进化的保留 | 基线有正式可达的属性/费用/显示链，只迁仍消费的倍率、材料、色阶；不以 JSON 存在作为有效性证据 | 证据列于内容文档；旧宝石/科学家/高等级行成长不恢复 |
| 默认沿用 drone 业务或旧测试 | **撤回**；依据功能重写算法/测试，不复制旧业务协调结构 | 保留例外限纯表现和高效 native/GPU |

## 4. 这套结构具体减少什么

删除 Game/presented_game 的双逻辑继承和 native/legacy 双执行；删除每个领域 prepare/proposal/version/freeze 的往返和整 Game 候选复制；删除阶段/项目游标恢复、表现层反查战斗、多个岗位占用事实、表/JSON/缓存多权威；删除精确材料账本和长 MAX 计算链。每项对应的旧文件、状态和新责任在结构文档列明。

保留完整正常玩法及有效配置：主线/驻守、六装备、共享强化全部分支、8科技、反应炉、船员/星球/银河、四异空间路线、12传说和无人机管理/改造。native 尚未接入的规则必须补齐，不能在最终交付中列为“以后扩展”。
