# 四个方向：同模板、同任务、不同组织

阶段1粗参考，均未选定或获视觉通过。沿用同一字体/资源与色彩层级，刻意不靠换色制造差别。14是唯一领域契约；本页只比较前端组织，不改正式规范。窗口1440×960是比较样本，不是批准的支持规格。

## A 全景战场＋侧浮坞

**设计目标/主场景：** 以持续航行为默认观看状态，需要成长时叫出局部工作点。空闲第一主体是中央交火，舰装打开后战斗位于左前方、工作浮坞在右近侧；模块收起后恢复全景，不留历史空白右栏。

**组织与信息：** 一组底部导航，紧凑飞行/资源仪器与对象工作点分开；没有额外模块横幅。对象名“巡洋舰整备”提供语境。盾甲在战场所属HUD，场景型科研/星球可用更宽浮坞，不冻结所有模块宽度。

**连续路径：** 槽位、+1与候选一直留在浮坞；成功只更新当前/下一报价，不结束工作台。打开/收起不改变暂停与合法选择。原型直接可试T1–T4。

**视觉意图与代价：** 尽量保留星空/交火为主场；浮坞的厚度与落点只是粗意图，不是最终舱内场景。打开会移动战场的屏幕位置，可能干扰跟踪；大型场景浮坞会遮掉更多环境，必须在后续比较其观看代价。不能因“全宽背景”就宣布有效交火区变大。

## B 舰桥下沿工作台

**设计目标/主场景：** 将“看上方、操作下沿”形成稳定分工。空闲仍看战场；工作时上方看交火，下方连续整备。导航是一根左侧短轨，不和工作台标题重复叠占上缘。

**组织与信息：** 打开后底部横向工作台把槽位、购级工作点、候选横向展开；反应炉把安装空间/当前分配/意图入口横排。主操作不再挤在窄竖条里，科研/星球暂只作场景容量粗参照。

**连续路径：** 共用8动作不需重开或重选操作。横向台面支持连续选择，但不同槽位与候选之间的鼠标往返较长，粗记录约2890 CSS像素。这个数字是中心点几何记录，不是用户用时/可用性研究。

**视觉意图与代价：** 低位控制台可在后续与舰桥近景结构联系，当前不是最终设备美术。模块打开时战场示意域从约472×792缩到292×490；战斗可见但辨识可能明显下降。底部台面深度也可能不足以容纳世界场景，不应硬塞所有模块。

## C 舱室模式＋战况仪

**设计目标/主场景：** 一次看一个主要空间。空闲全景战场；打开舱室后由机舱/整备空间主导，当前战况以固定仪器可知；看完整交火需要一次“看战场/收起”。

**组织与信息：** 同一左导航切换场所；工作场给舰体定位或设备安装空间与近侧操作点。只有战场隐藏时显示上缘盾甲战况仪，避免同数值跨区重复；关/点/波与暂停常驻。场景型模块可用整块观看区，不被固定右栏限制。

**连续路径：** 8动作留在舱室内，成功后继续操作；查看完整战场有额外一次切换，重开仍保留槽位与候选。这里是显示模式切换，不建议新增自动暂停规则。

**视觉意图与代价：** 最有机会把设备/环境做成完整工作场所，当前仍是粗SVG/现有图参考。代价是操作时看不到交火，只能读状态；若玩家希望持续看弹幕，这个方向可能失败。必须由用户审阅取舍，不能用状态数字替代其观看偏好。

## D 常驻双焦工作场

**设计目标/主场景：** 高频成长和战斗各自保留专属区域，避免以覆盖窗口组织工作；这不是开合时战场位置不动的保证。左侧舰桥/工作点，右侧交火；关闭具体模块后左侧仍是本舰概览。

**组织与信息：** 导航靠最左，工作点紧随其后，交火在右；分界可拖动/键盘调整，按模块用途分配空间。不是将旧右栏改宽：关闭后的空间生命周期、左右注意力归属和分界控制均不同，但仍保留并列结构的固有成本。

**连续路径：** 同一槽位工作点与战场同时存在，8动作无需重开工作台。但默认分界由空闲42%变为打开56%，在1440窗口战场中心实测向右移动100.8px，收起则移回，不能再称“位置保留”。双焦仍可能造成长期注意力竞争；原型概览同时出现舰体预览和战斗舰影，重复主体是否分散注意力是本方向的明确风险。

**视觉意图与代价：** 可形成稳定的调度桥，而非覆盖窗口；但即使空闲也不给战场整屏，可能重现“操作空间闲着、战场被挤”的问题。可调分界不是通过保证，拖动成本与各模块最低可读空间尚未定。

## 各模块粗构图的兼容性假设

| 模块 | 应保留的主体/工作点 | 对四方向的空间要求与未定问题 |
|---|---|---|
| 战斗 | 交火、环境、紧凑即时HUD | A/B/D连续画面与C模式取舍；G9全装配净空仍未证明 |
| 舰装 | 稳定槽位与购级/候选同处 | A浮坞、B低位台、C房间、D常驻台；完整防御槽/休眠槽后续深化 |
| 反应炉 | 有安装深度的机舱与共享配电工作点 | 当前SVG仅位置占位；阶段2要使意图操作与可信场景同时成立，不按设备等大排图 |
| 科研 | 当前设备/平台/探针与相邻工作点 | A可变宽浮坞、B需借出更深空间、C整舱、D调分界；不强迫终端/候选同时常驻 |
| 星球/星系 | 球体轨道或城市地图 | 需要更大观看面，A宽浮坞/B可能改为场景展开/C整场/D可变区；未接现原生渲染器 |
| 强化 | 顺位与分支路径 | 紧凑操作面可用，但分支审阅不能挤掉顺位；无旧宝石设备墙 |
| 船员 | 人物及实际任务 | 名册/人/派遣工作点，保留身份和实际占用；不能变成设备图标墙 |
| 超空间 | 四路线和无人机对象/仓储事务 | 场景与密集对象需求不同，应允许局部子区变化；不四页强套相同面板 |
| 档案/设置/危险事务 | 阅读对象与有效预览摘要 | 阅读面可临时扩大，但确认/取消和战况可知；不得用普通吐司承载危险预览 |

本表是共同框架兼容性假设，不是后续模块细稿完成或阶段3/4通过；本轮不把所有模块同时精做。
