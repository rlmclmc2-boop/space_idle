| 需求 | 主线已有事实 | 候选/待核对，如何处理 |
|---|---|---|
| 战斗状态与画面 | hud_values/statistics/progress_facts/presentation_clock、set_pause、拾取入口 | 显示变换由前端承担，点击逆变换到逻辑战场；真实炮口/碰撞不改。C模式仅候选，不改业务时钟。单一消费damage_receipts不复制 |

| 直接选候选并换装 | panel_slots/panel_equipment、equip_slot与原拒绝/冷却 | equipment_comparison/presentation_slots属未合候选，首要用途/取舍与深入同口径字段由所属模块提供；不能由UI编造DPS/解锁或费用 |
| 分配意图与实际量 | allocate_text/distribute、原Amount与分配规则 | presentation_model/allocation_preview/adjust_allocation属未合候选。意图到合法金额映射、基准与提交形式待原契约线程核对；主线缺口不由JS浮点换算填补。不擅自借用其他设备余额，不增原子全分配命令 |
| 机舱/科研/世界观看 | 各模块身份与现有资源来源 | 结构成立后再做设备/机器/视角/锚点安装元数据；本阶段粗SVG和旧资源引用不是资产批准 |
| 当前与草稿 | UI持有选中、候选、合法草稿、展开 | 后端实际状态独占；隐藏/关闭不清合法草稿，失效ID禁止提交。原型只保留局部样例选择，不证明正式同步正确 |

四方向使用同一有限样例：报价和数值从静态表读取，非规则求值。钱包为排版固定样例，不模拟完整经济账本；不能用截图证明扣费/余额一致性。换装锁固定显示10游戏秒，不模拟流逝；没有保存/导入/原生战斗。T3记录只证明这些控件能按给定路径持续使用，不证明接口/玩法或性能通过。

反应炉意图按钮只改变“意图预览”，不改变实际分配；不存在隐含后台请求。显示条的50/25/10等是固定样例关系，不是新输入粒度或建议的1%步进。没有生成、替换或导入新美术，没有复用已封存world试验作为新的批准依据。

13仍保留“桌面持续可见/并列”的旧句，同时新增“不固定左右分屏、待比较”作用域。本阶段依规划明确比较C的场景模式切换，把差异标出，不默默修改规范或声称C已合规实施。哪个组织应定稿仍需用户与父审；若选择模式方向，后续再统一正式规范。

模板已引用原契约线程提供的14作为事实输入；这里没有能力直接向另一个既有线程发消息，不新开代理/任务。原线程现已提供[76dbe1e2只读报告](https://github.com/rlmclmc2-boop/space_idle/blob/76dbe1e2e0f12341aa4d630cceea6ab8314fdef1/stage1-contract-review.md)：领域边界基本可用，不需要四套后台；不标为双方整体审批或新增实现授权。

后端只读核对补充：脉冲按现行飞行激光显示飞行接触，未落入即时命中默认分支。其余接口缺口维持原有待补状态，本阶段不实现、也不伪造已承接能力；正式报告见上述固定版本。

明确待补：真实卡片的结构化等级/冷却/属性口径不能解析label；allocation_preview不是最终接纳预览，可能截断/拒绝须所属Reactor只读求值；跨设备原子语义未定；关/点/波缺完整结构化当前事实。W1 19→20显示仅为操作样例，不覆盖进化费用/门槛，真实必要成本须读报价并在操作前可见。本轮一律不实现或伪造这些承接能力。
