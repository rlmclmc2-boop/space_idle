# 框架、主题与交互安排

本页是候选01的结构决策记录，均须结合[候选入口](README.md)的已定/待审边界阅读。全部定量值是设计提案，不是批准值。没有新增业务模型、公式或操作。

## 整体主题：从一艘持续航行的船观察整套系统

玩家始终能看见舰船作战；旁边的舱室解释它如何成长。战场的深海军蓝承托舰影与炮火，舱室的奶油白外壳和深蓝内腔承托设备、人员与事务；青色表示当前选择、能源和可执行主要动作，琥珀用于资源、等待和有限强调。危险操作另用明确文案与独立区域，不能用琥珀通用灯代替风险说明。

全局只有三个层次：顶部钱包/系统入口；持续战场；一个当前舱室。各舱室不再各自复制钱包、时间控制、保存状态和帮助正文。战斗详情在战场打开；研究设备详情在科研打开；读数属于对应对象。未处理的保存失败在全局栏下形成持续告警条，推挤工作区而非遮住舰体，直到真实状态解除。普通成功只显示局部短反馈。

导航八个目的地为舰装、反应炉、科研、强化、船员、星球、星系、超空间；档案/设置在顶栏。舰装含舰体、装备与属性；超空间内部保留路线/仓库/改造/过滤。重铸位于星球/系统事务的上下文入口，经同一个现有预览确认流程；没有第二套提交动作。导航只反映公开可见/开放选项，稿件为布局而显式列出目的地，不证明初档全开放。

宽屏导航横排并入舱室顶边，当前项深蓝实底。中窄屏用一个有文字的舱室选择器，所有目的地在同一层，不用双排图标加更多菜单。点击当前项不再次提交业务。收起舱室保留紧凑导航和展开动作；暂停/驻守只由其专属控制改变。设置、档案和危险预览只覆盖舱室区域是游戏接入目标；本HTML的示意模态层覆盖整屏以验证输入隔离，需接入时再核对实际覆盖边界。

## 宽窄空间预算

所有数值均为CSS/界面逻辑像素，与572×960战斗逻辑坐标分开。

| 窗口 | 框架与重排候选 | 主体与滚动 |
|---|---|---|
| ≥1200宽 | 顶栏64，底注24，外边12；战场33%，间隔12，其余舱室。≥1600时边距18、战场34%。 | 战场固定完整显示；模块正文独立滚动；模块标题、导航不滚动。 |
| 720–1199宽 | 顶栏64，外边8；战场30%，舱室余宽；导航切选择器。 | 反应炉仍核心/设备并置；正文溢出纵向滚动，不能缩小数字。 |
| 390–719宽 | 顶栏84两行，外边6，战场高clamp(230,30vh,300)，上下间隔6；舱室占其余。 | 舱室内核心在上、主管向下连接设备；科研控制台在舞台下；整页不滚动，舱室独立滚动。 |
| 窄屏B | 同上，但战场42vh。 | 战斗大一些，舱室滚动更多；供评审，不作为已定默认。 |
| 舱室收起 | 宽屏留240宽导航区，其余归战场；窄屏保留46高选择器，余高归战场。 | 只是显示重排，战斗时钟/暂停不变。 |

390×844是本稿压力样本，572×960是现有重点核对样本；不承诺390以下/短于700窗口已支持。200%字体/系统缩放尚待游戏实机评审，不把浏览器四窗口通过外推为全平台通过。

战场只有一个572×960逻辑空间，显示容器内使用 `s=min(W/572,H/960)`，中心等比contain，左右/上下剩余空间用环境延伸，不裁切、不非等比拉伸、不改共享几何。逻辑点到显示点为`screen=origin+s*logical`，拾取用逆变换且先拒绝黑边与HUD点击。HUD在独立界面层按实际字号绘制，不能跟随s缩成小字。本HTML的固定样例只画舰影/炮线，不是这个映射的运行实现；正式接入仍走同一个native/GPU链。

窄屏A的完整战场很小，尤其不能据此认定炮口/敌舰等级已可辨。若实机不达标，优先选B或提高最小支持窗口，不能裁掉编队、改伤害几何或把战场变成状态摘要。战场内部完整包络、五舰尺度、盾甲条与无人机预算由M1专项定稿，本轮不提供新的Excel倍率。宽屏也须在真实装配下测净空，不以示意截图验收。

## 代表控件与观看层级

候选字号：大标题23，中标题19，对象名15，正文14，辅助12；金额18，容量25；窄屏标题19、正文仍14。12用于非关键辅助，不把费用/输入/错误降成小注。HTML底部稿件标记9–10仅供评审，不是游戏文字标准。候选最小常用点击40，紧凑按钮32，仅用于邻接的增减/工具；正式游戏需结合鼠标/键盘与实际缩放确认，触屏支持尚未定。字号/按钮与场景尺寸分别缩放。

所有动作采用同一语义：青色主要执行、浅壳普通动作、细边框工具；已选深蓝底+文字，焦点外圈，禁用须带上下文原因。品质/收藏/已装备/保护各用独立形状/标签，不靠颜色。编辑数值要见草稿/已生效并能还原，合法性由业务决定。普通购级不加确认；导入、重铸、改造等沿用原事务预览。

反应炉输入以稳定设备ID为目标，增减只改本地文本草稿，提交单设备调用现有`allocate_text`，均分/清零分别映射原操作。这里是待审输入形式，不新定义跨设备原子应用。非法输入保留原文本，显示同一设备的领域原因；成功后重读`presentation_model`而非自己增减生效值。新增设备出现不能将正在编辑设备换成另一ID。

科研选择、投入与自动设置分别提交。自动投入比例与续研岗位分开显示；不承诺自动投入应用即更新预算。舞台设备跟随实际active研究，悬停不换台；暂停/无速度时不把剩余时间画成仍在倒数。HTML只展示固定快照和草稿边界，实际状态接入另验。

模态层打开后底层不接点击或全局快捷键，Tab限制在层内，关闭归还原焦点；切舱保留每舱选择、草稿、滚动是目标行为。本HTML目前切舱重建样例内容，未实现跨舱草稿持久化，不作为该项通过。隐藏舞台停止无用绘制；动画只读现有表现时钟，离页/遮挡/暂停分别按规则处理，不用CSS循环动效假装真实工作。

## 交给共用接口线程的必要需求

唯一业务入口仍是`a4d947fd:interface-candidate.md`；以下是该候选的消费清单/待补展示需求，不是另一个契约。不改后端，不增加通用DTO或事件总线。

| 需求 | 当前入口可供消费 | 缺口的处理 |
|---|---|---|
| 全局钱包、战况、时钟/暂停、保存告警 | Economy.balance_rows，Battle.hud_values，Campaign.progress_facts，Session暂停和SaveFiles现有状态 | 金额保留业务格式，不float重算；告警由同一真实状态驱动。 |

资产端口、文字安全区与布局槽位只属于前端；不要求后端提供像素、截图布局或设备管口。正式接入时由原线程逐项确认现有公开字段的实际保证，未审定候选不宣称已实现。

接口后续注意：`Battle.consume_damage_receipts`是会移除事件的表现流，继续由现有BattleView单一消费；HUD与本设计的其他区域不得把它当作可重复只读查询或再消费一次。共用候选的相应修正文档由原线程维护。
