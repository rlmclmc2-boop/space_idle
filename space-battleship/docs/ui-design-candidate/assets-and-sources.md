## 修订03沿用的资产安排

本轮只调整桌面结构，不生成最终资产。反应炉三种SVG机器是明确标记的安装占位，各有不同轮廓以检验设备体量与供能关系，不是对旧设备/新审美的批准。核心也为结构示意。船体、工厂背景、当前机器与探针取现有仓库资源；它们在本稿的构图与具体研究映射仍待审。

| 层 | 本稿用途 | 下一步资源要求 |
|---|---|---|
| 全局壳/控制样式 | 原生UI，浅壳与深蓝场景分层 | 先审构图与色彩比例，不为边框生成位图；文字/金额始终动态。 |
| 反应炉壳/核心/主管/平台 | 同一1000×740前端安装平面 | 分层复用或重做；先确定核心出口、主管分支、设备入口、文字安全区和遮挡次序。 |
| 三种设备/未来凝聚 | 约150–180界面像素等量级结构，设备占场景实体位置 | 正式透明设备不得夹带UI/管路/常亮运行效果。底座、power_in、可见主体和动态包络按M3既有v1元数据填draft→ready；未开放凝聚整套隐藏。 |
| 科研机器/探针 | 平台中心机器与上侧独立探针；右侧终端避让 | 完整研究ID映射、底座/透视/透明留白和效果包络核对；hightech用途仍待审，不和首代机器混为默认。 |
| 舰体与挂点 | 现Cruiser预览及manifest的3个mounts | UI用源画布768与同一图像变换投影；防御无已知挂点，不虚构物理安装位置。不修改战斗共享几何。 |
| 星球/星系 | 下一批继续复用现planet_visual/galaxy_map | 保留现球体/模型/场景；先适配相机、选中与详情，不另生一张城市替代图。 |
| 其余图标/人物 | 现功能/岗位图标；配置头像优先 | 实际ID清单后确认缺口，不造新职业/旧宝石玩法。 |

## 安装与制作边界

反应炉直接遵守正式[M3既有v1静态资产接口](../game-design/art/modules/reactor.md#v1元数据结构与稳定身份)，不另起字段版本。当前SVG的逻辑安装坐标是构图提案，不是最终资源的源像素/端口证据。每项记录资源路径/哈希、画布与可见主体边界、install/power_in/out、允许包络、文字区域和导入参数；缺字段保持draft。管路实体与流光只消费同一组最终端口变换，不另估路径。

控制台层级为后墙/外壳→核心与主管→设备/平台→局部工作效果→动态读数/控件。正式设备静态结构与局部动效分开，负载/运行只读真实状态；没有能量不能以光效假装工作。源输出分辨率、mipmap/过滤/压缩在最大桌面消费尺度与内存预算审定后填写，不拿旧1364×1200等画布冻结新稿。

科研设备的底座须落在平台面，主体、探针与终端分别声明包络。工厂背景可以裁环境边缘，机器与承托关系不能切断。舰装图像变换同时用于真实预览挂点，不能以独立按钮坐标凑位置；动态战斗仍用原几何链。

分别核对资源边界、可见主体、布局框和点击区域；透明留白/模型原点不等于视觉中心，按钮触达由UI定义。未来使用imagegen或Blender前，先确认宽屏构图、安装框/锚点/安全区与资源清单，再补不可复用的静态资产。本次没有制作或导入最终资产。
