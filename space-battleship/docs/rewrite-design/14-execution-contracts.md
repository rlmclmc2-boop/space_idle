# 14 跨模块执行链与 native 适配规格

本章是03/04的接口展开。P为新接口设计；R为现行行为保留建议。接口名称可按语言习惯改变，所有权、输入输出和失败语义不能隐藏在名称后改变。

## X01 执行责任：CPU、native、GPU各做什么

| 位置 | 当前查到的实际职责 | 新边界与必要原因 |
|---|---|---|
| GDScript game/attributes/各业务模块 | 主线、钱包与成长；生成战斗参数；当前有独立旧战斗及native准入/交接 | 新业务域保留产品规则、重写实现；只在创建/配置变化向native提交完整所需数据；删除正式运行的双执行器和交接壳，避免两种时序/两份HP |
| combat_execution_kernel.h / SpaceCombatExecution | C++ CPU：射击计划、弹体运动、命中几何、盾恢复、伤害/死亡、部分强化与传说、常驻数据 | 保留热路径；补齐规则与大数，仍是唯一战斗所有者；不把native称作GPU结算，也不因名称纠正而删其高效路径 |
| combat_presentation.h / combat_retained_presentation.h | native纯表现、驻留flight/beam/事件、实例写入，直接读取内核结构 | 保留驻留批次与只读数据通路；去除必要的旧宿主耦合即可，不套每帧全量中间模型 |
| retained_flights/beams/missile_events/gpu_contacts等shader | GPU根据实例参数和simulation_clock计算显示位置/形状/颜色 | 保留效果/布局协议与上传效率；GPU没有权威生命回写，shader事件不触发奖励或死亡 |
| 普通UI与3D/2D艺术 | 读状态、控件输入、血条/爆炸/轨迹/声音 | 纯绘制复用；业务回调改为明确域操作。显示血条插值是正常表现状态，不是第二业务结算 |

当前未找到compute shader承担伤害结算。这里纠正的是实现归属，不否定用户保留native/GPU快路径的约束。没有同工作量效率优势证据，不替换为GDS逐弹、Physics碰撞节点或逐命中跨语言调用。

## X02 具体数据传递

创建数据由三份只读值构成：

- `CombatRules`：伤害类型、抗性、运动单位/时长、强化参数、传说常量、合法阵型定义。源为Excel生成的完整配置；不夹带UI节点或源文件句柄。
- `LoadoutStats`：稳定moduleId/sourceId、武器种类与完整基值、装备级投影结果、冷却/束参数、静态贡献、有效强化节点、有效无人机贡献；防御逐模块max/type/recovery/delay；初始HP/盾由生命周期规则构造。不能只有合计HP而丢失Memory归属。
- `Encounter`：场景模式、敌id/slot/位置/有效基值/盾与反应装甲/武器安装、掉落规则、关卡倍率、会话RNG初态。未知字段/缺敌表/不支持效果拒绝创建，不能删掉该效果再成功。

`create`不扣资源、不授予解锁。`advance(dt)`接受非负有限游戏秒、拒绝重入；成功返回`accepted_dt, stop_reason, outcomes`，失败返回错误定位。stop_reason限定running/wave_cleared/encounter_cleared/player_dead；unsupported属于创建错误，不能假装一场loss。遇终止边界只接受到边界，余段由Session按新的Progression状态继续，不能把剩余dt既记为战斗又记为航行。

权威actor/weapon/flight数据只在native。GDS的显示视图是借用的只读投影，生命周期到下一次推进/更换会话；需要跨帧留存的UI仅复制选中ID与必要格式化值。局部ID结合sessionId，槽位不等于永久ID；回收旧槽后旧投射物仍不能命中新敌。该身份检查用于内存/业务正确性，不建全局注册中心。

`apply_loadout`输入已完成业务校验的最终受影响模块值，先验证native可接受，再由同步调用方支付/改级/安装；native安装阶段不得发生预期内可失败校验。能力预检只检查本次最终值和当前在途引用是否可保留，不能复制全战场做一套模拟事务。已出生攻击引用不可变birth参数，装备卸下不修改该次raw/type/effects/暴击结果。临时保护失去资格按04收敛、既有债务继续。预检与安装之间不让UI/信号重入。

输出分为两种有界批次：业务outcome含kill(actorId,sourceId,deathTime,dropFacts)、wave/end、历史变化及必要统计；表现feedback含birth/hit/death/retire、位置、类型、实际显示损失、效果身份。业务结果由Session本次推进同步消费一次，消费后释放；不落盘为永久事件日志。大量表现由驻留buffer直接读取，不把每弹转成Dictionary。UI统计开关只影响采样开销，不改变伤害和随机数。

## X03 支持矩阵与补齐顺序

以下“现行支持”来自准入条件和内核代码阅读，未经本轮运行验证；不能当性能/正确性结果。

| 能力 | 基准路径现状 | 最终要求 |
|---|---|---|
| 普通4武器、敌盾、反应装甲、规则掉落、模块防御 | 已有native处理；scope限制low/rich15、当前2/15敌人范围 | 保留机制，统一新配置与数值；普通/异空间都同核 |
| 大数、长期历史 | native主要double，历史<2^53、部分int32；越界交旧执行器 | 同一个BigNumber算法支持批准范围；删除越界换规则。紧凑表示可优化，但不是两套公式/精确副账 |
| 强化分支 | 只准入proficiency B2、repeat B1/B3；防御分支等被拒 | 04全部基础、A及B节点；未知能力在开发阶段显式阻止验收，最终正式内容不得依赖fallback |
| 传说 | 准入scatter_pulse/prism_tower/laser_charge/strange_matter/precise_guidance/wild_missile/endless_beam | 补higgs_cannon/dodge_counter/drone_master/drone_rebuild/black_hole及其交互，12项完整 |
| 手动异空间 | 当前准入明确拒绝 | 同核Encounter模式；H01返回等D项批准后接入 |
| 常驻/GPU表现 | 飞行/束/导弹事件/接触反馈已有驻留机制 | 保持外观、相同有效工作与低上传量；新增效果尽量用已有批次表达 |
| F8/F9自动评估 | 当前BalanceGame是另一模型 | 新工具只调用正式Session/Combat；有/无渲染只改消费者，不改战斗步与随机 |

不能为了早期阶段通过而把不支持分支从正式Excel删掉。实施顺序是配置/共享数值→普通闭环→完整效果→异空间→工具接入；旧分支可留Git历史供对照，不成为新正式运行的备用执行器。

## X04 五条跨域链路

**击杀到下一波。** native命中→盾/HP与死亡恰一次→产生掉落事实/击杀统计→Economy建立待拾取→Progression判当前组与整关→按规则建下一组或clear_wait→Presentation消费爆炸、掉落、清场反馈。钱只在collect到账；波次判定不等待爆炸动画；最后一组通关解锁也不能由掉落节点销毁回调触发。是否清除特定在途载体按B07，endless特殊保留按B06。效果中递归造成其他敌死亡，分别拥有唯一死亡记录。

**购买到战斗。** UI/船员→同Equipment报价公式→验证余额、最终装备限制、native能力及容量变化→Economy支付→Equipment记录购买级→Attributes生成变化值→Combat安装→卡片/资源条/模型局部刷新。不同入口不另算价格，购买不隐式存盘。UI在失败时保留输入、显示缺少哪种资源，不用重开会话修复失败。

**科研到属性与自动投入。** Session给Research已接受时间段→按资金/完成边界支付与工作→完成科技改级并置unread→Attributes和相关收益贡献更新→Combat安装新出生参数→Crew若已派且非手动暂停才选最短合格研究。自动投入从Economy窗口读取，输入变化只影响之后区间；已存在束与飞行弹仍用原快照。

**世界完成到容量变化。** Planets/Galaxy完成并激活效果→聚合当前贡献→Reactor计算新总容量/分配合法值→Equipment/Drone检查最终合法装配→Attributes与Combat安装→UI徽标和外观更新。收益只按已激活事实算一次，不给基础值反复加buff；若一种新增效果可能使现装配非法，必须在效果设计阶段规定处理，不能临时默认卸最贵装备。当前换船等需合法最终集合，无效操作整体拒绝。

**异空间奖励到库存。** run开始固定幸运/参考主线/时长→完成一次抽奖并保存pending→筛选对新奖励确定保留或转拆解→计算完整库存与材料变更→空间足够才claim→一次到账/入库/挂载成长→标记claimed→自动岗位可开下一轮。不能先加材料再因机库满失败；pending恢复仍用原奖励/RNG，不调用generate_reward重抽。

## X05 时序精度与资源上界

普通逻辑步上限1/60游戏秒。步内束脉冲按到期时刻、同刻按出生serial排序；先推进到该脉冲时刻的防御恢复，再执行脉冲及其同步派生。当前束period先于普通步边界撞击，选敌前敌盾结到查询时刻。债务付款/记忆恢复顺序按B05。发射/离管/束period/普通撞击不能只按数组遍历偶然排序，新增容器也不重新定义同刻优先级。

束参数明确：para1为从首个有效脉冲到最大倍率的增长时长，para2为最大倍率，para3为显式蓄力时长（可空的旧模式与显式0不同），cd为脉冲间隔并接受CD贡献。第k次有效脉冲伤害=冻结base×[1+(maximum−1)×clamp((k−1)×interval/ramp,0,1)]；ramp<=0时直接最大。不是para1蓄力。显式charge时首脉冲在charge结束。para3为空的现行模式首脉冲在interval，增长量使用该脉冲相对束出生的到期时间due/ramp，不能套(k−1)公式；编译成显式chargeMode=legacy_unset及其参数，保留该内容差异而不依赖运行缺字段猜值。新条目必须明确选模式，不复制缓存默认。

队列上界由实体数、合法最短CD、每批枚数、寿命、最大派生代数及允许迟到跨度推导；无界经济数值不等于无界实体数。分配失败/超声明上界属于明确运行错误，不丢伤害继续跑；开发诊断报告哪项配置导致需求。只允许丢弃已明确无业务意义的过期视觉缓存，不能丢业务outcome。帧预算用保留未接受时间控制，不跳过脉冲换速度。

## X06 扩展实例与不需要的机制

新增普通敌：Excel增加mon行、合法武器/盾/已有reactive选项、monGroup引用和level引用，导表跨引用校验；使用已有Actor与Damage，不新增EnemyManager。新增同模式武器：Excel加基值、图标和模式ID，现有birth/载体/伤害与表现适配即可。新增一种真正新攻击模式：在native增加明确运动/命中处理，复用AttackSnapshot、Damage、drop和表现批次；同一独立测试Excel添必要场景，F8自动获得该能力，不加模拟版实现。

新增科技：Excel一行合法effect及前置；现有effect只需数据，新effect增加一个明确贡献函数并写明作用于下一攻击还是当前容量。新增船员自动岗位：登记一个已存在业务操作和周期，不复制支付/升级逻辑。新增纯视觉：只读描述增加效果字段或新批次，不能给动画附加隐式业务回调。

每个边界都对应真实理由：域边界保护事实所有权；native边界保性能；表现边界避免动画支配结算；配置边界保护唯一输入；存档边界保护文件完整；测试入口保护独立源。除此之外不增加统一管理器、通用命令总线、每操作快照/revision、全局两阶段提交、多模型路由、收益精确副账或运行期多配置世代。
