# 超空间路线、任务与奖励还原资料

本自然批次为 A/B 两方向的可操作 docs 样本，不是原生游戏接线或完整 M9/G2 验收。主画布1440×900。入口为超空间「路线」；手动、在线任务分别保留自己的对象与奖励，浏览另一条路线不改变已有任务。

## 画面和连续操作

- 四条路线使用领域ID alpha/beta/gamma/delta，展示已通过层、下一层、最高层最佳时间；无最佳记录时先手动挑战，挂机入口说明原因。
- 手动确认下一层、0门票与返回地点；进行中显示战点/游戏时间，退出需确认且没有成功奖励。完成响应先冻结奖励。退出确认期间任务已完成时，不能丢弃已完成奖励。
- 单次挂机使用当前最高层与领域时长；自动先选真实空闲船员并保留，持续展示该任务船员快照。进行中停止不产生奖励并释放船员；待领奖励必须先解决。领取后自动等待下一游戏步，满仓则等待，不伪造实时计时。
- 奖励页由独立 round/run 凭据定位，不由当前浏览路线定位；重复完成不重抽、重复领取不重复入账，旧轮次不允许领取。技术标识折叠，玩家主操作为查看奖励、领取和查看仓库。
- 含无人机奖励在主仓200、溢出10均满时保留同一奖励；腾一格后领取同一凭据。仅核心/过滤后无无人机奖励不因满仓被阻止。过滤结果在完成时冻结，之后改规则不重算该回执。

## 数据和适配边界

`hyperspace-task-workbench.js`是可审阅的有限响应适配器；没有游戏循环、随机数、战斗、真实存档或本地业务公式。情境检查器驱动进行/完成/失败及满仓样本，不是玩家正常入口。奖励新实体携带明确字段，不能解析ID取得业务身份。固定回执先校验适用路线/层与过滤配置，未知响应不伪报成功。自动时长当前只覆盖Lv.3船员；其他等级明确提示缺完整响应，真实产品不得增加该等级限制。

现有原生链可复用：Hyperspace.routes（route/weapon/cleared）、online_status、manual_receipt、finish_manual、prepare_claim/accept_claim；Session.start_hyperspace_manual/exit_hyperspace_manual/start_single/start_auto/stop_auto/claim_hyperspace。手动8.4游戏秒可成为真实最佳记录，在线最短10游戏秒的展示消费独立提供的响应，不在前端推公式。

最小只读缺口：每条路线当前最高层最佳时间、单次准入及完整时长；自动选择船员时需要不占用船员的预览（route、crewId → 准入/拒绝原因、当前层、完整游戏时长及船员快照），复用现有 prepare_idle 语义但不得提前执行保留。金额/收益/过滤结果与领取必须继续消费领域响应，不在UI查询补账本。此处是需求，不能标成main已有；main仍为e93c2212，已审候选接口与主线边界不变。

## 路线/任务复审：当前过滤适用性与首屏密度

默认`rewardCase=drone`现在也检查**完成时当前生效规则**。有限响应只覆盖过滤关闭、all单条件quality=blue的keep_matches或clear_matches；清除蓝色会取得原已给定的拆解响应（相应材料+采集器副本2），不再生成蓝色实体，且不消耗实体序号。非空未覆盖规则（包括尚未覆盖的any组合）明确拒绝完成响应，保留任务running、层数、进度和序号，不能先冻结一只蓝机再补过滤。这里是对有限样本的适用性检查，不是新增前端过滤求值器。核心不含无人机，无需套无人机过滤。完成时规则快照连同奖励一起冻结；之后改当前规则不能改变已完成回执，重复完成/领取的原保护保持。

A/B首屏四路线压为58px左右的紧凑选择条，保留家族图标、路线名、已通过/下一层。最高层最佳与单次时长只在选中路线的一行出现；任务的实际绑定路线仍各自显示，不能被当前浏览取代。移除标题下重复“浏览路线/当前无人机”、常驻零门票说明；能源降为任务后的次要读数，0门票只在确需确认的动作中给本次代价。当前手动/在线任务进度与按钮优先可见。

回执首屏保留本次路线/层、状态、具体奖励、领取和仓库入口；冻结/不重抽/重复回调等实现语义移到技术详情或只在对应受限动作反馈。满仓原因、旧轮次拒绝及待领时停止受限仍就近显示，不因精简删掉必要反馈。仓储满200整理、双究极预设、指定下段截面此前已闭合，本批未重做或改变其语义。
