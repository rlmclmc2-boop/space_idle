# G1 内部方向构造：场景工作点 / 跨系统作业

本目录为**内部待审设计中间稿**，执行[已审规划](../README.md)，使用[G0约束](../g0-frontend-constraints.md)与[覆盖准备](../g0-system-coverage.md)。不是用户最终选择包，不称为两份完整前端；G2仍须逐一补齐全部模块、交互/状态/资产和Godot映射。准备依据按主线程交叉审结论准入G1，不等于候选或运行品质通过。

打开[index.html](index.html)切换A/B；“情境检查”切换反应炉、换装、星球与星系状态。它们使用相同演示对象/状态和相同高效基础动作，数值是模拟情境，不是报价/成长/任务计算。通过普通静态HTTP服务查看即可（从space-battleship目录运行 `python -m http.server 8765 --bind 127.0.0.1`，打开 `/docs/ui-redesign-plan/g1-internal/`）。无外部CDN、生成资源或运行游戏依赖。

## 1. 两种组织的设计命题与反例

| | A：机舱现场 | B：作业编排 |
|---|---|---|
| 玩家主要对象 | 先去所属场景，在核心/设备、舰体/槽位、星球/设施、星系/节点上工作；一个场景是当下停驻主体。 | 先进入战力维护、殖民推进、超空间收获或航行维护作业，保留相关系统的对象摘要，在当前工作点逐项操作。作业只组织UI，不是自动执行业务链。 |
| 全局工作结构 | 模块直接导航，场景完整展开；切换保留各对象/草稿，主操作固定到当前场景工作点。 | 任务关联对象保持可见，当前对象下钻到作业单；例如船员→星球→星系互查，核心供能与装备/科研摘要不因切换丢失。全系统索引始终可达，避免被任务分类藏掉。 |
| 场景/工作点关系 | 当前完整场景拥有最大观看区；主动作服务所选主体，详情围绕对象。 | 关联对象层承担跨系统当前判断，工作点仍保留专属场景与本次比较/代价；同一基础动作复用，不增加“确认整条作业”的新事务。 |
| 主要收益 | 停驻观看和对象识别直接，少一层作业归类，专属资产有空间。 | 跨系统连续任务不用记忆先前对象/状态，能从对象摘要判断下一步；不强迫先关当前模块再找另一个。 |
| 主要代价/应找反例 | 反复跨系统调整时导航成本、资源/任务状态可能需要记忆；须挑战换装→分配→研究与撤人→目标的路径。 | 关联对象和路径占用观看高度；无关对象或相同信息重复会制造工作负担。首轮内部检查已发现并修正主操作出屏问题，仍需挑战场景主体是否被摘要压缩。 |
| 是否已证明实质不同 | 未通过审查。须比较相同任务中“现场对象优先”与“跨系统关联保持”的实际差异，不靠左右分栏、换色或朝向。两方向当前共享稳定战场与基础操作。 | 若实际使用只剩A上方多一排卡片，应继续深化作业内的对象关系/跨系统连续性；不能以任务命名或多画摘要证明方向成立。 |

本轮不重选已确认奶油白/海军蓝/青色美术。预览的设备舱、星球轨道和星系多边形是G1结构占位，不是新资产定稿；已复用舰体预览、装备图标、星球表面和中文字体。敌舰使用静态舰图作位置代位，世界图不是真实敌阵、渲染或包络证据。

## 2. 主尺寸实际空间预算

仅1440×900作为主设计；1280×800与1600×900只记录边界，不同步精修，不算额外方案。当前HTML显式计入内部检查条30高，产品头64、底28；main外框高778，内边距上下28。工作区/战场纵向外框均750高，左右外边18，中间16。

- 战场外框：x≈956.9、y110、w≈465.1、h750；顶状态44、底盾甲42，逻辑投影宿主在中间662高、水平内边16。投影按s≈0.690得到约394.4×662的572×960逻辑参照；显示文字在UI层代位，不据此宣称现行世界文字已可读或已有投影接口。
- 工作区：x18、y110、w≈922.9、h750；导航约56，当前对象操作条62固定可达（当前浏览器边框/字号下实际高63），剩余工作内容可滚动。A给当前场景约880宽的工作空间；反应炉核心/支路、装备预览220宽与槽位比较、星球场景/设施详情260宽、星系地图/详情240宽分别组织，不能用同一张表替代。
- B在同一工作外框内先放关联对象与路径，再给当前作业单；摘要压缩到可判断对象的程度，操作条固定，作业单局部滚动。关联层不能遮掉费用/风险与下一步，也不能仅因预留过高而缩小战场；当前细节可继续修订。
- 收起/展开、切模块、切A/B均保持战场外框和投影规则；用户主动resize才重算显示。例外按已审规划先论证，本稿未提出开合自动变换例外。

572×960不是最终裁切框。上述投影预算之外仍须形成完整视觉安全区：盾、双条/文字、五架无人机机体、合法炮台扫掠及效果不能按零空间。世界参照线不裁切其中绘制；外框仍属临时显示容器，**不能在尚未补齐完整包络时批准贴边遮罩/导航位置**。后续需同一T下复核完整安全区，必要时调整候选显示预算，不改逻辑世界/真实炮口/拾取。

包络依据固定为[d48493ad报告](https://github.com/rlmclmc2-boop/space_idle/blob/d48493ad9dd9bf49be96b00b20a30085be38c450/g0-envelope-and-godot-coordinate-review.md)与[数据](https://github.com/rlmclmc2-boop/space_idle/blob/d48493ad9dd9bf49be96b00b20a30085be38c450/g0-static-envelope-data.json)。我舰Heavy_Battleship舰体+炮台保守框 `[147.848,374.106,423.676,665.894]` 投影在s≈0.690下约190.2×201.2；不含无人机/盾/文字。敌主线全表保守并集顶边-5.032投影约-3.47，跨组上界不证明实际裁切；不能以宿主662高直接决定这里必须clip。真实排布未按占位打包，G9仍开放，统一缩小也不消除逻辑相对重叠。

## 3. 全系统放入两种实际组织

“已安排”只指G1对象/工作点与空间职责，不等于模块已经可操作完成。当前预览仅四模块展开关键交互，其余呈现工作对象/路径卡，明确保留G2设计缺项。

| 范围 | A的场景与工作点 | B的关联对象与作业路径 | 信息/空间安排与待深化 |
|---|---|---|---|
| 航行/战场/资源/统计 | 稳定战场＋即时HUD，当前场景可展开资源/属性/统计详情。 | 同一稳定战场；作业摘要不重复主HUD，危险/保存错误跨作业可见。 | HUD用UI画布、世界锚点用同一投影；完整文字/盾甲和最大装配待证。 |
| 舰体/装备/属性 | 舰体预览→实际槽位→当前/候选对照→连续购级/换装；基础/最终/临时属性按需。 | 战力维护的配装对象；能源/研究摘要保持，所选槽位/候选成为当前作业单。 | 3武器/2防御槽样本、预览与比较同屏；冷却/余额/批量/MAX/换舰细节仍需完整扩展。 |
| 反应炉 | 核心、主管和设备舱构成场景，设备附近调节，草稿/当前及免费量分开。 | 战力维护中的供能对象；装备/研究摘要保留，供能拓扑仍为主体而非通用数据表。 | 核心预算/负载和设备支路；已模拟草稿/拒绝/无负载/开放，设备造型与真实效果资产未定。 |
| 科研工厂 | 当前设备/探针为主体，选择层切研究，投入工作点与实际进度相邻。 | 战力维护的研究对象，返回时保留研究/草稿；自动预算与岗位续研分开。 | 主体舞台优先，研究抽屉按需；当前仅范围卡，完整设备/状态/输入待G2。 |

| 星系 | 地图/节点主体，区域选择、平移/缩放后对象详情相随。 | 殖民推进中所选节点与人员关联，升级仍显示当前级主体，结果自动生效。 | 已展示迷雾/规划/施工/升级/建成；图仅结构示意，真实GLB、拖动/视角保存待G2。 |

## 4. 当前展开的具体状态与连续操作

- 反应炉：供能中→调设备草稿→额度超100演示拒绝（实际值不变）→修正/还原→应用→继续调节；无负载与凝聚未开放/开放分开。加减/均分仅为内部意图占位，最终分配粒度和后台接纳必须回原契约线程核实，不能把JS模拟变成业务算法。A直接去设备，B在配装/科研关联对象间切换保留草稿。
- 换装：选择实际槽位→看当前与购级/候选同口径比较→确认更换→冷却保留候选→继续查看其他槽。余额不足保留原选择；首防御槽无卸空动作。主购级/换装工作点固定可达；购级数值、MAX和部分成交尚无真实接入。
- 星球：施工中/缺人均显示62%且已领状态不提前出现；补人演示恢复施工，情境切到ready后才有领取→owned/Buff反馈。自动关闭表示本次后停，立即取消单列；完整探索/人员协调不由预览结算。
- 星系：迷雾/地基/施工/升级/建成是不同场景层，升级保留当前级设施主体的意图；选择节点详情相随，完成自动生效，没有领取按钮。“调整人员”回船员工作点，节点选择应保持。当前图形代位不证明GLB、camera或输入已经还原。

## 5. 本稿的接入边界与下一步

两方向只保存前端选择/情境/分配草稿，未连接GameSession/native。后续Godot沿G0的UI根与战场父canvas分离，保留既有真实时钟/原生缓存/单一receipt消费；Economy输入只做一次匹配节点局部逆变换，不重复DPI。每个读数/动作最终映射14的公开端口，现有/候选未合/待补必须逐项核实，不能读取私有核字段补图。

资产复用路径由index/style/app显式引用；本次新增的CSS/SVG形状只是结构构造，不生成或改动游戏资产。反应炉后续按M3安装/管口/控件/效果契约，星球/星系按现行舞台和模型枢轴，具体锚点/点击区/包络仍需候选定稿，不能由当前HTML像素位置反写业务。

当前未通过项：方向实质差异与全系统容纳仍需双审反例；其余模块只是工作点安排；完整状态、真实资产/特效、全部Godot装配/公开接口绑定与完整包络未交付。先审组织是否值得深化，再完成所有保留方向的G2，最终仍须多份完整前端达到同等完成度供用户选择。浏览器呈现检查仅检查本内部构造，不替代设计双审、真实报价/付款、存档/随机或V0–V10游戏验收。

当前浏览器检查：1440×900下已查看两方向的反应炉、装备、星球、星系整屏，并核对全系统导航、主操作可达、开合战场稳定、分配拒绝不改实际值/修正后应用、星球领取及星系无领取；无JS异常或缺图。未执行游戏测试；此检查不证明方向差异、完整性或玩法契约通过。
