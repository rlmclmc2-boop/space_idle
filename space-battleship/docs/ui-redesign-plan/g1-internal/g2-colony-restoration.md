# G2 第二批：人员、星球与星系还原边界

本批是两方向继续深化的实物，非G2完成。共用对象与动作以保证操作效率；A直接进入场景，B保留同组关联对象和工作上下文。浏览器展示快照不写入运行配置，不重建领域逻辑。

## 当前实物

- 船员：配置姓名与稳定id、当前岗位回退徽章、等级/经验、当前实际占用与派遣候选分列。六名可用成员，下一名开放预览；星球/设施目标与装备1/10/MAX模式可选。确认才改变占用，满员/无需额外人员/不在施工/在线任务保留有具体限制。释放、派驻后目标人数同步，返回不丢人物和候选。
- 星球：可用星球选择、当前球体/独立云层与探索机、四设施空间工作点；设施选择与星球分别记忆。未达门槛/施工/缺探索/缺额外施工人/待领/已领取分别显示。船坞额外1人，其他0；施工次数由探索完成推进。关闭自动保留本次探索；立即取消确认后清本次进度、关自动并释放探索者，施工次数保留。待领只领取所选设施。
- 星系：现有3D模型派生预览、总部、30节点与桥、表现运输船、当前节点详情；迷雾隐藏类型与效果，地基/施工/建成/升级保留当前级不同。选择、平移、缩放、归位与离页返回视角保持，拖动阈值6物理浏览器像素阻止误选。无领取按钮；自动完成不转成手动事务。
- 在线自动挂机：空闲成员选择在任务开始确认内，接纳后才保留。普通船员岗位列表不含超空间派遣；任务保留成员不能从普通页释放。停止Started任务不生成奖励，待领走对应任务回执。

`colony-models.js`只存配置事实与显式演示快照。基础人物/星球样本采用已通关40；星系单独使用已开放的未来工程情境（需通关60），不是同一自然流程证据。星球数值/经验、星系节点类型/进度均不证明实际可达。银河布局只复用既有视图映射，不生成领域蓝图或RNG。尚未演示自动完成边界、经验升级反馈和完整Buff数值；这些继续深化，不冒充V6–V8通过。

## 精确展示端口缺口（交原契约线程）

现有格式化文本不足以可靠接入以下设计；前端不得解析标签、读私有成员或补收益公式：

1. Crew：稳定id、配置头像、可用性/门槛、当前等级、经验Amount/所需Amount/比例、结构化占用(kind,target,mode)、任务保留原因、目标容量与当前人数、对应模块的实际效果摘要。现有member_options/status_rows的formattedname/text不替代该模型。派遣合法目标仍由现有job_options/admission提供。
2. Planet：每可用星球探索running/automatic/elapsed/duration、explorer；每设施稳定id、状态、work/required、门槛、extraCrew/实际人数、暂停原因、当前及领取后效果、claim允许性/原因。visual_snapshot已有视觉事实与built集合，building_options格式化名称不可解析为工作计数。领取、取消等命令保持现有入口。
3. Galaxy：区域/节点稳定id、实际父连接/可达性、explored与建设/升级状态、当前/目标level、工作量/所需/比例、当前/完成后贡献、实际人员/容量及汇总。GLB family与节点位置仅消费既有映射，不要求后端产生UI像素。

这些缺口阻断真实接入与G4，不阻断当前独立场景设计。新出口须原线程定最小范围；本批未增加业务API或读取私有字典。

## 第二批复审修订 R1

本修订承接83112e84复审意见，保留星球主体、人物实际占用/候选分离及原GLB权威。

- 迷雾隐私：地图、详情、页副标题、B关联卡、固定区与效果弹层共用隐藏身份语义；稳定节点ID可供定位，不泄露预生成设施名/类型/效果。
- 查看真实人员：星球探索/施工入口先查目标公开占用者并定位其member_id；存在探索者时显示该实际成员及原岗位/目标，不把原施工者改成探索草稿。暂无人时定位空闲候选、清楚提示尚未派遣，不自动assign。
- NoChange：同人物、同岗位、同相关目标（施工另比facility、装备另比mode）再次确认只显示未变化，不重启任务、不清elapsed、不重算duration、不调用模拟目标同步。生产消费Session既有NoChange结果，不把“查看/确认”当成新探索。
- 星系缺人：最后人员释放后详情、关联摘要、固定区一致显示“缺人停工·进度保留”；补人后恢复building/upgrading原状态和百分比。此处模拟状态反馈，生产读取Galaxy实际人员/暂停事实，不在UI推进或重置工程。已有级贡献在停工时仍保持。
- 地图焦点：主尺寸默认所选节点附近1.75倍观看，可用“总览”看全30节点、“所选”归位到当前对象；选择、pan/zoom与离页返回仍保留。地图只常驻当前节点标签，悬停另显相应标签，避免30标签覆盖主体。
- 可见体量：`render-sources.json`新增实际alpha可见框与四像素安全边界的browser_viewbox_px；`scene-models.js`消费对应展示元数据。用嵌套SVG viewBox按可见主体装入地图与所选详情，原PNG/GLB均不重画、不裁写。Godot继续使用原galaxy_map的GLB，通过相机/对象展示框适配可见体量，不导入这套PNG链。
- 详情服务选中对象：放大当前模型，进度/工程人数/当前与完成后贡献分列；精确数值仍需原列的Galaxy端口，不由UI按等级手算。迷雾用未知结构轮廓。
- B地图工具在主尺寸初始视图内完整可见，地图350高、详情内部滚动；人员名册卡不受flex压缩，长目标换行，列宽minmax(0,1fr)，经验条限制在卡/详情实际宽度内。

验证只覆盖本批受影响操作与边界：A/B真实探索者定位、重复探索/施工确认保进度、迷雾全链身份、最后星系人员撤出/恢复保62%、工具完整可点、长目标与经验条、默认所选与总览/视角记忆；JS语法、diff空白及浏览器无pageerror。主尺寸1440×900，不扩为多尺寸验收。源码SHA与同版整屏记录在`evidence/g2-colony-r1/manifest.json`。未运行Godot或游戏；不宣布V6–V8、全系统G2或画面通过。

## P3 ready／领取后的人员关联响应修订

根线程在`4f8ef18c`全模块装配图中指出：`work-planet-claimed.png`已领取180/180，但设施仍显示1/1施工者、人员摘要仍为高坚果施工。这组画面不能证明ready人员释放正确。核对03§5：达到ready即释放施工人员，领取才使设施收益生效。

问题来源是前批采集手工只改`facility.state/work`，没有载入同时包含Crew事实的完整响应；原情境入口虽有施工人释放样本，却把样本变化写成了UI扫描/修改占用。现在将building/paused/ready/owned的完整星球+人员响应固定在`ColonyModels.planetStageResponses`，情境入口仅按明确planet/facility/stage读取并替换响应对象，不在表现层判断完成阈值或执行业务释放；无匹配响应保留实际状态。

本批ready样本中船坞180/180、施工者高坚果已空闲、探索者仍为朱姐；领取动作只接纳owned，不再处理人员释放。ready/owned的详情显示实际占用0人/已释放，若收到仍占用的矛盾事实则保留“仍占用 · 待同步”，不靠隐藏读数掩盖。B上方人员摘要、名册卡、所选船员的当前占用和星球详情使用同一响应。完成边界的探索度225和人员经验仍是显式受控样本，不是浏览器运行69次探索或自然经验推进实证。
