## 2. 消除侧带的空间方式

不再冻结约614px居中的旧纵向装配，也不把左右各97px定义成待填背景带。新稿以完整808×835为画布，在中央核心＋四向短接的既有关系内重新组织**实际核心、设备、接头及其直接操作**的可见包络。

- 四设备态的主体/直接操作组合，横向有效包络以约720–760px为作图目标，外侧留白约24–44px；原组据真实设备轮廓和点击区给出最终包络。不是要求贴边或用装饰填满每个像素。
- 新稿应利用横向空间组织核心与四路设备，避免沿用窄纵图后两侧再塞框、墙、纹理或说明。中央核心、短接及四路相对方向保留；具体中心、半径、装配件和读控位置由原组设计，整体组不代画设备。
- 不得把旧图非等比拉到808宽；仅等比放大旧纵图会超出835高并切机器，也不成立。需要原组提供适合本画布的重新构图/导出，而不是宿主补两条材料。
- 三设备态按既有未开放规则隐藏凝聚整套设备/读控/效果，不造锁卡、设备空壳或假运行内容；布局仍须完整，不以恢复侧带补平衡。

用户要求新稿减轻厚壳/工业味。保留认可的视觉要素、圆润象牙装甲/海军蓝/青能量及克制琥珀；核心/设备工作主体优先，结构退后。这里不开放另选玩法或重做模块方向。

## 3. 可用控件空间与制作预算

**不指定内部控件摆位，也不画四块通用卡片。** 以下是原组在776×803安全内区里应留出的透明文字/输入安全面积预算；不是已测最小尺寸或必须画出的面板外框。位置可随核心/设备融合，但交回时必须标出实际矩形。

|---|---|
| 四路设备读控 | 每路留至少176×112的组合安全空间；设备身份/有效效果18px，必要供能/草稿读数16px；可分散依附该设备，不强制矩形卡片 |

| 核心购级 | 主动作至少151×44；真实费用单列或与按钮组合时留足至少200×48读区，不能为长金额压小字 |

| 局部结果/失败 | 至少320×48（16px两行）；长原因可展开，但关键失败不能只剩无解释灰态 |

## 4. 可直接交接的导出与坐标

- **整屏配合图**：1440×900；左侧按上述内容框，不画/重画右战场和顶部。原组可使用[边界模板](content-template.svg)与[宿主整屏范围图](../godot/evidence/reactor-drawing-bounds-1440x900.png)对照。
- **场景作图板**：1×808×835或2×1616×1670。提供无文字静态艺术层；运行文字、数字、费用、进度与控件另外覆盖。选择2×时所有源图锚点明确标为2×，安装坐标统一交1×内容本地值。
- 生成工具原始图片可以有其他像素尺寸；交付须在标准画板中按同一等比变换还原构图并交1×锚点，允许裁纯环境，不裁设备或临时改变目标宽高比。
- **组件**：核心、四路设备、短接/安装件、工作效果可按原组结构分层；给源尺寸/可见边界、视觉/底座/管口锚点、最终安装矩形、读控安全矩形与裁切限制。单件可以用原PNG/SVG规范，不能因组件分层改变功能ID。
- **坐标示例**：内容本地(100,200)→宿主(100,265)；2×源板锚点(200,400)以0.5安装→内容(100,200)→宿主(100,265)。艺术、效果、连接与点击使用同一个最终变换。
- **运行内容根**：外根808×900内置内容根`position=(0,65), size=(808,835), clip_contents=true`；所有新稿元数据以该内容根为原点。设备控件按Godot本地输入接收，不额外对UI重复逆变换；战场输入保持原路径。

配套[layout.json](layout.json)为纯前端作图/装配元数据，不是领域DTO。原组交回的文件：四设备图、三设备图；无字艺术层/必要部件；1×安装与管口/效果/读控元数据；同范围下必要状态；固定Git提交。先按范围做完整图面复核，再导入Godot，不把能载入或一张默认图当操作/动态通过。
