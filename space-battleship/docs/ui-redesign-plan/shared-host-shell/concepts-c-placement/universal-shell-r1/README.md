# C 风格公共壳：三模块通用边界 R1

本轮纠正先前左置/居中整屏图的根本问题：公共壳不能按“装备机库＋战场”画成固定房间，也不能靠缩小战场换连续性。导航位置**仍未选定**。先固定三块职责和真实几何，再以装备、反应堆、星球三种不同场景检验同一个公共界面语言。

**当前候选整屏 · 静域衔接 R3（同版公共层、真实 1440×900）：** [装备](equipment-quiet-transition-1440x900.png) · [反应堆](reactor-quiet-transition-1440x900.png) · [星球](planet-quiet-transition-1440x900.png)。三图以三张各自的原始实机 PNG 为独立底图，只在公共顶带与战场两侧原空带作 C 风格宿主概念；这是浏览器渲染的**设计成图**，不是 Godot 运行截图。中心 47.875px 图标轴是可比较的空间候选，**不是**已经选择的位置或完成输入验证；原视觉审已限定认可其公共层改善，待用户选择，不称定稿。

[与导航落点无关的公共状态规格草案](public-states.md)另列资源长值/详情、焦点/禁用、收起恢复、保存故障和弹层职责；它只延伸公共层设计，不表示 R3 已选或运行代码已变。

R3 保留 [R2 装备](equipment-open-transition-1440x900.png) · [R2 反应堆](reactor-open-transition-1440x900.png) · [R2 星球](planet-open-transition-1440x900.png) 的离散图标键及右侧轻量空带，但针对原审退回项收敛公共层。顶部改为哑光深色梁与独立资源暗槽，去掉过多金属纹样、金边和亮青接头，白字与底色拉开对比。中轴的星场/舰体环境只在不会露出敌舰和 HUD 字样的高度渐入，打断均匀蓝带；右下在原有右空带内延续相邻舰体边缘，缓解硬切。两处环境延续仅用于**概念图的边缘取样**，不代表运行时可直接镜像画面，也不改变真实战斗投影。公共层可在 [静域衔接预览](quiet-transition.html) 中切换三模块。R2 是已退回的历史比较图，保留供核对修订来源。

R2 针对 [R1 装备](equipment-shared-shell-1440x900.png) · [R1 反应堆](reactor-shared-shell-1440x900.png) · [R1 星球](planet-shared-shell-1440x900.png) 的已知“中轴隔墙／右侧直立边栏”问题：全局信息梁不在模块边缘硬断，而是在战场入口前收成短光学接头；九个图标键彼此分离，间隙露出星空；右余量只作稀疏星场与微弱环境过渡，不再画贯穿全高的金属边。信息与导航用象牙选中态、深青底和青/琥珀细光形成同一公共层；装备机库、反应堆设备、星球天体仍各用原组背景。新 [顶部细梁美术资产](open-header-art.png)由 image_gen 生成透明底无文字部件，数值/入口文本在可复现的 [开放衔接预览](open-transition.html) 中单独放置；生成资产没有替换任何模块或战场像素。

[公共壳成熟材质与控件图板](public-shell-materials.png)是新美术概念：深蓝钛合金、象牙陶瓷、低强度青色光学、稀疏琥珀节点；展示资源条、窄图标轴、两种轻量对接边、战场外侧星空环境和控件状态。它**只画共享件，不画任何模块内景、舰船或 HUD**。图板上的按钮/图标/数字不是最终信息架构，也不代表导航已选左置；按下述职责重新装配才有意义。

[三模块同尺寸边界预览](preview.html)把下表三张**原图以独立 `<img>`、原生 1440×900** 交替显示，公共顶带和战场左右原空带以单独 HTML/CSS 层示意。这只是中置 47.875px 的几何验证视图，未选定中置，也不是 Godot 截图或运行实现；原图文件未修改，战斗有效投影与舰船均不在覆层内。它可以直接切换三模块，判断同一壳是否依赖机库内景。

R3 三张导出均为浏览器对同一个 `1440×900` 预览容器的截取；底图解码尺寸逐一为 `1440×900`。导出后将每张设计图与各自原图转为 RGB 逐像素比对：模块内区 `x=0..807, y=65..899` 和战斗有效画面 `x=856..1391, y=0..899` 的差异包围框均为空（3/3）。因此图中装备舰、反应堆核心、星球天体、敌舰数量/尺寸、玩家舰及战斗 HUD 在这些区域保持**原图像素**；只有明确列出的公共层区域改变。`x=855.875` 的小数边界按当前投影计算，像素比较取完整的 `x=856..1391`。

## 固定区域与可替换内容

| 区域（真实 1440×900 基线） | 所有者与职责 | 本概念允许的动作 |
|---|---|---|
| 公共信息/导航 | 共享宿主；当前顶带 `x=0..808, y=0..65`。全局余额、当前入口、资源/状态、切换、收起/恢复、焦点与遮挡语义仍由宿主承担。 | C 风格统一文字层级与控件材料；导航位置另选，不能靠复制模块内标题或新增业务内容凑满。 |
| 可替换模块根 | 各模块所有者；保持 `x=0..808, y=0..900`，主体从其已约定的顶带/内容边界开始。装备、反应堆、星球保留各自独立背景、实体、局部操作与弹层。 | 共享壳只在模块**外缘**接一条细的可拆卸连接件，不把机库墙、反应堆臂或轨道带固化为全局装饰。安装净空由每个模块分别审。 |
| 战斗投影 | 战斗所有者；逻辑 `572×960`，保持比例 `0.9375`，实画 `536.25×900`，区域 `x=855.875..1392.125, y=0..900`。 | 完整保留真实四舰密度、玩家舰尺度、HUD、拾取与表现空间；不缩、不拉伸、不上压边框。 |
| 战场容器外缘 | 共享宿主可设计的环境/结构衔接候选；容器 `x=808..1440`，实画之外左右各 `47.875px`。 | 左带 `808..855.875` 可探索图标优先窄轴，右带 `1392.125..1440` 可做星空/舰体连续环境。R3 仅在静态概念中取相邻实机环境像素示意延续；实际方案须绘制与战斗联动的环境，不能拿固定镜像图充填或以实体底板掩盖裂缝。 |

最紧的几何约束是中置导航：在不改变两侧主体时，它最多占左空带 `47.875px`，只能是图标优先入口；完整文字须通过悬浮/焦点提示等宿主交互提供。左置实体导航若占额外宽度，会碰到 808px 模块根；需要新的安装协议，**当前不视为可行定稿**。右置虽然可用右空带，但入口远离模块内容，须另作可达性比较。美术图板的部件尺寸与画面不是 Godot 坐标证明。
