# G0 全系统覆盖准备表

从[唯一入口](../game-design/README.md)进入，落实[已审规划](README.md)第4–6节。基线 `main@6b8c2665`，前置显示/输入/资产规则见[G0约束记录](g0-frontend-constraints.md)。本表为已审准入依据中的范围准备；G1组织审已通过，后续按此范围进入G2。条目齐全不等于完整候选或适配可行，尚未选定任一UI。

核查基准：普通窗口物理客户区1440×900；1280×800紧凑、1600×900宽域样本，不含装饰、非全屏前提，尚无支持承诺。模块开合默认不改变战场显示区域/变换；经已审规划的完整影响论证可有例外，用户主动resize单列，不以缩小全部UI或丢弃功能来通过紧凑样本。

## 主尺寸设计、边界样本与resize的记录要求

各候选逐覆盖面给出整屏状态、当前主体、主动作/费用/结果、详情/确认层、最大内容和返回路径；常驻/按需/教学逐项归属。以1440×900完成全系统组织和完整工作路径。1280×800与1600×900仅暴露布局边界/反例，不要求同步精修或承诺支持，不是另外两份前端；不能将多尺寸适配变成新的主任务。

主尺寸记录实际可用UI矩形、战场R/T、布局/滚动/详情层规则、最终字号/点击尺寸、可见主体及完整效果包络、遮挡/裁切内容和输入归属；另两样本仅记录变化后的预算与具体失败反例，不新增全模块适配验收。模块开合前后R/T默认相同；例外须按已审规划完成稳定性/核心契约影响论证后再锁定；主动resize则记录前后映射、焦点/草稿/选择/滚动/地图视角保留及同一世界点输入结果的预期。DPI/引擎已处理比例不重复套算。

主尺寸无法容纳时写具体反例及最小所需空间，先判断信息层级/局部布局能否修正；如需要调整主核查基准，给证据提交主线程。边界样本问题先记录，不自动启动精修。不能为凑样本缩小文字至不可读、隐去必要功能、改战场计算、改舰船武器或大改后端。

## 跨系统与状态准备

完整任务链沿已审规划第5节准备：战斗中换装→反应炉调节→科研投入→返回；船员→星球/星系→完工/领取/调整人员；超空间任务→领取→仓储/编队→改造/过滤/兑换；战斗保存失败→设置处理→返回，以及危险预览换对象/来源与重复确认。各系统都需常态、关键详情、受限/失败、成功后继续及暂停/重开的对应场景，不只共用一个全局错误样板。

当前全部是范围/证据准备，尚无候选画面与具体任务链交互交付。14提供的是已记录版本事实，不表示原契约线程本次逐项确认所有端口已就绪；前端须列实际需求，原线程核实最小缺口与实现归属。每份候选最终必须回填同版本预览、装配/资产/接口绑定及双审记录，不能凭本表行数或接口名计为完成。
