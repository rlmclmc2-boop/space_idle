# UI 重设计推进规划

## 方向与边界

用户已授权先出规划、随后着手。采用**整体共同设计、模块逐个深化**；两个既有线程协作，不新增任务或独立复测。

- 左右分屏不是必须保留的框架。先比较整屏组织方式，再决定空间分配，不只调整两栏比例。
- 整体共同确定空间、导航、视觉语言、信息层级及各模块粗构图；不是模块各自设计后拼接，也不是全模块同时精做。
- 大数规模下由玩家表达分配意图，系统按现行规则换算金额。精确手输、固定金额步进、1%等比例粒度都不是预设要求。
- 换装先分清普通玩家首要信息与主动深入信息，再安排操作；不为数值展示完备牺牲连续使用。
- 本规划不批准玩法、配置、保存格式或新的业务事务变更。具体控件、映射与未决规则仍须按证据判断。

## 整屏组织比较项（未选定）

将“全宽战场作为主场景、模块按需展开”纳入候选，与其他可行整屏组织方式比较。模块工作区可随用途变化：星球/星系偏场景观看，装备/反应炉偏紧凑操作；统一的是导航、反馈和交互规律，不强制同尺寸、同布局。这些仅是待比较方向，用户尚未表示支持或反对，不能写成已选方案。

每个候选都比较**空闲、模块打开、连续操作**三种状态，包括战斗信息可知、打开/收起成本和多次操作的稳定性；不能只靠一张空闲全景决定框架。

## 阶段、依赖与产物

| 阶段 | 产物 | 门槛与后续依赖 |
|---|---|---|
| 1. 先统一设计思路模板，再探索多个实质不同方向（当前起点） | 先共同明确模板：设计目标、主要场景、信息层级、整屏组织、操作路径、视觉语言及取舍依据；再按同一模板提出多个实质不同的方向及粗构图，不以换色或微调两栏比例充数。 | 对各方向统一比较空闲、模块打开、连续操作，不能默认左右分屏。独立前端设计线程与原契约/后端线程各按职责协作，审核与主线程另行整体把关，供用户比较取舍；框架未成立不批量产资产或先精修局部。 |
| 2. 反应炉完整样板 | 在共同框架内完成机舱构图、普通/深入信息层级、分配意图表达、实际反馈、连续调节路径及关键状态。 | 依赖阶段1；观看品质和操作效率同时成立，不要求心算大数，不以旧控件齐全代替通过。预览、实际结果和拒绝可区分；仍需用户审图。 |
| 3. 对照科研与星球 | 用科研观察/投入、星球探索/建设与详情需求检查框架通用性，列出冲突与必要修订；此时不同时全面精做。 | 依赖反应炉样板；不强套反应炉布局。发现冲突先修共同框架及受影响样板，再继续深化。 |
| 4. 后续逐模块深化 | 在成立的共同框架下逐一完成模块，整屏与完整操作路径共同交付。具体后续顺序和范围再确认。 | 依赖阶段3；每批满足下述共用验收。静态设计不关闭实机未决项，不借此扩张实现范围。 |

## 协作职责与整体把关

两个既有协作线程是：
- **独立前端设计线程：** 与原契约/后端线程先统一设计思路模板，再提出多个实质不同方向；负责整屏及模块设计产物，说明当前阶段、选取理由、依赖和待定项，按门槛逐步深化。
- **原契约/后端线程：** 提供所属模块现有事实、公开接口、版本状态与约束，核对设计的数据需求及最小缺口；不以旧UI控件反推设计必需，不借设计协作改规则或擅自扩展后端实现。

审核与主线程另列整体把关，不计入上述两个协作线程：审核核对整屏框架、信息分层、规则边界和连续路径，主线程统筹阶段状态与交付；不以局部修补冒充整体认可。用户审阅视觉与关键取舍。任何文档提交、检查通过或候选完成均不自动等于视觉通过或主线合入许可。

## 共用验收

1. **整屏成立：** 主次、观看空间和导航有依据；战斗状态可知，不被默认两栏框架限制。
2. **普通玩家能行动：** 首要信息足够做选择，深入信息按需；分配不要求计算大数，换装/升级可连续完成，不在成功后撤掉工作区。
3. **事实可信：** 当前、候选、草稿、预览、接纳结果和失败明确；复用所属模块权威输出，不在前端另算玩法。
4. **验收层级明确：** 静态设计证明组织意图，不能代替真实提交、保存或战场全装配行为。只在后续授权且相关实现确受影响时安排对应验证，不新增独立复测。
