# 多份完整前端的重设计交付规划

唯一设计入口为 [game-design/README.md](../game-design/README.md)。本规划基于 `main@96b1e82a`，按本次接替交接重写：用户要求全系统、多份完整前端，并要求以后能直接按通过的方案放入 Godot。前端线程只负责前端；后端契约仍由原线程负责。本次提交只交付规划、覆盖范围、完成门槛和职责，不绘制新候选、不生成资产、不修改运行代码。

交接已明确退回 `4b38cdd7` 的四方向；本次未取得该提交内容，不声称重新审过这些画面。横竖分区变化属于同一设计家族，不能重新包装后算作不同方向。已有文档或局部检查通过均不改变整体设计未通过的状态。

## 1. 交付目标与边界

本轮后续交付是**多份彼此实质不同、每份均覆盖全系统、可以独立选择并据此完整实现的前端设计包**。每份都必须完成整屏、模块场景、信息层级、连续操作、关键状态、资产安装规格和 Godot/公开契约映射。用户选定后，剩余工作应是按定稿实现、接入已核实的接口、制作或提升已定义规格的资产与特效，并完成真实游戏验收；不能再决定核心导航、页面内容、主要操作方式或关键事务流程。

每份最终交付同时包括全系统可操作的前端设计预览，以及据此还原Godot的设计/装配资料。预览必须能进入全部模块、走完规定连续路径、查看关键状态；状态演示与真实业务接入明确区分。静态图与文字用于补充构图和规格，不能代替可连续使用的完整前端候选；预览载体也不能迫使Godot另做一套核心设计。

“整体共同设计、模块逐个深化”只允许作为制作顺序，不再作为缩减交付范围的理由。反应炉、科研、星球可以提前暴露问题，但不是三模块样板验收；其他系统也不留到选定后再设计。多份候选使用同一完整范围和同一状态事实，不能用一份完整方案配几张概念图供选择。

范围沿用入口的桌面宽屏。具体窗口、缩放与落地限制先核实，见阶段 G0；不擅自冻结旧 572×960 战场、六页舰桥、旧画布或旧截图尺寸，不开展窄屏工作。战斗持续可见、既有确认美术、共享几何和真实炮口等现行约束继续有效；不将“并列”解释为固定左右两栏。若候选确需偏离仍有效的规范，必须列出精确条款与影响，不能靠候选名称默默改写约束。

不改玩法、数值、Excel、随机、保存格式或业务归属；不恢复退役系统、旧渲染依赖或工具。前端不另算报价、MAX、伤害、供能增益、科研速度和任务推进。需要的最小展示交换由原契约线程核实，不把设计需求写成已存在端口，也不在本线程顺手实现后端。

## 2. 先核实约束，再展开候选

窗口与耦合只读依据已收到并阅读：[layout-display-input-baseline.md（99b35d3d固定版本）](https://github.com/rlmclmc2-boop/space_idle/blob/99b35d3dc5448b66e5238590c7e79d585ea0363f/layout-display-input-baseline.md)，代码核对基线为 `main@96b1e82a`。它是原线程执行机与现行代码的事实记录，**不批准目标窗口、布局或适配实现，G0 仍未通过**。本次据此补齐规划前置条件，不开始画新方向。

已知事实及强制接入边界：

- 原线程执行机主屏1920×1080、工作区1920×1040，副屏1920×1200、工作区1920×1160，两屏配置缩放100%。当时无Godot进程，未测游戏客户区、外框/装饰或每窗口DPI；不能把显示器分辨率直接当普通窗口客户区，也不能外推其他DPI。目标客户区、支持范围、窗口/全屏、最小尺寸、画布/区域比例与缩放/裁切策略仍待定。
- `project.godot` 为572×960、`canvas_items`；正常启动无额外分辨率/全屏覆盖。`main.gd` 的 `content_scale_size` 跟随 `Battle.view_size()`。主线尚无桌面UI画布与战场显示区分离的通用局部适配层；新设计不能假设它已经存在，需交付具体前端装配/变换规格。
- 配置战场572×960、玩家点(286,520)进入内核宽高与共享几何/炮口消费链。改变逻辑宽高、位置、舰体比例或炮口不是默认纯布局权限；本轮规划采用区分显示映射与逻辑几何的边界，不能靠改这些值解决画面空间。
- 若使用战场局部平移/缩放，必须在同一显示映射下覆盖舰体、武器、弹体、光束、接触效果与掉落物以及原生canvas RID挂接。背景延展/裁切单列为表现策略，不能只移动纹理便宣称完整适配。
- 当前 `EconomyView` 将 `event.position` 直传 `collect_at`，拾取距离18为逻辑单位，尚无局部逆变换。设计必须给出屏幕/视口→局部→战场逻辑的输入路径及UI遮挡归属，保证不重复变换、不穿透点击；不得将18当作物理像素触达规格。
- 布局与显隐不控制 `Session.frame`，`BattleView` 仍单一消费伤害表现事件。新HUD/布局不得另行drain。上述新适配层尚无运行验证，静态可行性与后续实机验收分开记录。

G0 形成一份共用的约束记录，逐项给出来源路径/提交、事实、设计影响和核实责任；缺项记录为缺证，不能套用旧样板默认值：

| 核实面 | 必须得到的可执行结论 | 责任与未满足时处理 |
|---|---|---|

G0 只核实与本轮前端相关的来源/消费链，不新建运行器或独立复测，不遍历无关任务。事实冲突按[07复查方法](../game-design/07-verification.md#0-复查方法)追查；仍有效的规则冲突由主线程带来源裁定，不能以旧实现代选。

## 3. 实质不同的判据与共同设计模板

先共同明确目标、玩家主要活动和约束，再展开多个方向；本规划不预选任何新布局或方向。差异须在整套前端中体现为功能性场景构图、主体与工作点的关系、观看焦点或信息组织，并说明如何支持导航、工作上下文及连续操作；允许共享高效操作，不强造操作路径差异。每个方向说明它解决什么问题、付出什么代价，以及这些决定如何贯穿所有模块。

**战场稳定性先行的候选筛选门槛：** 优先保持战场显示稳定。若候选依赖模块打开、收起或切换改变战场尺度/位置，必须先基于99b35d3d的耦合事实提交影响说明，明确变化前后映射、完整装配与合法朝向包络/净空、共享命中与炮口不变的边界、全部原生表现的一致变换、拾取逆变换/焦点/遮挡、现有渲染刷新代价和后端核心契约影响。视觉/交互审与落地/边界审据此挑战“变化可控”的结论；仅有框图或“接入时处理”不能完成影响说明。缺设计的先补设计，待实机验证的风险明确留到相应验证门槛；适配层尚未实现本身不构成方向不可行的证据。

若已按来源、消费链与明确场景证实，布局成立必须重做已确认舰船/武器、改变命中/炮口等逻辑几何或大改后端来迁就空间，且在保留该方向核心组织方式下无法修正，才论证淘汰该布局；设计尚未补齐或适配尚未实现不能推出这一结论。不能暗中把这些改动归入接入工作。可控影响论证只使用本轮已有只读事实与设计分析；本次仅规划该门槛，不启动额外测试。设计分析不能证明运行品质，后续授权实现的真实画面/输入/性能验收仍保留。

差异审查用相同起始状态和同一串玩家任务，对照空闲、模块打开、连续操作、详情/危险确认及切换后的整屏结果。归约只排除换色、横竖换位、比例或外形微调等充数；功能性场景构图、主体与工作点的空间关系及其信息/操作作用必须保留评估，不能先当装饰剥除。若差异确实仅为上述表面变化，仍属同一家族，须重做；共享高效操作本身不构成归约或否定方向的理由，也不能为差异牺牲战斗可见和现行操作能力。

每份候选按同一模板交付，交叉引用其具体画面、交互步骤和装配记录。Git交付索引逐份链接可操作预览、全系统场景/状态与流程、Godot装配规格、资产安装清单、领域绑定表和双审/修订记录，并标明同一版本；允许共用资料，但不能让链接替代候选自己的完整页面与行为：

1. **设计命题与整屏组织：** 全局/各模块主题、观看主体、停驻观看内容、区域主次、导航入口与层级，为什么适合该活动；明确不同状态下的空间去向与取舍。
2. **信息与动作层级：** 普通玩家做当前判断必需的对象、状态、效果、代价、风险、主动作；主动深入的比较/明细/规则；首次教程和之后的查阅入口。不是所有字段常驻，也不是删除必要反馈。
3. **连续路径与状态转换：** 入口→选对象→预览/编辑→提交/取消→实际结果→下一次操作→切换/重开。逐步给出选择、草稿、焦点、滚动、视角和提示的保留/失效规则。
4. **完整场景与状态稿：** 每个模块均有整屏上下文、常态、关键选择/详情及真实规则下的限制/结果状态；场景主体和控件一起设计，不用通用表格配插图替代专属场景。
5. **Godot 与资产接线：** 对象ID、场景层/节点职责、布局/变换、资源/样式、控制区、读数、输入路由、领域绑定与刷新映射。另一位实现者应能据此还原而无需补产品设计。
6. **取舍、证据与未决：** 关联覆盖表、约束记录、反例及修订。缺口写明阻塞何项；核心缺口未关闭不能把该候选交给用户当完整可选成品。

| M10/V10 重铸与危险事务 | 重铸资格、保留无人机、收益/清除/保留摘要；导入、新游戏、恢复的来源/对象/风险、持续预览、确认/取消/失效及结果。 | 不能只放一个危险按钮或短吐司；来源变化后不能确认旧预览；取消无提交，致命故障与普通拒绝区分，不假称回滚。 |
| M10/V10 设置、保存、档案与教程 | 目录、保存/备份/导入、自动保存间隔；音量/开关/伤害数字等现行设置；敌情/通知/首次教程、跳过及重读。保存状态与战斗全局反馈贯通。 | 排队≠写盘完成；未保存/写入中/成功/失败/恢复暂停分清，错误持续可达并可重试/换目录；已见≠已读，教学退出常驻，敌情缩略图身份准确。 |

## 5. 共用状态与跨系统连续操作

每份候选维护“对象/起始状态→动作→预期可见变化→下一步→证据”记录。共享状态至少处理普通/悬停/焦点/按下/已选、隐藏/未开放、受限/不足/占用/冷却、草稿/预览/实际、提交中/成功/普通拒绝/致命停机、空列表/失效对象、工作/停顿/完成/待领取、暂停/倍速/隐藏重开。某状态确实不适用时给规则依据，不强加不存在的加载、确认或业务事务。

连续使用必须以完整任务链检查，不能只截按钮点击前后：

- 战斗进行时打开装备，比较与连续购级/换装，再去反应炉调节、科研投入并返回；核对主体、读数、费用、草稿/选择/焦点与战况可知，失败后仍可修正继续。
- 船员派遣到星球探索/施工或星系，切到目标查看缺人、推进、完成和收益，再调整人员；区分星球待领与星系自动完成，各页面保持同一人物和目标身份。
- 超空间启动/查看任务，领取进入仓储处理，比较并应用编队、改造/取消/换对象、过滤与材料兑换；结果、保护与占用贯通，返回后不丢当前工作。
- 战斗中出现保存失败，前往设置处理后返回；危险预览期间对象/来源变化、取消/再次进入及重复确认；首次教学退出后所有系统仍有查阅入口而不重复常驻教学。

这些路径是必须挑战的场景，不是覆盖表的替代品。各候选还须提出自己结构最容易失败的真实使用链，不能都挑对自身有利的任务。

## 6. 资产安装与 Godot/领域契约映射

每份候选交付完整装配说明，并标明可共用部分与候选专属部分。不得只给HTML演示、整屏合成图或文件清单，让实现者重新猜测场景和状态。

| 记录 | 设计定稿时必须明确 |
|---|---|
| 页面/场景装配 | 稳定页面/对象/槽位ID；场景层级及职责、观看主体、局部舞台与前景控件、背景/效果/读数的遮挡顺序；各目标窗口的布局规则和关键定量值、锚点/容器/裁切、弹层安全区、滚动与焦点路径。可复用Godot场景/主题及挂载位置明确，不要求沿旧像素稿。 |
| 资产安装表 | 资源路径/版本与来源、沿用/适配/待制作、源画布与可见主体边界、安装框、锚点/端口、变换/包络/净空、文字安全区、点击区及输入逆变换；模型给枢轴/投影与装配关系。透明留白不代替可见体量，点击区不按图片自动推断。 |
| 状态与效果表 | 稳定业务身份→显示状态/设备/素材→效果挂点/允许遮挡；实际工作、停机、暂停、完成、选中与反馈时序，隐藏停绘与重开刷新。精确时长可在实机品质阶段微调，但触发、终止、作用对象、时钟和效果包络不得待定。 |
| 公开契约绑定表 | 每个读数/动作列所属模块、公开查询/具名命令/输入单位/结果、通知或现行轮询、实际接入提交；区分主线/候选/待补。前端选择、草稿、视角等本地状态单列；伤害回执仍由唯一消费方处理，不能重复drain。 |
| 资源交接与导入 | 每项现有导入事实与后续制作规格、目标消费尺寸和预定路径、替换位置/版本；反应炉沿用 M3 元数据语义与坐标变换，不另造业务协议。不把资源哈希/schema校验引入运行时。 |

可保留“待制作/待精修”资产，但必须已有确定的身份、用途、空间、安装/点击/效果契约和可还原的设计依据，替换它不应重新决定页面或流程。缺主体构图、关键造型语义、可读区域、尺寸/挂点或素材身份不能降格成“后续质量提升”。已有认可资产优先复用；反应炉旧设备造型等未认可素材不能因存在文件就转为批准稿。

**G4适配可行性门槛：** 节点或矩阵写全不等于适配可行。须有具体正向/逆向变换、全部原生绘制消费链及其一致映射、适配归属、输入路由/遮挡、完整装配包络与失败影响的依据，足以判断是否涉及后端核心契约变化。该影响仍未知时阻断G4，先补设计或依据；不能标成普通运行风险带入用户最终选择。只有失败也不会推翻核心设计的剩余运行问题，才可列普通风险并在G5验证。本轮不因此启动额外测试。

接口缺口由原契约线程给出核实结果与最小可接入结论；该线程负责契约更新和实现归属。前端设计可继续不依赖缺口的部分，但缺口影响核心显示/操作时，该候选不能通过“可直接实现”门槛。不得用假数据演示或“接后端时再说”关闭问题。

## 7. 执行阶段与交付门槛

阶段按依赖推进；模块可以分批制作，但所有保留候选必须达到同等全系统完成度才提交最终选择。阶段记录明确“未开始/进行中/阻塞/待审/已通过”，不能以文档提交自动过关。

| 阶段 | 可执行工作与交付 | 进入下一阶段的条件 |
|---|---|---|
| P0 本次规划 | 重写本文件，明确全系统范围、差异判据、交付模板、核实项、双审与职责；Git交接。 | 本次止于此，不把规划提交写成新方向或设计通过。 |
| G0 约束核实 | 已接收窗口只读依据；据此落实目标客户区与显示策略，前端与原契约线程分别补齐第2节相关记录，标明版本/事实/缺证与影响。 | 窗口、Godot落地、资产复用与必要接口限制足以指导设计；阻塞项有明确结论。当前依据已收到，但目标窗口/显示策略与适配层接入规格仍未定。 |
| G1 整体方向及差异审查 | 按共用模板形成多种真正不同的全系统组织骨架；所有覆盖行有位置与路径，验证主要任务链及代价。 | 方向不能互相归约为同一家族；战场显示稳定性筛选通过；依赖开合改变尺度/位置的方向已按本节门槛论证影响可控，已证实必须重做舰船武器或大改后端且无法在该方向内修正者论证淘汰；全系统均能容纳且无明显流程断路。此阶段产物只叫中间稿，不能作为本轮最终候选。 |
| G2 每份全系统深化 | 逐模块完成全系统可操作预览及第4–6节还原资料；反应炉等难点先做，用其问题修订整个候选；补齐全部模块和跨系统路径，记录核心设计缺口。 | 每份候选同等完整，窗口/最长内容/最大场景均有适用规格；所有核心缺口关闭。其他系统不再“范围另定”。 |
| G3 双审、反例挑战与修订 | 两个既有审查责任方审同一固定提交，分别找反例、互相挑战，再复核修改及受影响的整套结构。 | 分别给出有证据的结论；未证/失败不能算通过，也不能靠检查数量取平均。阻塞未清退回对应阶段。 |
| G4 用户比较与选定 | 交付多份完整前端包、同任务链比较、取舍说明和双审记录；用户可查看任一候选的任何系统/关键状态及Godot映射。 | 第6节适配可行性门槛通过，核心契约影响已查明；用户选择某一完整方案；局部喜欢、文档合入或技术检查不等于整套视觉/交互认可。 |
| G5 选定后实现与品质提升 | 后续按已选包装配Godot、接入已核实公开端口，制作/精修资产和效果；实施和真实游戏验收另按主线程安排推进。 | 实机按V0–V10验证整屏、操作、状态与装配。发现核心设计洞则退回修订，不能在实现时默默补设计并宣称按稿还原。 |

## 8. 双审：独立找反例并相互挑战

使用主线程协调的**两个既有审查责任方**，不新开任务/子智能体。视觉/交互审与落地/契约边界审各有主责，但都必须看完整候选与真实任务路径；不能一方只看好不好看、另一方只数控件/接口。由主线程明确既有承担者和审查版本；未实际完成两方审查时保持待审，前端自查不得代替双审。

- **审查A以玩家与整屏为起点：** 主动寻找场景失去主体、停驻空洞、信息挤占、当前选择看不懂、连续操作频繁丢上下文、受限状态无路可走等反例。指出具体候选/窗口/对象/状态/步骤和可见后果。
- **审查B以实现与真实状态为起点：** 主动寻找无法装配的净空/裁切/输入、不可用的接口或私有状态依赖、草稿被刷新覆盖、预览失效后仍可提交、唯一事件被重复消费等反例，同时挑战其对玩家理解与操作的影响。
- **交叉挑战：** A检查B的“可落地”结论是否仍需实现者补设计，B检查A的“体验成立”结论是否只在理想状态/假数据下成立。分别回应对方最强反例，说明成立、被证据驳回或证据不足；不能只互相签“同意”。
- **修订复核：** 前端对每个问题给修订位置、影响面和复核证据；修局部后重查被影响的整屏和任务链、候选差异及其他模块。两方保留各自结论及未决异议，由主线程处理冲突，不用一方认可覆盖另一方阻塞。

### 问题分类及阻断阶段

按[07复查方法](../game-design/07-verification.md#0-复查方法)核实来源和消费链；07的通用审阅方法由原线程维护，本文件仅明确本轮的阶段处置。每个问题须标明以下类别、证据、影响范围、阻断阶段与解除条件，不把“当前未做”直接写成“不可行”：

| 类别 | 判定及应做的工作 | 阻断何处，何时允许继续 |
|---|---|---|
| 设计未完成 | 如未给模块打开后的战场映射、操作失效规则、资产安装框或输入路径。先补设计，再由双审检查；不因候选尚不成熟直接淘汰。 | 缺G0目标/硬约束阻断依赖它的尺寸和构图定稿；缺G1必要组织/稳定性影响说明阻断该方向的G1通过，但可继续补设计；G2核心页面/流程/装配缺项阻断G3完整包验收与G4最终选择。独立部分可继续。 |
| 已证实实质缺陷 | 由可追溯事实和明确场景证明违反有效约束或核心任务无法完成，如合法装配必然裁切、输入无法对应、必须改变命中几何才能成立。先判断能否在该方向内修正并复核受影响整体。 | 阻断受影响阶段的通过；可修复则退回设计/实现修订。只有缺陷触及方向根本且在保留核心组织下无可行修正，才提交有依据的淘汰结论；不得用局部失败泛化整个方向。 |
| 待验证风险 | 已有完整设计、可追溯适配依据与实现路径，核心契约影响已查明；剩余运行问题尚缺实机证据，且失败不会推翻核心设计。明确验证命题、方法/所需环境、责任和失败时回退方案；不写成已通过，也不写成已失败。 | 不因适配尚未实现直接阻断G1/G2设计深化；满足第6节适配可行性门槛后可进入G3/G4，向主线程/用户披露残余风险，不能宣称实机通过。若仍未知是否迫使核心契约变化，阻断G4，先补设计或依据；不归入普通运行风险。普通运行风险在G5验证，未证前阻断对应实机验收与完成声明，不在本轮追加测试。 |

风险不能掩饰设计空白：如果实现者仍需选择核心页面、流程或变换策略，归“设计未完成”。“适配层不存在”是现状事实；只有进一步证明特定方向在既有约束下不能成立，才可能归“已证实实质缺陷”。设计期的“可直接实现”指设计、装配和契约足够明确，不承诺尚未执行的实机结果；实际核心端口缺失仍按第6节保留接入阻塞。

审查记录至少含固定Git提交、候选/模块/窗口/状态、来源或场景前提、反例步骤、预期与实际设计表现、严重性/影响、回应、修订和复核结论。无法成立的反例也保留驳回依据。数量表只能防漏，源码/字段/点击成功只能证明对应局部，均不能冒充整套设计通过。

设计期可交互演示只证明覆盖到的显示/操作意图，需标清静态、模拟状态及真实契约依据；不证明真实扣费、保存、随机或native全装配。实机期按13/V0–V10提交同版本真实整屏与操作证据，不用历史通过或模拟回执替代。

## 10. 最终完成门槛与当前状态

每份候选只有同时满足以下条件才能称为“可选的完整前端”：

- **范围闭合：** 全系统可操作预览和Godot还原资料齐备，第4节全系统和第5节跨系统链均有实际设计交付；没有未设计的子系统、隐藏菜单或仅写“沿用”的关键路径。
- **差异成立：** 通过第3节同任务、同状态的差异审查；保留功能性场景构图与主体/工作点关系评估，允许共享高效操作，换色或横竖换位不能充数。
- **体验闭合：** 普通玩家可据首要信息持续行动，必要详情/帮助可达；场景有主体且可停驻观看，失败/限制/危险选择后仍有清楚下一步。
- **实现闭合：** 战场稳定性筛选已通过，未以重做舰船武器或大改后端迁就布局；目标窗口已核实，Godot层级/布局/输入/状态/资产安装与公开契约映射齐全；独立实现者不需决定核心产品设计。第6节适配可行性依据充分，核心契约影响已查明；主线不存在的端口和核心缺证未被隐藏。
- **审查闭合：** 两方在同版本分别找反例并相互挑战，对应设计阶段的阻塞项已关闭，待实机验证风险单列责任与验证门槛，证据不足仍标未证；整屏和全系统结论不能由局部正确外推。
- **交付闭合：** 每份完整包、比较路径、版本/资产来源、映射及双审记录均可从Git交付索引到达；用户选定后仅剩实现、既定资产/效果品质提升和实机验收。

**本次完成的是规划重写，尚无任何新候选或设计通过。** 窗口只读依据已纳入第2节；G0仍待目标客户区、显示策略及适配层接入规格落实，其余约束记录、各候选设计包和实际双审尚未完成。本规划不虚报它们已存在，先交付可执行规划与明确门槛。当前仅修改本文件，文档检查不代表V0–V10或真实游戏通过；按仓库docs-only要求不运行游戏测试。
