## 2. UI虚拟画布与572×960战场分离：独立比较及建议规则

下表在同一设计核查客户区比较适配规则，不定义新候选布局。比例推导只按100%/UI坐标与物理预算一致的分析条件计算，实际引擎映射须在接入时读取并核对，不凭DPI设置再乘一次。

| 可执行规则 | 三客户区的结果与代价 | 前端判断 |
|---|---|---|
| 固定1440×900虚拟UI整幅等比容纳 | 1280×800倍率8/9，所有字体/点击区一起变小；1600×900倍率1，水平余160。16字号在紧凑样本约14.22，场景与表单全部被动缩小。 | 实现简单但不宜作为全系统默认；不能用整幅缩小证明可读和连续操作。 |
| 独立、可重排的UI虚拟画布；战场单独等比容纳 | UI画布使用引擎实际可用UI坐标范围；100%分析条件下分别为1440×900、1280×800、1600×900。字号/点击尺寸按UI主题保持，空间变化由布局、滚动与按需详情承担；战场逻辑仍572×960。 | **按主线程交叉审结论作为G1工作规则**；不预设战场左右位置或模块外形；1440×900完成全系统组织，紧凑/宽域样本仅记录边界反例，不要求同步逐系统精修或完成。 |
| 固定UI高度900、随客户区整体缩放并扩展横向 | 1280×800仍产生8/9的字体/点击缩小；1600×900可扩展为1600宽。解决宽域留白但未解除紧凑高度下的阅读压力。 | 不优于独立可重排画布，不作为默认；仅在有完整可读证据时再比较。 |
| 同viewport共享战场展示树 / 新SubViewport隔离 | 前者可复用现有canvas/子节点，保留retained缓存，无需新贴图或事件转发；后者另有渲染目标、输入转发和裁切/采样成本。 | 先采用同viewport展示树的接入建议；只有具体裁切/渲染需求不能满足时再提交SubViewport比较，不能因模块变多复制战场或每卡viewport。 |

建议规则的具体职责与执行顺序：

1. 前端壳层管理独立UI根画布，解除 `main._ready/_show_session` 中UI内容缩放基准跟随 `Battle.view_size()` 的绑定；UI画布取该viewport实际可用坐标，不把battle.view_size改成客户区，不更改Excel/内核。仅记录/适配前端状态，不写Session或存档。
2. 壳层在UI画布中为战场保留显示区 `R=(x,y,w,h)`，以 `s=min(w/572,h/960)`、`o=(x+(w-572*s)/2,y+(h-960*s)/2)` 建立展示父节点的等比正变换 `T(p)=o+s*p`，逆变换为 `(p-o)/s`。R的实际数值需候选证明，不在G0冒充已选构图；先完整容纳逻辑投影区，再另计视觉安全区，不按该矩形自动裁切；不独立缩放X/Y。
3. BattleScenery、BattleView（含原生flight/contact RID与beam子节点）及EconomyView使用同一战场展示树，原生offset保持零。UI中的航程文字、HUD/导航/工作区/确认层保持UI坐标。全部绘制使用同一权威T；不要同时改canvas父变换、每个世界点和shader坐标。
4. **模块打开、收起或切换默认保持R/T不变**，也不重建BattleView/presentation或暂停Session。候选如需改变，须先按已审规划提交稳定性影响论证；不能以模块需要空间为由自动缩小战场。模块在自身预算内重排/滚动/展开详情，保持操作对象和上下文。
5. **用户主动resize另走前端尺寸变更路径**：读取更新后的viewport/UI矩形，同一次布局更新重算R/T、输入有效区和覆盖层锚点；不改世界/炮口、不重启任务或重建核。若保留原生canvas节点，resize只变父变换；若确需销毁，说明释放/重新绑定顺序和影响，不能留失效RID。零尺寸/最小化不提交非法s，恢复时从最新快照重新布局；支持下界尚未定，不靠无限缩小所有控件兜底。
6. 引擎产生的 `InputEvent.position` 以事件所属viewport为起点，使用当前绘制链对应的实际canvas/节点逆变换到B；若引擎已完成content stretch/DPI映射，不再手工除DPI、除8/9或减一次窗口边框。GUI先消费其区域事件，未消费且命中合法战场交互区才调用既有collect_at；同一世界点的正投影与拾取逆投影必须匹配。

**预算边界而非验收结论：** 即使战场独占全客户区高度，1280×800的s也至多5/6，完整战场约476.67×800，逻辑拾取半径18映为15；两个900高样本的s至多15/16，约536.25×900、半径16.875。实际还需为布局安全区留空间，s只会更小。现行敌血量14字号在上述上界约为11.67/13.125，伤害数字16约为13.33/15；这是源码字号与倍率的静态推导，足以提出世界内文字缩小风险，不能证明真实可读或不可读。UI独立主题不会自动解决世界内文字。

候选以1440×900主尺寸证明战场信息、所有模块内容和点击可达；另两样本只记边界与反例。若需固定UI字号的世界锚点文字，应明确同一T投影、查询/绘制拆分与领域公开事实来源，由原契约线程核实最小呈现接口；不能读私有核状态或重复消费receipt。紧凑/宽域样本发现问题时仅记录对象/装配/状态、可用矩形及边界依据，不把适配精修扩大为主任务；主尺寸无法满足时再比较信息分层或基准调整，不暗改命中半径、舰船/武器/几何或大改后端来挤入。

**逻辑投影区与完整视觉安全区分开：** 572×960仅为逻辑世界范围，T投影得到的矩形不是自动裁切边界。完整视觉安全区须容纳同一T下舰体/炮台扫掠、盾外缘、双条/文字、最大五架无人机机体与动效等必要溢出；未接线部分不能按零空间。前端在投影区之外预留/投影安全边界，不改世界、真实炮口或collect_at的范围/半径；视觉溢出不自动获得逻辑拾取资格。具体净空可随候选补齐，但依赖贴边遮罩/导航位置的方向，必须在锁定构图前给包络与遮挡证据，不能先贴边再称后续接入处理。

补充依据：[d48493ad包络与Godot坐标核对](https://github.com/rlmclmc2-boop/space_idle/blob/d48493ad9dd9bf49be96b00b20a30085be38c450/g0-envelope-and-godot-coordinate-review.md)及同提交[g0-static-envelope-data.json](https://github.com/rlmclmc2-boop/space_idle/blob/d48493ad9dd9bf49be96b00b20a30085be38c450/g0-static-envelope-data.json)。最大我舰舰体+炮台保守框 `[147.848,374.106,423.676,665.894]`；主线敌阵全表保守并集 `[1.710,-5.032,569.161,389.936]`，异空间为 `[60.670,46.161,511.330,389.936]`。这是保守上界与跨组并集，非完整视觉框、非同一真实画面，也不证明已经重叠/裁切；排布未按M1占位打包，G9仍开放。无人机独立机体、盾外缘/双条尚未完整接线，不能把上述框当最终全装配安全框。引擎输入已处理stretch/global_canvas；同viewport中只选一次 `make_input_local` / `make_canvas_position_local` 或匹配 `get_global_transform_with_canvas` 的逆，不再反算DPI/整窗比例。`_gui_input`的局部事件不能当viewport事件再套一次逆变换。

## 4. 输入与坐标接入要求

现行事实：`EconomyView._unhandled_input` 把左键 `event.position` 直传 `collect_at`；99b35d3d确认18为逻辑拾取半径。`main._unhandled_input`处理空格，`CampaignView._unhandled_input`处理G。`galaxy_map._gui_input`处理地图点选/拖动/滚轮并调用 `accept_event`；前端不得增加全局监听与之竞争。

后续每个候选必须给出具体数值/变换与所有者，不能只填“正向/逆向变换存在”：

- 声明逻辑战场B→桌面UI画布U的显示映射，以及U→实际视口/客户区V的映射；写清节点祖先、CanvasLayer、原生canvas RID与shader在哪里各应用哪一步。若写组合 `pV=W(T(pB))`，输入先确认事件所处空间，再只逆变换尚未应用的部分；不能凭名称把 `event.position` 当物理像素或重复逆W。
- 明确战场显示矩形、完整装配/敌阵/效果包络、裁切和UI遮挡；仅在未被UI消费且落入合法拾取区时转回B调用现有接口。18保持逻辑单位，触达体验另按目标显示尺寸核对。
- 分别定义空格/G在输入框、选择层、确认层、教程覆盖时的焦点/事件消费路径；不靠增加自动暂停解决误触。地图局部变换、拖动阈值与滚动竞争由地图/所属Control处理。
- 资产锚点、控件点击区与最终显示必须使用相同最终变换；不得将透明画布边缘直接当点击范围。
- 仍由BattleView单一消费 `consume_damage_receipts`，HUD/其他模块使用独立只读状态。隐藏局部舞台不取消全局战斗表现的事件归属。

本节是接入要求，尚非某个候选的坐标定稿或原生变换证明。若具体适配仍未知会否迫使核心契约变化，阻断G4；不能因为节点/矩阵记录齐全就当可落地。未实现本身不等于不可行；只有不会推翻核心设计的剩余运行问题可列普通风险。
