## 3. 输入与坐标接入要求

现行事实：`EconomyView._unhandled_input` 把左键 `event.position` 直传 `collect_at`；99b35d3d确认18为逻辑拾取半径。`main._unhandled_input`处理空格，`CampaignView._unhandled_input`处理G。`galaxy_map._gui_input`处理地图点选/拖动/滚轮并调用 `accept_event`；前端不得增加全局监听与之竞争。

后续每个候选必须给出具体数值/变换与所有者，不能只填“正向/逆向变换存在”：

- 声明逻辑战场B→桌面UI画布U的显示映射，以及U→实际视口/客户区V的映射；写清节点祖先、CanvasLayer、原生canvas RID与shader在哪里各应用哪一步。若写组合 `pV=W(T(pB))`，输入先确认事件所处空间，再只逆变换尚未应用的部分；不能凭名称把 `event.position` 当物理像素或重复逆W。
- 明确战场显示矩形、完整装配/敌阵/效果包络、裁切和UI遮挡；仅在未被UI消费且落入合法拾取区时转回B调用现有接口。18保持逻辑单位，触达体验另按目标显示尺寸核对。
- 分别定义空格/G在输入框、选择层、确认层、教程覆盖时的焦点/事件消费路径；不靠增加自动暂停解决误触。地图局部变换、拖动阈值与滚动竞争由地图/所属Control处理。
- 资产锚点、控件点击区与最终显示必须使用相同最终变换；不得将透明画布边缘直接当点击范围。
- 仍由BattleView单一消费 `consume_damage_receipts`，HUD/其他模块使用独立只读状态。隐藏局部舞台不取消全局战斗表现的事件归属。

本节是接入要求，尚非某个候选的坐标定稿或原生变换证明。若具体适配仍未知会否迫使核心契约变化，阻断G4；不能因为节点/矩阵记录齐全就当可落地。未实现本身不等于不可行；只有不会推翻核心设计的剩余运行问题可列普通风险。
