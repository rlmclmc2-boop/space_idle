# 父协调者约束恢复

本文件仅由父协调者维护，供父在任务分配、验收和上下文恢复时读取。独立线程不读取、不维护整份文件；父仅下发当前任务必需的最小约束。后续双方明确确认的长期规划由父更新到原条目，撤销或被替代的约束及时移除，不累积历史版本；最新用户指令优先。技术规则与操作入口见 [WORKFLOW](WORKFLOW.md)。

1. **授权与任务边界。** 新任务、新线程、独立复测及并发扩展均须用户明确授权；只使用指定环境并履行指定角色，不擅用用户电脑。实现交付不等于持续试玩完成；按约定范围和终点停止，不自行补任务。区分环境故障、必要依赖、可避免空闲和已完成范围；运行标记不证明工作或恢复。角色与互评范围按用户明确分工，不自行扩大或排除；表现专职仅实现、不测试、不参与评分；依赖等待只阻塞依赖它的工作。

2. **Git 与发布。** Git 是唯一交接和恢复通道。禁止使用 ChatGPT Library，包括上传、下载、读写、重试及为该通道排障；文件交接仅走 Git，并继续遵守各类数据的上传授权边界。只上传任务代码、必要测试资产和明确获准的数据；凭据不得入库；玩家存档、缓存、原图、聊天及详细报告未经明确许可不得上传。阶段成果保存到工作分支并回读远端提交与树；候选不等于 main，正式合入须父验收并回读远端。保留无关改动，不扩大特例许可。

3. **独立判断与验收。** 父须直接阅读当前提交的相关实现并核对测量，亲自承担方向选择、架构方案和验收，不只依据线程摘要或转发案例；实现线程负责落地与验证，保留独立质疑。父在方案放行、路线切换和验收前重读本文件；独立线程只收到“请父先重读专用规范并确认适用条款”的提醒职责，不读取或维护全文。父未完成重读和源码核对，不得据摘要放行。每位参与者独立分析，交付先给接受或拒绝结论、至多三项关键风险、证据范围与建议；父指令与证据冲突时应明确反对，不能转交判断责任。保留玩家分歧，父记录采纳、延后或拒绝的理由、负责人及修改后的观察结果。复查旧低分项与复发，每项保留负责人、下一步及验收证据；实现完成不关闭体验问题。既定四方互评：发现20／修正25／对照25／实玩20／协作10，各方取另外三方评分的最低值；未齐或过期须如实说明。系统价值与协作评分分开，分数、旧评分和提交数量均不替代新验收证据。

4. **性能与画质。** 优先真实整帧耗时、尾部卡顿、明确余量与动态画质。父主动跨语言、引擎与技术领域查阅网络一手资料、源码和成熟案例选择方向，核对版本和适用边界；外部案例不能替代项目实测。结构改动前核主要成本及可得收益；真正替换原型尽早验证收益，不能先耗时补齐整套兼容再测。方案须说明减少哪些工作、执行次数、数据访问或跨层调用，以及新成本；把旧算法搬到新位置、换容器或换语言本身不是收益依据。原热路径已难继续压缩时，优先重新组织算法与数据流，评估配置变更时编译、事件驱动和批量处理，不能反复包装原计算。用户2026-10-15更新：性能优化转入收尾，只完成已有证据支持且值得保留的尾项，验收后暂止，不因忙帧目标尚未达到而扩展新方向；主要工作转向游戏体验改善。既定性能衡量目标仍为真实1倍速、60Hz逻辑、高负载完整画面忙帧低于10ms；同条件、同负载的完整整帧实测净节省至少0.5ms，且可区别于对照波动，才可保留；计入新增维护、上传及同步成本。同一实质方向做过一轮后，只有确定证据支持后续仍可净省至少0.5ms才继续，否则停止并切换其他方向；不得通过改名、换容器或拆分补丁重置轮次。必要正确性修复和验收不算新收益尝试；既有保留优化不重复计入收益。函数收益、回放上界和新增桥接成本的消除不算原基线收益；未完成原型不得冒称通过，反复微基准不算突破。所有测试关闭 FPS 上限和 VSync，记录并核实实际设置，排除失焦限速；保留真实1倍速与60Hz战斗逻辑，不修改正式游戏配置。含限帧等待的旧数据不用于收益判断，不因此自动重跑全部旧测试；整帧墙时、等待和 CPU 工作须区分。比较须同环境、同负载、干净隔离并重复测量，注明自然试玩或 QA、固定吞吐或 1×、软件或 GPU 渲染及未覆盖范围。验收新逻辑自身正确、画面与实际逻辑/结算合理对应；不要求与旧版状态、随机序列、逐帧轨迹、事件时序或像素完全相同。敌舰几何按用户2026-10-14凌晨更新采用性能优先、尽量一致：自动战斗无玩家操控避让需求，优先固定舰型尺寸、挂点、阵型槽距和边界，仅保留必要运动/瞄准/命中计算；允许取消纵深缩放、采用近似轮廓和调整旧阵型边距。布局或保护轮廓冲突优先调整模型大小和固定间距，不以动态避让、迭代尺寸/边界补偿修正布局。新模型尺寸与碰撞模板共享尺度，保留死亡冻结、波末残留与移交状态；该许可不扩展至伤害、逻辑/发射频率、弹体数量或任意画质削减。验证命中与扣血对应、目标/死亡/生命周期正确、连锁等机制遵守规则，允许合理实现差异；不可借此暗改伤害、掉落等玩法规则或靠明显降画质宣称优化。性能仍比较等价场景与工作量，避免通过减少实际战斗工作伪造收益；诊断性关闭效果仅提供边界。

   **架构替换硬条件。** 已授权大改时不得默认旧实现不可动。方案必须列明被替换的入口、唯一数据所有者、旧运行路径的退出点和新实现直接承担的工作；父直接核代码确认，不能只看“重构/拆分”命名。旧版仅供 Git 或独立基线对照；禁止旧系统照常计算后，又编码、搬运并重建第二套业务对象，以此冒充职责拆分。保持玩法语义、必要视觉效果和生命周期，不要求保留旧对象结构、回调组织、缓存副作用或偶然像素差异。若兼容层保留旧热路径且新增重复工作，拒绝路线，不继续补工程。阶段须分别验证正确性与成本；局部一致或线程启动不证明拆分完成，第一阶段未完成不得推进多核。2026-10-12 反例：旧战斗内核加展示 Game 与通用转换使候选更慢；根因是保留旧实现再叠系统，不是用户授权不足。

5. **玩家体验与节奏。** 恢复应提供缓慢修复与后续战斗准备，不能靠高恢复抵消持续敌方火力；优先修正过高收益点，并核对等级、分支与临防叠加，不能仅据单点突变推断整套成长系统须重构。评审主体必须是具体体验判断、机制解释、证据与反例、修改方向、代价及优先级；操作时间线仅作附录，不以功能存在或可运行代替体验合格。资源驻守允许回退几个战点，不应使回退整关成为提高资源效率的必要或显著优势路径；审查掉落与击杀频率、成长门槛的联动，不能仅靠限制操作掩盖经济问题。从普通玩家可见信息判断，不依赖作者知识；主界面简洁，次要细节深入查看。持续试玩记录系统动机、投入、操作、卡点与负反馈，不把可运行当体验通过。先审逐波战斗、等待和重打，再审投入前后推进及解锁前压力、解锁后释放，最后看总时长；同时检查敌方耐久与玩家生存压力。累计失败数既不是验收指标也不是停止门槛，不能以少失败为优化目标。QA 遇损坏、非有限数据或非法状态须中止；长期无前沿推进时结合收入、正常购买、生存、击杀、敌方剩余耐久和最远波次发诊断警告，不自动停止积累或削弱敌人。

6. **试玩轮次与接续。** 新一轮普通新档须先有充分、连贯的改进并通过针对性快速 QA，再按明确授权以新线程、正常资源新档开展；小改动复用最小相关检查，无未闭合风险不重复宽测。区分正常资源 1×、加速和定点夹具，记录版本、初态、修改与证据限度；不把混版本或断线墙钟算连续节奏。获准的三方试玩由两位主动策略玩家和独立低干预父样本组成，彼此不预知策略，旧轮意见与进度留给父比较，不灌入新玩家上下文；1–20 轮到达 20 后保存并结束，不在边界继续 farm。持续保存版本、输入、进度和恢复检查点；断线约五分钟后实际重连原环境，常规断线不逐次通知用户，成功工作区操作才证明恢复。长上下文替换须获用户许可，最小交接保留证据与未闭合项，不复制整段历史。

7. **玩家数字与说明。** 百分比显示整数；未缩写的普通小数仅允许 .5；资源显示整数。39.1K 等缩写可保留必要精度；显示规则不擅改内部数量、计费或扣款。文字说明必须与实际机制一致，具体契约见 [UI_TEXT](UI_TEXT.md)。

8. **维护与汇报。** 每三小时内部整理，按用户约定时间汇报；达到授权任务的整体验收终点才结束，不以单个候选结束代替任务完成；停止无依据的重复尝试并接续有证据的路线，不制造忙碌。停止或阻塞必须及时反馈停止位置、原因及是否需要用户决定，不静默停工。对话直接给结果、具体问题和下一步；未验证默认不通过，只有严格证据支持才下确认断言。不反复写“不能宣称/不能确定”等免责声明；仅说明会改变判断、行动或风险的具体证据限制。约束改变时更新原条目并删除过期规则，不堆叠历史结论、临时进度或聊天；每个事实只保留一个权威来源。正式交接须核对当前私有台账，检查通过只证明完整性，不证明结论真实。
