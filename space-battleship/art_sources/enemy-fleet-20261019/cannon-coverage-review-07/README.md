## 尺寸依据

measure_coverage.py直接读取现有融合舰体源图，以各底座轴心±2像素三条水平线测量第一圈酒红色承载缘和外侧黑边。取左右较短半径形成保守、关于原轴心对称的外承载宽度，再按既有源图/运行PNG比例换算。此为设计测量，不修改运行manifest；每个底座的源坐标、三组扫描值、外承载宽度和实际覆盖值均保留在coverage-measurements.json。

提案目标为外承载宽度95%，使底座主要露出下层/边缘，白侧甲和深炮机成为主体。随后对每个底座按原舰体alpha边界限幅。最终宽约18.5–24.6屏幕像素，指挥BOSS约21.6–22.1（原16.4），反应精英22.9（原16.8），锚定精英22.1–22.8（原18.9）。显示体量仍沿用既有main.tscn记录，约0.7屏幕像素/逻辑像素；不是生产配置。

## 检查与结论

将06炮图主连通体全部alpha>230像素映射到原舰体，在0/±35/±55度读取原舰体alpha>64轮廓。两档共240个底座/角度探针，越界样本0。二分寻找边界限制并额外留0.015覆盖比例余量；几何分析仅读PNG，不改图像像素。每对炮塔用包含完整炮管的旋转外接圆检查任何转向下的互叠，最小间隙约10屏幕像素，均不互叠。

正常窗口对比中，主体占比及白甲/深色炮机的可读性有改善，尤其指挥BOSS和反应精英；但并非所有底座都能放满95%。锚定精英和反应BOSS部分底座先碰到原舰体边界，已独立限幅，因此部分同舰炮身有尺寸差异。本轮提供这个真实约束，不宣称仅靠比例已彻底解决所有位置的小团块问题；最终外观仍待父审。
