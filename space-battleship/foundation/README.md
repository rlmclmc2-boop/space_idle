# 当前保留的基础代码

当前保留 Excel 转 JSON、共享 C++ Amount/绑定和保存骨架，入口在 `src/main.tscn`，由 `src/game_session.gd` 驱动持续存在的 native 核。整体架构完成后再安排整体测试；本阶段只检查编译，并运行独立 Amount 的直接 C++ 正确性测试。

## Excel 导入

在 space-battleship/ 运行：

```powershell
python foundation/import_excel.py
# 也可指定另一个 Excel 目录和输出位置：
python foundation/import_excel.py --source <Excel目录> --output <输出JSON>
```

默认读取 config_excel/ 根目录的 *.xlsx，不递归进入 published/ 等子目录。输出 generated/config.json，结构为 `{工作簿文件名: {工作表名: [数据行对象]}}`。表头来自第一行，第二、三行为说明，数据从第四行起。公式读取 Excel 已保存的缓存值，导入器不计算公式。

没有逐字段 schema、逐表输入清单、主键/引用/规则检查。它只转换数据，不决定哪些候选或旧内容在游戏里启用。运行方直接读取生成 JSON，例如：

```gdscript
var text := FileAccess.get_file_as_string("res://generated/config.json")
var config = JSON.parse_string(text)
var equipment_rows: Array = config["equipment"]["equipment"]
```

`GameSession.initialize()` 直接读取该文件并调用普通组装函数，不经过配置包装层。文件名和工作表名原样作为两层键，不生成额外索引、哈希、元数据或发布指针。

Excel 是配置输入权威。需要大数表示的字段应在 Excel 中以文本保存，避免 Excel 自身的数值精度损失；普通数值字段保持原样。导入器原样传递文本，不解析、计算、舍入大数，也不复制 Amount 范围规则或与另一套算法比对。Amount 是唯一数值语义实现；保存层只保管其表示，不重算金额。

不存在 ConfigBundle 或查询包装。配置修改在对应 Excel 中进行，再重新导入；生成 JSON 只是运行产物，不作为测试或人工改值的入口。

## 原生构建

Amount 值及绑定在 addons/native_battle/src/amount_value.hpp、amount_api.hpp，平台文件替换原语在 foundation_disk.hpp；与保留的 native/GPU 源码一起构建。

```powershell
powershell -ExecutionPolicy Bypass -File addons/native_battle/build_native.ps1
```

该脚本使用其参数指定的构建及工具目录，要求固定的 godot-cpp 版本和 Godot API，输出 DLL。运行程序需要加载对应 GDExtension；最小入口通过构建产物中的 GDExtension 清单加载该 DLL。现有 native retained/GPU 表现读取同一个战斗核。

## 保存骨架

foundation/host/save_files.gd 只通过显式目录创建，request() 接收本次 payload 快照，poll() 回收写入结果，dirty()/close() 提供状态。保留实际保存需要的写入失败处理、flush/回读、checksum、A/B 槽与主备指针保护；测试专用故障注入已移除。没有默认个人存档路径。保存层不接收配置身份参数，也不写入或匹配配置哈希；文件 checksum 和 payloadHash 继续只校验保存数据的完整性。


## 唯一保留的正确性测试

`foundation/tests/amount_value_tests.cpp` 直接包含 `amount_value.hpp`，不依赖 Godot、Excel、配置或保存设施。它覆盖大数四则运算、幂、等比和、取整、编码范围及非法输入边界；含 0–10000 整数的 floor/ceil 一致性回归。必须启用 assert，不使用 `-DNDEBUG`。

```powershell
& '<C++编译器>' -std=c++17 -O1 -static foundation/tests/amount_value_tests.cpp -o "$env:TEMP/space-idle-amount.exe"
if ($LASTEXITCODE -eq 0) { & "$env:TEMP/space-idle-amount.exe" }
```

不保留阶段配置/保存测试、测试 Excel、无界面工程、runner 或验证记录。整体玩法、游戏中的配置读取、Godot 绑定运行和保存恢复行为均留待架构完成后整体测试。


## 运行入口与职责

在本目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File addons/native_battle/build_native.ps1
powershell -ExecutionPolicy Bypass -File run_game.ps1
```

启动脚本先按原路线将 Excel 导入为 JSON，再运行正常 Godot 主场景；原生 DLL 与 GDExtension 清单仍生成在显式 D 盘构建目录。它是游戏启动入口，不是测试 runner。编译检查不会执行该启动脚本。

`GameSession` 协调共享步长、跨模块贡献和原生提交；玩法状态由对应模块持有。核只初始化一次，随后通过 `start_wave/finish_wave/begin_retreat/finish_retreat/advance/take_results` 推进；成长和换装调用 `set_player_configuration` 原位更新，提交入口校验一次。已飞出攻击持有出生快照，防具模块损伤是生命的唯一权威，合计盾甲仅供读取。

船员的唯一占用是 Crew 内部成员记录的 `kind/target`；星球推进接收即时人员视图，完成详情由 Session 当场消费，不在星球状态重复保存人员。建筑达到探索门槛即进入 `building`，后续探索完成才累计施工；缺少额外施工人员时暂停并保留次数，`ready` 后由玩家领取。关闭自动探索完成本次后停止，取消才立即中止；每秒购买岗位离岗清余量，科研续研和投入周期独立保留。

`systems/galaxy.gd::generate` 按 Excel 槽数从核心四方向广度展开，仅生成节点身份、父节点和深度；可达性只读取父节点探索状态。总探索工程量分给全部节点，地图视觉面积不决定工作量。蓝图不消耗随机数；配置 seed 用于同深度节点选择、普通类型洗牌及特殊类型选择。星系探索/施工与并行升级分别推进，完成本项只丢本项余时。

世界成长以 `refit` 原位更新核，付费防具仍走 `upgrade`，科研、强化、反应炉保持绝对生命。各模块进度仅驻留内存，本阶段不接 SaveFiles，也不提供绕过重铸代价的首次征服动作；永久 Buff 读取已记录的征服标记。

核内金额和 Economy 钱包共用 C++ Amount；边界使用 Amount 生成的十进制文本。装备的成长、Q 与首级特例、进化报价及数量搜索只在 `systems/equipment.gd` 定义；该模块借用经济的只读支付和候选付款端口，不解释钱包明细。批量及各槽位 MAX 保持武器后防具、槽位原序报价扣款，最后合并提交一次，长激光保留本模块冷却。熟练、适应和战斗临时效果由 native 计算，Amount 只保留通用数值运算。

纯几何函数位于 `scripts/ship_geometry_convention.gd`。舰体 alpha 轮廓生成的逻辑凸包同时供接触计算与绘制；`ship_geometry_convention.gd::battle_geometry` 组装凸包和稳定来源 ID 炮口，Battle 提交几何输入，避免禁用无人机或内部槽复用改变数组对应。表现读取现有核与运动租约，不拥有伤害结算。

推进按武器、连发、离管、光束及奇异物质的真实到期时间切段。同刻先恢复及延期结算，再按来源处理出生（我方炮在出生调用内命中），随后把已有光束跳、飞行接触和到期奇异物质按时刻、阵营、来源槽、武器槽及生成序结算。每项执行前复查存活和代际；命中及其合法局部派生结束后再处理下一项。奇异物质到期伤害不重新触发主攻击派生。

非终波保留合法旧弹体；终波由核清攻击，宿主按自动领取口径收齐后等待、驻守或前进。死亡演员会回收，仍有合法在途引用的来源槽保留代际。敌炮与激光按舰体凸包检测接触，导弹沿用既定命中半径。

掉落按花括号内分号拆项，再解析资源、数量和概率。待领集合使用 `native:<DropId>` 与 `timed:<宿主序号>` 分域；native 登记游标只消费死亡结果流，两域领取后删除待领项，不积累永久已领集合。重复登记由游标拒绝，重复领取无效。

定时资源来自 `config.autoGenRes`，在航行、战斗、清关等待、驻守等待和撤退中累计生成时间，离港和暂停不推进。数量按战点倍率用 Amount 计算并取整，自顶部移动，到达、手动领取和终波强制领取共用入账函数。移动物不使用死亡掉落的自动领取期限；`timed_drop` 与 `enemy_drop/fragment_drop` 一同计入原生收入峰值。收入样本维护和窗口查询归 Economy；Research 只消费查询结果。星系收益参与 AI 实际收入，不进入原生峰值或生产基数。科研完成先同步收入效果；峰值在原生入账变化时更新。峰值历史始终保留，只有已生效的科研因子实际改变才触发成长刷新；未研发一体化或有效倍率不变时不提交。自动投入到期计算，最短续研平局保留 Excel 顺序。

`src/main.gd` 挂载模块视图和共享命令结果区域。空格暂停；G 驻守由 CampaignView 处理，掉落拾取由 EconomyView 处理，成长、人员、行星、星系与舰船控件由所属视图直接订阅模块信号。到期/终波领取与普通碎片损耗规则保持原行为。Battle 持有几何资源与战斗装配，BattleView 负责战斗绘制及 GPU 上传。

当前验证范围仅为 C++/GDScript 编译及既有独立 Amount 测试，不新增配置、保存或战斗测试设施。整体玩法、完整页面和长期保存恢复仍待后续阶段统一运行验证。

本轮职责整理：Session 保留跨域推进顺序、钱包支付与提交。槽位购级只为实际变化的已装备槽位提交基础值和等级元数据；纯外部倍率直接提交相关来源的 external_factors，无装备重算、强化/无人机/传奇重装或队列过滤。同一步世界变化涉及装备等级、外部倍率和反应炉容量时合并一次原生数值提交。长激光付费等级变化只重新选择必要的无尽光束来源；在途攻击继续使用出生快照。强化购级、顺序、分支与世界强化额外等级统一消费 Enhancement 的内部效果计算 的有效输出；CombatSetup 不再计算强化规则。输出相同只保存进度/支付结果，不调用原生；输出变化按字段更新相关武器/防具与分支历史，复用原生数值事务和防具生命结算。连发第二节点 B、重复选择及未改变有效效果的顺序不再提交配置；从 A 改为该 B 仍提交移除 A 的实际差异。世界强化等级与其他世界数值在同一事务提交。换船、换装、无人机结构变化才走配置安装。Research 自管选择、投入、续研及效果失效；门槛/可选项只在关卡或科研等级变化时刷新，同等级工作量复用到该项完成，不再按固定步重新检查和求幂。删除无消费者的完成未读标记，最高进度只保留一个恒同来源。Reactor 自管购级候选、支付后按新容量均分、模块贡献与开放范围变化判断，Session 不读取其内部缓存。

Crew 在每个固定步一次生成探索者、施工者、星系人数和岗位顺序的临时视图，保留原人员选择与自动购买顺序；派遣及升级明确返回受影响岗位，只计算这些岗位；删除四岗位重扫和成员倍率缓存。Planet 按发生探索或领取的星球/建筑更新对应贡献，删除全星球建筑重扫与建筑倍率缓存。Galaxy 按建造/升级完成的区域节点更新对应效果，删除全区域四效果入口与区域失效缓存；收入直接消费该区域已结算的收益贡献。最终某一倍率变化仍按原来源顺序折叠该字段的贡献值，保留 Amount 运算顺序，不扫描无关实体或重算其他效果。升级只推进活动索引，有空闲升级位置时才收集候选。敌舰尺度沿用原规则。

原生表现按存活顺序逐项读取有限绘制字段与运动租约，表现自持槽位生命周期、轨迹和 GPU 缓存；删除每帧完整 vector 快照、逐弹体 String/Array 输出及临时 serial 索引。光束段、功率和充能表现计算归表现模块，入口仅收集上传。导弹点火使用运动实际模拟年龄，轨迹采样也只随模拟运动推进；暂停不推进点火。地图准备结束时按真实 explored 状态更新迷雾，防止节点快照先更新而漏揭示。地图仍未接入当前场景。

各面板直接订阅所属模块信号，仅合并受影响 ID 或选项失效；在 Session 推进后的可见显示帧统一格式化状态、选项或报价，每帧只消费一次待更新集合。人员面板只订阅目标模块的公开选项/分组变化；主入口没有全局 display_changes 路由，也不刷新其他模块内部控件。星系显示读取所属模块维护的计数，不扫描节点。

收入样本只在固定步开头裁剪，所有收入查询仍按各自时钟过滤。自动领取只排序当次到期集合，定时掉落按单调 UID 的既有插入顺序移动/领取；终波强制领取仍保留原跨域出生排序。装备 MAX、强化回退和船员升级复用搜索中已经确认可支付的报价，不创建候选钱包或再次计算最终报价。几何/显示纹理同路径时共用一次读取，所选舰体几何高度直接使用初始化模型结果；尺度规则不变。

各 `src/ui/*_panel.gd` / `*_view.gd` 自管显示、选项、领域错误和刷新。人员目标选择只消费目标提供者的公开分组/选项及 describe_error，不读取目标内部状态。候选结果只由所属模块接纳，协调端不解读其私有缓存。

战斗旧链清理已覆盖生产与消费：不输出原始 weapon row，不保留仅供旧导出的 Attack/Instance/MissileContext ID、只写参数/计数/入伤时间镜像、deferred_total 和 MotionLease 查询绑定；保留 arena/slot/generation 析构回收及真实接触顺序，primary 明确返回是否发射。Actor 视图只保留几何/HUD 实际消费字段，endless 使用类型化生命盾值。传奇配置解析归原生适配器；BattleStatistics 保持每次 native advance 的原 Amount 聚合顺序。

边界验收以内部玩法大改的外部影响判断：内部曲线、搜索、顺序、门槛、选项和状态表示应只修改所属模块/视图；只有公开贡献、经济/人员/进度/几何/原生契约确实改变才修改协调端。每次分项提交都保留这个口径，不把编译或局部复核当整体通过。

当前分支为 `rewrite/stage4-world`，待父线程总审，未合入 main；编译通过不代表游戏运行或架构验收通过。
