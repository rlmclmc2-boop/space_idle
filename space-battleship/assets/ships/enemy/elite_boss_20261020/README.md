# Four hulls × elite/BOSS static variants

Source/provenance/prompt: `art_sources/enemy-fleet-20261019/README.md` and `elite-boss-generation-request.json`. Eight true-alpha top-down bow-up PNGs, 887×1774 with transparent safe margin. Main hull identities retained with approved armor/emitter accessories; no installed guns, shield rings, text or background baked into sprites. Enemy renderer rotates 180°. All weapons remain independent components with unchanged original geometry_texture, hardpoints and slot_map.

Data adds eight enemy_opening_{anchor,reactive,shielded,command}_{elite,boss} presentation rows. Ordinary rows and PNGs stay unchanged. Elite skin uses the existing published combat_tier=elite field; BOSS/ultimate skin uses that tier AND encounter_leader=true. Boss escorts remain ordinary, numeric size never chooses rank. Missing variant assets retain their ordinary skin; armour mismatch retains existing fallback.

Display allowance derives from the established 114.4×133.333 logical single-cell guide, without a placement/packing system: elite 2×2 frame228.8×266.667, margins left/right12/top42/bottom12, body204.8×212.667; BOSS3×2 frame343.2×266.667, top60 for title+shield+health, body319.2×194.667. Rows record display_span and display_size. Uniform rotated-AABB fit preserves shape, not forced stretching to frame edges. Existing protection draw is display-only and uses the same body allowance; numeric centre/protection geometry is unchanged.

No formation coordinates, capacities, encounter tables, saves or combat values are changed. Frame outlines in evidence are QA-only guides, not production slot allocation. Dense natural formations are outside this asset-preview acceptance while formation redesign remains paused; do not infer new fit/capacity rules from these variants.

## Reserved 1/2/4 weapon interface (not applied)

The latest user scope explicitly leaves production numbers and equipment counts unchanged. `ship_weapon_visuals.json.enemy_weapon_interface` is a dormant contract: normal1/elite2/BOSS4, authored rotating mounts and one-to-one slot maps returned by `scripts/enemy_weapon_interface.gd:describe`. It never creates equipment, modifies cooldowns, adds damage multipliers or runs from spawn/fire. Rank uses the same published tier/leader policy. Existing active row hardpoints and slot_map remain exactly those of the ordinary hull, so existing production weapons retain their current geometry and fire loop.

Reserved mount coordinates are relative to the alpha-centred displayed texture canvas, not the old numeric model. Four archetype overrides put turret axes on opaque armor (checked against PNG alpha). The read-only interface returns a deep copy. An explicitly authorized consumer can adapt the returned positions to its display/model basis; the QA adapter in test_enemy_ranked_art.gd does so only in an isolated in-memory scene, installs2/4 cannon entries with independent rotating components, and leaves ordinary escorts at1. Neither that adapter nor equipment multiplication exists in production scripts. Source sprites have no baked turrets. New weapon-count balance is deliberately unapplied and needs a later authorized production integration/budget decision.
