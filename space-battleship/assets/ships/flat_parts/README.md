# Complete flat-ship candidate

Opt in with `SPACE_IDLE_FLAT_SHIPS=1`; default remains the existing 3D path. `presented_ship_view.gd` owns switching and exposes `flat_compositor.active` / `fallback_reason`. Original nodes, sockets, aiming and camera projection remain alive. No battlefield/gameplay edits. Dirty resources/tree changes and candidate disable schedule one deferred owner recheck, including pause. Every layout notification checks native pixel coverage even if the 3D scale remains clamped; unchanged assets are not rebuilt.

Assets: original project weapon GLBs and materials, Godot 4.6.3 Compatibility, existing fixed light with the accepted all-body-baked shadow policy. Recipe: `dev/toon_ship/export_flat_parts.gd`. Art export only; no game or saves. Each of four weapons has bearing/turret color and height atlases, 64 directions, 192² per direction, 4×MSAA. Identical bearings share files. Runtime rotates adjacent samples onto the exact angle before lighting interpolation; it does not quantize aiming. Depth selects actual per-pixel order. Existing 1024² body textures are reused. The 1024² shield map stores interpolants from the original 32×16 sphere; shield and additive exhaust retain their dynamic formulas. Exhaust uses the existing presentation clock to freeze with pause; its pulse phase may differ from the realtime shader clock.

A frame switches only with full visible geometry coverage. Unknown geometry/ornaments, changed weapon materials/geometry/shaders/lighting, non-top-down transforms, above-native magnification, >48 items or >12 unique textures retain the complete realtime viewport. The original procedural quality ornaments, T1/T2 category glyphs and independent ultimate orbit have offline color/height coverage (117 deduplicated groups). The orbit retains its Node3D angle continuously; unexported ornament geometry/materials still force complete fallback. Texture dimensions, AA and authored transforms are not reduced at runtime.

This is an unaccepted structural candidate. Directional lighting interpolation, transparent edges/overlaps, shield/exhaust color and depth, pause/resize/appearance transitions, GPU sampler capacity, memory and actual frame cost need parent GUI review. No visual-equivalence or speed claim. The compositor trades the live 3D target for bounded per-fragment sorting and static texture memory; four weapon families share five packed color/height atlas textures (~90 MiB decoded), plus used body/shield textures. Only current appearance textures stay referenced; shader code is reused by layout size.

The compositor preserves both original alpha stages: transparent 3D accumulation followed by the default TextureRect mix. Weapon/ornament/normal-map exports contain premultiplied edge pixels; decode those before shading/depth interpolation. Keep the existing body proxy texture semantics. Reference: Godot 4.6 Compatibility `rasterizer_scene_gles3.cpp` blend modes and `rasterizer_canvas_gles3.cpp` mix mode.
