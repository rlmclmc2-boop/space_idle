# 1 倍速 / +1：共享 CPU 与绘制故障

基线 `dff1477cd6665c9832aaabceaa81bebdb03a5c15`，tree `6afa8d70b33ad20405da84e1a13c4f10fd2fbe47`。本轮未测 MAX 或高倍速战斗，不包含新美术。独立分支 `perf/one-times-spikes-dff1477`；未推送。

## 环境与范围

云端 CPU 配额 `400000/100000`（4 核），可见 5 CPU，Xeon Platinum 8573C；内存 16 GiB；无 `/dev/dri`。Godot 4.6.3，Compatibility，llvmpipe LLVM19.1.7 CPU 软件渲染。用户真实日志则为 Godot4.7.2 / NVIDIA610.82 / RTX3090；不能把下面的软件渲染 FPS 当作用户机器结果。

重载夹具：实际 main.tscn + PresentedBattleGame，Heavy_Battleship，8件150级武器、4件防御、3无人机，有效强化479，3个高生命敌人。固定随机种子1701；正常真实帧回调，speed1、+1、未暂停，禁用保存。分支选择为空，不能代表用户全部 B 分支/债务/覆盖状态。轻载对照是同一解锁环境的默认 Frigate，非全新存档。正式前后每轮从相同夹具重新初始化；装备页与反应炉各约120帧，1373×883、60帧上限、关闭VSync。两轮按固定帧数测量，墙钟/战斗进度随性能而变；行为等价另用规则回归验证。

## 已交付修复

1. `7bf0be9`：fire事件保留140ms，flash在75ms已透明，原版仍提交 `[back,kick,kick,kick]`。透明期直接返回；原凹四边形按其已知对角线提交两个三角形，并保护零方向/零面积。没有删除有效闪光或更改命中逻辑。边界夹具原版14次triangulation错误，候选0次；18个普通闪光截图逐像素一致。正常整游戏短测两边均没有该错误，因此没有把本次CPU收益归因于日志消失。查阅4.7.2官方 `core/math/triangulate.cpp` 与 `renderer_canvas_cull.cpp`；没有在Windows4.7.2运行验收。
2. `5a327f2`：分支查询先判断实际选择，未选分支不再重复扫描解锁表；单一分支选择直接读标量，公开字典接口仍复制。纯效果存在性查询不再构造全套效果字典；memory只创建自己的payload，非结算步不提前创建。没有跨帧缓存、降频、修改模拟步长或攻击队列。

120帧同条件headless细粒度归因（包含插桩开销，不能当FPS）：`active`调用23629→23499，耗时4.305→0.643ms/帧；分支解锁查询23629→0次（仅未选分支夹具）；全效果数组创建3726→1578次。正常模拟tick均值5.938→2.940ms/帧。原版此链路是最大的共享CPU热点；图形慢帧还会导致正常1倍速每帧执行更多固定子步，放大CPU峰值。

## 本地最小诊断入口

先关闭其他游戏实例。正常 `启动.cmd` 不变。

- `性能采样.cmd`：同一4.7.2引擎、APPDATA、玩家存档、帧率和VSync。关闭登录/工具弹窗，在目标页保持1倍/+1后自动记录20秒；F7重新采一页。继续正常游戏和原手动/定时保存，不自动切页/暂停/改速。输出 `.runtime/frame-sample-时间.json` 与 `frame-sample.log`。含实际适配器/引擎、源文件hash、完整帧间隔/main/嵌套CPU阶段/保存/事件/队列/内存/绘制计数；阶段会重叠，不可相加为总耗时。
- `系统消融.cmd`：不带参数是全系统对照；参数 `3d`、`vfx`、`ui`、`enhancement`、`combat` 一次只关闭一项。每次新建固定合成初态，六秒后退出，不读写玩家存档；隔离用户目录。使用当前安装的代码而非偷偷切换旧基线。建议只测对照→最可疑单项→对照，输出 `.runtime/ablation-*.json`。Windows CMD入口仅静态核对，脚本在Linux真实图形环境短测，Windows实机未验收。
