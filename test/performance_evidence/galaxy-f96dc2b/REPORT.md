## 热点与修复

真实 `main.tscn`，第一星系30座满级建筑，使用上一阶段同一合成重型战舰夹具。Linux/Godot 4.6.3，1373×883；cgroup 4核、16GiB，无 `/dev/dri`，实际 OpenGL Compatibility renderer 为 llvmpipe (LLVM 19.1.7, 256 bits)。这是 CPU 软件渲染，不是 Windows GPU 测试。

第一阶段后星系主逻辑约7ms、整帧约335ms。灯光原本不投影，隐藏页 Viewport 原本也会停绘；未发现重复星系 Viewport。模型资源缓存、建筑变更才重建、静态运输网络也已存在，未再次造缓存。核心文件原始约85,772三角形不等于实际提交量：导入器已生成 LOD，单独隐藏核心只节省约25ms，不能仅凭文件大小判它为主因。

建筑几何和 MSAA 像素负担共同占大头。实际星系显示约815×558像素，旧 Viewport 却为1324×907；旧整数缩小规则在0.6比例上跳档，当前比例0.615落入约2.64倍显示像素的超采样。

只修改 `scripts/galaxy_map.gd` 的呈现：

- 用复用的 TextureRect 显示独立 Viewport，按显示像素分配缓冲；最大保持原来的逻辑尺寸预算，避免大窗口反而增加开销。4×MSAA 保留，全局分辨率不变。仍由原地图 Control 接收输入，原有 view.size / map.size 坐标换算不变。
- 全景使用导入模型自带 LOD，阈值4；随放大连续降为 `clamp(4 / zoom², 1, 4)`，2倍及以上恢复默认阈值1。所有建筑等级、活动环、交通、建设/升级表现仍运行，不换资产、不永久静止、不删除部件。
- 自动 LOD 的像素阈值语义依据 [Godot官方文档](https://docs.godotengine.org/en/4.6/tutorials/3d/mesh_lod.html)。这是有限的几何细节取舍，不是视觉逐像素无损；全景/近景截图在交付包内。

按原生显示尺寸，阈值1/2/4/8的诊断均值分别223.43 / 201.59 / 157.80 / 139.25ms；选择4而非更激进的8。真实全景截图检查未发现建筑缺失或明显轮廓损坏，近景恢复阈值1。单纯降低 Draw Call 并非当前首要方向：主逻辑已很短，而最终星系 Draw Call 仍为287。
