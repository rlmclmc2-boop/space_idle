# Enemy intelligence page opening cost, targeted follow-up

## Diagnosis

The same existing mixed high-load driver (`five-environment-20261015/baseline/driver.gd`, 240 warm-up steps, 480 sampled steps, actual 1× 60Hz, stat cache on, save off, FPS 0, VSync off) was run in the isolated candidate project. `diagnostic-open.json.gz` contains timing probes added only to the ignored QA copy of the former `3aa52c25` page. The exact probe insertion is in `diagnostic-instrumentation.py`; the production source had no timing probes.

The original three-state run recorded first open at 28.220ms synchronous / 37.975ms through the next rendered frame, and visible stage change at 25.760ms / 35.441ms. The diagnostic repeat measured first open 28.350ms, of which 19.927ms was creation and attachment of 12 route `Button` nodes and 5.990ms was detail construction. Route data projection was 0.044ms, texture retrieval 0.058ms, and encounter-capacity projection 1.628ms. The stage-three repeat had the same profile: 19.801ms for 12 new buttons and 5.674ms detail. The re-open probe deliberately switched to equipment and back: 7.656ms to equipment, 3.150ms back to intelligence; the route was not rebuilt. These are wall-clock subdivisions from the instrumented run, not additive estimates for a different run.

The page now uses one `ItemList` for route entries and reuses an image and detail labels across selections and stage changes. Programmatic tab selection no longer refreshes navigation twice when `tab_changed` has already done so. It creates no combat actors, performs no battle-rule compilation, and does no page work while hidden. The 10 reusable detail labels are created once with the page during scene setup; no all-stage prebuild or hidden-frame update was added.

## Same-fixture result

`final-open.json.gz` and `final-open.log` are the final-source mixed high-load run; `final-stage-three.png` is the main scene at the normal 1600×1000 resolution. The final source and fixture/DLL hashes are in `final-source.json`. Original and final open runs have exactly matching event counts, fires (1665), hits (9173), and 480 sampled steps. Final first open was **5.898ms synchronous / 17.129ms through the next rendered frame**; stage-three switch **2.128ms / 12.458ms**; equipment-to-intelligence re-open **8.595ms**, with no route rebuild. The open-state mean full frame was 7.662ms (original 7.502ms); this pair is a page-path check under the same fixture, not a new five-suite absent/present bracket. The original five-suite results remain in the adjacent evidence folder.

The first rendered-frame elapsed value includes time until `frame_post_draw`, so it is not a pure rendering duration. It still sits slightly above a 16.7ms budget in this sample and should remain visible to review. The first synchronously blocked period fell from about 28ms to 6ms. The visual layout and reactive-armour text are visible in `final-stage-three.png`.

The final open run reports zero immediate battle compilations, equipment projections, or equipment refresh passes on selecting the page. Across the full fixture it reports `final_compile_delta=8` and `final_projection_delta=12`; the instrumented same-event closed runs each report `final_compile_delta=8` and `final_projection_delta=96`. The eight compilations match eight `upgrades_completed` events in all runs. The 96 closed projections are consistent with eight visible equipment updates across 12 slots; while the enemy page is open, equipment invalidations accumulate and one return to equipment builds 12 projections. The page transition itself causes none. The page's 25-check real tab chain and 21-check tutorial/pickup suite pass.
