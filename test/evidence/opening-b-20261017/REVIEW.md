# 太空战舰开局实玩独立评测 B

## 范围与方法

- 基准：`main` 的 `f578e4a26d88709690a31cba2ef85edd9cedd670`；独立分支 `review/opening-b-20261017`。本次在独立 Linux 云电脑用隔离的 `user://` 正常新档，通过实际窗口的鼠标点击、移入和自动战斗推进；没有修改游戏、注入资源或改存档。
- 第 1/2/3 关分别完成 5/6/7 战点，进入第 4 关 1/5 画面即停止，见[入口截图](screens/13-stage4-entry.png)。18 个战点均由游戏流程经过；其中 1-1、3-1 在我取得可辨认画面前结束，交战细节为观察缺口，以下不编造评分。
- 操作策略：按教程移入拾取；先升级脉冲激光与复合装甲；第 1 关完成后换追踪导弹，第 2 关升级装甲和反应炉并用“均分”分配能量；第 2 关完成后换偏转护盾；第 3 关末切磁轨火炮并升级。正常的生命归零及自动撤退均保留，没有追求零失败。
- 评分为资深自动战斗玩家视角的 **10 分扣分制**。严重度：轻=局部观感或短暂辨识成本；中=持续影响判断、操作或节奏；重=明显打断通关或造成误判。自动战斗本身和没有手动瞄准、闪避、切目标均不扣分。单战点只评当次可见流程，评分不能外推到后续关卡。

## 环境与证据边界

- Linux Debian 13 虚拟显示 1920×1080、Godot 官方 Linux `4.7.2.stable`，OpenGL 兼容渲染走 Mesa `llvmpipe`。工程正式 Windows 启动器要求 Windows DLL；本机在仓库外以原生源码编译 Linux 扩展，绑定固定 `godot-cpp` 提交 `507ed9d840c01a3c5b2a39af8bb4000bfac30bf5`，引擎导出的 API SHA256 与构建脚本指定值同为 `d0e4c08c03b165156dabe6bfb6a906baf0069189f62035341230a246c86d6986`。本地 Linux `.so` SHA256 为 `1caffcc6cc0d3f53f003b402a9037fb258cbc68cf50a18e4cfcc482b3e0419c6`；游戏数据 SHA256 为 `71f26e2dc2d55fe96616747c3042318389ba3d436b0c47b5011ac065240effbd`。
- [运行日志](runtime.txt)记录虚拟显示无 V-Sync、ALSA 输出设备打不开并回退 dummy 音频驱动。因此**不能评价音效，也不构成 Windows 性能验收**。未对软件渲染器的帧率给性能分。
- 录屏尝试因 1373×883 窗口奇数尺寸使编码器初始化失败，未形成视频；证据为逐次亲眼查看的原始全屏截图。本报告没有从脚本、测试矩阵、历史评测或源码推算战点结论。截图只提交能支持关键场景者；个人存档、编译产物、缓存均未纳入版本控制。
