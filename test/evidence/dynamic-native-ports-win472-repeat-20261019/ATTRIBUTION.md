# 脉冲 / 导弹涨幅归因

结论：原单次脉冲+5.72%、导弹+3.76%没有稳定复现。新增动态炮口投影确有小量CPU段墙钟成本，主要是每逻辑步重算阵列，不是频繁原生输入。该预算远小于原单次完整帧差值；后者随交错配对反向，不能全部归因到动态炮口，更不能归因于两版共有的新弹体。

## 最小定点诊断

仅在正式重复结束后，各运行一对带RAM计时的原基线/候选。源码仅在隔离工程插桩，生成的完整qa.patch逐次保留：prepare_geometry、advance、consume_feedback包装器各只调用原函数一次，保持参数与返回；kernel.advance依然只调用一次；候选新增炮口块内部计时。未替换或跳过计算、弹体、出生射线、渲染节点、贴图、shader或任何效果。驱动只在wall结束后的冷区导出计时字典。480次采样调用及事件/状态检查通过。

## 前后共有的新弹体与精确差异范围

两版都已使用相同新弹体/retained GPU管线，旧pipeline class均不存在；武器资产与shader无差异，共同manifest和combat_presentation.h等Git对象相同，见input-manifest.json。候选仅增加动态显示炮口、出生显示射线和反馈origin选择；retained头的一行变更是选择presentation ray，不是新建另一套弹体管线。完整指定差异保存在source-scope.diff。

## 结论边界与交付

可确认：新增炮口重算解释局部prepare小幅成本，原生输入不是主要预算；旧+5.72%/+3.76%未稳定复现，多个墙钟段的跨运行波动足以影响原单次差值。不能确认：调度/频率/温度/驱动中哪个是每次波动的唯一原因、物理GPU逐帧耗时、零开销或稳定无回归。没有通过更多挑选重跑来消除这些限制。
