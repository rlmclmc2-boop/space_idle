# Player entry validation after main updates

Candidate commits: `c352047e51675694dd6cce109d00eca884dd5caf` (main and native inventory validation), `0fa0a35479f0228d817cae1101e3f9d1d9bf6e0d` (generated translation handling), and `3238c77cd27f04d2963b65c7202615c860c6fbe8` (uncommitted player command guard). These commits remain on `fix/main-startup` pending review. The earlier fixed-anchor change in `c4c0d751` is superseded by this candidate.

The entry now compares local `main` with its locally fetched `origin/main` for the approved GitHub repository. When a normal pull advances both, committed gameplay changes need no new anchor value. It rejects a different branch, an unexpected origin, a missing or different tracking ref, uncommitted runtime or entry edits, and unexpected untracked runtime files. The native inventory must cover every tracked native source file; each source blob, bundled DLL hash, installed DLL hash, and Godot version must match it. Updating native code or the bundle therefore requires an accepted inventory update.

Verification used a separate disposable checkout. For a post-merge launch simulation, its local `main` and cached `origin/main` refs were both set to each candidate commit; **GitHub main was not moved**. No original checkout, user save, or GitHub main ref was reset.

1. `python test/test_player_entry.py -q`: **14 tests passed**. They include normal main advancement, reviewed native advancement, wrong branch or remote, a local commit ahead of the tracking ref, uncommitted source and entry edits, unexpected untracked runtime files, missing engine, mismatched installed or bundled DLL, stale native source inventory, and generated CSV translations.
2. With the first candidate and an isolated save directory, `python tools/play_main.py --install-native` succeeded. `SPACE_BATTLESHIP_VERIFY_WINDOW=1` and `SPACE_BATTLESHIP_VERIFY_QUIT_AFTER_FRAMES=120` then produced a successful Godot import and game exit code **0**.
3. That import produced 19 `.translation` files from three tracked evidence CSV files. The first candidate incorrectly rejected those files on the next launch. The second candidate limits the generated-file exception to translations whose same-directory source CSV is tracked. Its repeat entry check passed with the generated files present, and a second 120-frame launch exited **0**.
