# catalog / sources：哪些可冻结，哪些仍漏可调数值

冻结f9d31b92；只读源代码、原JSON与原生成清单，不导入/不改表/不运行游戏。结论：sources是结构派生映射；catalog大部分数值可归属主线Excel，但25个无早段实例的回退模板仍有真正生效、未入新表的数值。仅换“阶段1”措辞不能消除这个缺口。

## 来源核实

`space_enemy_reward_sources.json`只有version、源hash与1960条(stage,node,group,source_group)。1960条逐项等于`test/progression/candidates/progression-v29-short-wave-budgets.json`的waves对应四列，源文件SHA也匹配；没有amount/chance/倍率等平衡数值。stage/node/group对应生成后的主线level/monGroup结构；source_group由`test/progression/generate_levels.py:67–71/106`从battle_design所选原设计组与攻击变体构成。它不是可以仅从最终主线JSON某个现成来源列直接读出的金额参数，不能冒称改主线Excel就必然重新生成映射；但它也不是独立可调奖励数值。保留已确认映射及来源清单，锁定结构合理；未来主线重新生成时需同步验证/更新，不能1960条永远静默沿用。

catalog40参考的source_design_group_id及reference_member_count均与当前game_data.groups一致；40组late_drop_blocks逐块等于late_reference_actual_group_id下现有mon掉落，15参考有early_existing_encounters，其对应早段实际group掉落也逐块等于early_drop_blocks。这些已存在主线Excel权威，不应再给一份金额编辑源。late_reference_*是生成回退块的来源关联，运行bind并不直接读这两个关联ID来重取金额：实际fallback读catalog快照。因此主线相关mon金额改了，若catalog不刷新，未匹配当前来源的异空间仍可能吃旧快照。即使不补这55组数值页，也须补“导入时由主线来源重新派生并验证catalog快照”或运行时按确认来源重取；不能只hash冻结并声称所有主线改值自动传到回退。

关键差异：25参考的early_existing_encounters=[]且early_rule_only_no_existing_encounter=true，共95个early_drop_blocks。它们不存在对应早段实际主线group模板；当前为每成员一个iron(资源ID1)掉落，normal amount8、其他amount20、chance1。`generate_levels.py:84`存在匹配8/20的旧生成规则，但catalog记录的`test/build_candidate_reward_plan.py`仅有hash，在冻结Git树缺文件，不能仅凭相同公式认定全部catalog已可重生成。附source-audit.json列出25参考及95块原件。

这些值不是未消费的展示元数据：`hyperspace_reward_binding.bind:45–46`按resource_level≤5选early_drop_blocks，遍历sources无法匹配时直接使用这些块；85/223零预算成员由recipe依旧正确保留。至少5关已清、主线最高到达≥7时可以选择合法异空间，而resource_reference仍可能处早段，回退值影响普通奖励。没有运行实测，本结论来自明确消费分支。

`early_stage_range=[1,5]`、late_stage_minimum=6、early_existing_encounters、early_rule_only...等catalog字段运行不读取；1..5分界在bind代码固定。它们是来源/诊断说明，不应包装成有效开关。source_hashes/status/schema同属审计或协议，不是经济调参。

## 最小补表方案

若本轮要求覆盖所有现有真正可调数值，建议只补早段无实例模板，不复制有主线实例的预算：在异空间敌群工作簿新增“早段回退预算”实体页，95个现有drop行，列：reference_id（既有25个只读外键）、reference_member_ordinal（0起，只读）、drop_order（0起，只读）、resource_id（当前1，现有资源外键）、amount（当前8/20，非负有限）、chance（当前1，0..1）。先保持所有默认值与数组顺序；落到catalog对应25个early_drop_blocks，与其余JSON一起原子提交。作用说明写“仅当前主线source无匹配且资源参考关≤5的回退”，不是所有异空间奖励倍率。不得自动扩参考ID/成员数或补未授权新资源。

若父必须保持两本20页，可在现有奖励参考40行增加仅上述25行允许填的early_fallback_resource_id/amount/chance三列，其余15行留空锁定，由编码器重复到既有reference_member_count个块；当前95块均同参考内一致，默认可等值重建。限制需明示“当前统一每成员模板”，不能声称支持任意逐成员独立预算。此方案最少改工作簿布局，也不改当前运行结果；新增三列不应以字符串JSON方式替代实体字段。

有主线实例的15早段/40晚段块则继续只读，导入器需要读取当前主线game_data或主线表正式导入结果进行派生；不可从旧catalog拷贝后称动态联动已完成。正式candidate验收只需小定向检查：默认catalog全量等值；临时副本改一个无实例fallback.amount后消费者bind确实使用；改一个主线mon.drop后对应派生回退同步；sources无法匹配/能匹配两分支各一例。无需进度长测。

本轮建议不变更任何实际数值，不私自补表；父需与实现线程确认覆盖方案。sources冻结可以解释为结构来源保护，25早段预算冻结不能解释为“已在主线Excel可调”。
