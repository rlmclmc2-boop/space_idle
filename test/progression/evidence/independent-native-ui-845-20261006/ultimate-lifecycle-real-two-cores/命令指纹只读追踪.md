# 只读追踪：20与20.0的命令指纹语义

结论：本轮command_conflict由QA自行把原生请求保存到审计JSON、解析后重放时改变target_level类型产生。当前正常GUI付款、保存/恢复与重复点击路径没有读取该审计JSON，也不序列化/恢复quoted_request；已有真实重复点击、三档恢复均未复扣。因此不判生产BUG，记为外部请求格式兼容建议，不阻塞父当前运行；未测试、未改代码，未放宽幂等校验。

## 严格事务校验

`hyperspace_system.gd:256–270`先拒绝stale_round与invalid_arguments；按operation、drone_id、args、expected_revision生成排序且保留精度的JSON指纹。若请求序号等于last_command.seq，只有指纹完全一致才返回缓存结果，否则command_conflict；其他不等于当前command_seq的请求返回stale_command。全部拒绝在复制/规划/付款/publish之前，不能二次扣款。成功才写last_command、递增command_seq、验证结果和装备约束并发布。

该流程保留原序号和原请求内容的事务身份。不能为了消除QA错误而忽略目标、revision或指纹差异，也不能把command_conflict转为无条件成功。

## QA实际变型证据

`independent_ultimate_observer_retest.gd:57、65–67`读取native/audit.json，取snapshot.request直接调用领域forge。原native脚本捕获的现代化请求target_level为整数20，QA JSON.parse_string还原数值为浮点20.0。原付费收据fingerprint：

```json
{"args":{"target_level":20},"drone_id":"space:1:2","expected_revision":3.0,"operation":"modernize"}
```

QA变型请求的指纹投影：

```json
{"args":{"target_level":20.0},"drone_id":"space:1:2","expected_revision":3.0,"operation":"modernize"}
```

字段按数值语义相等，但指纹字符串不等。现有observer-retest/audit记录error=command_conflict、applied=false、before==after；这是额外QA重放检查，不是正常GUI报错，也不是存档业务字段改变。正常GUI同报价的原生重复点击和真实三档正式恢复已分别有不复扣证据。

## 兼容建议与限制
