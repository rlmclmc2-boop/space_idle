## 奖励及可见文案路径

`space-battleship/scripts/drone_rewards.gd:generate()`通关奖励只产生无人机或核心以及对应材料，没有挂设奖励；`dismantle()`才按品质数量从挂设模块池随机抽副本，同时返对应武器材料。`credit_modules()`首次副本unlocked=true并先消耗一份解锁，其余副本才加经验、升级。重铸会重新锁定模块。

现UI文案检索唯一拆解与挂设来源说明为 `data/ui_text.json` 的dismantle_confirm：“拆解将移除此无人机，并按领域规则发放材料与挂设奖励。继续？”正常管理窗口显示等级/经验与禁用复选框，没有说明首次副本解锁；帮助文案只有重铸重置及保留挂设待重解锁。

本次实际拆解报价显示“消耗：无材料消耗；抽取次数：1”，没有收益品名/数量；确认框泛称领域规则；支付后只显示“本次消耗：无材料消耗”“改造已完成”，没有提示新增胶球或首次解锁的模块。它们是观察到的体验缺口，不是挂设奖励未到账。

## 一次真实补操作及机会成本

使用父双核心原周期档，SHA `2f61c5c26094236fc4a293854deb9edb04a08c3105d0a3f40e100258d5976887`。真实选择space:1:3，15级导弹白机，0普通词条、0挂设槽，非究极非传说；未装备、未收藏、未在预设/封存，领域保护判定通过。现役主力导弹60，故该机是现存低级多余对象；仍是不可逆移除一架，放弃其未来现代化/拆给其他随机结果的可能性，不能说毫无机会成本。

原生菜单选择拆解，先预览，再打开确认框，确认前业务状态保持；原生确认后：

- 仓库38→37，移除且仅移除space:1:3。
- 胶球263→264；其他材料及2核心不变。
- 恰一份随机挂设副本：gem_refiner/宝石提炼装置首次解锁，仍level0、exp0；不是免费获一级。
- 所有其他无人机、现役装备、收藏、预设、封存保持。

随后原生选择已有现役space:6:8（60级蓝色非究极导弹机，有1个空挂设槽），打开管理；首次解锁宝石提炼装置可选择，实际点击并应用，无新资源付费。该机hangings由[]→[gem_refiner]，装备总统计有该挂设但数值0。原配置 `pow(1+effect_growth,level)-1` 在level0为0，因此此次仅解锁并验证挂设流程，不能宣称获得了宝石产出增益；还需真实重复副本成长。未为得到重复或有利挂设再抽样、换种子或多拆。

## 最小策略修正建议（未实施）

在自然QA策略space_action的满仓清理分支之外，增加“挂设来源补操作”条件：无人机已解锁且适用模块全锁/存在明确的模块成长目标时，只从真实仓库中选择一个非装备/收藏/预设/封存的低价值多余对象；优先如本次0词条0槽且明显落后现役的白机。继续走forge_choice预览、真实原生拆解确认，不补资源或指定随机副本。保留全部保护边界和可能保留的替换机；一次操作后按实际所得重算目标，不能批量清空或无限追抽指定模块。

首次全锁的来源补动作能填覆盖缺口，但首份0级没有加成。若希望自然玩家策略验证正收益，再以实际取得的重复副本/等级、合法现役空位和机会成本决定是否继续；不可为凑完整而拆高价值候补、预设、收藏或究极。预算/频次应作为可审阅策略选择单独商定，父当前运行不热修改，追加运行要明确区分原始策略与补操作策略。

UI最小改进建议（未实施）：在全锁管理窗口常驻说明“拆解多余无人机获得挂设；首次解锁、重复副本成长”；拆解确认或预览显示品质决定的实际材料/挂设副本数量与随机性质，执行后依据已提交事务的真实奖励展示材料、模块解锁/经验结果。预览必须只读且由领域提供，不让UI为显示结果另抽随机，也不复发奖励。可以保留不提前揭示随机品名的设计，但应明确范围、数量与首次规则。
