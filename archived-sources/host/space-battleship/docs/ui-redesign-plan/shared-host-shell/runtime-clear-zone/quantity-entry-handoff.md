# ×1／×10／MAX 两控件规则：入口与归属

本页记录 `main@e3b38d7b` 的当前实际入口及旧反应堆候选 `8ef154a3` 的接线位置。统一规则已写入唯一规范 [13 §2.3](../../../game-design/13-art-interaction.md) 与 [14 公共前后端契约](../../../game-design/14-ui-contracts.md)：一个数量键循环 `×1 → ×10 → MAX → ×1`，一个购买／升级键执行。切换只刷新当前对象的报价和可购买状态，不下单；业务求值与支付仍由原模块所有。

新布局必须把**报价／费用、数量键、执行键**作为完整操作组重新组织，报价随当前数量同步，执行键有清楚主次与可购／禁用状态。禁止从旧三键排布删两枚留空，或把剩余键拉长充数；具体模块工位、设备位置仍由原组设计。

| 入口 | 当前事实 | 接线所有者 |
|---|---|---|
| `src/ui/equipment_panel.gd` 单槽升级 | `+1`、`+10`、`MAX` 三枚并列键在工位底栏，另有购买键；三个键只改 `_quantity/_maximum` 和 `_dirty`，购买由 `_buy_selected` 提交。 | 装备原组把三键替成循环数量键，并保留独立购买键及现有报价／支付通道。公共壳不改已验收装备内部。 |
| `src/ui/equipment_panel.gd` 全部装备升级弹层 | `_batch_quantity` 是单个三选项 `OptionButton`，`_batch_submit` 执行购买；虽已分开选择与执行，也需装备原组按用户统一循环键语义核对，不由公共壳擅改。 | 装备原组。 |
| `src/ui/reactor_scene.gd` 候选 `8ef154a3` | `×1`、`×10`、`MAX` 三枚并列键在升级区，`_purchase` 执行命令；该场景尚未进入本轮 main 基线。 | 反应堆原组在自身候选实现，之后按模块交接接入；公共壳不移植此内部场景。 |

| `src/ui/archive_panel.gd` 帮助文字 | 旧文案仍写“用+1、+10或MAX升级”，是上述装备旧布局的说明。 | 装备两控件实际接入 main 时同步更新帮助文案，避免提前与当前实机不符。 |
