# P3 修订方向：地表/轨道分工，观看与操作分开

[唯一入口](../../game-design/README.md)及[M7候选规范](../../game-design/art/modules/planet.md)为模块入口；共享风格继续仅引用13@bf359c0d，由装备组维护。本轮获准按新分工继续设计并生成image，图像完成后交原独审及用户确认，未授权实施UI或性能基准。

## 已定与建议

| 对象/职责 | 本轮依据 | 构图处理 |
|---|---|---|
| 空间站 | 用户已定适合轨道绕转 | 保留双翼身份，独立轨道及姿态，与地表不同步 |
| 资源工厂（现有精炼厂） | 用户已定放表面 | 底座贴同一地貌，随地表相位改变位置/朝向，球缘缩短并逐步遮挡；不改其原生掉落贡献规则 |
| 工坊 | **本轮建议地表，未由用户选定** | 压床/加工设施与工业地貌相容；可用另一个地表锚点表现过球缘，保留现有设备身份及装备贡献语义 |
| 船坞 | **本轮建议近轨固定停靠，未由用户选定** | 现有开放U形坞适合轨道停靠，维持当前站位稳定的构图，不擅加公转；仍只承接既有施工/重铸入口，不新增造船玩法 |
| 建筑交互 | 用户已定只观看和状态表现，不需点击建筑 | 场景不承载建筑命中/悬浮操作；选择、领取、人员、探索等全部在独立稳定控制区 |

上一轮“点击建筑/追踪锚点控制/背侧点击映射”的方案由本轮已定交互覆盖。不要因为设施转到背面就隐藏其领取/人员入口，不为新稿增加碰撞体或建筑射线选取。

## 新图构图

仍以待确认的1440×900整窗、左808模块及固定右战场为工作画布；不是main尺寸或最终布局冻结。原P2图稿分区偏差已记录，不能当新稿的精确几何来源。

左模块上部和中段为延伸至边缘的连续轨道空间，无球体内框。球体暂约380px直径、中心约(375,365)，保留大陆、独立云层及固定上左光照。浅暖全局/观察台与深青场景相接，不再在建筑周围摆浮动名称牌和动作。右战场仍仅参照，不另设计舰船或护盾。

- 精炼厂置于正面大陆的一处地貌，双横罐/中央机体与基地接触；基座和投影与局部切面一致，小而有体积，不能是始终面向屏幕的图标。ready只给克制的琥珀状态点，不播放已领取的生产表现。
- 工坊按**待确认建议**放在偏左球缘的另一块地貌：三时刻可呈现正面可辨、侧面缩短、绕到背侧消失，检验贴附而非图标平移。
- 空间站在球外独立轨道，可穿过前后层；船坞按**待确认建议**在近轨保留未完工U形轮廓。建筑均无点击圈、按钮或追踪详情。
- 模块下缘是一块连续浅暖观察操作台，约y=650–900，接续场景边缘而非将球体包进卡片。上段集中探索者/本次进度/自动设置、停止和取消；下段用清楚的设施名称、状态、次数与对应普通按钮组织四行，不给每设施套卡。精炼厂领取与船坞人员入口均固定在台上，建筑遮挡时仍可操作；累计加成/重铸预览紧凑按需进入。
- 控制台按稳定星球/设施ID消费现有公开事实，图像的设施位置不能成为按钮身份。建筑对象本身可缩小，不承担最小点击尺寸要求；按钮/文字仍须在实际工作画布下可读。

同一排版样例延续D68：空间站/工坊built，精炼厂ready，船坞building 38/180、额外人员1/1，探索者1人、自动开启。t=0/4/8为未暂停且人员持续在岗的游戏秒，1×对应墙钟；60秒本次进度68/约75/约81，期间无完成，施工次数不提前增加。动态附图将同一精炼厂绑定到同一大陆，并保持地表/云/固定光源职责分开；分镜是生成设计示意，不冒充实机或精确相位动画。工坊/船坞建议在图外说明，不把“建议”或技术图层文字烘焙进正式UI。

## 两路线的新增贴附/遮挡成本（静态分析，未测）

当前main的设施位置由planet_visual._facility_point及orbital PATHS驱动，全是轨道/固定停靠关系；没有地表经纬锚点或局部切面姿态。不能把地表设施说成改一个坐标即可完成。当前模型图集的通用BODY_SPIN也不能直接用在贴地建筑上：建筑主体必须随同一地貌/地表相位转动，内部Motion部件可另依真实状态呈现。

| 项目 | A：解析球面＋设施呈现 | B：球体网格＋同质量设施 |
|---|---|---|
| 贴附 | 地理锚点记录在前端表现元数据，使用球面同一地表相位反投影；取局部法线/切线更新基座及朝向。不能只把PNG中心移到球面上 | 地表锚点与地表网格共享旋转变换，模型基座沿球面法线放置；复用原GLB，外层变换适配底座，不改Facility/Motion根约定 |
| 球缘压缩/体积 | 平面贴花只能表达贴地轮廓，不能拿它与B完整模型公平比较。若保留同质量体积，可用3D设施图集/姿态采样加解析球面合成，需处理切面方向及近球缘外形，而非固定视角图标 | 模型投影随朝向变化，适量细分的球面及模型相对高度支持轮廓缩短；仍需校对模型底座、穿地与尺度 |
| 部分遮挡 | 仅用基座z正负决定整图显隐会在球缘跳变。完整设施需按其高度/可见轮廓与解析球面遮挡，可能需要片元深度/遮罩或图集深度信息；是新增呈现和维护工作 | 球体与设施在同一深度空间时，不透明深度测试可处理部分遮挡；若分视口再合成，不能免费获得此收益。透明施工轮廓/云层仍需处理排序与遮挡 |
| 云、光照 | 地表设施跟地表相位，不跟云相位；同一固定光向下调整姿态/材质，云覆盖关系须与合成层一致。不能让始终同一光照的图标浮在云上 | 固定光源及独立云材质可沿同一场景组织，但透明云并非自动正确；不默认新增PBR、阴影贴图或体积云 |
| 点击/操作映射 | **用户已撤销建筑交互需求**；不做地表UV反查选建筑，不设计移动点击区。只需普通稳定控件提交既有ID | 同样无需建筑RayCast/碰撞体/投影拾取。3D投影不是操作链，用户不需要等待建筑转到正面 |
| 开销/维护判断 | 少量锚点投影及姿态本身可描述，但模型图集更新、遮罩和额外采样的CPU/GPU/内存均未测 | 增加共享3D场景、模型与深度/视口的成本均未测；地表贴附与局部遮挡的结构较直接，不等于总资源必然更省 |

A的位置关系应与当前shader同一坐标定义：屏幕球面UV加phase.x取地表，因此地理锚点的可见经度应扣去该phase，而不是与云相位或探索elapsed另算一套自转。朝向、足点和局部投影均需同步。B可将锚点作为旋转表面的子变换；Godot的[Node3D父子变换](https://docs.godotengine.org/en/stable/classes/class_node3d.html)支持此类关系。其局部遮挡收益依赖共享深度，[深度精度及透明排序限制](https://docs.godotengine.org/en/stable/tutorials/3d/3d_rendering_limitations.html)仍适用。以上为结合当前源码的方案推断，不是实现或实测结论。

新增要求使B在地表设施姿态/部分遮挡的维护上更有结构优势；A仍可采用解析球体与同质量设施/深度合成的混合路线。**不据此选路线，也不报性能胜者。** 后续比较继续区分C当前图标控制组、A同质量模型设施解析球面、B同质量模型设施网格，不把设施恢复/地表功能新增量全部计入球体路线差异；沿既有不限帧同条件方案，本轮不实施/复测。

## 数据与资产边界

仅表现元数据拟描述surface/orbit/fixed、地理锚点/局部朝向/资产底座，按既有(planet_id,facility_id)关联；不加入业务接口或改保存、随机、支付、人员占用、施工次数与收益来源。读取继续使用09af963c候选已实现的facility_facts/automatic及既有命令，未合main状态不变。图中把精炼厂落地不会把其效果改成新的地表产出系统。

本轮图稿只示范始源星。气态巨星/恒星等非固体天体如何承托资源设施，需后续按星体视觉形态确定，不能把始源星大陆机械套给全部天体，也不能因此隐藏原本适用设施或改开放规则。此待定不阻止已授权的始源星构图出图。
