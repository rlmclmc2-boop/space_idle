## 历史非阻断审计记录（977e602之前）

### C10 identity contract audit

The earlier entry treating absent numeric root/parent receipt fields as an implementation blocker was too strong. Design02 line7 defines canonical attack identity and line157 still requires parent AttackId/type for derived attacks. Design05 lines169/174 require contact identity, generation safety and shared birth snapshots. Design06 line124 excludes live carriers, beams and temporary event queues from saves; Design05 line152 reopens a fresh encounter on load. Current production consumers do not query a numeric parent graph, but that absence does not erase the written parent-relationship requirement.

| Required identity role | Current implementation and evidence |
|---|---|
| One canonical birth and shared rolls/damage | `combat_execution_kernel.h:126` immutable Attack snapshot; `primary` at1525 creates one shared Attack only after finding a valid target and increments root history once. `Instance` at136 and `Timed` at171 retain strong references to that same Attack. Salvo carriers and delayed repeats reuse it, and derived Instance flags separate shared provenance from each finite chain allowance. CR08 snapshot and four-weapon matrix assert this behavior. |
| Derived provenance and no recursive main trigger | Repeats/chains retain the birth object and explicit derived/carrier flags (`launch`/`birth`); strange packets carry copied damage/type/source and a unique event order rather than a retained parent graph. Their typed settlement path suppresses main triggers. Black-hole release similarly carries accumulated raw and its selected owner. Counters create a separate derived Attack snapshot from the selected weapon and do not increment root history; they do not store an enemy-parent graph. These routes have no consumer that queries a parent AttackId. Strange/wild/counter/explosion tests assert source totals, finite packet counts and unchanged root counts. |
| Each contact executes once | Flight pool generation and live state are checked against frozen contacts at1854; target Handle generation/live checks reject dead/reused actors before damage. Beam `next_hit` advances to due+interval and ticks increments at1666, so settled jumps are not offered again. Ordinary impacts retire their carrier. This is single-owner synchronous execution, not an external hit-message stream requiring a processed-HitId hash set. Shared/independent instances have their own finite chain state. |
| One death/drop owner | The positive-to-dead transition is guarded by `hp<=0 && live` at852; generation is incremented before effects continue. DropId is monotonic and host Economy separately de-duplicates registrations. The combined identity probe checks unique drop/source IDs, post-clear cancellation and derived deaths not rerunning the root passive. |
| Save identity continuation | Native `persistent_state` at2278 stores root history, RNG and serial watermarks, not object references. The existing wire name `next_ids.attack` contains `flight_serial` (carrier serial), restored as `projectile_serial` in `Battle.initialize_player` at250 and into flight_serial at2308. It is a monotonic carrier watermark, not a root-to-parent lookup. GameSession's cross-owner validation consumes DropId versus the Economy registration frontier (line187), not root/parent IDs. The checkpoint probe asserts history restoration, nondecreasing serials and actor progression. |

Strong Attack references and generation/ordinal ownership support the current sharing, deduplication and trigger semantics; queued owners keep birth objects alive until their work finishes. Typed derived routes and source snapshots support current damage/statistics consumers. This is not complete representational equivalence to the written identity contract: strange packets and counters do not retain a full parent attack relationship, and `next_ids.attack` is a carrier watermark. Parent incremental review reports no new P1/P2 and classifies these as nonblocking contract differences. Preserve the design requirement and this evidence; do not silently waive it, change save shape, or expand production solely to expose test IDs.

### Drone capacity source conflict

Two distinct limits can coexist: `hyperspace_config` basic parameter `maximum_equipped=5` says "全局装备数量硬上限" and "最终还受当前舰型容量限制". Design 04 says "最多装备2架传说、1架究极以及船型容量允许的总数". `Hyperspace.prepare_loadout` independently checks both the supplied ship capacity and maximum_equipped. Therefore current ship capacity 4 under global hard limit 5 is consistent and is not a gameplay decision blocker.

A separate unused data table, catalog 09's `舰型容量` (lines 773-781), lists Heavy_Battleship capacity 5; the `ship` table lists para_5=4. `Campaign.ship_facts` returns para_5; Session passes that result to equip/preview/preset/ship-change operations, and Battle slices contributions and writes native capacity from it. The current hyperspace owner has no hull-capacity map and receives capacity from Session. Thus the unused per-hull table differs from active ship data, but it is not the global hard-limit field and does not affect current four-drone behavior. No values or consumers were changed. Reconcile that redundant per-hull table in a later configuration-authority review; do not block unrelated acceptance or silently reinterpret it as a hard limit.

`_stage6_legend_overlap_probe.gd` adds native C11 overlap/unload/reinstall coverage: scatter plus three-source laser charge yields 875 damage, removing charge yields 350, removing both yields 100, and reinstalling both yields 875. Other legendary pairs and rebuild/cooldown combinations remain open. The C14 explosion fixture now uses the existing player cannon, avoiding the earlier extra drone-configuration fixture path; its measured times and amounts are asserted directly rather than treating the old unexpected contact as a kernel failure.

### Native proficiency boundary follow-up

The dodge-counter oracle found another floating-point timer boundary: at3.16, exactly two seconds after a1.16 dodge, the old strict comparison still treated cooldown as active. The kernel now applies its existing1e-9 scheduling tolerance to dodge readiness. The fixed-RNG oracle passes after incremental rebuild. Legend fixtures also now preserve explicitly injected drone contributions when publishing their controlled defence values; a default growth refresh instead rebuilds contributions from the formal Hyperspace loadout, which was empty in these fixtures. This explains the absent-effect fixture failure without changing production loadout behavior.

`_stage6_proficiency_native_probe.gd` verifies authored proficiency A1/A2/A3 together, eight B1 focus hits, B2's 1.50 -> 1.05 second interval, and B3 resistance against matching armour. It exposed a native floating-point floor boundary: after three complete focus seconds the old kernel applied two growth ticks (144 damage instead of approximately 173). The kernel now uses the same time tolerance as scheduled boundaries. The new probe and the existing CR01-CR07/CR09 native oracle pass after incremental rebuilding in the existing build directory. The current fixed ledger above supersedes earlier historical gaps.
