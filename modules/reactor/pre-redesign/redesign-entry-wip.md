## 本轮重做动作与完成标准

先从 B01 设计稿确定四设备的各自形体、接口及工作腔，独立生成每件设备资产，不从旧整场景硬裁或拼用有问题的旧设备。生成前在同一源坐标系固定资产原点/缩放、核心出口及四设备入口的中心、轴线、端面尺寸与前后层深度。选可复现的固定接口方法，例如 Blender 几何接口配独立表面；设备资产自带预制接口，管段和运行流光读同一接口数据，不能让随机生成图上的孔口充当精确接口。逐个在源画布与 Godot 原尺寸核设备端面确实套住管口，特别核炼铁斜管，不能靠遮挡图补缝。核心工作需让能量在球内产生、被约束并送入对应出口；停止供能时停止工作动作，正载时变化因果和方向可见。武器、盾、炼铁、凝聚各用符合设备身份的内部运动，退役水波式叠层；静态金属/玻璃和真实工作材质分层，零载与正载的差异须在整屏与正常动态都可辨。

下部控制板重排原生控件：均分完整嵌入金色凹槽安全区，单路名称、滑条、百分比和倍率形成一个读控组，四路仍保持完整行、报价与独立升级可读。以 1/2/3/4 路整屏和连续正常 1× 动态检查主次、读序、字形净空、接口端接及工作因果；参数相等、元素存在或清单逐项勾完都不替代实际品质。Owner 分配/均分、数量循环、费用和拒绝链不改；装备、公共壳与 `main` 不归本轮改动。旧 R5f 上部机械环/实体连接的历史“通过”结论不限制本轮核心和接口重做。

## 本版画面与运行边界

B01 保留中央球形核心、四身份设备和各自短实体管线。新版去掉旧核心图内烘焙的穿球横带，用透明球体源、Blender 前/后分层的实体机械环和两侧夹具组成空间约束；R5c 将两夹具的黑块面改成与环同族的银灰机加工面、凹入导轨和金色接触边。四路端点、轴线和管段由同一生成源分别定义。各条内腔以路径弧长从核心口送往设备口，前后实体层遮挡管线；核心离散事件和四设备各自工作由真实 Owner 负载驱动。正常 1× 视频与整屏均可见，不能仅凭素材目录宣称视觉通过。新核心源和可复现装配命令在[资产入口](../../../../../assets/ui/reactor/b01/README.md)。

当前本组临时宿主只提供 `808×900` 外根、65 顶轨及右侧导航；本组没有修改 `main`、战场或导航。下方浅色完整操作板按 1/2/3/4 路重排原生 `Panel/HSlider/Button/Label`，1 路为双层信息/滑杆组，R5c 倍率与比例处于同一读线，4 路有四条完整行，字形/图标/按钮在实际整屏核对。R3 控件材质最小消费来自 `design/clear-zone-host@6e0e86c80d7cc7ee4f8623fca929c2f4828b6215`。费用消费 Owner 的 `cost_integer_texts`，资源显示走 `PlayerText.resource_number`；不足时只把对应数字置红、图标保原色，点击执行后才出现 Owner 拒绝提示。R5b 预算证据受控入账1000铀，MAX真购11级扣752、余248，后续×1报价272；MAX零可购仍走拒绝链。循环数量 ×1→×10→MAX 仅影响报价，独立升级按钮执行购买。

正式 `unlock.xlsx` 仅 feature/reactor 第1关、condensation 第15关门槛；Owner 前三模块硬开放。1/2/3 路是隔离参数副本，4 路受控开放，不证明自然解锁。分配和均分直接 Owner 接纳，真零关工作光；暂停/隐藏按 Session 时钟与可见性。整数资源事实来自 `feat/amount-safe-previews@f9244a30ad1843128aaa0a620c4dc3e4866685b2`，UI 不重算。规则和视觉口径见[当前 M3](../../../../game-design/art/modules/reactor.md)、[13§2.4](../../../../game-design/13-art-interaction.md)与[07](../../../../game-design/07-verification.md)。

## 性能：上次已报 → R5b 定位 → R5d 限域

R5d 将四设备工作光 `ColorRect` 收至 shader 数学非零包围域：约 148k→20k 屏幕像素/帧；舞台屏幕坐标还原原设备 UV，四路同相位左舞台 `808×835` 逐像素 AE=0。工作光、负载、相位和正常刷新频率未减少。同实例全矩形 A／限域 B：A1 `33.72 fps / 29.66 mean / 28.70 p50 / 34.73 p95 ms` → B1 `35.06 / 28.52 / 28.16 / 33.69`；A2 `33.68 / 29.69 / 28.63 / 34.69` → B2 `34.24 / 29.21 / 28.16 / 34.32`。B1 游戏只推进5.42秒而 A1推进6.02秒，收益有混杂；第二对均约6.02秒，实测为 +0.55fps、mean少0.48ms。相同当前实现的全舞台显示／关闭诊断为 `34.26→44.05` 与 `33.89→44.74 fps`，mean `29.19→22.70` 与 `29.51→22.35ms`，软件渲染仍有约6.5–7.2ms舞台成本。关闭只用于定位，产品保持完整效果。

R5b 产品缓存只在可用集合变化时一次合成静态背景/管壳/控制台，同相位全屏 RGB 零差，但短窗收益小且波动；R5b 核心动态光单项只约0.4–0.9ms，不是全部热点。当前代码的静态节点只在可用路数变化时重建，常态 Owner 模型/报价只在 dirty 时读取；游戏时间连续推进时整舞台视口必须重绘。其余图层/重复纹理赋值尚无单项收益证据，故未以减帧或关效果冒充优化。没有用户目标机器 renderer/分辨率下同场 profile，不能称稳定恢复约10fps，**目标性能验收未成立**。
