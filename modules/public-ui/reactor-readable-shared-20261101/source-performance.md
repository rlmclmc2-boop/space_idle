# 本轮性能记录及限制

上次已实际送用户的旧软件ABAB为31.29→32.33、31.61→32.23FPS（31.96→30.93、31.64→31.03ms），架构/场景不同，不得与本轮拼接。上一制作源a1406959的同方法短窗与本轮并列，不宣称优化收益。

Godot4.7.2/Linux Mesa25.0.7 llvmpipe LLVM19.1.7 Compatibility，1440×900，左808×835，真实四路25%快照；固定战场和Session tick，视觉1×。无录制/其他Godot或Blender并行，每窗5秒，同进程显示→冻结→隐藏→返回。两次启动未锁定随机战场像素，不是严格单变量ABAB。

冻结窗有明显长帧尾部，原因未由此短窗定位，不能据此归因到某个特效或宣称CPU更新成本；不删除该窗口换漂亮数字。显示/隐藏整帧差分约5.37–5.80ms，不是独占GPU成本。四窗Owner/报价/预览/命令增量0，界面直接子节点30不变，静态采样增量0，初始3次。接收光面在其不可能发光的阶段不绘制，未降时钟/删效果换结果。

正常两段视频是有录制的另一场景，25fps源视频不等于游戏恒定25fps。没有证明用户机器约10FPS损失已消除，目标机仍需要同构建、同战场的显示/关闭基线。本轮只做当前效果改动的性能观察，不把目标环境缺口当无限新增测试。
