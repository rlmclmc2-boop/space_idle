## 2. 可检查契约

**D01-1 容量与等级。** 对可表示且配置有效的目标等级，能源乘积、`floor` 容量、逐级 `ceil` 费用采用可持续增长表示；普通有限域结果与基线一致。整数容量保持整数语义，永不因 float→int 溢出变 0、负数、INF、NaN 或饱和。等级不加新的玩法上限。

**D01-2 分配守恒。** 每模块 `allocation≥0`，总分配 `≤floor(energy)`，剩余 = 容量−总分配且非负；单模块更改保留其他模块；均分保留原商/余数顺序。已有合法存档的分配加载、保存、便携往返后逐项相同。容量因配置真正缩小才按现有顺序约束，不能因表示失败伪缩小。

**D01-3 免费充能与倍率。** 免费比率保留在手动容量之外，按照旧公式恰加一次；有效比率和 `pow` 不出现非有限值。视觉比率可以夹到 [0,1]，游戏倍率不能因此夹断。超 native 支持域按显式能力路径处理。

**D01-4 交易原子性。** MAX/x10/单级逐级报价并在扣费前完整比较；不够时无副作用，足额时扣恰好总价，升级后新容量、分配、缓存与事件一致。S07 缓存失效不能回退。

**D02-1 单价。** 每资源每目标级保留 `base×(1+multi)^(level−1)`、原 `<100` 分支、原十进量级四舍五入形式以及最后的 `ceil`；进化材料只在原间隔级出现。普通有限报价逐项回归一致，包含临界 100、十进位进位和 .5 步边界。高阶不以近似几何和替代逐级量化。

**D02-2 批量、MAX、扣费。** 对每目标级已取整的价格逐资源相加；批量总价可比单价先跨 float 边界。所有比较与扣费使用相同报价对象和大数域；MAX 找到首个不可负担级，不能基于显示值、纯未取整几何和或浮点近似决定购买次数。多槽批量顺序不变；缓存失效覆盖钱包/配置/等级改变。

**D02-3 展示、存档、native。** 单价、x10/MAX 总价、余额和不足额状态不能显示 INF；缩写仅 UI。旧合法资源和装备级数往返，支持 `{m:1,e:400}` 等已合法资源。native 支持域内复核，超域明确 legacy 交接或无副作用拒绝；任何路径不能先扣费后发现不支持。

## 4. 迁移、支持与拒绝边界

- S10/S12 保存与便携导入必须覆盖旧版合法有限数字以及已支持的资源大数字典。若容量/分配需新增编码，只在受影响字段增加版本化识别；先完整语义校验再提交 live state。旧档不得因为新编码缺失被一概拒绝，非法数值不得通过字符串或非规范字典绕过校验。
- 对合法旧档，加载前后的资源、装备等级、反应炉等级和每模块分配均可核对；迁移不得自动退款、额外收费、补发免费能量、重置分配或改已购数量。只有真实容量变化适用已有约束规则。先用合成旧档及导入前备份做往返。
- 支持：有效非负资源与费用、大数容量/分配/剩余、原规则允许的目标级、逐级批量及原玩法倍率。拒绝：负数、NaN/INF、畸形 `{m,e}`、非整数等级/分配、未知模块/货币和计算不可表达的非法配置；拒绝应在副作用前给出原因并保留状态。表示或引擎能力边界必须记录为技术限制，不能悄悄当作新等级政策。
- native 的能力矩阵按实际 DLL 和编译器检查逐路径登记：反应炉更改、装备单次、装备 x10/MAX、银河重配；分别给出有限域 PASS、超域 legacy 交接或拒绝的证据。S09 只定义期望，不宣称测试已运行或 native 已支持大数。
- 本阶段不决定 S20 模拟器的 float 域政策，不改伤害成长、装备属性、船员收益、离线收益或配置值。若实现发现原规则无法推导且会改变经济结果的边界（例如现有大数 helper 精度不足导致临界报价不同），保留复现和候选选择报父级；D01/D02 本身无需再询问。
