## 政策与优先级

用户明确说：“极端max完全不用完全精确,大体数量级对就行了”。本修订优先于旧 P0、性能预登记和 V3 场景中关于极端 MAX 精确最大数量、逐级精确累计作为全阶段前置的要求。普通 x1/x10、科研、收入、保存、退款及其他交易不改为近似。用户未明确批准额外扣费、折扣或改变退款。

撤销极端 MAX 必须求出精确最大数量及必须先构造从1到十亿级精确累计钱包才能推进的绑定。旧两秒/十秒等目标的失败记录保留，不改判 PASS；旧精确压力场景成为历史/可选研究证据，不能继续绑住整个交易阶段。新极端查询验收以安全数量、已批准费用规则、真实响应性和明示精度为准。账本4毫秒目标及其他未冲突要求未由此次授权自动撤销。

## 已批准范围内可实施的最小规则

令旧规则逐级取整后的资源总费用为 C(n)，材料费用为 M(n)。查询可用快速、向外舍入的上下界 L(n) <= C(n) <= U(n)，以 U(n) <= 当前资源余额且 M(n) <= 当前材料证明 n 安全；数量向保守可支付侧取整，不要求找到最大整数。材料保持原解锁/逐级费用规则，可用等价闭式累计，不允许近似产生材料或越过int64。

“证明能买 n”与“本次实际扣多少钱”分开：U 仅用于安全性证明时不是已授权扣费额。若已在有界工作内得到 C(n)，按该准确费用报价和提交；数量仍可估算。禁止先展示估计费用，提交时偷偷改用另一费用；禁止把金额转float扣除，或负余额夹零。余额/配置/等级/profile代次变化使计划失效；同一报价对象绑定数量、费用、材料、规则版本与依赖，提交重验后一次写入。多槽购买仍按原顺序逐槽允许部分成功，单槽x10及整批退款维持原子性。

不能以“购买前遍历全部等级算精确费用”重新引入阻塞。仅放宽数量未必解除 C(n) 的成本；不能因为这个缺口声称本政策无效，也不能直接把 U 当 C。

## 若精确整批费用仍阻塞：唯一待确认的最小费用选项

建议供 dot 提交用户决定：**仅极端 MAX，按公开的保守总费用上界 U(n) 报价并扣费**；n 的选择同时保证 U(n) 可支付。普通单价、x1/x10及材料不变。此规则可能比原逐级总价多扣资源，必须明说，不能称为只近似数量。费用区间过宽时减少数量或提高区间精度；不得收费超钱包，也不得把所有钱包扫空作为默认费用。

如果采用该选项，必须同时冻结可接受费用偏差及退款规则。本审计建议保留既有按等级计算退款，不默认退还上界溢价，并明确这可能造成额外净支出；这也是待批准内容，不能静默实施。另一条不改变经济规则的退路是保持准确费用、只提交能在预算内准确报价的保守批量，但必须诚实标明该批量可能达不到“大体数量级正确”，不能冒充已满足极端 MAX。

本次没有为全部交易引入近似，没有创建新货币编码，也未授权上界溢价。若 dot 找到不逐级枚举且足够快的准确费用算法，则无需启用该费用选项。

## 切换、显示与验收收敛

切换不依据固定等级上限：由报价工作预算、可证明费用区间和数量不确定性选择 exact/approximate 模式。普通路径可快速完成时保持现规则；相同输入不能仅因机器快慢而无标识地改变已确认的扣费规则。一次报价固定模式，提交不重新偷偷选模式。UI 标明“约可购买 N 级”、本次确定扣费/材料；未完成、失效、不可支付分别表达。跨切换边界比较同一输入下的数量与费用，避免突发大幅跳变；精确上下界重合时两模式结果应一致。

“大体数量级”尚非明确误差常数。dot 可先选择可审查的工程提案：在有上下界证明的样本中，保守数量与最大可支付数量上界之比至少为1/10；达不到则报告精度未满足，不返回看似可靠的 MAX。此比例是待双方审定的实现目标，不冒充用户逐字授权，不影响安全性硬约束。若启用费用近似，费用偏差必须另外确认，不能用数量十倍区间推导可接受十倍收费。

本轮只保留三个决定性验收点：①真实主线程响应与取消，不能用自我call_deferred续排当跨帧；②精确账本提交/保存及非法输入无副作用；③极端查询的保守数量、材料、预览与扣费一致，且无全量逐级最终复验。无需重做全域数学证明或将历史压力场景改判通过。性能实测应覆盖实际公开入口，不只计内核。
