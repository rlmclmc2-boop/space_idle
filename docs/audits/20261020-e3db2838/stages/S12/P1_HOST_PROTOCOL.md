# P1 finite host protocol and handoff map

The audit-only `p1_proto/p1_host_contract.py` is one owner for the finite transaction models, backed by `ledger.py`, `price.py` and `transaction_model.py`. The profile remains a Dictionary-like plain object. Untrusted load data are copied and validated once; a failed import invalidates the prior session. A purchase ticket binds host object identity, generation and a full source snapshot. The owner never publishes a mutated input alias. A successful command publishes one replacement profile; failure, cancellation, stale, zero purchase or unsupported input publishes none. `test_p1_host_contract.py` exercises this owner; its Python types are a semantic interface model, not a claim of GDScript or native isolation.

| Audit call/outcome | Existing main call/write site at `31e7933` | P1 assertion and P2 responsibility |
| --- | --- | --- |

| `batch(slots)` | `game.gd:2875 upgrade_equipment_batch`: weapons then defence; each success visible to next slot, final `upgrades_completed` | Shadow executes that order; middle failure does not suppress later affordable slot, then one publication of the resulting ordered receipt. P2 verifies real partial events/native interaction. |
| `refund(slots)` | `game.gd:1093 refund_all_equipment`: whole equipment refund and material credit | All material/resource totals and save-size preflight on a shadow; overflow returns without any resource event/write. P2 validates game mutation order. |
| `research_step(dt,rate)` | `ai_tech_tree.gd:126 advance`: shrink paid step to available input, then continue baseline research after depletion | R-HALF spends the exact 0.5 input for 0.5 second and advances the full one-second request, with the remaining half basic/unpaid; no float projection is written back as wallet authority. P2 supplies real speed, progress, completion/events and native before-change behavior. |
| `collect_source(index)` | `game.gd:2685 collect`: amount credit, sample/run/peak updates, source removal | Source amount and `production_base` remain distinct; validate/credit before removing a drop, on one shadow. P2 checks actual collector and source event payload. |

Tamper, stale or kernel rejection leave host unchanged; accepted descriptor publishes once. P2 checks a real DLL/handoff and that actual slot set matches planned slots. |

The host returns `ready/committed`, `insufficient_resource`, `insufficient_material`, `not_affordable`, `stale`, `unsupported_mode`, `unsupported_level_representation`, `invalid_*`, `material_overflow`, `save_size`, `descriptor_mismatch` or `handoff_rejected` as applicable. Ordinary x1/x10 have no MAX approximation dispatch. A `max` request is explicitly `unsupported_mode` in this finite Python host until a separately validated Godot `MAX-APPROX-v1` quote and certificate are bound to the same owner/revision. The current [Godot MAX prototype](P1_PARAM_MAIN_FAMILY.md) demonstrates that quote and same-quote debit for its supported six-row family; a serialized external quote is **not** accepted as authority by this Python host. This is a visible remaining P1 interface join, not a product shortcut.

The Python ledger accepts old int64, finite float, `{m,e}`, v1 decimal and experimental v4 sparse inputs. V1 conversion now consumes four-digit chunks, so a legal old decimal wallet beyond Python's 4,300-digit integer parser limit keeps its low units; the audit test uses 5,000 digits and an old `{m:1,e:1e308}` gap. Failed real resource allocation remains an explicit exception path to report; no fixed value or exponent cap is introduced here. The prototype does not prove full save/portable round-trip, UI, native DLL or the game's complete legal input domain. Those remain P2 runtime work or a concrete P1 blocker if the public audit interface cannot preserve them.
