# P1 finite host protocol and handoff map

The audit-only `p1_proto/p1_host_contract.py` is one owner for the finite transaction models, backed by `ledger.py`, `price.py` and `transaction_model.py`. The profile remains a Dictionary-like plain object. Untrusted load data are copied and validated once; a failed import invalidates the prior session. A purchase ticket binds host object identity, generation and a full source snapshot. The owner never publishes a mutated input alias. A successful command publishes one replacement profile; failure, cancellation, stale, zero purchase or unsupported input publishes none. The prior 23-test aggregate was **7 same-host protocol tests, 6 pre-existing transaction-model tests and 10 ledger/price tests**, not 23 same-host cases. `test_p1_host_contract.py` exercises this owner; its Python types are a semantic interface model, not a claim of GDScript or native isolation.

The host returns `ready/committed`, `insufficient_resource`, `insufficient_material`, `not_affordable`, `stale`, `unsupported_mode`, `unsupported_level_representation`, `invalid_*`, `material_overflow`, `save_size`, `descriptor_mismatch`, `handoff_rejected` or `partial_handoff_stop` as applicable. Ordinary x1/x10 have no MAX approximation dispatch. A `max` request is explicitly `unsupported_mode` in this finite Python semantic host: a serialized external quote is never accepted as authority here. The [Godot MAX audit host](P1_PARAM_MAIN_FAMILY.md) owns its own quote and same-quote commit in one host/revision boundary for the supported six-row family. Its legacy-wallet bridge now uses the earlier reviewed arbitrary-position sparse core to accept old int, float, `{m,e}` and v1 wallet inputs without expansion across the exponent gap. The two languages demonstrate the contract at different boundaries; no production dispatcher or shared runtime object is asserted.

The Python ledger accepts old int64, finite float, `{m,e}`, v1 decimal and experimental v4 sparse inputs. V1 conversion now consumes four-digit chunks, so a legal old decimal wallet beyond Python's 4,300-digit integer parser limit keeps its low units; the audit test uses 5,000 digits and an old `{m:1,e:1e308}` gap. Failed real resource allocation remains an explicit exception path to report; no fixed value or exponent cap is introduced here. The prototype does not prove full save/portable round-trip, UI, native DLL or the game's complete legal input domain. Those remain P2 runtime work or a concrete P1 blocker if the public audit interface cannot preserve them.
