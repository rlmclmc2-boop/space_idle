# Frozen P2 reproduction notes

Use [P2_FINAL_DELIVERY.md](../P2_FINAL_DELIVERY.md) and [P2_FINAL_OBJECT.json](../P2_FINAL_OBJECT.json) for results and immutable hashes. Raw PASS markers do not override a receipt FAIL or the open combined heartbeat gate.

The runners expect a sandbox layout with sibling `p2-runtime` (Git clone), `p2-validation` (this audit tooling) and `p2-audit`. Copy these tooling files into `p2-validation`, with a separate `game-project` stage. Substitute local engine/root paths only when reproducing; retain the recorded engine and DLL hashes for a same-environment comparison. Use the direct Godot executable, not the console wrapper. Required engine is 4.7.2.stable.official.ed1daf0bf; DLL is the unchanged candidate `tools/player_runtime/space_native.dll`, SHA256 `4f19359bebcccb38d0d32ff27fc9bd887d98bef0afac5212fe440aaa1ac5b11f`. Supply the public Git CA bundle as `ca-bundle.crt`; no credentials or saves belong in this tooling tree.

First stage/import the clean project with `python run_game.py --git-ref 062168c31017a53686da53488cfeefef473b542b`. This copies project assets and writes only isolated stage/APPDATA/LOCALAPPDATA paths. GPU assets need editor import. Then use the same command with `--probe`, `--native-probe`, `--chain-probe`, or `--ui-probe --gpu`. Each invocation overwrites stage scripts with Git archive bytes before launching, emits a receipt and preserves raw streams. Run sequentially because these scripts share the stage.

Core: `python run_core.py --runtime game-project`, then `--script query_probe.gd`, `--script finite_price_probe.gd`, and `--script finite_max_probe.gd`. For each of the latter two output directories run `python finite_oracle.py evidence/<run>`. The independent Decimal oracle covers the declared fixed six-row family and samples; it is not a universal arbitrary-config proof. Runners hash materialized modules; the final object manifest verifies those hashes against the runtime commit.

Frozen matrix: `python run_cold.py` pins the final runtime SHA and four existing classes, ten fresh processes each. Combined: `python run_workload.py --runtime-ref 062168c31017a53686da53488cfeefef473b542b`. Do not use diagnostic `--trace-*` flags for acceptance, and do not use run_workload's old default freeze. Its 45-second runner guard is separate from the 50 ms heartbeat acceptance gate. RSS sampling reads only its own child handle.

The baseline-save runner is a historical diagnostic: it temporarily materializes pinned main and restores an older WIP stage. Run it only in a separate diagnostic stage or restage the final candidate afterward. Its PASS is execution/semantic success, not a timing PASS. Earlier run probe versions are available in prior audit commits; final probes and two corrected fixture FAIL variants are retained here. Synthetic `user://` files, application caches, public CA copy and generated import caches are excluded from Git. Do not point any runner at personal APPDATA or the user's original checkout.
