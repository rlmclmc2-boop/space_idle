# S12 sparse core: audit-only checkpoint

The prototype and its contract are in `probes/sparse_wallet_core.gd` and `SPARSE_CORE_PLAN.md`. This checkpoint does not alter the pushed runtime candidate `82492c5ed267044e66840ed3fd99e9aad707b814`, does not close S12/A07, and does not authorize a main merge.

Reproduce: copy `probes/sparse_wallet_core.gd`, `probes/audit_s12_sparse_core.gd`, and `probes/sparse_decimal_oracle.json` to `space-battleship/test/`, then run Godot 4.7.2 console with `--headless --path space-battleship --script test/audit_s12_sparse_core.gd`. Raw output: `logs/sparse-core-audit.log`.

Result: **3290 checks, zero failures**. The audit covered both operand orders for `10^1000000000 - 1 + 10^1000000100` (three nonzero blocks), subtraction back to each operand, distant borrow/refund, cancellation and zero, exact difference one, fractional binary64 income and reversal, JSON round trip, malformed/duplicate/out-of-order position and digit rejection, negative balance, and a legacy exponent beyond int64. It also compared 1000 seeded small random integer pairs against native integer operations and 250 seeded binary64 sums against independent Python `Decimal.from_float` vectors generated by `probes/generate_sparse_decimal_oracle.py`.

The parent review of the previous audit object found an actual v2 JSON regression: `delta:1234` parsed as `1234.0`, and direct digit string splitting changed the debit to `120034`. The corrected core obtains canonical integer digits with `ReactorInteger.command_floor` after strict v2 validation. New matrix checks small integer delta, large v1 delta, and fractional `places` values before and after JSON, converted to v3 and refunded to the original base; all pass. The earlier 3273-check object remains superseded, not accepted.

The prototype has not yet been wired into `GrowthNumber`, quote/cache, save schema, native handoff, or actual pickup. In particular, the current one-base runtime still rejects an independently distant large income before effects. Runtime replacement must also verify actual block-count/work/document-size limits and the local income factor path; the audit test alone is not a transaction PASS.
