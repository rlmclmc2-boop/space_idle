## Method and invariant

`max_approx_probe.gd` quotes the first 257 levels with the original exact price function. If the 257th purchase is not affordable it returns an exact count in 0..256. Otherwise it searches the first unaffordable count using a conservative fee upper bound and exact material total; if 257 is not affordable under that bound, it returns 256 with its exact fee. It does not scan the extreme count level by level. The threshold chooses the rule, never a gameplay level limit.

For the remaining terms, `approx_bounds.gd` derives the exact decimal coefficient of the binary64 growth factor, then uses directed 32-digit interval arithmetic and binary power/series composition. The experiment encloses the original rounded high-price branch with 0.95 and 1.05 times the unrounded geometric sum. It produces sparse integer bounds `L <= C <= U` and verifies `25*U <= 28*L + 24`, equivalent to the amendment's `U <= ceil(1.12*L)`. The price printed in the quote and removed from the wallet is the same `U`; material `M` uses the exact tier sum. A failed bound, arithmetic, material, wallet, or host check returns an explicit failure without a live debit. The finite original-price inputs through target 3872 were checked individually; the fixed higher-level analytical enclosure and the directed-series implementation remain a fixed-configuration prototype, not a universal pricing proof.

The fee calculation runs in a Godot worker while the main thread awaits frames; 257-item setup also yields. The search uses exponential bracketing and binary search, then records the next rejected candidate. It does not stop at a clock deadline or substitute a truncated affordable count. The synthetic `HostState` keeps a Dictionary profile and binds the quote to owner identity, profile/config identity and generation, full snapshots, and exact quote text. Commit rechecks them, calculates both debits, then publishes one replacement Dictionary. A future product interface must still prove equivalent ownership and save admission.

## Raw evidence and independent checks

The `p1_proto/exploratory_approx_*_freeze.{stdout.log,stderr.log,meta.json}` triplets are the frozen Godot 4.7.2 Windows executions, generated through `run_probe.py` with isolated app data. Their JSON `success:true` and process exit 0 are prototype outcomes; the engine also printed shutdown RID-leak diagnostics, retained in the raw logs. `verify_approx_bounds.py` independently builds the exact binary64 factor with Python Decimal and checks six count intervals plus 3,617 original finite-price targets; see [raw result](p1_proto/exploratory_approx_bounds_independent_1.log). `verify_approx_quotes.py` reads the fixed compact Godot price export (`6b376b85a21a303481f1e64a88f44ec956777018edab1fbc636c540c40aa5f15`) and compares exact totals, material, displayed/debited fee, wallet remainder and the next boundary for the ordinary-size samples. Its [later sparse readback](p1_proto/exploratory_approx_quotes_independent_sparse_1.log) adds the exact far-wallet balance identity described below; the [first readback](p1_proto/exploratory_approx_quotes_independent_freeze.log) remains historical evidence.

The later [independent sparse readback](p1_proto/exploratory_approx_quotes_independent_sparse_1.log) uses the fixed old wallet `10^1000000000`, the logged fee and the logged new wallet as three separate operands. Its Python base-10000 signed-coefficient reducer checks `old - fee - new = 0` **exactly**, carrying only across occupied neighboring positions; a one-unit perturbation is detected. It also checks wallet nonnegativity and `25U <= 28L + 24` with exact sparse integers. The first 256 prices come from the fixed independent price export and are summed exactly before being removed from the reported far-distance L/U bounds. A separate directed 120-digit Decimal computation cross-checks the distant **tail's scale and enclosure** for the fixed binary64 factor; it does not independently reconstruct every original price in the 848-million-item range. Exact material consumption and the next-tier stop are independently calculated. The previous readback's candidate `remaining_matches` Boolean and 120-digit Decimal wallet projection alone did not establish low-unit conservation; this new sparse identity does. The claimed original-cost enclosure beyond the finite export continues to rely on the fixed high-price branch reasoning and directed interval arithmetic documented above.

The `stale`, `wallet_stale`, `config_stale`, `silent_replace`, and `tamper` frozen triplets all reject without an additional live debit after, respectively, host replacement, in-place wallet change, config replacement, equal-value Dictionary replacement, or changed quote text. The `cancel` triplet requests cancellation during worker activity, reports `cancelled` with no live change, and measures 31.024 ms from request to stop with a 16.694 ms maximum observed frame gap. The worker does not stop mid-fee: cancellation is observed only after its current fee calculation finishes and the main thread rejoins it. These are single-process exploratory observations, not a universal cancellation bound, ten-run certification or proof that every front-end dependency has been captured.
