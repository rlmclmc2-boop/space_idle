## 3. 最小接口及强制边界

名称可调整，职责不可合并为另一套任意 Variant helper。公开入口有类型化值、结果和错误；编码字典只在 profile/存档边界出现。

| 接口能力 | 输入/结果 | 禁止项 |
|---|---|---|
| decode_legacy / decode_storage | 合法旧有限数、m/e、v1及明确保留的候选编码 → CurrencyValue 或 error | 非法值默认零；暴露 live 可修改块；任意字符串强转 |
| from_generated_income | 原生成数值 → CurrencyValue 或 error | 把 UI/报表投影作为权威收入 |
| price / price_sum | 冻结配置、等级 → PriceResult；逐级价格先取整后求和 | 显示值参与定价；未取整几何和冒充总价 |
| compare / add / subtract | 类型化货币值 → typed success/error | 减法静默夹零；通过 parts/float 近似实际余额 |
| plan / commit | 独立快照、费用/收入及依赖 → Plan；重验后提交 → Receipt/stale/rejected | 计划阶段写 live；过期提交；原地改块；部分单槽写入 |
| finite_research_balance | 已确认有限不足额分支 → 原时间计算所需的有限值/明确失败 | 用通用显示投影决定能否支付；改变科研微量清零 |
| encode | CurrencyValue → 独立规范存储值 | Object 直接 JSON 序列化；共享 live 嵌套引用 |
| display / analysis_projection | CurrencyValue → 明确有限投影或 out_of_domain | 以 0/INF伪装成功；投影作为交易输入 |

纯账本运算只有 success/error，**没有业务 pending**。只有 MAX 的 QueryOutcome 有 pending/complete/stale/cancelled（非法输入/资源失败另有 error）。查询完成不等于购买完成。

Plan 至少包含相关钱包/材料快照、目标槽和等级、报价配置与解锁依赖、profile 代次及操作身份。提交前复核；profile 整体替换也使旧计划失效。expected 的前序单槽扣费不能误作外部 stale；事件回调额外修改必须重新验证。回执保留 source amount、实际成本和成功槽，不凭余额差生成生产样本。

GDScript 下公开 Dictionary 仍可被绕过。P1/P2 必须交资源写入允许清单、typed 边界校验、快照隔离证据，以及权威路径新增 float/parts/通用近似操作的检查；不声称编译器已经完全禁止绕过。类型化对象仅放接口内部，不要求迁移整个 profile 对象图。

## 4. 原子语义、事件与 native

- 单槽 1/x10/指定数量：本槽完整报价和全部货币一起预检；本槽成功或零购买，不自动缩为买得起的级数。
- 多槽购买：按 weapons→defence、各槽索引顺序；允许部分成功，失败槽不扣费但继续后续槽；后槽使用前面成功后的余额。不能改为整批全有或全无。
- 多槽 MAX：同样按上述顺序及剩余钱包计算。查询/计划不得把各槽都绑定到初始未扣费钱包。
- 原 bool 返回语义为“至少一槽成功”；内部回执记录 changed_slots 和逐槽结果。completed 不代表全部槽成功。
- `upgrade` 按实际成功槽发布；最后 `upgrades_completed` 仅含实际成功槽。资源事件、失效、属性更新及通知相对顺序须对照基线，不因回执设计随意重排。
- 整批退款：按已确认要求先汇总、全量预检再提交；任意货币/材料失败不得先返还部分资源。
- 反应炉批次：保留 S09/S10 独立契约和普通域累计规则；新增精确余额域保持逐级报价精确守恒。
- native 预测必须使用同一单槽顺序、余额与保存条件；描述符只对应实际成功配置。计划偏离时不得提交旧描述符，不得为描述符一致性撤销已合法完成的槽；安全交接失败路径必须验证。

依据：main `game.gd:upgrade_slot/upgrade_equipment_batch/upgrade_reactor`、`native_execution_session.gd:prepare_numeric_batch/commit_numeric_batch`。事件重入、单槽提交和 native 所有权之间的可观察顺序尚需 P1 建模及 P2 实际验证，不能用“原子”一词代替证据。

## 6. 价格算法、MAX 与性能约束

价格按 S09 全部分支：一级/无倍率直接 ceil；成长零值；0<v<100 的 floor(v/10)*10+5；大值量级量化；逐资源 ceil；进化材料。中间 pow 溢出不证明最终金额>=100。快速区间算法须证明外向界、边界歧义处理和原规则等价，不能只测典型高价。

MAX 是只读查询。输入包括起始等级、货币预算、完整报价/进化配置、解锁状态和 profile 身份。未完成不等于 0/不足额；查询不自动排队购买。购买时重新验证当前状态。

价格前缀/游标按完整报价配置复用、钱包只重新比较，是**待比较选项**，不是指定实现。必须分析内存、生成成本、钱包减少回退、等级/配置失效；不能以简单 revision 重启宣称避免饥饿。持续收入增长快于计算时可能永不追上，应如实显示 pending，不提交旧 MAX。

P1 必须区分：单次工作/取消响应、稳定输入完成时间、持续变动正确性、巨大范围未证明边界。逐级枚举十亿次即使可续算也可能不实用；外层预算不约束单级报价内部耗时。不得新增永久等级/余额拒绝上限。真实资源失败可报告，但不可掩盖表示或算法缺陷。

P1 开始前由 dot 确认测量平台、单次工作/取消时限、稳定查询目标时间及代表规模；先登记再测，不见结果后改门槛。未确认时可交正确性研究，但性能门禁只能 PENDING，不能整体 PASS。至少覆盖现配置普通域、3873、4001、10000、50000及十亿等级的报价/查询可行性；高等级案例注明配置、材料和钱包，不能用立即不足额冒充大范围搜索完成。
