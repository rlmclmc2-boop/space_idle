# P2 有限精度规则修订（待同对象双审）

唯一入口仍为 [IMPLEMENTATION_PLAN.md](../../IMPLEMENTATION_PLAN.md)。本修订仅替代 [接线契约](P2_WIRING_PREREQUISITES.md) 中资源余额/大额结算的全尾数保真前提；其余接线、恢复和最终双审要求保留。授权：用户“简化继续”，`Sentinel_51be8bfcc91c8191b9ae2bc15ed0ae0a`；表示及单次结算允许约 0.001% 误差，旧余额允许一次性有界舍入，不承诺无限累计误差。

1. **有界表示。** 每个资源固定一个主值和一个有符号残差；各保留 9 位十进制有效数字（约 6 位目标加 3 位保护）。分量为 int 系数及规范有符号十进制指数串，指数用整数快路径/字符串加减，不展开指数间空位；零唯一。主值非负，残差绝对值不超过主值最后保留位的半单位；归一化可进/借位、残差可晋升。每次运算至多处理固定数量分量，不保存不断增长的尾数块。候选资源 schema 为 `{currency_version:2,main:{c:int,e:String},residual:{c:int,e:String}}`，`c` 可有符号（主值除外），非零 `|c|` 为 100000000..999999999，值为 `c*10^(e-8)`；零分量固定 `{c:0,e:"0"}`。
2. **误差口径。** 非零金额的转换/报价相对其原规则金额误差目标 `<=1e-5`；余额归一化相对其输入分量之和也以此为目标。金额以确认/入账记录为准，不用两个已舍入余额之差反算；这不保证每个远小于已有残差的来源永远保留。内部采用最近舍入、正中取偶，9 位提供余量；不要求逐位 binary64 往返。零单独处理。近零结果重新定阶，不用全局绝对 epsilon 归零。该口径不是连续任意次交易后的总误差保证，也不是把 MAX 已批准的费率估计误差改为 0.001%。
3. **有限累计。** 每次收入/扣款的舍入余量进入同一资源的一个残差，后续收支先合并该残差，再归一化；残差随存档持久化，不因刷新或读档丢弃。这样保留常见小额收支累计，不宣称保留无限多个相距任意指数的来源尾数。单个残差也只保留 9 位；其余舍入损失受本次上述预算约束，不扩展为现金流队列。
4. **临界支付。** 报价先规范化，展示与提交复用同一金额/指纹。按当前“主值+残差”比较可支付性，不用 0.001% 容差把不足判为足够，不扣后再饱和为零。支付后余额非负；无法满足此条件则该次零写入。量化后的极近临界结果可能与旧全尾数判断不同，这是本次有界表示的可见变化；不额外赠款、扩大数量或重复扣款。科研保留既有 `remaining>1e-10`、严格小于的微量清零和两类 no-op，在新表示上判断；只转换已证明不足的有限余额，取消 1200 位/逐位舍入证明。
5. **价格与 MAX。** 普通单价的现有公式、分支和取整保持；x1/x10 保留原逐级/顺序语义，结果接有界金额。已验证单价资产可保留，停止追求任意尾数。在已批准六行成本支持族内，大批量原规则费用/退款用有限末段累计及剩余尾项界，在上述单次误差预算内停止，不按等级数遍历全区间；不能直接把 MAX 收费 U 当退款。MAX 继续固定预算异步查询、当前钱包新票和同报价确认；其已批准的保守 U/12% 费率政策独立保留，证书核对规范化后的 U，不恢复全局 v3。
6. **加载/保存。** main 已支持的 int/float、旧 m/e、ReactorInteger v1 资源值仍接受，首次转为新主值/残差时一次性有界舍入；随后写固定 schema，读回保留这两个分量。旧 WIP 的 CW1 只作本线程测试/内部转换资产，不新增个人历史格式义务。材料及等级保持原整数契约，其他 ReactorInteger 字段不变；普通/备份/portable/import 共用校验，失败保留 live 和恢复材料。

保留异步 MAX、UI 确认、crew/batch、native 聚合、收入来源事件/统计及恢复保护。只替换现有资源数值模块和必要适配；不增加压力档。验收针对误差预算、有限残差累计、临界支付/非负/重复确认、科研原行为及保存往返；旧“任意尾数仍存在/逐位浮点一致”的断言不再作为新政策门槛，原 FAIL 留档。保存停顿分别报告：基线 main 已测约 438 ms；P2 token 及数值新增开销单列，不顺带重写全存档。
