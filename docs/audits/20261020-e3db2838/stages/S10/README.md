# S10 implementation blocker — representation boundary

Status: BLOCKED for parent review. No product code changed. Runtime candidate `s10/reactor-numeric` starts at main `cf213e2f36e4b0ec60a0629e2ed641ac93ef5cd8` and has no commit. S09 contract: `0442a1b627a07fa1af0d0671cdeb97dd070c5efc`.

The S09 requirement is to preserve an exact nonnegative integer allocation and remaining amount beyond the signed 64-bit boundary, retain the free-charge contribution once, and keep the original multiplier with no new gameplay cap. Two existing representation boundaries prevent an implementation by merely replacing `int` with `GrowthNumber`:

1. `space-battleship/scripts/growth_number.gd` uses a binary64 mantissa. `add({m:1,e:20}, 5)` forms `1.0 + 5e-20`, which rounds to `1.0`; `subtract({m:1,e:20}, 5)` likewise forms `1.0 - 5e-20`, which rounds to `1.0`. Such values cannot preserve a module's small allocation or the exact remainder, nor perform the integer quotient/remainder required by equalization. The current `game.gd:1200-1298` additionally uses `int`, `float`, `maxi`, `clampi`, `/` and `%` on these values. A distinct exact integer representation is required for D01-2 and save transfer; a `{m,e}` capacity alone cannot meet it.
2. `game.gd:1216-1220` returns a `float` multiplier; `game.gd:1171,2539,3155`, `main.gd:3364` and `native_execution_compiler.gd:123` consume it in stat, drop and fragment calculations. For sufficiently large valid capacity with positive free charge, `pow(allocation, reactorBoostExponent)` crosses binary64, producing INF. An exact big multiplier requires changing these gameplay consumers; a finite clamp or refusal at a level threshold would impose a new effective limit. S09 explicitly defers the broader simulation float-domain policy to S20.

Decision requested from parent and original astra: determine whether S10 is authorized to extend the involved gameplay consumers to a large-number multiplier, with exact integer capacity/allocation support, or whether a technically explicit refusal at a documented representation boundary is permissible under D01-1/D01-3. If neither fits the approved stage, adjust the stage contract/sequence before implementation. No numerical policy or refusal threshold has been selected here.

No Godot result is claimed. A local headless probe did not complete in the allotted wait and was terminated; its temporary script was removed. Static source trace is the present evidence. No S10 verification has passed, no main integration is eligible, and parent/astra reviews are pending.
